## 三、判断题（5 题，每题 2 分，正确填 √，错误填 ×）

**1.** 文件系统已经实现了数据的高度共享和低冗余，因此基本可以替代数据库系统。

**2.** 模式是相对稳定的，而实例是相对变动的；同一模式在不同时刻可以有不同的实例。

**3.** 由于一个数据库只有一个模式和一个内模式，所以模式/内模式映像是唯一的，但外模式/模式映像可以有多个。

**4.** 关系模型与层次模型、网状模型一样，都通过显式的物理指针来表示实体之间的联系。

**5.** DBA 是一个具有最高权限的"人员"，而非软件或角色账号。

### 一、单选题答案

**1. C**
数据管理技术发展的三个阶段依次为：人工管理 → 文件系统 → 数据库系统。

**2. C**
数据库系统的特点是数据共享性高、**冗余度低**（并非"完全无冗余"），适度冗余有时是必要的（如为提高查询性能建立的派生数据）。"完全无冗余"的说法过于绝对。

**3. C**
物理存储结构变化属于内模式变化，应修改**模式/内模式映像**使模式不变，从而保持外模式与应用程序不变，对应物理独立性。

**4. D**
数据模型三要素为数据结构、数据操作、数据的完整性约束条件。数据存储介质属于物理实现细节，不是数据模型的组成要素。

**5. C**
E-R 图中：矩形表示实体，椭圆表示属性，菱形表示联系，无向边连接。"选修"是联系，故用菱形。

**6. C**
层次模型的数据结构是**树**；网状模型是有向图；关系模型是二维表。

**7. C**
关系模型用二维表表示实体及实体间联系，无显式指针，数据独立性高，可表示任意联系。A 是层次/网状模型特征；B 错误；D 错误。

**8. B**
一个数据库有**一个**模式、**一个**内模式、**多个**外模式。

**9. A**
外模式/模式映像保证**逻辑独立性**；模式/内模式映像保证物理独立性。

**10. B**
DDL（Data Definition Language）是数据定义语言；DML 是数据操纵语言（查询、更新）。

### 四、简答题参考答案

**1. 数据管理技术发展的三个阶段及特点：**

| 阶段 | 主要特点 |
| ---- | ---- |
| 人工管理阶段 | 数据不保存；由应用程序管理数据；数据不共享；数据不独立 |
| 文件系统阶段 | 数据可长期保存；由文件系统管理；共享性差、冗余大；独立性差；文件间无联系 |
| 数据库系统阶段 | 数据结构化；共享性高、冗余度低；独立性高；由 DBMS 统一管理与控制（安全、完整、并发、恢复） |

**2. 数据模型三要素及反映的特性：**

- **数据结构**：描述数据库组成对象及对象间联系，反映**静态特性**，是数据模型最基本的部分，也是数据模型分类的依据；
- **数据操作**：描述允许执行的操作及规则（检索、插入、删除、修改），反映**动态特性**；
- **数据的完整性约束条件**：一组完整性规则的集合，反映**约束特性**，保证数据的正确、有效、相容。

**3. 三级模式与二级映像：**

三级模式：

- **外模式**（子模式/用户模式）：用户可见的局部数据逻辑结构，**多个**；
- **模式**（逻辑模式/概念模式）：全体数据的全局逻辑结构，**1 个**；
- **内模式**（存储模式）：数据的物理存储结构与存取方法，**1 个**。

二级映像与独立性：

- **外模式/模式映像**：当模式变化时，修改此映像使外模式不变，应用程序不变 → **逻辑独立性**；
- **模式/内模式映像**：当内模式（物理存储）变化时，修改此映像使模式不变 → **物理独立性**。

**4. DBMS 的主要功能：**

1. 数据定义（DDL）：定义三级模式、二级映像、完整性约束、安全性约束；
2. 数据操纵（DML）：检索、插入、修改、删除；
3. 数据库运行管理：并发控制、安全性控制、完整性检查、恢复管理、事务管理；
4. 数据库建立与维护：载入、转换、转储、恢复、重组织、重构造、性能监控；
5. 数据组织存储与管理：数据字典、文件组织、索引结构、缓冲区管理；
6. 数据通信接口：与 OS、网络、其他 DBMS 或文件系统的接口（ODBC、JDBC 等）。

### 五、分析题参考答案

**1. 三种逻辑模型对比：**

| 维度 | 层次模型 | 网状模型 | 关系模型 |
| ---- | ---- | ---- | ---- |
| 数据结构 | 树 | 有向图 | 二维表 |
| 联系表示 | 仅 1:n（双亲-子女），无法直接表示 m:n | 1:n（多对多需用两个 1:n 拆解） | 任意联系，统一用表与外码 |
| 数据独立性 | 差 | 较差 | 高 |
| 查询语言性质 | 过程性 | 过程性 | 非过程性（SQL） |

关系模型由于结构单一、理论严谨、独立性高，已成为现代数据库主流；层次/网状模型已基本退出主流应用。

**2. 数据独立性分析：**

模式变化（员工拆分为在职/离职两表）属于**逻辑结构变化**，应通过修改**外模式/模式映像**使外模式保持不变，从而原有基于外模式编写的应用程序无需修改。

- 修改对象：外模式/模式映像；
- 不变层：外模式、应用程序；
- 实现的独立性：**逻辑数据独立性**。

这正体现了二级映像将应用程序与逻辑结构解耦的设计目标。

**3. E-R 模型描述：**

- **实体**：学生（属性：学号、姓名、性别）、课程（属性：课程号、课程名、学分）；
- **码**：学生的码为学号；课程的码为课程号；
- **联系**：学生与课程之间为"选修"联系，类型为 **m:n**，该联系自身带属性"成绩"；
- **E-R 图描述**：画两个矩形（学生、课程），椭圆分别连接各自属性（学号下加下划线表示主码，课程号同理），中间画一菱形（选修），菱形两侧用无向边分别连到学生和课程矩形，边上标 m 与 n；菱形另连一椭圆"成绩"作为联系属性。

**4. DBS 组成与角色差异：**

DBS 由 DB、硬件、软件（含 DBMS）、人员四部分组成。三类人员角色：

- **DBA**：全面管理和控制数据库，决定模式与存储结构、定义安全性与完整性、监控运行与恢复、重组重构；
- **应用程序员**：在外模式基础上设计与编写应用程序，并进行调试与安装；
- **最终用户**：通过应用系统界面或 DBMS 查询语言访问数据库，是数据的实际使用者。

三者权限依次降低，DBA 拥有最高权限。

### 六、综合题参考答案

**1. 文件系统改用数据库系统的综合分析：**

（1）数据库系统相比文件系统的优势：

- **数据结构化**：数据面向整个组织，整体结构化，并描述数据间联系；文件系统记录内有结构但整体无结构；
- **共享性**：数据为多用户多应用共享，冗余度低；文件系统共享性差、冗余大；
- **独立性**：通过二级映像实现逻辑/物理独立性；文件系统独立性差；
- **控制能力**：DBMS 提供安全性、完整性、并发控制、恢复能力；文件系统无统一控制。

（2）两级映像与独立性：

- **外模式/模式映像** → 逻辑独立性；
- **模式/内模式映像** → 物理独立性。

（3）更换存储设备与升级索引结构的处理：

- 该变化属于**内模式变化**（物理存储结构与存取方法变化）；
- 由 DBA 修改**模式/内模式映像**，使**模式保持不变**；
- 由于模式不变，外模式不变，应用程序无需修改；
- 这体现的是**物理数据独立性**。
- 实操中通常通过 DBMS 提供的工具调整存储参数、重建索引，由 DBMS 自动维护映像。

**2. 图书馆数据库系统综合设计：**

（1）E-R 图（文字描述）：

- 实体：图书（书号、书名、作者、出版社）、读者（读者号、姓名、单位）；
- 码：图书的码为书号；读者的码为读者号；
- 联系：图书与读者之间为"借阅"联系，类型为 **m:n**，带属性"借阅日期"；
- 图形：两个矩形（图书、读者），各自属性用椭圆连接（书号、读者号下加下划线表示主码），中间一菱形（借阅），菱形两侧无向边连到两矩形并标注 m、n，菱形另连一椭圆"借阅日期"作为联系属性。

（2）转换为关系模型：

```sql
-- DBMS: MySQL 8.0；存储引擎：InnoDB
CREATE TABLE Book (
    BookNo   CHAR(10)  NOT NULL,
    Title    VARCHAR(100) NOT NULL,
    Author   VARCHAR(50),
    Publisher VARCHAR(50),
    PRIMARY KEY (BookNo)
);

CREATE TABLE Reader (
    ReaderNo CHAR(10)  NOT NULL,
    Name     VARCHAR(50) NOT NULL,
    Unit     VARCHAR(80),
    PRIMARY KEY (ReaderNo)
);

CREATE TABLE Borrow (
    BookNo    CHAR(10)  NOT NULL,
    ReaderNo  CHAR(10)  NOT NULL,
    BorrowDate DATE     NOT NULL,
    PRIMARY KEY (BookNo, ReaderNo, BorrowDate),
    FOREIGN KEY (BookNo)   REFERENCES Book(BookNo),
    FOREIGN KEY (ReaderNo) REFERENCES Reader(ReaderNo)
);
```

- `Book` 主码：`BookNo`；
- `Reader` 主码：`ReaderNo`；
- `Borrow` 主码：`(BookNo, ReaderNo, BorrowDate)`；外码：`BookNo`（引用 Book）、`ReaderNo`（引用 Reader）。

（3）采用关系模型而非层次模型的理由：

- 图书与读者之间是典型的 m:n 联系，关系模型可直接通过"借阅"关系表表达；层次模型只能表示 1:n，需用冗余结点或虚拟结点拆解，复杂且失真；
- 关系模型数据独立性高，结构简单、易扩展；
- 关系模型基于集合论与关系代数，理论严谨，支持非过程性 SQL，便于开发；
- 完整性约束（实体、参照、用户定义）支持强。

（4）DBA 关键职责（结合图书馆场景）：

- 决定数据库的信息内容与结构（如确认图书、读者、借阅三个关系的字段与码）；
- 决定存储结构与存取策略（如为 BookNo、ReaderNo 建立 B+ 树索引，对借阅表按借阅日期分区）；
- 定义安全性约束（如读者只能查询自己的借阅记录）和完整性约束（如还书日期不早于借阅日期）；
- 监控数据库运行，制定转储与恢复策略，定期备份借阅记录；
- 根据运行情况改进设计、重组织或重构造数据库；
- 管理用户与权限，维护审计日志。

</details>
