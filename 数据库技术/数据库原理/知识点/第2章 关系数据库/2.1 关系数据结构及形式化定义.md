# 2.1 关系数据结构及形式化定义

关系数据库是建立在**关系模型**（relational model）基础上的数据库。关系模型由 E.F. Codd 于 1970 年提出，其数据结构非常单一，在用户看来，关系模型中数据的逻辑结构就是一张二维表。本节从严格的集合论角度给出**域**、**笛卡尔积**和**关系**的形式化定义，进而讨论关系的性质、关系模式与关系数据库模式，为后续的[[2.3 关系的完整性|完整性约束]]与[[2.4 关系代数|关系代数]]奠定形式化基础。

## 2.1.1 域

> [!definition] 域的定义
> **域**（domain）是一组具有相同数据类型的值的集合。记作 $D$。

域是关系模型中最基本的构造单元。例如：

- $D_1 = \{张三, 李四, 王五\}$（姓名集合）
- $D_2 = \{男, 女\}$（性别集合）
- $D_3 = \{18, 19, 20, 21\}$（年龄集合，整数子集）

域中元素的个数称为域的**基数**（cardinality），记作 $|D|$。例如 $|D_2| = 2$。

> [!tip] 域与数据类型
> 域强调的是"取值范围"这一语义概念，而数据类型是数据库系统层面的实现概念。关系模式中每个属性都对应一个域，用以限定该属性可取的合法值集合。

## 2.1.2 笛卡尔积

> [!definition] 笛卡尔积
> 给定一组域 $D_1, D_2, \cdots, D_n$（这些域可以有相同的），则
> $$D_1 \times D_2 \times \cdots \times D_n = \{(d_1, d_2, \cdots, d_n) \mid d_i \in D_i, \, i = 1, 2, \cdots, n\}$$
> 称为这组域的**笛卡尔积**（Cartesian product）。

其中：

- $(d_1, d_2, \cdots, d_n)$ 称为一个**元组**（tuple）；
- $d_i$ 称为元组的一个**分量**（component），$d_i \in D_i$；
- 若所有域 $D_i$ 均为有限集，且 $|D_i| = m_i$，则笛卡尔积的基数为：
  $$|D_1 \times D_2 \times \cdots \times D_n| = \prod_{i=1}^{n} m_i$$

笛卡尔积可表示为一张二维表，每行对应一个元组，每列对应一个域。

**示例**：设 $D_1 = \{张三, 李四\}$，$D_2 = \{男, 女\}$，$D_3 = \{19, 20\}$，则笛卡尔积 $D_1 \times D_2 \times D_3$ 共有 $2 \times 2 \times 2 = 8$ 个元组：

| 姓名 | 性别 | 年龄 |
| ---- | ---- | ---- |
| 张三 | 男   | 19   |
| 张三 | 男   | 20   |
| 张三 | 女   | 19   |
| 张三 | 女   | 20   |
| 李四 | 男   | 19   |
| 李四 | 男   | 20   |
| 李四 | 女   | 19   |
| 李四 | 女   | 20   |

> [!warning] 笛卡尔积的语义问题
> 笛卡尔积将所有可能的组合都列出，其中很多元组在现实中并无意义（如"张三"不可能既"男"又"女"）。因此实际的关系只是笛卡尔积的一个**有意义的子集**。

## 2.1.3 关系

> [!definition] 关系
> 笛卡尔积 $D_1 \times D_2 \times \cdots \times D_n$ 的子集称为在域 $D_1, D_2, \cdots, D_n$ 上的**关系**（relation），记作
> $$R(D_1, D_2, \cdots, D_n) \subseteq D_1 \times D_2 \times \cdots \times D_n$$
> 其中 $R$ 表示关系的名字，$n$ 称为关系的**目**或**度**（degree）。

- 当 $n = 1$ 时，称该关系为**单元关系**（unary relation）；
- 当 $n = 2$ 时，称该关系为**二元关系**（binary relation）；
- 一般地，$n$ 目关系有 $n$ 个属性。

关系中的每个元素是关系的一个**元组**，通常用 $t$ 表示。关系是一张二维表，表的每一行对应一个元组，每一列对应一个域（属性）。

### 候选码与主码

> [!definition] 候选码
> 若关系中的某一属性组的值能**唯一地标识**一个元组，而其任意真子集都不能标识一个元组，则称该属性组为**候选码**（candidate key）。

> [!definition] 主码
> 若一个关系有多个候选码，选定其中一个作为该关系的**主码**（primary key）。

相关术语：

- **主属性**（prime attribute）：包含在任何一个候选码中的属性；
- **非主属性**（non-prime attribute）或**非码属性**：不包含在任何候选码中的属性；
- **全码**（all-key）：关系模式的所有属性都是这个关系模式的候选码时，称为全码。

> [!example] 候选码示例
> 在学生关系 `Student(学号, 姓名, 身份证号, 年龄, 系别)` 中：
> - `学号` 能唯一标识一个学生，是候选码；
> - `身份证号` 也能唯一标识一个学生，是候选码；
> - 选定 `学号` 为主码，则 `学号` 和 `身份证号` 都是主属性，`姓名`、`年龄`、`系别` 是非主属性。

### 三类关系

| 类型 | 含义 | 在数据库中的角色 |
| ---- | ---- | ---------------- |
| 基本关系（基本表/基表） | 实际存在的表，实际存储数据的逻辑表示 | 数据库中实际存储数据的表 |
| 查询表 | 查询结果对应的表 | 临时存在，查询产生的结果 |
| 视图表 | 由基本表或其他视图表导出的表，是虚表 | 不实际存储数据，只存储定义 |

## 2.1.4 关系的性质

> [!theorem] 关系的基本性质
> 关系是一种规范化的二维表，作为关系数据模型的数据结构，关系必须满足以下六条性质：

1. **列是同质的**：每一列中的分量是同一类型的数据，来自同一个域。
2. **不同的列可出自同一个域**：每一列称为一个属性，不同的属性要给予不同的属性名以示区分。
3. **列的顺序无所谓**：列的次序可以任意交换，不改变关系的语义（实际数据库系统中列有存储顺序，但关系理论中无序）。
4. **任意两个元组不能完全相同**：关系中不允许出现重复元组（集合的性质）。
5. **行的顺序无所谓**：行的次序可以任意交换（实际数据库系统中行有存储顺序，但关系理论中无序）。
6. **分量必须取原子值**：每一个分量都必须是不可分的数据项，即满足**第一范式**（1NF）。

> [!warning] 规范化要求
> 性质 6 是关系模型最基本的要求。所有关系都必须是规范化的，即每一个分量必须是不可分的数据项。不允许"表中套表"，不允许属性值是集合、数组等复合结构。这一约束即为第一范式（1NF）的要求，详见[[6.3 范式（1NF、2NF、3NF、BCNF）]]。

> [!example] 违反第一范式的例子
> 下表中"联系电话"属性包含了多个值（集合），违反了分量原子性：
>
> | 姓名 | 联系电话              |
> | ---- | --------------------- |
> | 张三 | 13800000000, 010-1234 |
>
> 正确做法应拆分为两行，或拆分为"手机号"和"座机号"两个属性列。

## 2.1.5 关系模式

> [!definition] 关系模式
> 关系模式是**型**（type），关系是**值**（value）。关系模式是对关系的描述，必须指出这个关系由哪些属性构成、这些属性来自哪些域、属性与域之间的映像关系，以及属性间的数据依赖关系。

关系模式形式化地表示为一个五元组：

$$R(U, D, DOM, F)$$

| 符号   | 含义                                                                 |
| ------ | -------------------------------------------------------------------- |
| $R$    | 关系名                                                               |
| $U$    | 组成该关系的属性名集合                                               |
| $D$    | 属性组 $U$ 中属性所来自的域                                          |
| $DOM$  | 属性向域的映像集合（即每个属性来自哪个域）                           |
| $F$    | 属性间数据的依赖关系集合（函数依赖等，详见[[6.2 函数依赖]]）         |

> [!info] 关系模式与关系
> - **关系模式**是静态的、稳定的，描述关系的结构（型）；
> - **关系**是动态的、随时间变化的，是关系模式在某一时刻的当前值（值，也叫关系的实例/状态）。
>
> 关系模式往往简记为 $R(A_1, A_2, \cdots, A_n)$，其中 $R$ 是关系名，$A_i$ 是属性名。域 $D$ 和映像 $DOM$ 通常直接说明为属性的类型和长度。

**示例**：学生关系模式可记为

```
Student(学号, 姓名, 年龄, 性别, 系别)
```

其中 `学号` 为主码（用下划线标识）。

## 2.1.6 关系数据库与关系数据库模式

> [!definition] 关系数据库
> 在一个给定的应用领域中，所有实体及实体之间联系的**关系的集合**构成一个关系数据库。

与关系模式对应，关系数据库也有**型**与**值**之分：

| 概念             | 型                                     | 值                                     |
| ---------------- | -------------------------------------- | -------------------------------------- |
| 关系层面         | 关系模式 $R(U, D, DOM, F)$             | 关系（某一时刻的元组集合）             |
| 数据库层面       | 关系数据库模式（所有关系模式的集合）   | 关系数据库（所有关系的集合）           |

关系数据库模式是对关系数据库的描述，它包括若干域的定义以及在这些域上定义的若干关系模式。关系数据库是关系数据库模式在某一时刻对应的当前关系的集合。

## 小结

本节从集合论出发，依次定义了**域**、**笛卡尔积**和**关系**，确立了关系模型数据结构的形式化基础。关系是笛卡尔积的有意义子集，必须满足六条性质（尤其是分量原子性，即第一范式）。关系模式 $R(U, D, DOM, F)$ 是关系的型，描述关系的静态结构；关系是其值，随时间动态变化。这些概念是理解[[2.3 关系的完整性|完整性约束]]与[[2.4 关系代数|关系代数]]的前提。
