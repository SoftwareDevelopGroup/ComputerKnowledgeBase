# 11.3 物理优化

本节解决的核心问题是：**在代数优化（[[11.2 代数优化]]）确定了逻辑操作次序后，如何为每个操作选择代价最小的物理执行算法与存取路径**。物理优化决定"用什么算法执行选择、用什么算法执行连接、走索引还是全表扫描"，直接影响 I/O 与 CPU 代价。它是 [[11.4 查询优化器原理]]（CBO 代价估算）的核心内容，依赖 [[10.3 索引结构（B+树、散列索引）]] 的存取路径知识。

## 11.3.1 物理优化的概念

> [!definition] 物理优化（Physical Optimization）
> 物理优化是在代数优化得到的逻辑执行计划基础上，为每个操作选择**存取路径**（索引扫描 or 全表扫描）与**执行算法**（如连接的嵌套循环/排序归并/散列），生成物理执行计划的过程。

物理优化有两种方法：

| 方法 | 依据 | 特点 |
| ---- | ---- | ---- |
| **基于启发式规则** | 经验规则 | 简单快速，但不一定最优 |
| **基于代价估算** | 统计信息 + 代价模型 | 更精确，但需维护统计信息、计算开销 |

实际 DBMS 通常**二者结合**：先用启发式缩小候选计划空间，再用代价估算选最优。

## 11.3.2 基于启发式规则的物理优化

### 1. 选择操作的存取路径选择

对选择操作 $\sigma_F(R)$，存取路径选择规则：

> [!theorem] 选择操作的启发式规则
> 1. 若 $F$ 是**等值条件**且对应属性有**主索引或聚簇索引** → 用索引扫描；
> 2. 若 $F$ 是等值条件且属性有**辅助索引** → 视选择率：选择率低（命中少）用索引扫描，选择率高（命中多）可能退化为全表扫描；
> 3. 若 $F$ 是**范围条件**且属性有 B+ 树索引 → 用索引范围扫描；
> 4. 若**无可用索引**或选择率接近 1 → 全表扫描；
> 5. 若使用索引的代价（多次随机 I/O）超过全表扫描 → 选全表扫描。

> [!tip] 选择率阈值经验
> 经验上选择率 $< 10\%$~$20\%$ 时索引扫描通常更优；选择率更高时全表扫描更划算（顺序 I/O 比多次随机 I/O 快）。结论随磁盘类型变化：SSD 随机 I/O 代价低，索引扫描阈值可更高。

### 2. 连接操作的算法选择

连接是查询中最耗时的操作，算法选择至关重要。设连接 $R \bowtie S$，$R$ 为外层（驱动）表，$S$ 为内层表，$b_R, b_S$ 为各自页数，$n_R, n_S$ 为元组数，$M$ 为可用缓冲区页数。

#### 算法 1：嵌套循环连接（Nested Loop Join, NLJ）

> [!definition] 嵌套循环连接
> 对外层表 $R$ 的每个元组，扫描内层表 $S$ 全部元组匹配连接条件。
> - 简单形式（无索引）：$R$ 每元组扫一次 $S$，I/O 代价 $b_R + n_R \times b_S$；
> - 块嵌套循环（Block Nested Loop）：以块为单位，外层每块读入后内层扫一次，$b_R + b_R \times b_S / M_{\text{外}}$；
> - 索引嵌套循环（Index NLJ）：内层 $S$ 在连接属性上有索引，$R$ 每元组用索引查 $S$，$b_R + n_R \times h$（$h$ 为索引高度）。

适用：小表驱动大表；内层有索引时尤其高效。

#### 算法 2：排序归并连接（Sort-Merge Join, SMJ）

> [!definition] 排序归并连接
> 先对 $R, S$ 按连接属性排序，再用双指针归并匹配。
> - 代价：排序代价 + 归并代价（各扫一遍）$C_{\text{sort}}(R) + C_{\text{sort}}(S) + b_R + b_S$；
> - 若输入已按连接属性有序（如有聚簇索引），省去排序。

适用：大表连接、输入已有序、等值或范围连接。

#### 算法 3：散列连接（Hash Join, HJ）

> [!definition] 散列连接
> 用连接属性对较小的表（建表）$R$ 建散列表，再扫描 $S$ 探查匹配。
> - 代价：建表 $b_R$ + 探查 $b_S$（若散列表全在内存）$\approx b_R + b_S$；
> - 内存不足时分区（Grace Hash Join），多次刷盘。

适用：等值连接、无序输入、内存足够。

### 3. 三种连接算法代价对比

| 算法 | 代价（I/O） | 适用条件 | 局限 |
| ---- | ---- | ---- | ---- |
| 嵌套循环 NLJ | $b_R + n_R \times b_S$（无索引） | 小表驱动大表；内层有索引更佳 | 大表无索引时极慢 |
| 块嵌套 BNL | $b_R + b_R b_S / M_{\text{外}}$ | 大表连接、无索引 | 内存小时仍慢 |
| 索引嵌套 INL | $b_R + n_R \times h$ | 内层连接属性有索引 | 索引随机 I/O |
| 排序归并 SMJ | 排序 + $b_R + b_S$ | 大表、等值/范围、可利用有序 | 排序代价 |
| 散列连接 HJ | $\approx b_R + b_S$（内存足） | 等值连接、无序输入 | 不支持范围连接 |

> [!note] 算法选择启发式
> - 等值连接 + 内存足 → 散列连接；
> - 输入已有序（聚簇索引）→ 排序归并；
> - 小表驱动 + 内层有索引 → 索引嵌套循环；
> - 大表无索引、内存小 → 块嵌套循环。

## 11.3.3 基于代价估算的物理优化

启发式规则给出候选算法，最终选择基于代价估算。

### 1. 统计信息

代价估算依赖 DBMS 维护的统计信息（存于数据字典）：

| 符号 | 含义 |
| ---- | ---- |
| $n_R$ | 关系 $R$ 的元组数（基数） |
| $b_R$ | 关系 $R$ 占用的页数 |
| $l_R$ | 单元组字节数 |
| $V(A, R)$ | $R$ 中属性 $A$ 的不同值数 |
| $h$ | 索引高度 |
| $M$ | 可用缓冲区页数 |

### 2. 选择率估算

> [!theorem] 选择率公式
> - 等值选择 $\sigma_{A=c}$：$s = 1 / V(A, R)$；
> - 范围选择 $\sigma_{A > c}$：$s \approx (\max(A) - c) / (\max(A) - \min(A))$；
> - 合取 $F_1 \wedge F_2$：$s = s_1 \times s_2$（独立性假设）；
> - 析取 $F_1 \vee F_2$：$s = s_1 + s_2 - s_1 s_2$。

### 3. 代价估算公式

> [!theorem] 操作代价估算（I/O 为主）
> - **全表扫描**：$b_R$（无选择）/ $b_R \times s$（带选择，但通常仍扫全表 $b_R$，选择只影响输出大小）；
> - **索引等值扫描**：$h + s \cdot n_R / B_R$（索引高度 + 命中记录所在页数，若聚簇则连续）；
> - **嵌套循环连接**：$b_R + n_R \times b_S$；
> - **排序归并连接**：$3(b_R + b_S)$（排序 2 倍 + 归并 1 倍，简化估算）；
> - **散列连接**：$b_R + b_S$（内存足）。

> [!example] 代价估算示例
> 设 $R$ 100 页 10000 行，$S$ 200 页 20000 行，$M$ 足够大。
> - NLJ：$100 + 10000 \times 200 = 2,000,100$ 页 I/O（极慢）；
> - SMJ：$3 \times (100 + 200) = 900$ 页；
> - HJ：$100 + 200 = 300$ 页。
> 散列连接最优。若 $S$ 在连接属性上有索引（高度 3），INL：$100 + 10000 \times 3 = 30,100$，仍不如 HJ。
> 结论假设：传统机械磁盘、内存足够、等值连接、统计信息准确。

## 小结

物理优化为逻辑计划的每个操作选存取路径与执行算法。启发式规则（选择率低用索引、等值连接用散列、有序用排序归并、小表驱动用嵌套循环）缩小候选空间，代价估算（基于基数、选择率、页数、索引高度的公式）选最优。三种连接算法各有适用条件，代价对比是选择依据。物理优化与代数优化结合，构成查询优化器的核心。
