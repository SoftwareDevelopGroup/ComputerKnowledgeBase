# 3.1 SQL概述

SQL（Structured Query Language，结构化查询语言）是关系数据库的标准语言。本节解决的问题是：理解 SQL **是什么**、它**为什么能成为标准**、它由哪些**基本概念**构成，以及它在功能上由哪些**动词**支撑。这为后续 3.2–3.6 节的具体语法学习奠定整体认识。

## SQL 的产生与发展

SQL 是 1974 年由 Boyce 和 Chamberlin 提出，并在 IBM 公司的 San Jose 研究实验室研制的关系数据库管理系统原型 System R 上实现。由于 SQL 简洁易学、功能丰富，先后被美国国家标准局（ANSI）和国际标准化组织（ISO）制定为国家标准：

- **SQL-86**：第一个 SQL 标准；
- **SQL-89**：增加了完整性约束；
- **SQL-92（SQL2）**：显著扩展，目前广泛支持；
- **SQL:1999（SQL3）**：引入面向对象特性、触发器、递归等；
- 之后还有 SQL:2003、SQL:2008、SQL:2011、SQL:2016 等版本。

> [!info] SQL 与方言
> 不同 DBMS（MySQL、PostgreSQL、Oracle、SQL Server）对标准 SQL 的支持程度不一，并各自扩展了方言。本章 SQL 示例以 **MySQL 8.0** 为基准方言，标注其与标准 SQL 的差异。

## SQL 的特点

> [!definition] SQL 的主要特点
> 1. **综合统一**：SQL 集数据定义语言（DDL）、数据操纵语言（DML）、数据控制语言（DCL）于一体，可独立完成数据库生命周期中的全部活动。
> 2. **高度非过程化**：用户只需提出"做什么"，而无需指明"怎么做"；数据的存取路径和具体执行由 DBMS 的优化器自动完成。
> 3. **面向集合的操作方式**：操作对象和结果都是元组的集合（关系），而非一次一记录。
> 4. **以同一种语法结构提供多种使用方式**：SQL 既是交互式语言，也是嵌入式语言，二者语法一致。
> 5. **语言简洁，易学易用**：核心动词很少，接近自然语言。

### 1. 综合统一

在非关系模型（层次、网状）中，数据定义语言、数据操纵语言与数据控制语言彼此分离，定义与操作不能在运行期交替进行。SQL 把数据定义、操纵、控制统一在一种语言中，可以独立完成数据库生命周期的全部活动：

- 建立和删除数据库、模式、表、视图、索引；
- 数据查询、插入、删除、修改；
- 数据库安全性、完整性控制；
- 事务管理与嵌入式使用。

### 2. 高度非过程化

> [!tip] 非过程化的含义
> 用户只需用 SQL 描述"要什么数据"，而**不必关心存取路径**——DBMS 自动选择最优的存取路径并执行。这与层次/网状模型必须显式导航记录指针形成鲜明对比。

### 3. 面向集合的操作方式

非关系模型的一次一记录操作方式被 SQL 的**一次一集合**方式取代：查找、插入、删除、修改的对象都是元组集合，且操作结果也是集合。

### 4. 以同一种语法结构提供多种使用方式

SQL 既能作为**交互式语言**在终端或工具中直接使用，也能作为**嵌入式语言**嵌入到 C、Java、Python 等主语言中使用。两种方式下语法结构基本一致，便于学习和复用。详见 [[3.6 嵌入式SQL基础]]。

### 5. 语言简洁，易学易用

> [!example] SQL 核心动词极少
> 完成核心功能仅 9 个动词：`CREATE`、`DROP`、`ALTER`、`SELECT`、`INSERT`、`UPDATE`、`DELETE`、`GRANT`、`REVOKE`。

## SQL 的基本概念

SQL 支持数据库的三级模式结构，其中**基本表**对应模式，**视图**对应外模式，**存储文件**对应内模式。

```mermaid

    Ext[外部世界/用户视图]

    Base[基本表 Base Table<br/>模式]
    File[存储文件 Stored File<br/>内模式]

    Ext -->|定义于| View
    View -->|虚表, 来自| Base
    Base -->|存储于| File

    classDef ext fill:#fff3cd,stroke:#d39e00;
    classDef logic fill:#d1ecf1,stroke:#0c5460;
    classDef phys fill:#f8d7da,stroke:#721c24;

    class View,Base logic;
    class File phys;
```

### 1. 基本表（Base Table）

> [!definition] 基本表
> **基本表**是本身独立存在的表，在 SQL 中一个关系就对应一个基本表。一个（或多个）基本表对应一个存储文件；一个表可以带若干索引，索引也存放在存储文件中。

基本表是数据的实际载体，其结构由 [[3.2 数据定义]] 中的 `CREATE TABLE` 定义。

### 2. 视图（View）

> [!definition] 视图
> **视图**是从一个或几个基本表（或视图）导出的表。它本身不独立存储在数据库中，数据库中只存放视图的定义而不存放视图对应的数据，这些数据仍存放在导出视图的基本表中，因此视图是一张**虚表**。

视图的作用、定义与更新详见 [[3.5 视图]]。

### 3. 存储文件（Stored File）

存储文件是内模式层对数据的物理组织。一个存储文件存放一个或多个基本表的数据及索引。存储文件的逻辑结构组成了关系数据库的内模式。

## SQL 的功能动词

SQL 按功能划分为四类，每类由少量动词支撑：

| 功能分类 | 动词 | 主要作用 | 详见 |
| -------- | ---- | -------- | ---- |
| 数据查询（DQL） | `SELECT` | 查询数据 | [[3.3 数据查询]] |
| 数据定义（DDL） | `CREATE`、`DROP`、`ALTER` | 定义/删除/修改模式、表、视图、索引 | [[3.2 数据定义]]、[[3.5 视图]] |
| 数据操纵（DML） | `INSERT`、`UPDATE`、`DELETE` | 插入/修改/删除数据 | [[3.4 数据更新]] |
| 数据控制（DCL） | `GRANT`、`REVOKE` | 授予/回收权限 | [[MOC - 第4章]] |

> [!warning] 易错点
> - **DDL 与 DML 不可混淆**：`CREATE TABLE` 是定义表结构，不属于数据操纵；`SELECT` 虽常被单独称作 DQL，但教材通常并入广义 DML。
> - **`UPDATE` 是动词而非动词短语**：不要写成 `UPDATE TABLE`，标准 SQL 中表名前不带 `TABLE` 关键字（区别于 `ALTER TABLE`、`DROP TABLE`）。

## SQL 语句的书写约定

> [!tip] 大小写与分号
> 1. SQL 关键字大小写不敏感，本笔记采用**大写关键字 + 小写标识符**的教材惯例，提升可读性。
> 2. 每条 SQL 语句以**分号 `;`** 结尾（交互式终端通常强制要求）。
> 3. SQL 语句可跨多行书写，子句间换行以增强可读性。
> 4. 标识符（表名、列名）大小写敏感性取决于 DBMS：MySQL 默认对表名大小写敏感（受 `lower_case_table_names` 影响），对列名不敏感。

## 小结

- SQL 是关系数据库的标准语言，集 DDL、DML、DCL 于一体，特点为综合统一、高度非过程化、面向集合、语法统一、简洁易学。
- SQL 中**基本表**对应模式、**视图**对应外模式、**存储文件**对应内模式；视图是虚表。
- SQL 核心动词仅 9 个：`CREATE`、`DROP`、`ALTER`、`SELECT`、`INSERT`、`UPDATE`、`DELETE`、`GRANT`、`REVOKE`，分属数据定义、数据查询、数据操纵、数据控制四类。
