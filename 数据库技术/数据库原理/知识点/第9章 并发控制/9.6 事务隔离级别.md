# 9.6 事务隔离级别

[[9.3 封锁协议]] 的三级封锁协议与 2PL 是理论基础，但工程上 SQL 标准提供了更直观的**事务隔离级别**接口。本节介绍 SQL 标准定义的四种隔离级别（读未提交、读已提交、可重复读、串行化），给出各级别能解决的并发问题对照表，并简介 MySQL InnoDB 的默认级别与 MVCC 实现。

## SQL 标准四种隔离级别

> [!definition] 四种隔离级别（SQL-92 标准）
> SQL 标准定义了四种事务隔离级别，从低到高：
> 1. **读未提交（Read Uncommitted）**：事务可以读取其他事务未提交的数据。
> 2. **读已提交（Read Committed）**：事务只能读取其他事务已提交的数据。
> 3. **可重复读（Repeatable Read）**：保证事务内多次读取同一数据得到相同结果。
> 4. **串行化（Serializable）**：事务串行执行，完全隔离。

> [!note] 幻读
> SQL 标准还定义了一种现象——**幻读（Phantom Read）**：事务 $T_1$ 读取某些行的数据后，$T_2$ 插入了新行满足 $T_1$ 的查询条件。$T_1$ 再次执行同一查询时，多出一些"幻影"行。这与不可重复读（修改）不同，是新增数据引起的。

## 各级别能解决的并发问题对照表

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 一致性保证 |
| ---- | :---: | :---: | :---: | ---- |
| Read Uncommitted | ✗ 可能 | ✗ 可能 | ✗ 可能 | 无 |
| Read Committed | ✓ 防止 | ✗ 可能 | ✗ 可能 | 防脏读 |
| Repeatable Read | ✓ 防止 | ✓ 防止 | ✗ 可能（SQL 标准下） | 加防不可重复读 |
| Serializable | ✓ 防止 | ✓ 防止 | ✓ 防止 | 完全可串行化 |

> [!note] 表格解读
> - **隔离级别越高，一致性越强，但并发度越低**。
> - **Read Uncommitted 几乎不阻止任何问题**，实际中很少使用。
> - **Serializable 完全避免并发问题**，但接近串行执行，性能差。
> - **Repeatable Read 在 SQL 标准下不防幻读**——但 MySQL InnoDB 通过间隙锁（Gap Lock）在 RR 级别下也防幻读，是工程加强。

## 隔离级别与封锁协议的关系

> [!info] 隔离级别对应封锁协议
> 各隔离级别可以通过相应的封锁协议实现：

| 隔离级别 | 实现机制（基于封锁） | 防止问题 |
| ---- | ---- | ---- |
| Read Uncommitted | 不加锁（或仅 X 锁至事务结束） | 丢失修改 |
| Read Committed | 二级封锁协议 | 丢失修改 + 读脏 |
| Repeatable Read | 三级封锁协议 | 丢失修改 + 读脏 + 不可重复读 |
| Serializable | 严格两阶段封锁协议（S2PL）+ 范围锁 | 全部问题（包括幻读） |

> [!note] 范围锁与防幻读
> 防幻读需要在"查询的范围"上加锁——如对 `WHERE balance > 1000` 的查询条件加范围锁（Gap Lock），阻止其他事务插入满足条件的新行。这是 Serializable 级别与普通 RR 级别的区别。

## MySQL InnoDB 默认级别与 MVCC

### InnoDB 默认 Repeatable Read

> [!info] InnoDB 默认隔离级别
> MySQL InnoDB 默认隔离级别是 **Repeatable Read**（可重复读）。这与 SQL 标准的"默认"无关，是 InnoDB 的工程选择。在 RR 级别下，InnoDB 通过**间隙锁（Gap Lock）/ Next-Key Lock**也防止幻读——这是对 SQL 标准的加强。

### MVCC 多版本并发控制

> [!definition] MVCC
> **多版本并发控制（Multi-Version Concurrency Control, MVCC）**通过为每个事务提供数据的**历史版本快照**，实现"读不阻塞写、写不阻塞读"：
> - 每行数据保留多个版本（通过隐藏列 + undo log 链）。
> - 读事务根据隔离级别选择合适的快照版本读取，不加锁。
> - 写事务创建新版本，不修改旧版本。

> [!info] MVCC 在不同隔离级别下的行为
> - **Read Committed**：每次 SELECT 都读取最新的已提交版本（语句级快照）。
> - **Repeatable Read**：事务首次 SELECT 时建立快照，事务内所有后续 SELECT 都用此快照（事务级快照）——保证可重复读。
> - **Serializable**：InnoDB 在 RR + 强制所有读加共享锁，退化为基于锁的实现。

> [!example] MVCC 的优势
> - **读读并发**：多个读事务互不干扰。
> - **读写并发**：读事务读历史版本，写事务写新版本，互不阻塞——大幅提高并发度。
> - **避免死锁**：读不加锁，与写不形成循环等待。

> [!warning] MVCC 的代价
> - 需要存储多个版本，占用更多空间。
> - 长事务持有旧版本快照，导致 undo log 链变长，影响性能。
> - 仅对**读已提交**与**可重复读**两个级别实现，Serializable 退化为基于锁。

## SET TRANSACTION ISOLATION LEVEL SQL 示例

> [!example] 设置隔离级别
> ```sql
> -- 设置全局隔离级别
> SET GLOBAL TRANSACTION ISOLATION LEVEL READ COMMITTED;
>
> -- 设置会话隔离级别
> SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;
>
> -- 设置下一个事务的隔离级别
> SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
> ```

> [!example] 查看与切换隔离级别
> ```sql
> -- 查看当前会话隔离级别
> SELECT @@transaction_isolation;
>
> -- MySQL 5.7 之前的旧语法
> SELECT @@tx_isolation;
>
> -- 查看全局隔离级别
> SELECT @@GLOBAL.transaction_isolation;
>
> -- 临时切换到读已提交并验证
> SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
> START TRANSACTION;
> -- 此事务在读已提交级别下运行
> SELECT * FROM account WHERE id = 'A';
> COMMIT;
> ```

> [!warning] 隔离级别设置时机
> `SET TRANSACTION ISOLATION LEVEL` 必须在事务**开始前**设置。事务开始后无法更改隔离级别——SQL 标准要求隔离级别是事务的属性。

## 小结

> [!summary] 本节核心
> - SQL 标准定义四种隔离级别：读未提交 < 读已提交 < 可重复读 < 串行化。
> - 各级别依次解决：脏读 → 不可重复读 → 幻读。
> - 隔离级别对应封锁协议：RU 无保护、RC 二级协议、RR 三级协议、Serializable S2PL + 范围锁。
> - InnoDB 默认 RR，通过 MVCC 实现读写不阻塞，并通过 Next-Key Lock 防 SQL 标准未要求的幻读。
> - 用 `SET TRANSACTION ISOLATION LEVEL` 在事务前设置隔离级别。
