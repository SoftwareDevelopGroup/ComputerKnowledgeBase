# 4.2 身份鉴别

身份鉴别（Identification & Authentication）是数据库安全的第一道防线。任何对数据库的访问，DBMS 必须首先确认操作者的身份，只有通过鉴别的用户才能进入数据库系统并进一步接受存取控制。本节介绍身份鉴别的概念、常用鉴别方法，并以 MySQL 8.0 为例给出用户创建与口令管理的可运行 SQL。

## 一、身份鉴别的概念

> [!definition] 身份鉴别（Identification & Authentication, I&A）
> 用户访问数据库时，系统对用户身份进行识别与验证的过程，包括两个步骤：
> 1. **识别（Identification）**：用户声明自己是谁（提供用户标识，如用户名、账号）；
> 2. **鉴别（Authentication）**：系统验证用户声明的身份是否真实（提供凭证，如口令、指纹）。

身份鉴别解决的是"**你是谁**"的问题，是后续 [[4.3 存取控制]]（决定"你能做什么"）的前提。

> [!note] 识别 vs 鉴别
> 识别是"声明身份"，鉴别是"证明身份"。仅声明不证明，或证明与声明不符，都不能通过身份鉴别。

## 二、常用鉴别方法

| 鉴别方法 | 凭证类型 | 优点 | 缺点 | 典型应用 |
| ---- | ---- | ---- | ---- | ---- |
| 口令鉴别（密码） | 你知道的 | 简单、低成本、普及广 | 易被猜测、窃听、字典攻击 | 绝大多数 DBMS 默认 |
| 智能卡鉴别 | 你拥有的 | 比口令安全、可加密存储 | 卡片易丢失、需读卡设备 | 银行、高安全系统 |
| 生物特征鉴别 | 你本身的特征 | 唯一性强、不可转让 | 设备成本高、可能有误识率 | 指纹、虹膜、人脸 |
| 双因素/多因素 | 上述组合 | 安全性显著提升 | 流程稍复杂 | 重要业务系统 |

### 2.1 口令鉴别

最常用、最基础的鉴别方法。用户输入用户名和口令，DBMS 将口令与系统表中存储的口令比较，匹配则通过。

> [!warning] 口令存储安全
> 数据库**不得明文存储用户口令**。应使用加盐哈希（如 bcrypt、PBKDF2、Argon2）存储口令摘要，即使口令表泄露也无法反推原文。MySQL 8.0 默认使用 `caching_sha2_password` 插件对口令进行 SHA-256 哈希存储。

### 2.2 智能卡鉴别

智能卡内置加密芯片，存储用户私钥或数字证书。鉴别时需物理持有卡片并结合 PIN 码，属于"你拥有的"凭证。常用于 PKI 体系下的强身份认证。

### 2.3 生物特征鉴别

利用人体固有的生理特征（指纹、虹膜、人脸、声纹）或行为特征（签名笔迹、键盘敲击节奏）进行身份识别。优点是唯一性强、不可转让；缺点是设备成本较高，且存在误识率（FAR）与拒识率（FRR）。

### 2.4 多因素鉴别（MFA）

> [!tip] 多因素鉴别原则
> 同时验证"你知道的（口令）+ 你拥有的（智能卡）+ 你本身的（生物特征）"中的两个或多个因素，安全性远高于单一因素。如网银登录需"密码 + 短信验证码"。

## 三、MySQL 中的用户创建与口令管理

> [!info] 环境说明
> 以下 SQL 适用于 **MySQL 8.0**，使用 `mysql` 客户端连接，假设以 `root` 管理员身份执行。MySQL 8.0 默认认证插件为 `caching_sha2_password`，用户与权限信息存储在 `mysql` 系统库的 `user`、`db`、`tables_priv` 等表中。

### 3.1 最小示例表

为便于后续权限演示，先建立示例数据库与表：

```sql
-- MySQL 8.0，以 root 管理员执行
CREATE DATABASE IF NOT EXISTS scdb DEFAULT CHARSET utf8mb4;
USE scdb;

-- 学生表
CREATE TABLE Student (
    Sno   CHAR(9)      PRIMARY KEY,
    Sname VARCHAR(20)  NOT NULL,
    Ssex  CHAR(2)      CHECK (Ssex IN ('男','女')),
    Sage  INT,
    Sdept VARCHAR(20)
);

-- 插入示例数据
INSERT INTO Student VALUES
('202400001','张三','男',20,'计算机'),
('202400002','李四','女',21,'数学');
```

### 3.2 创建用户

```sql
-- 语法：CREATE USER '用户名'@'主机' IDENTIFIED BY '口令';
-- '主机' 限制该用户只能从哪些主机登录；'%' 表示任意主机（生产慎用）

CREATE USER 'u_reader'@'localhost' IDENTIFIED BY 'Reader@2024';
CREATE USER 'u_admin'@'localhost'  IDENTIFIED BY 'Admin@2024';

-- 查看已创建用户
SELECT User, Host, plugin FROM mysql.user WHERE User LIKE 'u_%';
```

> [!note] MySQL 8.0 用户标识
> MySQL 中用户由 `'用户名'@'主机名'` 唯一标识，`'u1'@'localhost'` 与 `'u1'@'%'` 是两个不同的用户。创建用户时若省略 `@'主机'`，默认为 `@'%'`。

### 3.3 修改口令

```sql
-- 方法一：ALTER USER（推荐，MySQL 8.0 标准方式）
ALTER USER 'u_reader'@'localhost' IDENTIFIED BY 'NewReader@2024';

-- 方法二：SET PASSWORD（兼容旧版本）
SET PASSWORD FOR 'u_reader'@'localhost' = 'AnotherPwd@2024';
```

> [!warning] MySQL 8.0 与旧版本差异
> MySQL 8.0 移除了 `GRANT ... IDENTIFIED BY` 直接在授权时创建用户的语法，**必须先用 `CREATE USER` 创建用户，再用 `GRANT` 授权**。这是与 MySQL 5.7 的一个重要区别。

### 3.4 删除用户与重命名

```sql
-- 删除用户（同时删除其权限）
DROP USER 'u_admin'@'localhost';

-- 重命名用户（保留权限）
RENAME USER 'u_reader'@'localhost' TO 'u_reader2'@'localhost';
```

### 3.5 查看用户权限

```sql
-- 查看当前用户权限
SHOW GRANTS;

-- 查看指定用户权限
SHOW GRANTS FOR 'u_reader'@'localhost';
```

> [!example] 身份鉴别的完整流程
> 1. 管理员 `root` 创建用户并设置初始口令：`CREATE USER ... IDENTIFIED BY ...`
> 2. 用户首次登录，输入用户名 + 口令；MySQL 8.0 默认使用 `caching_sha2_password` 校验
> 3. 用户登录后可自行修改口令：`SET PASSWORD = 'NewPwd@2024'`
> 4. 通过身份鉴别后，用户才能进入下一步存取控制（[[4.3 存取控制]]）

## 小结

- 身份鉴别包括**识别**（声明身份）和**鉴别**（验证身份）两步，是数据库安全的第一道防线。
- 常用方法：口令、智能卡、生物特征、多因素鉴别，安全性依次提升。
- MySQL 8.0 必须先 `CREATE USER` 创建用户，再用 `GRANT` 授权；口令默认以 SHA-256 哈希存储。
- 身份鉴别只回答"你是谁"，回答"你能做什么"需要 [[4.3 存取控制]]。
