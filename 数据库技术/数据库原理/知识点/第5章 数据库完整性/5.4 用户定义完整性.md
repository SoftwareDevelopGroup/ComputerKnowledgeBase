# 5.4 用户定义完整性

实体完整性（[[5.2 实体完整性]]）和参照完整性（[[5.3 参照完整性]]）是关系模型必须满足的两类"固有"约束，由 SQL 标准自动支持。但实际业务中还有大量领域特定的约束——"年龄必须在 0-150 之间"、"性别只能是男或女"、"部门名称不能为空"——这些无法用主码或外码表达，由用户根据业务规则自定义，称为**用户定义完整性**。本节介绍 NOT NULL、UNIQUE、CHECK 三类约束及其在 MySQL 8.0 中的实现。

## 一、用户定义完整性的概念

> [!definition] 用户定义完整性（User-Defined Integrity）
> 针对具体应用领域和业务规则，由用户自定义的完整性约束。它表达领域特定的语义约束，如取值范围、格式、列间关系等。
>
> 用户定义完整性是**前两类完整性的补充**：实体完整性与参照完整性由 SQL 标准强制支持，而用户定义完整性依赖 DBMS 提供的 `NOT NULL`、`UNIQUE`、`CHECK` 等机制由用户声明。

用户定义完整性按作用范围分为：

| 类别 | 作用对象 | 实现机制 | 示例 |
| ---- | ---- | ---- | ---- |
| 属性（列）上的约束 | 单个列 | `NOT NULL`、`UNIQUE`、`CHECK` | `Sage INT CHECK (Sage>0 AND Sage<150)` |
| 元组上的约束 | 一个元组内多列关系 | `CHECK`（表级） | `CHECK (EndDate >= StartDate)` |

## 二、属性上的约束

### 2.1 NOT NULL 约束

> [!definition] NOT NULL
> 限制列不允许取 NULL 值。INSERT/UPDATE 时若该列为 NULL，则拒绝操作。

```sql
-- MySQL 8.0，使用 scdb 数据库
USE scdb;

CREATE TABLE Student (
    Sno   CHAR(9)      PRIMARY KEY,        -- 主码自动 NOT NULL
    Sname VARCHAR(20)  NOT NULL,           -- 姓名不允许为空
    Ssex  CHAR(2),
    Sage  INT,
    Sdept VARCHAR(20)  DEFAULT '未分配'     -- 允许为空，默认值为'未分配'
);

-- 违约演示
INSERT INTO Student(Sno, Sname) VALUES ('202400001', NULL);
-- ERROR 1048 (23000): Column 'Sname' cannot be null
```

### 2.2 UNIQUE 约束

> [!definition] UNIQUE
> 限制列（或列组合）的取值必须唯一，允许有多个 NULL（NULL 不参与唯一性比较）。

```sql
CREATE TABLE Student (
    Sno    CHAR(9)      PRIMARY KEY,
    IDCard CHAR(18)     UNIQUE,             -- 身份证号唯一
    Email  VARCHAR(50) UNIQUE              -- 邮箱唯一
);

-- 违约演示
INSERT INTO Student(Sno, IDCard) VALUES ('202400001', '110101200001011234');
INSERT INTO Student(Sno, IDCard) VALUES ('202400002', '110101200001011234');
-- ERROR 1062 (23000): Duplicate entry '110101200001011234' for key 'IDCard'

-- 多个 NULL 允许（NULL 不参与比较）
INSERT INTO Student(Sno, IDCard) VALUES ('202400003', NULL);
INSERT INTO Student(Sno, IDCard) VALUES ('202400004', NULL);   -- 允许
```

> [!note] UNIQUE vs PRIMARY KEY
> | 对比项 | PRIMARY KEY | UNIQUE |
> | ---- | ---- | ---- |
> | 是否允许 NULL | 不允许 | 允许（多个 NULL） |
> | 每表数量 | 仅 1 个 | 可多个 |
> | 自动建索引 | 聚簇索引 | 非聚簇索引 |
> | 语义 | 实体标识 | 唯一性约束 |

### 2.3 CHECK 约束（列级）

> [!definition] CHECK
> 限制列值必须满足指定条件（布尔表达式）。INSERT/UPDATE 时若条件为假，则拒绝操作。

```sql
CREATE TABLE Student (
    Sno   CHAR(9)      PRIMARY KEY,
    Sname VARCHAR(20)  NOT NULL,
    Ssex  CHAR(2)      CHECK (Ssex IN ('男','女')),    -- 性别只能是男或女
    Sage  INT          CHECK (Sage >= 0 AND Sage <= 150),  -- 年龄合理范围
    Sdept VARCHAR(20)
);

-- 违约演示
INSERT INTO Student(Sno, Sname, Ssex, Sage) VALUES ('202400001','张三','X',20);
-- ERROR 3819 (HY000): Check constraint 'student_chk_1' is violated.

INSERT INTO Student(Sno, Sname, Ssex, Sage) VALUES ('202400002','李四','女',200);
-- ERROR 3819 (HY000): Check constraint 'student_chk_2' is violated.
```

> [!info] MySQL 8.0.16+ 的 CHECK 支持
> MySQL 8.0.16 起原生支持 `CHECK` 约束（之前版本仅解析语法但不强制执行）。MySQL 8.0.16 之前需用触发器（[[5.5 触发器实现完整性]]）模拟 CHECK 行为。其他主流 DBMS（Oracle、PostgreSQL、SQL Server）早已支持 CHECK。

## 三、元组上的约束

### 3.1 表级 CHECK 约束

> [!definition] 元组级 CHECK
> `CHECK` 约束写在表级（不在某列内），可引用同一元组的多个列，约束列间关系。

```sql
-- 示例：员工合同的结束日期不早于开始日期
CREATE TABLE Contract (
    ContractID CHAR(10)    PRIMARY KEY,
    EmpID      CHAR(9)      NOT NULL,
    StartDate  DATE        NOT NULL,
    EndDate    DATE,
    Salary     DECIMAL(10,2),
    -- 元组级 CHECK：EndDate 必须大于等于 StartDate（EndDate 允许为 NULL 表示无固定期限）
    CHECK (EndDate IS NULL OR EndDate >= StartDate)
);

-- 违约演示
INSERT INTO Contract VALUES ('C001','202400001','2026-01-01','2025-12-31',8000);
-- ERROR 3819: Check constraint 'contract_chk_1' is violated.

-- 正常插入
INSERT INTO Contract VALUES ('C002','202400002','2026-01-01','2026-12-31',9000);
INSERT INTO Contract VALUES ('C003','202400003','2026-01-01',NULL,7500);   -- 允许，EndDate 为 NULL
```

## 四、MySQL 中的 CONSTRAINT 与 CHECK

### 4.1 命名约束

> [!definition] CONSTRAINT 子句
> SQL 标准允许通过 `CONSTRAINT 约束名 ...` 为约束命名，便于后续查看、启用/禁用、删除约束。

```sql
-- 命名约束示例
CREATE TABLE Employee (
    EmpID    CHAR(9)        PRIMARY KEY,
    Name     VARCHAR(20)   NOT NULL,
    Age      INT,
    Salary   DECIMAL(10,2),
    Dept     VARCHAR(20),
    
    -- 命名的列级 CHECK
    CONSTRAINT chk_age CHECK (Age >= 18 AND Age <= 65),
    -- 命名的元组级 CHECK
    CONSTRAINT chk_salary_positive CHECK (Salary > 0)
);
```

### 4.2 查看与删除约束

```sql
-- 查看表的约束
SHOW CREATE TABLE Employee;

-- 查询 information_schema 中的约束信息
SELECT CONSTRAINT_NAME, CHECK_CLAUSE
FROM information_schema.CHECK_CONSTRAINTS
WHERE CONSTRAINT_SCHEMA = 'scdb';

-- 删除命名约束
ALTER TABLE Employee DROP CHECK chk_age;            -- MySQL 8.0 语法
-- 或标准 SQL：ALTER TABLE Employee DROP CONSTRAINT chk_age;
```

### 4.3 综合示例：完整用户定义完整性

```sql
-- 综合：包含 NOT NULL、UNIQUE、CHECK 的完整表定义
CREATE TABLE Employee (
    EmpID     CHAR(9)        PRIMARY KEY,
    Name      VARCHAR(20)   NOT NULL,
    Gender    CHAR(2)        CHECK (Gender IN ('男','女')),
    Age       INT            CHECK (Age BETWEEN 18 AND 65),
    Email     VARCHAR(50)    UNIQUE,
    Phone     CHAR(11),
    HireDate  DATE           NOT NULL,
    Salary    DECIMAL(10,2)  DEFAULT 0,
    Dept      VARCHAR(20)    DEFAULT '未分配',
    ManagerID CHAR(9),
    
    -- 命名元组级约束
    CONSTRAINT chk_phone_length CHECK (CHAR_LENGTH(Phone) = 11),
    CONSTRAINT chk_salary_range CHECK (Salary >= 0 AND Salary <= 999999.99)
);
```

## 五、用户定义完整性的检查与违约处理

| 操作 | 检查内容 | 违约处理 |
| ---- | ---- | ---- |
| INSERT | 新元组的列值是否满足 NOT NULL / UNIQUE / CHECK | 拒绝操作并返回错误 |
| UPDATE 列 | 更新后的列值是否满足约束 | 拒绝操作并返回错误 |

> [!note] CHECK 约束的局限性
> CHECK 约束只能引用当前元组的列，**不能跨元组或跨表**。例如：
> - 不能在 CHECK 中查询其他表（如"部门必须在 Department 表中存在"——这是外码职责）；
> - 不能在 CHECK 中查询本表其他元组（如"工资不得超过本部门平均工资的 3 倍"）；
> - 不能引用聚合函数、子查询。
>
> 这类复杂业务规则需用**触发器**（[[5.5 触发器实现完整性]]）实现。

## 小结

- 用户定义完整性表达领域特定业务规则，是实体完整性与参照完整性的补充。
- 属性级约束：`NOT NULL`（非空）、`UNIQUE`（唯一）、`CHECK`（条件）。
- 元组级约束：表级 `CHECK`，可引用同一元组的多列。
- MySQL 8.0.16+ 原生支持 CHECK；使用 `CONSTRAINT 约束名` 为约束命名便于管理。
- CHECK 约束不能跨元组或跨表，复杂业务规则需用触发器实现。
