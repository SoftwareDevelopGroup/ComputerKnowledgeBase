触发器在事件发生时自动执行，函数是可在 SQL 中调用的计算单元。二者都是数据库端的可编程对象，但触发时机、调用方式与典型场景不同。本节基于 MySQL 8.0，Oracle/SQL Server 差异处单独标注。

## 触发器（TRIGGER）

触发器是绑定到表事件（`INSERT/UPDATE/DELETE`）的特殊过程，由 DBMS 在事件发生时自动调用，应用无法显式调用。

### 创建触发器

```sql
-- MySQL 8.0
-- 依赖表：employee(id, name, salary, dept_id, updated_at)
--          employee_audit(id, emp_id, old_salary, new_salary, op_user, op_time)
CREATE TABLE employee_audit (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    emp_id      BIGINT       NOT NULL,
    old_salary  NUMERIC(15,2),
    new_salary  NUMERIC(15,2),
    op_user     VARCHAR(64)  NOT NULL DEFAULT CURRENT_USER(),
    op_time     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP
);

DELIMITER $$
CREATE TRIGGER trg_employee_salary_audit
AFTER UPDATE ON employee
FOR EACH ROW
BEGIN
    IF OLD.salary <> NEW.salary THEN
        INSERT INTO employee_audit(emp_id, old_salary, new_salary)
        VALUES (NEW.id, OLD.salary, NEW.salary);
    END IF;
END$$
DELIMITER ;

-- 触发测试
UPDATE employee SET salary = salary + 500 WHERE id = 1;
SELECT * FROM employee_audit WHERE emp_id = 1;
```

### 触发时机与事件

| 维度 | 取值 |
| ---- | ---- |
| 时机 | `BEFORE`（事件前校验/改写）、`AFTER`（事件后处理） |
| 事件 | `INSERT`、`UPDATE`、`DELETE` |

MySQL 仅支持行级触发（`FOR EACH ROW`）。Oracle 与 SQL Server 同时支持语句级触发（`FOR EACH STATEMENT`），适用于批处理后的聚合操作。

### 触发器应用场景

1. **审计日志**：记录敏感表的变更前后值（上例）。
2. **数据校验**：`BEFORE INSERT/UPDATE` 检查业务规则，不满足则 `SIGNAL SQLSTATE` 报错。
3. **级联操作**：维护冗余字段或派生数据，如主表更新时同步更新汇总表。
4. **软删除实现**：`BEFORE DELETE` 改写为 `UPDATE ... SET deleted=1`。

> [!warning] 触发器的隐式执行风险
> - 触发器对应用层不可见，排查问题时易遗漏。
> - 触发器内访问的表若也带触发器，可能形成递归或锁等待。
> - 高频表上的行级触发器会显著放大写开销，应在性能基线中测量。

## 自定义函数（FUNCTION）

函数是可在 SQL 表达式中调用的过程对象，必须返回一个值，且在 MySQL 中**不能**直接执行修改数据的语句（`SQL SECURITY` 限制）。

### 创建函数

```sql
-- MySQL 8.0
-- 计算给定部门平均薪资，返回 NUMERIC
DELIMITER $$
CREATE FUNCTION fn_dept_avg_salary(p_dept_id BIGINT)
RETURNS NUMERIC(15,2)
READS SQL DATA
DETERMINISTIC
BEGIN
    DECLARE v_avg NUMERIC(15,2);
    SELECT AVG(salary) INTO v_avg
    FROM employee
    WHERE dept_id = p_dept_id;
    RETURN IFNULL(v_avg, 0);
END$$
DELIMITER ;

-- 在 SQL 中调用
SELECT dept_id, fn_dept_avg_salary(dept_id) AS avg_salary
FROM department
ORDER BY avg_salary DESC;
```

> [!note] MySQL 函数声明关键点
> - `READS SQL DATA`：声明函数读取但不修改数据，否则默认禁止查询。
> - `DETERMINISTIC`：相同输入恒定输出；缺省时 MySQL 可能拒绝创建以避免复制不一致。
> - 函数内禁止 `INSERT/UPDATE/DELETE`（存储过程可以）。

## 函数 vs 存储过程

| 维度 | 函数 | 存储过程 |
| ---- | ---- | ---- |
| 返回值 | 必须**一个**标量/表值 | 可 0 或多个 `OUT/INOUT` |
| 调用位置 | SQL 表达式中 | `CALL` 语句 |
| 数据修改 | MySQL 中一般不允许 | 允许 |
| 事务控制 | 不应包含 | 可包含 `START TRANSACTION/COMMIT` |
| 典型用途 | 计算、格式化、派生列 | 业务编排、多步写操作 |

详见 [[2.1 视图、存储过程]]。

## 限制与易错点

- MySQL 不支持同一表同一事件/时机创建多个同类触发器（如两个 `AFTER INSERT`），Oracle 支持。
- 触发器中使用 `NEW`/`OLD` 引用前后值，`BEFORE` 时机可修改 `NEW`，`AFTER` 时机不可。
- 函数在 `WHERE` 中调用会阻碍索引使用（函数作用在索引列上时索引失效），应改用生成列或表达式索引。
- Oracle 的 `CREATE TRIGGER` 语法、`BEFORE` 语义与 `:OLD`/`:NEW` 引用方式与 MySQL 不同，不能直接迁移。
