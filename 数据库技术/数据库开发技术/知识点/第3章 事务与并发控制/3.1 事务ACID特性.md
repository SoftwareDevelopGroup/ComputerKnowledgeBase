事务（Transaction）是数据库管理系统保证数据一致性的基本执行单元。本节不仅给出 ACID 定义，更通过具体并发与故障场景说明每个性质“解决什么问题、如何实现、在何种条件下失效”。本节以 MySQL 8.0 InnoDB 为例，Oracle/PostgreSQL 差异处单独标注。

## 事务定义

事务是一组数据库操作的逻辑单元，这些操作要么全部成功提交，要么全部回滚，对数据库而言是一次不可分割的状态转换。

```sql
-- MySQL 8.0 / InnoDB
-- 场景：账户 A 向账户 B 转账 100 元，必须保证两个 UPDATE 同时生效或同时回滚
START TRANSACTION;
UPDATE account SET balance = balance - 100 WHERE id = 1;  -- A 扣款
UPDATE account SET balance = balance + 100 WHERE id = 2;  -- B 入账
COMMIT;
-- 若两步之间发生故障，执行 ROLLBACK 而非 COMMIT
```

### 原子性（Atomicity）

> [!def] 定义
> 事务中的全部操作要么全部执行成功，要么全部不生效，不存在“部分执行”的中间状态。

**解决什么问题**：上例中第二个 `UPDATE` 失败时，第一个 `UPDATE` 必须被撤销，否则钱会“凭空消失”。

**实现机制**：InnoDB 通过 undo log 记录修改前的数据，回滚时按 undo log 反向恢复。

### 一致性（Consistency）

> [!def] 定义
> 事务执行前后，数据库从一个合法状态转换到另一个合法状态，所有约束（主键、外键、CHECK、业务规则）都得到满足。

**注意**：一致性是应用层与 DBMS 协作的结果。DBMS 保证约束不被违反；应用层保证业务规则正确（如转账后 A+B 总额不变）。

**关系**：原子性、隔离性、持久性是手段，一致性是目标。

### 隔离性（Isolation）

> [!def] 定义
> 并发执行的事务之间互不干扰，一个事务的中间状态对其他事务不可见。

**解决什么问题**：事务 A 转账过程中余额的中间状态不应被事务 B 读到。详见 [[3.2 并发问题与隔离级别]]。

**实现机制**：锁机制与 MVCC（多版本并发控制）。InnoDB 在 REPEATABLE READ 下通过 MVCC 让读不阻塞写、写不阻塞读。

### 持久性（Durability）

> [!def] 定义
> 事务一旦提交，对数据的修改永久保存，即使系统崩溃也不丢失。

**实现机制**：InnoDB 通过 redo log（WAL，Write-Ahead Logging）记录修改，提交时强制刷盘 redo log，崩溃后重放 redo log 恢复已提交数据。

> [!warning] 持久性的边界
> - 持久性不保证磁盘物理损坏后数据不丢失，需要备份策略（见 [[Oracle 数据库管理]]）。
> - 某些配置（如 `innodb_flush_log_at_trx_commit=0`）会牺牲持久性换取性能，生产环境必须设为 1。

## 事务控制语句

| 语句 | 作用 | MySQL 语义 |
| ---- | ---- | ---- |
| `BEGIN` / `START TRANSACTION` | 开启事务 | 后者可带隔离级别与访问模式 |
| `COMMIT` | 提交事务，使修改永久生效 | 默认 `AUTOCOMMIT=1` 时每条语句自动提交 |
| `ROLLBACK` | 回滚事务，撤销全部修改 | 回滚到事务开始 |
| `SAVEPOINT name` | 设置保存点 | 支持部分回滚 |
| `ROLLBACK TO name` | 回滚到保存点 | 保存点之后撤销，之前保留 |
| `RELEASE SAVEPOINT name` | 删除保存点 | 不影响事务状态 |
| `SET TRANSACTION ISOLATION LEVEL ...` | 设置隔离级别 | 影响后续事务 |

### 保存点示例

```sql
-- MySQL 8.0
START TRANSACTION;
INSERT INTO orders(id, customer_id) VALUES (100, 1);
SAVEPOINT sp_items;
INSERT INTO order_item(order_id, product_id, quantity) VALUES (100, 1, 2);
-- 若该项校验失败，回滚到保存点而非整个事务
ROLLBACK TO sp_items;
-- 仍可继续插入其他明细
INSERT INTO order_item(order_id, product_id, quantity) VALUES (100, 2, 1);
COMMIT;
```

## 事务边界与隔离

事务边界由应用控制：在 JDBC 中通过 `conn.setAutoCommit(false)` 显式开启，`commit()`/`rollback()` 结束（见 [[4.1 ODBC、JDBC原理]]）。事务应**短**，长事务会持有锁、阻塞并发、放大死锁概率。

> [!note] MySQL AUTOCOMMIT
> MySQL 默认 `AUTOCOMMIT=1`，每条 SQL 自动作为一个事务提交。要开启显式事务必须先 `SET AUTOCOMMIT=0` 或使用 `START TRANSACTION`。Oracle 默认不自动提交，必须显式 `COMMIT`。

## 限制与易错点

- ACID 不是免费的：隔离级别越高，并发度越低（详见 [[3.2 并发问题与隔离级别]]）。
- 分布式场景下本地 ACID 不足以保证全局一致，需 2PC/3PC/TCC 等分布式事务协议。
- 长事务在 MVCC 下会阻止 undo log 回收，导致表空间膨胀。
