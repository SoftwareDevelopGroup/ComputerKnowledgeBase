# 5.1 用户创建、修改、删除

本节解决的核心问题是：**如何在Oracle中创建业务用户？如何安全管理用户的表空间配额、默认表空间、密码过期、账户锁定？如何正确删除用户？** 用户是数据库安全的第一防线，不合规的用户配置会导致安全漏洞或存储空间滥用。

## 5.1.1 用户与身份验证方式总览

> [!definition] Oracle用户（User / Schema）
> Oracle用户（Schema）是数据库对象（表、索引、视图、存储过程等）的**逻辑所有者**，也是权限管理的**基本载体**。"用户"与"模式（Schema）"在Oracle中几乎一一对应：一个用户默认拥有一个与用户名同名的Schema，二者通常混用。

| 身份验证方式 | 语法 | 说明 | 适用场景 |
| ---- | ---- | ---- | ---- |
| **密码验证（默认）** | `IDENTIFIED BY password` | 用数据库内部存储的加密密码验证。11g+密码默认大小写敏感！ | 绝大多数业务用户、应用连接用户 |
| **外部验证（OS验证）** | `IDENTIFIED EXTERNALLY` | 通过操作系统用户验证，数据库不存密码。登录时要求OS用户与数据库用户存在映射关系（OS认证、LDAP/Kerberos） | DBA本地登录（/ as sysdba）、批量运维脚本 |
| **全局验证** | `IDENTIFIED GLOBALLY AS 'DN'` | 通过企业目录服务（Oracle Internet Directory/OID）集中验证，SSL证书或LDAP。 | 大型企业统一身份认证 |

> [!warning] Oracle 11g+ 密码大小写敏感
> Oracle 11g R1开始，密码默认区分大小写。以下两种情况会导致密码错误：
> - 老应用密码写的是大写，实际数据库密码是小写（或反过来）
> - 从10g expdp导出导入到11g+，SEC_CASE_SENSITIVE_LOGON参数设为TRUE（默认），老密码可能不被识别
>
> 临时关闭大小写敏感（生产不推荐，仅用于升级过渡期）：
> ```sql
> ALTER SYSTEM SET sec_case_sensitive_logon = FALSE SCOPE=BOTH;
> ```

## 5.1.2 CREATE USER创建用户完整语法

> [!definition] CREATE USER 语法（Oracle 19c常用子句）
> ```sql
> CREATE USER 用户名
>   IDENTIFIED { BY 密码 | EXTERNALLY | GLOBALLY AS '外部名' }
>   [DEFAULT TABLESPACE 默认表空间名]
>   [TEMPORARY TABLESPACE 临时表空间名 | 临时表空间组名]
>   [QUOTA { 整数 K|M|G|T|E|P | UNLIMITED } ON 表空间名 [, QUOTA ...]]
>   [PROFILE profile文件名]
>   [PASSWORD EXPIRE]          -- 首次登录必须改密码
>   [ACCOUNT { LOCK | UNLOCK }] -- 账户锁定状态
>   [DEFAULT TABLESPACE  ...]
>   [DEFAULT ROLE { ALL | role [, role ...] | ALL EXCEPT role [, role ...] | NONE }]
>   [ENABLE EDITIONS]          -- 11g+基于版本的重定义
> ```

### 1. 完整SQL示例（Oracle 19c）

```sql
-- ==========================================
-- 案例1：创建标准业务用户（生产常用模板）
-- ==========================================
CREATE USER scott
  IDENTIFIED BY "ScottPass123##"          -- 密码（大小写敏感，建议含特殊字符）
  DEFAULT TABLESPACE users                 -- 表、索引默认创建在此
  TEMPORARY TABLESPACE temp                -- 排序、哈希连接等临时操作使用
  QUOTA 100M ON users                      -- users表空间限额100M
  QUOTA UNLIMITED ON indx                  -- indx索引表空间不限额
  PROFILE app_user_profile                 -- 使用自定义业务用户Profile
  PASSWORD EXPIRE                          -- 首次登录必须修改密码
  ACCOUNT UNLOCK;                          -- 解锁（默认就是UNLOCK，显式写更清晰）

-- ==========================================
-- 案例2：创建HR演示用户（自带样例Schema）
-- ==========================================
CREATE USER hr
  IDENTIFIED BY hr
  DEFAULT TABLESPACE example
  TEMPORARY TABLESPACE temp
  QUOTA UNLIMITED ON example;

-- 授予基本权限（见5.2/5.3节）
GRANT CREATE SESSION TO hr;
GRANT CREATE TABLE, CREATE VIEW, CREATE SEQUENCE TO hr;

-- ==========================================
-- 案例3：创建只读报表用户（仅查询）
-- ==========================================
CREATE USER report_user
  IDENTIFIED BY "Report2024##"
  DEFAULT TABLESPACE users
  TEMPORARY TABLESPACE temp
  QUOTA 0 ON users                          -- 禁止创建任何对象
  PROFILE readonly_profile
  PASSWORD EXPIRE;

-- ==========================================
-- 案例4：创建OS外部验证用户（运维脚本用）
-- ==========================================
CREATE USER ops$oracle
  IDENTIFIED EXTERNALLY                     -- 由OS用户oracle验证
  DEFAULT TABLESPACE users
  TEMPORARY TABLESPACE temp
  QUOTA 10M ON users;
-- 用法：OS登录为oracle后，sqlplus / 即可直接登录数据库（无需密码）
```

> [!note] 密码复杂度函数verify_function_11g
> 生产强制密码复杂度，Oracle内置提供：
> ```sql
> -- 执行Oracle自带脚本创建校验函数（11g+版本）
> @$ORACLE_HOME/rdbms/admin/utlpwdmg.sql
> -- 该脚本会：① 创建verify_function_11g函数 ② 修改DEFAULT PROFILE的PASSWORD_VERIFY_FUNCTION为该函数
> -- 密码要求：至少8位、包含字母+数字+特殊字符、不能和用户名相同、不能是常用弱口令
> ```
> 自定义校验函数参见[[5.4 资源配置与Profile文件]]。

## 5.1.3 必设子句说明

### 1. DEFAULT TABLESPACE（默认表空间）

| 不设置的后果 | 设置建议 |
| ---- | ---- |
| 11g+默认是`USERS`表空间；10g及以前默认是`SYSTEM`表空间（**非常危险！SYSTEM满了数据库挂**） | 业务用户**必须显式指定**非SYSTEM的业务表空间，如`USERS`、业务专用表空间 |

> [!note] 数据库级默认临时/永久表空间设置
> ```sql
> -- 查数据库级默认永久表空间
> SELECT property_value FROM database_properties WHERE property_name='DEFAULT_PERMANENT_TABLESPACE';
> -- 查默认临时表空间
> SELECT property_value FROM database_properties WHERE property_name='DEFAULT_TEMP_TABLESPACE';
>
> -- 修改数据库级默认（影响后续CREATE USER未显式指定的）
> ALTER DATABASE DEFAULT TABLESPACE users;
> ALTER DATABASE DEFAULT TEMPORARY TABLESPACE temp;
> ```

### 2. QUOTA配额：用户能在表空间用多少空间

| 语法 | 效果 |
| ---- | ---- |
| `QUOTA 500M ON users` | 在users表空间最多占用500MB，超过报ORA-01536 |
| `QUOTA UNLIMITED ON users` | 无限制（相当于表空间多大就能用多大） |
| `QUOTA 0 ON users` | 完全禁止在users上创建任何对象 |
| 不写任何QUOTA子句 | 所有表空间默认QUOTA=0，无法创建表/索引 |

```sql
-- 授予所有表空间不限配额（系统权限，比一个个QUOTA ON方便）
GRANT UNLIMITED TABLESPACE TO scott;

-- 撤销：
REVOKE UNLIMITED TABLESPACE FROM scott;
```

> [!tip] QUOTA绕过风险
> - 拥有`UNLIMITED TABLESPACE`系统权限或`RESOURCE`角色（12c之前版本的RESOURCE隐含带UNLIMITED TABLESPACE）会忽略QUOTA限制。
> - Oracle 12c+：`RESOURCE`角色不再隐含带`UNLIMITED TABLESPACE`权限，需单独授予。

## 5.1.4 ALTER USER修改用户

> [!definition] ALTER USER：修改用户属性
> 语法与CREATE USER几乎完全一致，所有CREATE USER支持的子句在ALTER USER中都可用。

### 1. 常用ALTER USER场景（Oracle 19c）

```sql
-- ========== 1. 修改密码 ==========
ALTER USER scott IDENTIFIED BY "NewScottPass2024##";

-- DBA在用户忘记密码时重置（不需要知道旧密码）
ALTER USER hr IDENTIFIED BY hr2024 REPLACE old_password;  -- 可选REPLACE（用户自己改密码时需要旧密码）

-- ========== 2. 解锁/锁定账户 ==========
ALTER USER scott ACCOUNT UNLOCK;     -- 解锁（如因FAILED_LOGIN_ATTEMPTS超限被锁）
ALTER USER old_user ACCOUNT LOCK;    -- 锁定离职员工账户（比删除更安全，可随时恢复）

-- ========== 3. 强制立即改密码（下次登录必须改） ==========
ALTER USER scott PASSWORD EXPIRE;

-- ========== 4. 调整表空间配额 ==========
ALTER USER scott QUOTA 500M ON users;            -- 从100M提升到500M
ALTER USER scott QUOTA UNLIMITED ON indx;        -- 索引表空间放开
ALTER USER scott QUOTA 0 ON users;               -- 收回users所有配额

-- ========== 5. 切换默认表空间/临时表空间 ==========
ALTER USER report_user DEFAULT TABLESPACE report_data;
ALTER USER report_user TEMPORARY TABLESPACE temp_report;

-- ========== 6. 切换Profile ==========
ALTER USER scott PROFILE security_strict_profile;

-- ========== 7. 强制结束当前用户所有连接会话（改密码/删除前常用） ==========
-- 查SID, SERIAL#：
SELECT s.sid, s.serial#, s.username, s.status, s.sql_id
  FROM v$session s WHERE username='SCOTT';
-- 逐个Kill：
ALTER SYSTEM KILL SESSION 'sid, serial#' IMMEDIATE;
-- 12c+ 一次性Kill用户所有连接：
ALTER USER scott ACCOUNT LOCK;   -- 先锁，防止新会话进来
-- 然后执行上面的KILL
```

## 5.1.5 DROP USER删除用户

> [!danger] DROP USER ... CASCADE 不可逆永久删除！
> CASCADE会级联删除该用户Schema下的**所有对象**（表、索引、视图、序列、存储过程、触发器、同义词、DBLink...），且Oracle不提供回收站闪回（Flashback Drop对整用户CASCADE无效）。
> **生产删除用户前，务必先：**
> 1. **先导出用户所有对象备份**：`expdp system/password schemas=scott directory=dump_dir dumpfile=scott_20240101.dmp logfile=scott_20240101.log`
> 2. **先锁定账户30天观察**：没有业务报错再真正删
> 3. **对象数超过1000个的大Schema**，建议先`ALTER USER scott ACCOUNT LOCK;`稳定观察一周再DROP

### 1. 语法与示例

```sql
-- 情况一：用户下无任何对象（空用户）
DROP USER report_user;              -- 直接删即可

-- 情况二：用户下有任何对象（有表、视图、存储过程等）
DROP USER scott CASCADE;            -- 必须CASCADE！否则报错：
-- ORA-01922: CASCADE specified to drop 'SCOTT'
-- CASCADE会级联删除：表、索引、约束、视图、序列、同义词、存储过程、包、函数、触发器、类型、库、DBLink、Java类……所有该Schema的对象
```

> [!warning] 用户拥有对象但其他Schema引用时的报错
> 例如B用户的视图VIEW_B依赖SCOTT的TABLE_A，DROP USER SCOTT CASCADE时：
> - TABLE_A被删除
> - VIEW_B会被**标记为INVALID无效**，不会自动删除
> - 所有引用SCOTT对象的同义词、存储过程、视图都可能变为INVALID，需要后续编译修复
>
> 删前查依赖：
> ```sql
> SELECT owner, name, type, referenced_name
>   FROM dba_dependencies
>  WHERE referenced_owner = 'SCOTT' AND owner <> 'SCOTT';
> ```

## 5.1.6 预定义DBA用户区别

> [!note] Oracle关键预定义账户说明
> Oracle安装后默认有几十到上百个预定义账户（19c约110+个），绝大部分生产建议保持锁定。重点掌握前4个：

| 账户 | 默认密码 | 身份 | 能否AS SYSDBA | 用途说明 |
| ---- | ---- | ---- | ---- | ---- |
| **SYS** | 安装时设置（同SYSTEM） | **超级用户，数据字典所有者** | ✅ **必须**用AS SYSDBA登录 | 所有数据字典基表（TAB$/IND$/USER$等）、系统包（DBMS_STATS等）都在SYS Schema。DBA日常不要直接用SYS做普通DDL。 |
| **SYSTEM** | 安装时设置（同SYS） | 普通DBA管理用户 | ❌ 默认不能（除非显式GRANT SYSDBA给SYSTEM） | OEM控制台创建的默认DBA账户，做日常DBA工作。不要把业务对象建在SYSTEM Schema下！ |
| **DBSNMP** | 12c+默认锁定，手动设置 | OEM代理监控账户 | ❌ | Oracle Management Agent用它来监控数据库性能与可用性。12c+ Cloud Control时代用得少了。 |
| **SYSMAN** | 已淘汰（12c+删除） | EM资料档案库所有者 | ❌ | 11g及之前的Enterprise Manager Grid Control用。12c EM Express取代后不再创建。 |
| **OUTLN** | 锁定 | 存储大纲（Stored Outline） | ❌ | 优化器计划稳定功能，强制SQL走固定计划。11g+被SQL Plan Baseline取代，保持默认锁定即可。 |
| **XDB** | 锁定 | XML DB功能账户 | ❌ | XMLType、XML DB Protocol Server使用。用到XML存储时解锁。 |
| **ANONYMOUS** | 锁定 | HTTP匿名访问XDB用 | ❌ | 不对外提供HTTP访问时保持锁定。 |

> [!warning] SYS登录必须AS SYSDBA（11g+强制）
> 直接写`CONNECT SYS/password`会立即报错：
> ```
> ORA-28009: connection as SYS should be as SYSDBA or SYSOPER
> ```
> 正确写法：`CONNECT SYS/password AS SYSDBA;` 或本地OS认证：`CONNECT / AS SYSDBA;`（要求当前OS用户在dba组）。

## 5.1.7 查询用户信息的数据字典视图

| 视图 | 用途 | 典型SQL |
| ---- | ---- | ---- |
| **DBA_USERS** | 所有用户详细信息（用户名、状态、默认表空间、Profile、创建时间、锁定时间、过期时间） | `SELECT username, account_status, default_tablespace, profile, created FROM dba_users ORDER BY username;` |
| **DBA_TS_QUOTAS** | 各用户在各表空间的配额使用情况 | `SELECT tablespace_name, username, bytes/1024/1024 used_mb, max_bytes/1024/1024 max_mb FROM dba_ts_quotas;` |
| **USER_USERS** | 当前登录用户自身信息（不需要DBA权限） | `SELECT * FROM user_users;` |
| **V$SESSION** | 当前在线用户会话 | `SELECT username, sid, serial#, program, machine, logon_time FROM v$session WHERE username IS NOT NULL;` |

```sql
-- 综合查询：SCOTT用户完整画像（创建时间、状态、配额、Profile、对象数、当前连接数）
SELECT u.username, u.account_status, u.created, u.lock_date, u.expiry_date,
       u.default_tablespace, u.temporary_tablespace, u.profile,
       (SELECT COUNT(*) FROM dba_objects o WHERE o.owner = u.username) total_objects,
       (SELECT COUNT(*) FROM v$session s WHERE s.username = u.username) active_sessions
  FROM dba_users u
 WHERE u.username = 'SCOTT';

-- 所有账户状态分布统计（查看有多少被锁/过期/开放）
SELECT account_status, COUNT(*) AS cnt
  FROM dba_users
 GROUP BY account_status
 ORDER BY cnt DESC;
-- 典型状态：OPEN（正常）、LOCKED（锁）、EXPIRED（密码过期）、EXPIRED & LOCKED、EXPIRED(GRACE)（宽限期）
```

## 小结

本节详述了CREATE USER完整语法（IDENTIFIED BY/DEFAULT TABLESPACE/QUOTA/PROFILE/PASSWORD EXPIRE/ACCOUNT LOCK各子句），ALTER USER的常用修改场景（改密码、解锁、调整配额），以及DROP USER CASCADE的高风险注意事项（务必先备份+先锁定观察）。区分了SYS（超级用户，必须AS SYSDBA登录）与SYSTEM（普通DBA）的职责差异，以及11g+密码大小写敏感、verify_function_11g密码复杂度校验等Oracle专有特性。配合DBA_USERS/DBA_TS_QUOTAS视图可全面掌握用户配置状态。
