# 5.5 Oracle安全审计基础

本节解决的核心问题是：**如何记录数据库用户操作的审计轨迹？标准审计和统一审计（12c+推荐）的区别是什么？如何开启SYSDBA操作审计、登录审计、关键表DML审计？** 审计是数据库安全合规（等保2.0、SOX、GDPR）的刚需，事后追责与安全事件溯源离不开审计记录。

## 5.5.1 为什么需要审计

> [!definition] 数据库审计（Database Auditing）
> 数据库审计是记录用户对数据库执行的**操作行为日志**的机制。典型审计内容：谁（用户名/OS用户）、在何时、从哪里（IP/主机名）、对什么对象、执行了什么操作（SQL）、执行结果（成功/失败）、影响多少行。

| 审计目标 | 典型场景 |
| ---- | ---- |
| **事后追责溯源** | 核心业务表被恶意删改时，查到是谁、几点、哪台机器执行的DROP/TRUNCATE/DELETE |
| **合规要求** | 等保2.0三级/四级要求保留6个月以上审计日志；金融/医疗/央企强制合规审计 |
| **入侵检测** | 异常行为识别：某用户凌晨3点批量SELECT敏感表（疑似拖库），某用户1小时内200次登录失败（暴力破解尝试） |
| **内部威胁防范** | DBA滥用高权限：监控SYSDBA执行的所有SQL，防止删表/泄露数据 |

## 5.5.2 两种审计体系：标准审计 vs 统一审计（12c+推荐）

| 对比项 | 标准审计 Standard Auditing（11g及以前） | 统一审计 Unified Auditing（12c+） |
| ---- | ---- | ---- |
| **引入版本** | Oracle 8i时代起存在 | 12c R1新增，19c默认启用 |
| **审计记录存储** | SYS.AUD$系统表（SYSTEM表空间）、操作系统文件 | 统一审计AUDSYS Schema下的只读视图（默认SYSAUX表空间，可迁移） |
| **查看视图** | DBA_AUDIT_TRAIL / DBA_AUDIT_SESSION / DBA_AUDIT_OBJECT / DBA_FGA_AUDIT_TRAIL | **UNIFIED_AUDIT_TRAIL**（单视图统一所有审计源，含标准审计+FGA+RMAN+DV+SYS操作） |
| **SYSDBA审计** | 默认不记录，需单独设AUDIT_SYS_OPERATIONS=TRUE写入OS文件 | 默认开启，统一写入UNIFIED_AUDIT_TRAIL，**无法关闭**（合规要求） |
| **性能影响** | 较高（写SYS.AUD$有行锁竞争，大量并发时SYSTEM表空间争用） | 低（SGA中的审计缓冲区异步写，几乎零影响） |
| **审计管理** | 分散（AUDIT/NOAUDIT标准审计、DBMS_FGA细粒度审计、RMAN配置分别开） | 统一（AUDIT POLICY一条策略覆盖标准+FGA+管理操作） |
| **生产推荐** | 11g及以前版本用 | **12c+首选，迁移旧系统必须切换到统一审计** |

> [!note] 19c统一审计默认启用
> Oracle 19c新安装实例默认启用**混合模式统一审计**（纯统一审计需手动 relink oracle 开启），即同时写入UNIFIED_AUDIT_TRAIL和SYS.AUD$，但推荐只用前者。

## 5.5.3 标准审计（Standard Auditing，兼容旧系统）

### 1. 开启步骤（11g）

```sql
-- (1) 设置审计开关参数（需重启实例）
ALTER SYSTEM SET audit_trail=DB, EXTENDED SCOPE=SPFILE;
-- audit_trail可选值：
--   NONE        = 关闭
--   DB          = 写入SYS.AUD$，SQLTEXT和绑定变量不存
--   DB,EXTENDED = 存SQLTEXT和绑定变量值（★推荐用这个，才能查到具体SQL）
--   OS          = 写操作系统文件（不用数据库表，满了不会影响SYSTEM表空间）
--   XML         = 写XML格式OS文件

-- (2) 重启生效
SHUTDOWN IMMEDIATE;
STARTUP;
SHOW PARAMETER audit_trail;   -- 确认是DB, EXTENDED

-- (3) 开启SYSDBA操作审计（可选，但安全合规必开，写入OS文件！）
ALTER SYSTEM SET audit_sys_operations=TRUE SCOPE=SPFILE;
ALTER SYSTEM SET audit_file_dest='/u01/app/oracle/admin/orcl/adump' SCOPE=SPFILE;
-- 重启后，所有SYS/AS SYSDBA用户执行的SQL都会被写到audit_file_dest下的*.aud文件中（不是DB！因为SYS.AUD$还没OPEN前就要记录启动操作）
```

### 2. 常用AUDIT语句（开审计）

```sql
-- ========== 语句级审计 ==========
-- 审计所有建表删表（不区分哪个用户建的）
AUDIT CREATE TABLE, DROP TABLE, ALTER TABLE BY ACCESS;
-- 审计登录失败（防止暴力破解，WHENEVER NOT SUCCESSFUL）
AUDIT SESSION WHENEVER NOT SUCCESSFUL;
-- 审计所有登录（成功+失败）
AUDIT SESSION;

-- ========== 权限级审计 ==========
-- 审计任何使用DROP ANY TABLE系统权限的操作（查谁乱删表）
AUDIT DROP ANY TABLE BY ACCESS WHENEVER NOT SUCCESSFUL;
-- 审计ALTER SYSTEM/ALTER DATABASE（改参数/数据文件）
AUDIT ALTER SYSTEM, ALTER DATABASE BY ACCESS;

-- ========== 对象级审计 ==========
-- 审计对HR.EMPLOYEES表的所有DML/DDL（敏感工资表）
AUDIT SELECT, INSERT, UPDATE, DELETE, ALTER ON hr.employees BY ACCESS;
-- 审计对关键业务表的TRUNCATE
AUDIT TRUNCATE ON app.big_transaction_table BY ACCESS;

-- 说明：
-- BY ACCESS = 每发生一次就记一条（准确但量大）
-- BY SESSION = 同一会话同类操作只记一条（省空间但细节少）
-- WHENEVER [NOT] SUCCESSFUL = 只记成功/失败的，不加就都记
```

### 3. 关闭审计NOAUDIT

```sql
NOAUDIT CREATE TABLE, DROP TABLE, ALTER TABLE;
NOAUDIT SESSION;
NOAUDIT ALL ON hr.employees;
```

### 4. 查看标准审计记录（常用视图）

```sql
-- 总审计记录视图（SYS.AUD$的公开视图）
SELECT TO_CHAR(extended_timestamp, 'YYYY-MM-DD HH24:MI:SS') audit_time,
       username,                       -- Oracle用户名
       os_username,                    -- OS登录用户名
       userhost,                       -- 客户端主机名
       terminal,
       action_name,                    -- 操作名：LOGON/LOGOFF/CREATE TABLE/DROP ANY TABLE等
       returncode,                     -- 0=成功，非0=错误号（如1017=密码错）
       obj_owner, obj_name,            -- 被操作对象
       sql_text, sql_bind              -- audit_trail=DB,EXTENDED时才有具体SQL
  FROM dba_audit_trail
 WHERE extended_timestamp > SYSDATE - 7   -- 查最近7天
 ORDER BY extended_timestamp DESC;

-- 登录/登出专项视图
SELECT * FROM dba_audit_session WHERE username='SCOTT' ORDER BY timestamp# DESC;
```

> [!danger] 标准审计空间管理陷阱
> 标准审计开了DB/EXTENDED后，**SYS.AUD$会不断膨胀占满SYSTEM表空间**，SYSTEM满了数据库就挂！必须：
> 1. 把SYS.AUD$迁移到独立的AUDIT表空间（11gR2+支持迁移）：
>    ```sql
>    BEGIN DBMS_AUDIT_MGMT.SET_AUDIT_TRAIL_LOCATION(
>      audit_trail_type => DBMS_AUDIT_MGMT.AUDIT_TRAIL_DB_STD,
>      default_tablespace => 'AUDIT_TS', default_temp_tablespace => 'TEMP'); END;
>    /
>    ```
> 2. 配置自动清理作业（DBMS_AUDIT_MGMT包）：保留6个月，过期自动删
> 3. 每月检查AUD$表大小与AUDIT_TS表空间使用率

## 5.5.4 统一审计（Unified Auditing，12c+推荐）

### 1. 确认是否启用纯统一审计（可选，推荐19c开启）

```bash
# 纯统一审计需要relink（12c~18c需要手动，19c默认混合模式）
cd $ORACLE_HOME/rdbms/lib
make -f ins_rdbms.mk uniaud_on ioracle
# 检查：SELECT value FROM v$option WHERE parameter='Unified Auditing';  应为TRUE
```

### 2. 统一审计三大组成

| 组成 | 说明 | 典型用途 |
| ---- | ---- | ---- |
| **预定义审计策略（Built-in Policies）** | ORA_SECURECONFIG、ORA_LOGON_FAILURES、ORA_ACCOUNT_MGMT、ORA_DATABASE_PARAMETER等Oracle自带默认启用的策略 | 覆盖了绝大多数安全敏感操作，直接用就行，不用自己写 |
| **自定义审计策略（CREATE AUDIT POLICY）** | 可以自定义审计条件：WHEN 'USER IN (SCOTT,HR)' EVALUATE PER STATEMENT/Session/Instance，支持动作+对象+用户+IP条件组合 | 业务定制：比如只审计财务用户9点~18点外的登录、只审计SALES表工资列的UPDATE |
| **角色启用审计（AUDIT ROLE）** | 12.2+：拥有某角色的用户，所有操作自动被审计 | 给DBA角色开审计，所有拥有DBA的用户操作全记 |

### 3. 常用统一审计SQL示例（19c）

```sql
-- ========== (1) 查看默认启用的预定义策略 ==========
SELECT policy_name, enabled_option, user_name, audit_option
  FROM audit_unified_enabled_policies
 ORDER BY policy_name;
-- 重点关注默认启用的：
-- ORA_SECURECONFIG       = 审计所有系统/角色权限授予回收、USER/PROFILE/ROLE变更、审计策略变更等
-- ORA_LOGON_FAILURES     = 审计所有登录失败（抓暴力破解）
-- ORA_ACCOUNT_MGMT       = CREATE/ALTER/DROP USER
-- ORA_CIS_RECOMMENDATIONS= CIS基准合规的推荐审计项

-- ========== (2) 自定义策略：审计对HR.EMPLOYEES的SELECT/UPDATE工资操作 ==========
CREATE AUDIT POLICY hr_salary_audit
  ACTIONS SELECT on hr.employees,
          UPDATE(salary, commission_pct) on hr.employees
  WHEN 'SYS_CONTEXT(''USERENV'', ''SESSION_USER'') NOT IN (''SYS'', ''SYSTEM'')'   -- 排除DBA自己查
  EVALUATE PER STATEMENT
  ONLY TOPLEVEL;
-- 启用策略（可仅给某些用户启用，不审计SYS的话就EXCLUDE）
AUDIT POLICY hr_salary_audit;
-- 或：AUDIT POLICY hr_salary_audit BY HR, FINANCE;  -- 仅审计HR/FINANCE用户

-- ========== (3) 自定义策略：审计DROP/TRUNCATE任意表（查删库跑路）==========
CREATE AUDIT POLICY table_drop_audit
  ACTIONS DROP TABLE, TRUNCATE TABLE;
AUDIT POLICY table_drop_audit;

-- ========== (4) 自定义策略：审计ALTER SYSTEM/ALTER DATABASE（改参数改文件）==========
CREATE AUDIT POLICY dba_admin_audit
  ACTIONS ALTER SYSTEM, ALTER DATABASE;
AUDIT POLICY dba_admin_audit;

-- ========== (5) 审计所有拥有DBA角色的用户操作 ==========
AUDIT ROLE dba;  -- 12.2+新语法，简单粗暴直接把拥有DBA角色的人全审计了

-- ========== 关闭/删除策略 ==========
NOAUDIT POLICY hr_salary_audit;       -- 仅停用策略，策略定义还在
DROP AUDIT POLICY hr_salary_audit;    -- 彻底删除策略定义
```

### 4. 查看统一审计记录★万能视图UNIFIED_AUDIT_TRAIL

```sql
-- 统一审计所有来源都汇到这一张视图：标准审计+FGA细粒度+SYS操作+RMAN+Data Pump+Dataguard代理，不用再拆N张表查了！
SELECT TO_CHAR(event_timestamp, 'YYYY-MM-DD HH24:MI:SS.FF3') event_time,
       audit_type,                     -- Standard Audit/FineGrained Audit/Operating System等
       unified_audit_policies,         -- 命中了哪个自定义策略
       dbusername,                     -- Oracle用户名
       os_user,                        -- 系统用户名
       userhost, terminal,
       client_program_name,            -- 客户端程序名（SQL Developer/Toad/jdbc/Oracle.exe）
       client_identifier,              -- 应用传的终端用户标识
       action_name,                    -- LOGON/CREATE TABLE/SELECT等
       return_code,                    -- 0成功/非0错误号
       object_schema, object_name,     -- 对象
       sql_text,                       -- 具体SQL（★永远有，不需要像标准审计那样开EXTENDED）
       bind_variables,                 -- 绑定变量值
       scn,                            -- 事务SCN
       rlb_info                        -- 回滚前SQL旧值？（12.2+行级）
  FROM unified_audit_trail
 WHERE event_timestamp > SYSDATE - 30  -- 最近30天
   AND dbusername NOT IN ('SYS', 'DBSNMP', 'SYSMAN')  -- 过滤系统用户
 ORDER BY event_timestamp DESC
 FETCH FIRST 200 ROWS ONLY;            -- 数据量大先看TOP 200
```

> [!tip] 12c+最实用的抓暴力破解SQL
> ```sql
> -- 1小时内登录失败超过10次的IP+用户名（攻击源定位）
> SELECT os_user, userhost, client_program_name, dbusername, COUNT(*) fail_count,
>        MIN(event_timestamp) first_fail, MAX(event_timestamp) last_fail
>   FROM unified_audit_trail
>  WHERE action_name = 'LOGON'
>    AND return_code = 1017         -- ORA-01017: invalid username/password
>    AND event_timestamp > SYSDATE - 1/24
> GROUP BY os_user, userhost, client_program_name, dbusername
> HAVING COUNT(*) >= 10
> ORDER BY fail_count DESC;
> ```

## 5.5.5 细粒度审计（FGA：Fine-Grained Auditing，更高级）

标准审计只能到"谁对哪个表做了SELECT/UPDATE"，但不能精确定位到**具体哪些行/哪些列**被操作。FGA细粒度审计（也叫"基于策略的审计"）通过DBMS_FGA包实现，可精确到：

- **列级**：只有SELECT了EMPLOYEES表的SALARY工资列才记审计，SELECT其他列不记
- **行级条件**：只审计部门=10的行被UPDATE，部门=20的不记
- **绑定应用上下文**：只审计特定IP段/特定程序的操作
- **触发处理函数**：审计命中时自动执行存储过程（如发短信告警、立刻Kill会话）

简单示例：
```sql
-- 审计SELECT工资列（防止DBA/HR看老板工资）
BEGIN
  DBMS_FGA.ADD_POLICY(
    object_schema => 'HR',
    object_name   => 'EMPLOYEES',
    policy_name   => 'audit_hr_salary',
    audit_column  => 'SALARY,COMMISSION_PCT',  -- 只有访问这两列才记
    audit_condition => 'SYS_CONTEXT(''USERENV'',''IP_ADDRESS'') NOT IN (''192.168.1.1'')',  -- 排除HR部门IP
    statement_types => 'SELECT,UPDATE',
    audit_trail     => DBMS_FGA.DB + DBMS_FGA.EXTENDED,   -- 存SQL+绑定
    handler_schema  => NULL,
    handler_module  => NULL,
    enable          => TRUE);
END;
/
-- 查FGA审计记录（12c+统一审计后也统一进UNIFIED_AUDIT_TRAIL；标准体系看DBA_FGA_AUDIT_TRAIL）
SELECT * FROM dba_fga_audit_trail WHERE policy_name='AUDIT_HR_SALARY';
```

## 小结

本节概述了Oracle安全审计的两大体系：**标准审计**（旧系统兼容，写SYS.AUD$，需注意表空间膨胀管理）与**统一审计**（12c+推荐，单视图UNIFIED_AUDIT_TRAIL汇总所有审计源，性能优、默认启SYSDBA审计，符合合规要求）。详述了标准审计的audit_trail/audit_sys_operations参数、三类AUDIT语句；统一审计的预定义策略、自定义AUDIT POLICY与AUDIT ROLE语法；并补充了FGA细粒度审计的列级/行级条件能力。配合UNIFIED_AUDIT_TRAIL视图与DBA_AUDIT_TRAIL，可构建覆盖登录、权限、DML/DDL、SYSDBA操作的完整数据库安全审计体系。
