# 6.5 LOB对象、外部表与数据库链接

本节解决的核心问题是：**大文件（PDF/图片/长文本）如何在Oracle中高效存储（SecureFile vs BasicFile）？OS文件（CSV/日志/TXT）如何映射成表直接SELECT？跨Oracle数据库/跨库（MySQL/SQL Server）如何透明访问？** 这三类对象是DBA日常ETL、跨库数据同步、多媒体业务开发的基础工具。

---

## 6.5.1 LOB大对象：CLOB/BLOB存储详解

> [!definition] LOB（Large Object）
> Oracle用于存储**超过4000字节的非结构化/半结构化大对象**的数据类型。分4种：CLOB（字符大对象，存大文本，最大4G×块大小）、BLOB（二进制大对象，存图片/PDF/附件）、NCLOB（Unicode国家字符集CLOB）、BFILE（外部操作系统文件指针，只读，文件存在OS上数据库只存路径）。

### 1. SecureFile LOB vs BasicFile LOB（★11g+ SecureFile是生产唯一选择）

| 对比项 | SecureFile LOB（11g+默认推荐） | BasicFile LOB（老版本，18c+已不推荐） |
| ---- | ---- | ---- |
| 压缩 | ✅ 原生**LOB压缩**（行内透明压缩，空间省50%~80%） | ❌ 无压缩，占原始空间 |
| 加密透明列加密TDE | ✅ 原生**LOB加密**（TDE表空间下SecureFile自动加密） | ❌ 无原生加密，应用层加密 |
| 去重（Deduplication） | ✅ 相同LOB内容只存1份（文件系统重复上传的附件省大量空间） | ❌ 每份都存，重复浪费空间 |
| 读写性能 | 快1.5~5倍（小LOB自动存入行内、日志优化、碎片少） | 慢，LOB段碎片多，大量CHUNK读写慢 |
| 空间碎片 | 少（自动管理CHUNK，类似ASSM段） | 多，大量DELETE后产生大量不可用CHUNK |
| 分区支持 | 支持分区表的LOCAL LOB分区，与表分区对齐 | 支持但参数少 |
| 启用条件 | ① ASSM表空间（强制）② COMPATIBLE>=11.1 ③ 表级`LOB(col) STORE AS SECUREFILE` | 老版本默认；MSSM表空间只能BasicFile |
| 生产建议 | ★所有新建LOB必须用SecureFile | 仅兼容老代码迁移用，新系统绝对不用 |

```sql
-- ========== 生产完整建表：SecureFile LOB（12c+ 默认就是SecureFile）==========
CREATE TABLE hr.documents (
  doc_id NUMBER(18) CONSTRAINT doc_pk PRIMARY KEY
    USING INDEX TABLESPACE hr_indx,
  doc_title VARCHAR2(200) NOT NULL,
  doc_content CLOB,              -- 大文本：Word转文本、邮件正文、文章正文
  doc_blob BLOB,                 -- 二进制：PDF/Word原文件/图片/压缩包
  create_time DATE DEFAULT SYSDATE
)
TABLESPACE hr_data
LOB (doc_content, doc_blob) STORE AS SECUREFILE (   -- ★★★ 声明SecureFile（12c+可省略，建议显式写）
  TABLESPACE hr_lob_ts        -- LOB段单独放LOB表空间（数据块与业务表分开，I/O均衡+备份灵活）
  CHUNK 8192                  -- CHUNK=DB_BLOCK_SIZE（8192=8k默认），读写LOB最小单元
  ENABLE STORAGE IN ROW       -- ★<4000字节的小LOB直接嵌入行数据块（省一次I/O访问LOB段，90%的小PDF/文本符合！）
  PCTVERSION 10               -- 旧版本LOB保留（读一致性）10%空间
  NOCACHE LOGGING             -- LOB不缓存SGA（太大），普通LOGGING
  COMPRESS MEDIUM             -- ★SecureFile压缩：LOW（最快速）/MEDIUM（均衡，推荐）/HIGH（最大压缩省空间）
  -- DEDUPLICATE LOB           -- ★SecureFile去重：相同内容LOB只存一份！（上传重复的合同/PDF省大量空间，CPU换空间）
  -- ENCRYPT USING 'AES256'    -- ★透明加密：TDE表空间下对LOB加密（金融/医疗合规）
);
```

### 2. SecureFile三大高级特性启用方式

```sql
-- 表创建后也可以修改LOB属性迁移到SecureFile（大表要用在线重定义DBMS_REDEFINITION，ALTER TABLE MOVE锁表）：
ALTER TABLE hr.documents MOVE
  LOB (doc_content) STORE AS SECUREFILE COMPRESS MEDIUM DEDUPLICATE LOB
  LOB (doc_blob) STORE AS SECUREFILE COMPRESS LOW DEDUPLICATE LOB
  TABLESPACE hr_data ONLINE PARALLEL 4;  -- 12c+ 支持ALTER TABLE MOVE ONLINE（不锁DML）

-- 单独在LOB列建索引（Oracle Text全文索引，用于对CLOB内容做关键词检索）
-- （详见Oracle Text文档）
CREATE INDEX hr.doc_content_ctx_idx ON hr.documents(doc_content)
  INDEXTYPE IS CTXSYS.CONTEXT PARAMETERS('SYNC (ON COMMIT)');
```

> [!danger] LOB存储生产注意事项
> 1. **CLOB不能直接WHERE中用=精确等值查询**（只能用DBMS_LOB.COMPARE/全文索引CONTAINS）；4000字符以内可以用TO_CHAR转后再比较。
> 2. **不要在LOB列上建普通B树索引**，除了Oracle Text/域索引。
> 3. 大量DELETE BLOB行后LOB段空间不会自动回收，需`ALTER TABLE ... SHRINK SPACE`或MOVE回收。
> 4. 不建议把>2GB的文件存数据库BLOB，存文件系统+BFile指针更省数据库备份空间（但要保证文件系统备份一致性）。

## 6.5.2 外部表（External Table）：OS文件透明映射成表

> [!definition] 外部表
> 表结构定义在Oracle数据字典中，但**数据不存数据库，而是存在OS上的普通文本文件（CSV/固定宽度TXT/日志）**或DataPump Dump文件中。可以把外部表当成普通视图/表直接SELECT JOIN WHERE GROUP BY（只读，不能DML INSERT/UPDATE/DELETE）。是**ETL加载工具**，比SQL*Loader更灵活（不用写CTL控制文件，纯SQL操作）。

### 1. 外部表创建步骤（ORACLE_LOADER驱动，读CSV/TXT★最常用）

外部表用ORACLE_LOADER驱动读取文本文件（和SQL*Loader同一引擎）。

```sql
-- ===== Step1：在Oracle服务器OS上建目录，把CSV文件放到该目录 =====
-- Oracle服务端OS上：mkdir -p /u01/app/oracle/ext_data/ && chown oracle:oinstall /u01/app/oracle/ext_data
-- 上传sales_2024.csv：每列逗号分隔，每行1条记录，第一行表头，双引号括字符串

-- ===== Step2：DBA创建DIRECTORY目录对象（映射OS路径到Oracle）=====
CONNECT / AS SYSDBA
CREATE OR REPLACE DIRECTORY ext_data_dir AS '/u01/app/oracle/ext_data';
-- 授权给读写用户
GRANT READ, WRITE ON DIRECTORY ext_data_dir TO hr;
-- ★WRITE权限：ORACLE_DATAPUMP类型外部表可以把Oracle内部数据卸载为外部文件，或创建坏文件/日志文件

-- ===== Step3：hr用户创建外部表（★核心）=====
CONNECT hr/hr_password
CREATE TABLE hr.ext_sales_csv (
  sales_id       NUMBER(18),
  prod_id        NUMBER(6),
  time_id        DATE,
  cust_id        NUMBER(10),
  channel_id     CHAR(1),
  quantity_sold  NUMBER(3),
  amount_sold    NUMBER(10,2),
  remark         VARCHAR2(500)
)
ORGANIZATION EXTERNAL (
  TYPE ORACLE_LOADER                 -- ★驱动类型：ORACLE_LOADER（读取文本/CSV，只能SELECT不能写）
  DEFAULT DIRECTORY ext_data_dir
  ACCESS PARAMETERS (
    RECORDS DELIMITED BY NEWLINE     -- 每行1条记录（Windows CSV是NEWLINE=\r\n，UNIX=\n）
    SKIP 1                           -- ★跳过CSV第一行表头（不要LOAD表头行）
    CHARACTERSET ZHS16GBK            -- ★文件字符集，和CSV文件实际编码匹配！UTF8用AL32UTF8
    BADFILE 'sales_csv_%a_%p.bad'    -- 解析失败的行写入bad文件（%a=进程号,%p=并行号）
    DISCARDFILE 'sales_csv_%a_%p.dsc'-- 被WHEN条件过滤丢弃的行
    LOGFILE 'sales_csv_%a_%p.log'    -- SQL*Loader日志（记录LOAD细节，必须有WRITE目录权限）
    FIELDS CSV WITH EMBEDDED         -- ★★★ Oracle 12c+ 新语法：标准CSV格式解析（自动处理逗号嵌入引号、内嵌换行符），不用写TERMINATED BY ","
    -- 老版本写法（11g）：FIELDS TERMINATED BY ',' OPTIONALLY ENCLOSED BY '"' LDRTRIM
    MISSING FIELD VALUES ARE NULL    -- 列缺省值视为NULL
    REJECT ROWS WITH ALL NULL FIELDS -- 全空行直接丢弃
    (
      sales_id       CHAR(20),
      prod_id        CHAR(6),
      time_id        CHAR(10) DATE_FORMAT DATE MASK "YYYY-MM-DD", -- ★日期格式要和CSV中格式完全匹配
      cust_id        CHAR(10),
      channel_id     CHAR(1),
      quantity_sold  CHAR(3),
      amount_sold    CHAR(14),
      remark         CHAR(500)
    )
  )
  LOCATION ('sales_202401.csv','sales_202402.csv')  -- ★支持多个文件同时读，逗号分隔文件名
)
REJECT LIMIT UNLIMITED    -- 允许多少坏行后中止加载（默认0=1行坏就报错；UNLIMITED=忽略所有坏行只写BADFILE）
PARALLEL 4                -- 并行4读文件（大文件加快）
NOMONITORING;

-- ===== Step4：直接SELECT外部表（透明，和普通表一样！）=====
SELECT time_id, SUM(amount_sold) total_amount, COUNT(*) cnt
  FROM hr.ext_sales_csv
 WHERE channel_id = 'S'
 GROUP BY time_id
 ORDER BY time_id;

-- ★典型用法：CREATE TABLE AS SELECT 直接把外部表数据装入生产表（APPEND NOLOGGING并行超快）
CREATE /*+ APPEND PARALLEL(8) */ TABLE hr.sales_staging NOLOGGING
  PARALLEL 8
AS SELECT * FROM hr.ext_sales_csv;
-- 之后再对STAGING表做清洗/约束校验/EXCHANGE PARTITION进分区表秒级入仓
```

### 2. 两类外部表驱动对比

| 驱动类型 | 用途 | 读写性 | 典型场景 |
| ---- | ---- | ---- | ---- |
| **ORACLE_LOADER** | ★读OS上的CSV/固定宽度文本/日志文件 | 只读SELECT（不能DML写回OS） | 日常ETL加载：业务系统导出CSV入仓、日志分析加载 |
| **ORACLE_DATAPUMP** | 读/写DataPump二进制Dump文件（跨平台可移植） | 可读SELECT + 可CREATE TABLE AS SELECT把数据卸载到外部Dump文件（可写！）| 跨库/跨平台数据搬运（OS上FTP Dump文件到目标服务器，再挂外部表SELECT）；大表卸载归档Dump |

```sql
-- ORACLE_DATAPUMP：把Oracle内部大表卸载为Dump文件（可写）
CREATE TABLE hr.big_table_archive
ORGANIZATION EXTERNAL (
  TYPE ORACLE_DATAPUMP
  DEFAULT DIRECTORY ext_data_dir
  LOCATION ('big_table_2020.dmp')
)
PARALLEL 4
AS SELECT * FROM sh.big_sales WHERE time_id < DATE'2021-01-01';
-- 执行完就会在ext_data_dir目录生成Oracle专有格式Dump文件，跨库直接COPY dmp文件再挂外部表就能SELECT！

-- DROP PARTITION前，把老分区数据卸载为Dump归档（DROP后不丢数据，需要时再挂外部表查询）
CREATE TABLE sh.sales_2020_archive
ORGANIZATION EXTERNAL (TYPE ORACLE_DATAPUMP DEFAULT DIRECTORY ext_data_dir LOCATION('sales_2020.dmp'))
PARALLEL 4
AS SELECT * FROM sh.sales_range PARTITION (p2020);
ALTER TABLE sh.sales_range DROP PARTITION p2020 UPDATE GLOBAL INDEXES;
```

> [!warning] 外部表生产坑
> 1. **DIRECTORY目录是OS上Oracle服务端（不是客户端！）的路径**，文件必须上传到Oracle数据库服务器OS对应目录，不是你本机电脑路径。
> 2. 字符集必须匹配！中文CSV用GBK写AL32UTF8会全乱码。
> 3. `REJECT LIMIT UNLIMITED`：数据量大时要检查BADFILE坏行数，不然默认识别失败一行就中止加载。
> 4. 外部表没有索引，全表扫描。大文件数据多加载要先CTAS到STAGING表再加索引。

## 6.5.3 数据库链接（Database Link/DBLink）：跨库透明访问

> [!definition] Database Link（DBLink）
> 在本地数据库中定义指向**远程数据库**的连接配置（连接串/用户名/密码）。创建后可以直接`SELECT * FROM 远程表@DBLink名`就像访问本地表一样，跨Oracle库/甚至跨异构库（MySQL/SQL Server通过Gateway）做JOIN查询、INSERT远程表，对应用透明。

### 1. 三类DBLink + 创建SQL

```sql
-- ====== ① PRIVATE DBLink（私有/用户DBLink）★最常用，生产推荐 ======
-- 归属特定用户，只有创建者用户能用
CONNECT hr/hr_password
CREATE DATABASE LINK remote_prod_dblink
  CONNECT TO app_user IDENTIFIED BY "AppUser@20240501!"   -- 远程库的用户名+密码
  USING '(DESCRIPTION=
           (ADDRESS=(PROTOCOL=TCP)(HOST=192.168.1.100)(PORT=1521))
           (CONNECT_DATA=(SERVICE_NAME=PROD_SVC))
         )';
-- USING后面是标准Oracle连接串（和tnsnames.ora中配置一模一样），也可以直接写SERVICE_NAME别名（前提是本服务器tnsnames.ora有PROD_SVC的条目）

-- ====== ② PUBLIC DBLink（公有DBLink）慎用！======
-- 归属PUBLIC用户，全库任何用户都能直接使用（安全风险大：密码明文存在SYS.LINK$表，可能泄露）
CONNECT / AS SYSDBA
CREATE PUBLIC DATABASE LINK remote_hr_pub_dbl
  CONNECT TO hr IDENTIFIED BY hr_password
  USING 'PROD_TNS';

-- ====== ③ SHARED DBLink（共享DBLink）======
-- 共享服务器模式（Shared Server）下复用连接，减少远程连接数（专用服务器模式不常用）
CREATE SHARED DATABASE LINK shared_link
  CONNECT TO remote_user IDENTIFIED BY pw AUTHENTICATED BY shared_user IDENTIFIED BY shared_pw
  USING 'PROD';
```

### 2. DBLink使用SQL（透明跨库）

```sql
-- ========== SELECT跨库查询 ==========
SELECT e.employee_id, e.last_name, d.department_name
  FROM hr.employees@remote_prod_dblink e      -- ★@后加DBLink名
  LEFT JOIN hr.departments@remote_prod_dblink d ON e.department_id=d.department_id
 WHERE e.hire_date > DATE'2023-01-01';

-- ========== INSERT远程表 ==========
INSERT INTO hr.employees@remote_prod_dblink
  (employee_id, last_name, email, hire_date, job_id, department_id)
VALUES (9999, 'NewEmp', 'new@example.com', SYSDATE, 'IT_PROG', 60);
COMMIT;
-- ★跨库INSERT/UPDATE/DELETE：本库COMMIT就同步提交远程库，两阶段提交（2PC）保证分布式事务一致性

-- ========== JOIN跨库表+本地表（应用开发最常用场景）==========
SELECT l.order_id, r.customer_name, l.amount
  FROM local_orders l
  LEFT JOIN customers@remote_crm_dbl r ON l.customer_id = r.customer_id
 WHERE l.create_date > SYSDATE-7;

-- ========== 同义词+DBLink：简化代码 =====
CREATE OR REPLACE SYNONYM remote_employees FOR hr.employees@remote_prod_dblink;
SELECT * FROM remote_employees;   -- 代码里看不到DBLink，像本地表！环境切换只改同义词
```

### 3. 跨异构数据库（MySQL/SQL Server/PostgreSQL/Hive等）

Oracle通过**Oracle Database Gateway（透明网关）** 实现非Oracle数据库的DBLink访问：

```sql
-- 访问MySQL（已在网关服务器安装DG4ODBC + MySQL ODBC驱动，配置监听）
CREATE DATABASE LINK mysql_crm_dbl
  CONNECT TO "mysql_user" IDENTIFIED BY "mysql_pw"
  USING 'MYSQL_CRM_GATEWAY';    -- tnsnames.ora中HS=OK的异构网关连接串
-- 之后直接SELECT：
SELECT * FROM crm.customers@mysql_crm_dbl WHERE `create_time` > '2024-01-01';
-- 注意：异构库DBLink注意列名大小写（MySQL默认小写字段名，Oracle默认大写，加双引号""括列名）
```

> [!danger] DBLink生产8大注意事项（安全+性能）
> 1. **密码安全**：DBLink密码明文存在SYS.LINK$/USER_DB_LINKS中，SYS用户/EXPORT导出能查看到。生产不要用高权限用户（如SYSTEM）做DBLink连接用户，用最小权限专用账号。定期改密码！
> 2. **PUBLIC DBLink禁止使用！** 安全红线：PUBLIC DBLink任何用户都能访问，一旦泄露全库风险。用PRIVATE用户专属。
> 3. **分布式事务2PC风险**：INSERT/UPDATE跨库+本地表COMMIT = 2PC分布式事务；任何一个库网络抖动或中途CRASH可能导致分布式挂起事务（DBA_2PC_PENDING视图），需要手动FORGET COMMIT/ROLLBACK清理，避免业务阻塞。跨库大事务尽量拆成单库事务+应用补偿。
> 4. **驱动列在哪侧？性能大坑！** JOIN中`本地表 LEFT JOIN 远程表@dbl ON ...`：Oracle会先把远程表**整表拉到本地**再JOIN（远程500万行拉500万行过网络，慢）。优化：把小表放本地做驱动，大表放远程且WHERE条件过滤尽量在远程侧先做（用DRIVING_SITE提示）：
>    ```sql
>    SELECT /*+ DRIVING_SITE(r) */ * FROM local_tbl l, remote_big_tbl@dbl r WHERE l.id = r.id;
>    -- 告诉CBO把本地表小表推到远程库侧执行JOIN，只JOIN结果集返回本地。
>    ```
> 5. **LOB/CLOB跨DBLink限制多**：不支持直接SELECT远程CLOB列到本地（会报ORA-22992），需要把远程CLOB用TO_CHAR(4000)截断，或DBMS_LOB包+临时表先落地本地。
> 6. **远程DDL不能直接DBLink执行**：不能`TRUNCATE TABLE t@dbl;`。要执行远程DDL用DBMS_JOB/DBMS_SCHEDULER在远程库作业，或`DBMS_UTILITY.EXEC_DDL_STATEMENT@dbl('TRUNCATE TABLE t');`。
> 7. **dblink连接泄漏**：应用连接池用了大量dblink后连接不释放，导致远程库sessions爆满。关闭本地session才释放dblink连接；或用`ALTER SESSION CLOSE DATABASE LINK remote_prod_dblink;` 手动关。
> 8. **查询远程V$视图需特殊权限**：普通用户远程查V$INSTANCE需要远程用户有SELECT ANY DICTIONARY或SELECT_CATALOG_ROLE。

### 4. DBLink查询字典视图

```sql
-- 查看本库所有DBLink
SELECT owner, db_link, username, host, created
  FROM dba_db_links
 ORDER BY owner, db_link;
-- OWNER=PUBLIC = 公有DBLink
-- HOST列是USING后的连接串配置

-- 验证DBLink是否通（最简单测试）
SELECT * FROM DUAL@remote_prod_dblink;   -- 返回X就通；报错TNS/密码/网络问题要看具体错误号
```

## 小结

本节深入三大实用数据库对象：① LOB：SecureFile是唯一生产选择，CLOB/BLOB压缩+去重+加密三大高级特性；② 外部表：ORACLE_LOADER加载CSV入仓（ETL神器）、ORACLE_DATAPUMP跨平台卸载Dump归档；③ 数据库链接DBLink：PRIVATE/PUBLIC/SHARED三类，跨Oracle同构/MySQL异构透明访问，详解了分布式事务2PC风险、性能优化DRIVING_SITE提示、密码安全等生产坑。配合字典视图DBA_LOBS/DBA_DIRECTORIES/DBA_DB_LINKS形成完整运维能力。
