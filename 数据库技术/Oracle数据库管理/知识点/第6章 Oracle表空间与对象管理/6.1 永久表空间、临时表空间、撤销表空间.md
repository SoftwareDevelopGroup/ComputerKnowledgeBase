# 6.1 永久表空间、临时表空间、撤销表空间

本节解决的核心问题是：**Oracle三种核心表空间（永久/临时/撤销）的作用、创建、维护与区别？DMT vs LMT、ASSM vs MSSM如何选择？DROP TABLESPACE永久删除数据文件的注意事项是什么？** 表空间是Oracle数据库逻辑存储→物理存储的映射层，是对象容器与IO均衡、备份恢复粒度划分的核心。

## 6.1.1 Oracle表空间体系总览

> [!definition] 表空间（Tablespace）
> 表空间是Oracle数据库的**最高逻辑存储单元**，一个数据库由**一个或多个表空间**组成；一个表空间由**一个或多个数据文件**（Data File）组成（物理存储在磁盘）；一个表/索引等段（Segment）只能存放在**一个表空间**中。表空间是逻辑容器，数据文件才是物理文件——这是Oracle"逻辑-物理分离"的第一层映射。

```mermaid

    A[Oracle Database] --> B[永久表空间 Permanent<br/>存永久对象：表/索引/视图/存储过程]
    A --> C[临时表空间 Temporary<br/>存临时数据：排序/哈希连接/全局临时表<br/>使用TEMPFILE]
    A --> D[撤销表空间 Undo<br/>存撤销数据：事务回滚/一致性读/闪回<br/>AUM自动撤销管理默认]
```

### 5大默认表空间说明（创建数据库时自动生成）

| 默认表空间 | 类型 | 作用 | 存储内容 | 能否删除/重命名 |
| ---- | ---- | ---- | ---- | ---- |
| **SYSTEM** | 永久 | 数据字典系统表空间 | SYS用户数据字典基表（TAB$/IND$/USER$等）、PL/SQL系统包源码、数据库元数据 | ❌ 绝对不能删、不能OFFLINE、不能重命名，数据库启动必须挂载 |
| **SYSAUX** | 永久 | 系统辅助表空间（10g+引入） | AWR/ASH性能统计、OEM资料、TEXT索引、XDB、Optimizer统计、Spatial、Data Mining等系统辅助组件 | ⚠️ 不能删，可OFFLINE（但不建议），可传输表空间迁移 |
| **TEMP** | 临时 | 默认临时表空间 | 排序操作（ORDER BY/GROUP BY/索引创建排序）、哈希连接临时段、全局临时表GTT数据 | ⚠️ 不能直接删，可创建新临时表空间SWITCH DEFAULT后再删旧的 |
| **USERS** | 永久 | 默认用户永久表空间 | CREATE USER未显式指定DEFAULT TABLESPACE时，用户对象默认建在此 | ✅ 可替换为业务表空间后删除 |
| **UNDOTBS1** | 撤销 | 默认撤销表空间 | 事务撤销数据（UNDO段）：回滚事务、一致性读、闪回查询、闪回表 | ⚠️ 不能直接删，可ALTER SYSTEM SWITCH UNDO TABLESPACE到新的后再删 |

> [!note] 12c+ PDB多租户与表空间
> CDB根容器CDB$ROOT有自己的SYSTEM/SYSAUX/TEMP/UNDO；每个PDB又有独立的SYSTEM/SYSAUX/TEMP/业务表空间，UNDO默认共享CDB的（12.2+本地UNDO模式可选PDB本地独立UNDO）。

## 6.1.2 永久表空间（Permanent Tablespace）详解

### 1. CREATE TABLESPACE完整语法（Oracle 19c）

> [!definition] CREATE TABLESPACE完整语法（常用子句）
> ```sql
> CREATE [UNDO | TEMPORARY] TABLESPACE 表空间名
>   [BIGFILE | SMALLFILE]     -- BIGFILE单文件表空间（默认SMALLFILE）
>   DATAFILE|TEMPFILE '路径1' SIZE 整数 K|M|G|T|E|P
>     [REUSE] [AUTOEXTEND { OFF | ON [ NEXT 整数 K|M MAXSIZE { UNLIMITED | 整数 } ] }]
>   [, DATAFILE|TEMPFILE '路径2' ...]     -- 可同时加多个数据文件
>   [MINIMUM EXTENT 整数 K|M]
>   [BLOCKSIZE 整数 K]                    -- 非标准块（2K/4K/8K/16K/32K），需db_16k_cache_size等参数
>   [LOGGING | NOLOGGING | FILESYSTEM_LIKE_LOGGING]
>   [FORCE LOGGING]
>   [EXTENT MANAGEMENT
>       { DICTIONARY        -- 字典管理DMT（已淘汰，不推荐）
>       | LOCAL             -- ★默认，本地管理LMT，生产必选
>           { AUTOALLOCATE | UNIFORM [ SIZE 整数 K|M ] }
>       } ]
>   [SEGMENT SPACE MANAGEMENT { AUTO | MANUAL }]   -- ★AUTO=ASSM（默认），生产必选
>   [DEFAULT STORAGE (                         -- LMT下几乎不用了，兼容保留
>       INITIAL 整数 K|M NEXT 整数 K|M
>       MINEXTENTS 整数 MAXEXTENTS { 整数 | UNLIMITED }
>       PCTINCREASE 整数 )]
>   [FLASHBACK { ON | OFF }]                   -- 11g+闪回表空间
>   [ENCRYPTION [USING 'AES256'] IDENTIFIED BY "wallet密码" ENCRYPT FILE_NAME_CONVERT ...]  -- TDE透明加密
>   [COMPRESS { HIGH | MEDIUM | LOW | NOCOMPRESS } DEFAULT]                       -- 12c+默认压缩
>   [INLINE EXTERNAL STORE BY REF | STORE IN ROW];
> ```

### 2. 生产级永久表空间SQL示例（Oracle 19c）

```sql
-- ===========================================
-- 案例1：业务数据表空间（最常用模板）
-- LMT + AUTOALLOCATE + ASSM + 多数据文件 + AUTOEXTEND
-- ===========================================
CREATE TABLESPACE app_data_ts
  SMALLFILE
  DATAFILE
    '/u02/oradata/orcl/app_data01.dbf' SIZE 10G REUSE
      AUTOEXTEND ON NEXT 512M MAXSIZE 30G,
    '/u03/oradata/orcl/app_data02.dbf' SIZE 10G REUSE
      AUTOEXTEND ON NEXT 512M MAXSIZE 30G,
    '/u04/oradata/orcl/app_data03.dbf' SIZE 10G REUSE
      AUTOEXTEND ON NEXT 512M MAXSIZE 30G
  LOGGING
  EXTENT MANAGEMENT LOCAL AUTOALLOCATE
  SEGMENT SPACE MANAGEMENT AUTO
  BLOCKSIZE 8K
  DEFAULT COMPRESS FOR OLTP                -- 12c+ OLTP压缩推荐
  FLASHBACK ON;

-- ===========================================
-- 案例2：索引表空间（与数据分开放不同磁盘，均衡IO）
-- ===========================================
CREATE TABLESPACE app_indx_ts
  DATAFILE
    '/u05/oradata/orcl/app_indx01.dbf' SIZE 8G
      AUTOEXTEND ON NEXT 256M MAXSIZE 20G,
    '/u06/oradata/orcl/app_indx02.dbf' SIZE 8G
      AUTOEXTEND ON NEXT 256M MAXSIZE 20G
  EXTENT MANAGEMENT LOCAL AUTOALLOCATE
  SEGMENT SPACE MANAGEMENT AUTO;

-- ===========================================
-- 案例3：大文件BIGFILE表空间（数据仓库大表用，单个数据文件支持128TB）
-- ===========================================
CREATE BIGFILE TABLESPACE dw_hist_ts
  DATAFILE '/u07/oradata/orcl/dw_hist01.dbf' SIZE 100G
    AUTOEXTEND ON NEXT 10G MAXSIZE UNLIMITED
  EXTENT MANAGEMENT LOCAL UNIFORM SIZE 64M       -- 大表推荐UNIFORM大区，减少区分配次数
  SEGMENT SPACE MANAGEMENT AUTO
  DEFAULT COMPRESS FOR QUERY HIGH;               -- 数据仓库查询压缩

-- ===========================================
-- 案例4：OMF（Oracle Managed Files）模式（不用写路径，Oracle自动管理文件名）
-- ===========================================
-- 先设置DB_CREATE_FILE_DEST参数
ALTER SYSTEM SET db_create_file_dest = '/u01/oradata/orcl' SCOPE=BOTH;
ALTER SYSTEM SET db_create_online_log_dest_1 = '/u02/fra/orcl' SCOPE=BOTH;
-- 不用写DATAFILE子句，Oracle自动创建合理大小+名字的文件
CREATE TABLESPACE omf_ts DATAFILE SIZE 5G AUTOEXTEND ON MAXSIZE 20G
  EXTENT MANAGEMENT LOCAL AUTOALLOCATE SEGMENT SPACE MANAGEMENT AUTO;
```

### 3. 关键参数深度解读

#### (1) EXTENT MANAGEMENT：区管理方式（LMT vs DMT对比表）

| 对比项 | LOCAL本地管理（LMT，9i+默认，生产必选） | DICTIONARY字典管理（DMT，已淘汰） |
| ---- | ---- | ---- |
| 区分配位置 | 数据文件头部的**位图块（Bitmap Block）**记录哪些块已用/未用 | SYSTEM表空间的UET$/FET$数据字典表记录 |
| 性能 | 高（位图更新是内存操作+物理单块读，无行锁竞争） | 低（修改字典表产生回滚+重做+字典表锁，大量创建删对象时SYSTEM争用） |
| UNIFORM vs AUTOALLOCATE | ✅ 支持 | ❌ 只支持DEFAULT STORAGE参数 |
| 碎片管理 | 好（位图合并相邻空闲区，自动合并） | 差（易产生"蜂蜜洞"碎片，需定期ALTER TABLESPACE COALESCE） |
| DEFAULT STORAGE子句 | 几乎无效（LMT用UNIFORM/AUTOALLOCATE决定） | 有效（但参数多易配错） |
| 迁移/兼容性 | 生产100%用LMT，12c+ DMT已不支持新建 | 仅用于极老数据库（8i及以前），可DBMS_SPACE_ADMIN.TABLESPACE_MIGRATE_TO_LOCAL迁移到LMT |

**LMT下 AUTOALLOCATE vs UNIFORM：**
| 选择 | 适用场景 | 优缺点 |
| ---- | ---- | ---- |
| **AUTOALLOCATE（默认）** | 表空间大小不一、对象数量多、OLTP杂项对象混合放 | 省空间（小对象小区），碎片略多可接受，生产90%场景选这个 |
| **UNIFORM SIZE 1M/16M/64M** | 大表专用表空间、分区表专用、分区数量巨大（几十万分区） | 无碎片、空间管理简单可预测，大对象不会产生百万级小区；小对象略浪费 |

#### (2) SEGMENT SPACE MANAGEMENT：段空间管理方式（ASSM vs MSSM）

| 对比项 | AUTO（ASSM，自动段空间管理，默认，生产必选） | MANUAL（MSSM，手动，兼容保留） |
| ---- | ---- | ---- |
| 实现方式 | 段头+数据块中的**PCTFREE状态位图**（块空闲比例：0~25%、25~50%、50~75%、75~100%四级），INSERT自动找足够空闲块 | **PCTUSED + FREELIST空闲链表**，INSERT扫FREELIST找满足PCTUSED阈值的块 |
| 高并发INSERT性能 | 好（位图无锁竞争、多级空闲分类适合并发） | 差（FREELIST热点、需要配置FREELIST GROUPS=CPU个数才勉强） |
| 需要的表级参数 | 仅需PCTFREE（块预留空间百分比，用于UPDATE膨胀）| **PCTFREE、PCTUSED、FREELISTS、FREELIST GROUPS、INITRANS**一堆手动参数，极易配错 |
| RAC支持 | 天然友好，不需要额外配置 | 每个节点需单独FREELIST GROUP，配置复杂易错 |
| 对LOB/高级对象 | ✅ SecureFile LOB要求ASSM | ❌ MSSM不支持SecureFile，只能用BasicFile |

> [!tip] 生产最佳组合（19c默认）
> ✅ **EXTENT MANAGEMENT LOCAL AUTOALLOCATE + SEGMENT SPACE MANAGEMENT AUTO**
> 这两个组合是Oracle开发了20多年迭代出的最佳默认值，除极特殊场景（超百万分区的大表UNIFORM 64M）不用改。

#### (3) LOGGING vs NOLOGGING

| 模式 | REDO日志产生量 | 恢复性 | 适用场景 |
| ---- | ---- | ---- | ---- |
| **LOGGING（默认）** | 100%产生重做日志，所有DML/DDL全写REDO | ✅ 可从备份恢复到任意时间点，DG备库正常同步 | 绝大多数OLTP生产表空间，任何时候需要可恢复性 |
| **NOLOGGING** | 产生极少的REDO（仅写少量字典变更REDO，不记数据块REDO）| ❌ 出现介质故障时，NOLOGGING操作的数据块会被标记为"不可恢复"，备份恢复后查询会报错ORA-01578；DG备库执行到NOLOGGING也坏块 | 大批量数据加载（INSERT /*+ APPEND*/、SQL*Loader DIRECT PATH、CREATE TABLE AS SELECT大表建表、CREATE INDEX建大索引）操作时临时ALTER对象NOLOGGING，做完切回LOGGING；**操作完必须立即做一次全备**，保证备份链完整 |

> [!note] NOLOGGING使用最佳实践
> ```sql
> -- 1. 大表批量加载前临时改表NOLOGGING
> ALTER TABLE big_sales NOLOGGING;
> -- 2. 执行APPEND直接路径INSERT（/*+ APPEND */才会走NOLOGGING，普通DML还是记）
> INSERT /*+ APPEND PARALLEL(8) */ INTO big_sales SELECT * FROM stage_sales;
> COMMIT;
> -- 3. 立即改回LOGGING
> ALTER TABLE big_sales LOGGING;
> -- 4. ★立即备份这个表空间（或增量备份）
> RMAN> BACKUP TABLESPACE sales_data_ts;
> ```

#### (4) BLOCKSIZE非标准块（需参数）

Oracle默认标准块是**db_block_size=8K**（建库时指定，终身不可改！），非标准块用于特殊场景：

| 块大小 | 参数设置 | 适用场景 |
| ---- | ---- | ---- |
| 16K | db_16k_cache_size=4G | 数据仓库大表、大表全表扫描效率高（每次读更多行），LOB大对象列 |
| 32K | db_32k_cache_size=8G | 超大型数据仓库，单表TB级 |
| 4K/2K | db_4k_cache_size | OLTP小行表（每行<200字节），减少块内空间浪费 |

注意：非标准块的表空间不能跨平台传输，会增加Buffer Pool管理复杂度；生产除数据仓库外，全用标准8K，不折腾。

### 4. ALTER TABLESPACE维护操作

```sql
-- ========== (1) 增加数据文件（最常用，解决空间不足）==========
ALTER TABLESPACE app_data_ts
  ADD DATAFILE '/u02/oradata/orcl/app_data04.dbf' SIZE 10G
    AUTOEXTEND ON NEXT 512M MAXSIZE 30G;

-- ========== (2) 改变数据文件大小/AUTOEXTEND属性 ==========
-- 手动扩文件
ALTER DATABASE DATAFILE '/u02/oradata/orcl/app_data01.dbf' RESIZE 20G;
-- 开启/调整AUTOEXTEND
ALTER DATABASE DATAFILE '/u02/oradata/orcl/app_data01.dbf'
  AUTOEXTEND ON NEXT 1G MAXSIZE 50G;

-- ========== (3) 重命名/迁移数据文件（注意顺序）==========
-- 方法A：ALTER TABLESPACE RENAME（表空间先OFFLINE，OS再mv，然后RENAME）
ALTER TABLESPACE app_data_ts OFFLINE NORMAL;
HOST mv /old_path/app_data01.dbf /new_path/app_data01.dbf;  -- OS物理迁移
ALTER TABLESPACE app_data_ts
  RENAME DATAFILE '/old_path/app_data01.dbf' TO '/new_path/app_data01.dbf';
ALTER TABLESPACE app_data_ts ONLINE;
-- 方法B：ALTER DATABASE RENAME（MOUNT状态下执行，适合所有表空间含SYSTEM）
SHUTDOWN IMMEDIATE;
HOST mv /old_path/system01.dbf /new_path/system01.dbf;
STARTUP MOUNT;
ALTER DATABASE RENAME FILE '/old_path/system01.dbf' TO '/new_path/system01.dbf';
ALTER DATABASE OPEN;

-- ========== (4) OFFLINE/ONLINE（表空间级维护）==========
ALTER TABLESPACE app_data_ts OFFLINE NORMAL;     -- 正常离线，无未提交事务（最干净）
ALTER TABLESPACE app_data_ts OFFLINE TEMPORARY;  -- 临时离线，允许有未提交事务，ONLINE时需恢复
ALTER TABLESPACE app_data_ts OFFLINE IMMEDIATE;  -- 立即离线，需介质恢复（SYSTEM不能OFFLINE）
ALTER TABLESPACE app_data_ts ONLINE;

-- ========== (5) 热备模式BEGIN/END BACKUP（用户管理备份，RMAN不常用了）==========
ALTER TABLESPACE app_data_ts BEGIN BACKUP;
HOST cp /u02/oradata/orcl/*.dbf /backup/hot/
ALTER TABLESPACE app_data_ts END BACKUP;

-- ========== (6) READ ONLY/READ WRITE（报表库、历史表空间）==========
ALTER TABLESPACE hist_2022_ts READ ONLY;   -- 只读，只有SELECT，查询不产生UNDO
ALTER TABLESPACE hist_2022_ts READ WRITE;  -- 可读写

-- ========== (7) 闪回/强制日志/压缩属性变更 ==========
ALTER TABLESPACE app_data_ts FLASHBACK OFF;       -- 关闭闪回数据库对此表空间的支持（省闪回空间）
ALTER TABLESPACE app_data_ts FORCE LOGGING;        -- 强制所有操作写REDO（DG主库建议）
ALTER TABLESPACE app_data_ts DEFAULT COMPRESS FOR OLTP;  -- 新对象默认OLTP压缩
```

### 5. DROP TABLESPACE：永久删除，高风险★

> [!danger] DROP TABLESPACE INCLUDING CONTENTS AND DATAFILES — 不可逆永久删除！
> 执行前必须：① 先做RMAN表空间备份 ② 查DBA_SEGMENTS确认真的没有重要对象了 ③ 先`ALTER TABLESPACE XXX READ ONLY`观察一周没问题再删

```sql
-- 空表空间（没有任何段/对象）
DROP TABLESPACE empty_ts;   -- 只删控制文件中的字典记录，不删物理OS数据文件

-- 有对象的表空间，级联删对象
DROP TABLESPACE app_data_ts INCLUDING CONTENTS;   -- 删表空间+所有段，OS数据文件不删（需要手动rm）

-- ★生产一次性全删（控制文件+所有对象+OS物理数据文件一起永久删！）
DROP TABLESPACE app_data_ts INCLUDING CONTENTS AND DATAFILES
  CASCADE CONSTRAINTS;  -- CASCADE CONSTRAINTS：删除其他表空间中引用本表空间表主键的外键约束
-- 执行完OS层面数据文件就没了，真·永久删除！

-- 含分区表跨表空间时，必须加INCLUDING ALL CONSTRAINTS或单独处理
DROP TABLESPACE hist_part_ts INCLUDING CONTENTS AND DATAFILES CASCADE CONSTRAINTS;
```

### 6. 永久表空间查询视图

| 视图 | 用途 | 典型SQL |
| ---- | ---- | ---- |
| **DBA_TABLESPACES** | 所有表空间属性（类型/块大小/区管理/段管理/日志属性） | `SELECT tablespace_name, contents, extent_management, segment_space_management, logging, status, bigfile FROM dba_tablespaces;` |
| **DBA_DATA_FILES** | 所有永久/撤销数据文件路径、大小、使用率 | `SELECT tablespace_name, file_name, bytes/1024/1024 size_mb, maxbytes/1024/1024 max_mb, autoextensible FROM dba_data_files ORDER BY tablespace_name;` |
| **DBA_FREE_SPACE** | 表空间剩余空闲空间（用于算使用率） | 见下方使用率SQL |
| **DBA_SEGMENTS** | 各段（表/索引/回滚）占用空间 | `SELECT owner, segment_name, segment_type, bytes/1024/1024 mb FROM dba_segments WHERE tablespace_name='APP_DATA_TS' ORDER BY bytes DESC;` |

```sql
-- 表空间使用率SQL（生产最常用）
SELECT
  dfs.tablespace_name,
  dfs.total_space_mb,
  NVL(dfs.free_space_mb, 0) free_space_mb,
  (dfs.total_space_mb - NVL(dfs.free_space_mb, 0)) used_space_mb,
  ROUND(((dfs.total_space_mb - NVL(dfs.free_space_mb, 0)) / dfs.total_space_mb) * 100, 2) used_pct
FROM
  (SELECT tablespace_name, SUM(bytes)/1024/1024 total_space_mb
     FROM dba_data_files GROUP BY tablespace_name) dfs,
  (SELECT tablespace_name, SUM(bytes)/1024/1024 free_space_mb
     FROM dba_free_space GROUP BY tablespace_name) dfr
WHERE dfs.tablespace_name = dfr.tablespace_name(+)
ORDER BY used_pct DESC;
```

## 6.1.3 临时表空间（Temporary Tablespace）详解

> [!definition] 临时表空间（Temporary Tablespace）
> 存储**临时数据**的专用表空间，排序操作（ORDER BY/GROUP BY/窗口函数/DISTINCT/索引创建排序、哈希连接HASH JOIN、MERGE JOIN、位图合并、全局临时表GTT）在PGA内存不够用时，溢出到临时表空间的临时段。数据文件叫TEMPFILE（非DATAFILE）。

### 1. 临时表空间特性（vs永久表空间区别）

| 特性 | 永久表空间 | 临时表空间 |
| ---- | ---- | ---- |
| 文件类型关键字 | **DATAFILE** | **TEMPFILE** |
| 是否产生REDO | 正常DML/DDL写（除非NOLOGGING） | ❌ 不写重做日志（TEMPFILE操作不记REDO，恢复时不需要） |
| 实例恢复处理 | 需要前滚+回滚 | ❌ 实例恢复时SMON直接清空临时段即可，不参与恢复 |
| DG备库处理 | 正常同步 | 备库的TEMPFILE也需创建，只读Active DG备库查询也会排序用到 |
| 是否允许只读 | READ ONLY/READ WRITE均可 | ❌ 不能READ ONLY |
| 备份（RMAN） | 正常BACKUP DATABASE备份 | ⚠️ RMAN默认不备份TEMPFILE，备份完成后会自动创建同名空文件；用户管理备份时不cp临时文件 |
| 是否可临时ALTER OFFLINE | NORMAL/TEMPORARY/IMMEDIATE | 不能OFFLINE（实例起来就要用） |
| 段分配 | 永久段（CREATE TABLE后持续存在） | 永久临时段（建库后SMON自动创建临时段，会话用后标记空闲不删，复用避免频繁分配） |

### 2. 创建与维护SQL示例

```sql
-- ===========================================
-- (1) 标准临时表空间创建（最常用）
-- ===========================================
CREATE TEMPORARY TABLESPACE temp2
  TEMPFILE '/u03/oradata/orcl/temp2_01.dbf' SIZE 20G REUSE
    AUTOEXTEND ON NEXT 1G MAXSIZE 64G,
           '/u04/oradata/orcl/temp2_02.dbf' SIZE 20G REUSE
    AUTOEXTEND ON NEXT 1G MAXSIZE 64G
  EXTENT MANAGEMENT LOCAL UNIFORM SIZE 1M;   -- 临时表空间推荐UNIFORM，排序段是固定大小

-- 临时表空间100%选LMT！DMT临时段管理在临时表空间已完全淘汰
-- 临时表空间没有SEGMENT SPACE MANAGEMENT AUTO参数（临时段位图管理，天然ASSM式）

-- ===========================================
-- (2) 临时表空间组（大并发排序分散IO）
-- 原理：多个临时表空间组成一个GROUP，用户排序会话随机用组内不同TS分散IO
-- ===========================================
-- 先创建3个独立临时TS
CREATE TEMPORARY TABLESPACE temp_grp_a TEMPFILE '/u03/oradata/orcl/tempa01.dbf' SIZE 10G
  EXTENT MANAGEMENT LOCAL UNIFORM SIZE 1M TABLESPACE GROUP temp_grp;
CREATE TEMPORARY TABLESPACE temp_grp_b TEMPFILE '/u04/oradata/orcl/tempb01.dbf' SIZE 10G
  EXTENT MANAGEMENT LOCAL UNIFORM SIZE 1M TABLESPACE GROUP temp_grp;
CREATE TEMPORARY TABLESPACE temp_grp_c TEMPFILE '/u05/oradata/orcl/tempc01.dbf' SIZE 10G
  EXTENT MANAGEMENT LOCAL UNIFORM SIZE 1M TABLESPACE GROUP temp_grp;
-- 设置数据库级默认临时表空间为这个组
ALTER DATABASE DEFAULT TEMPORARY TABLESPACE temp_grp;

-- ===========================================
-- (3) 切换数据库默认临时表空间（删除旧TEMP前）
-- ===========================================
ALTER DATABASE DEFAULT TEMPORARY TABLESPACE temp_new;
-- 等所有旧TEMP中无活动排序会话后，删旧的
DROP TABLESPACE temp INCLUDING CONTENTS AND DATAFILES;

-- ===========================================
-- (4) TEMPFILE扩容/增加/迁移
-- ===========================================
ALTER DATABASE TEMPFILE '/u03/oradata/orcl/temp01.dbf' RESIZE 30G;
ALTER TABLESPACE temp
  ADD TEMPFILE '/u04/oradata/orcl/temp02.dbf' SIZE 20G AUTOEXTEND ON NEXT 1G MAXSIZE 64G;
-- TEMPFILE无法通过ALTER TABLESPACE RENAME方式，正确方式：
ALTER DATABASE TEMPFILE '/u03/oradata/orcl/temp01.dbf' DROP INCLUDING DATAFILES;
ALTER TABLESPACE temp ADD TEMPFILE '/new_path/temp01.dbf' SIZE 20G;
```

### 3. 临时表空间查询视图

| 视图 | 用途 | 典型SQL |
| ---- | ---- | ---- |
| **DBA_TEMP_FILES** | 所有TEMPFILE路径与大小 | `SELECT tablespace_name, file_name, bytes/1024/1024 size_mb, autoextensible, maxbytes/1024/1024 max_mb FROM dba_temp_files;` |
| **DBA_TABLESPACE_GROUPS** | 临时表空间组成员 | `SELECT * FROM dba_tablespace_groups;` |
| **V$TEMPSEG_USAGE / V$SORT_SEGMENT** | 当前谁在用临时段（排序爆满定位） | `SELECT username, session_addr, sql_id, contents, segtype, extents, blocks*8/1024 mb FROM v$tempseg_usage ORDER BY blocks DESC;`（定位排序会话） |
| **DBA_USERS** | 用户临时表空间分配 | `SELECT username, temporary_tablespace FROM dba_users;` |

> [!tip] 临时表空间暴满定位（最常见运维问题）
> 排序/哈希操作多的DW/报表库TEMP突然100%：
> ```sql
> -- 谁在用最多临时段（SQL_ID查SQL）
> SELECT s.sid, s.serial#, s.username, s.sql_id, s.program,
>        t.segtype, t.blocks*8/1024 temp_mb
>   FROM v$session s, v$tempseg_usage t
>  WHERE s.saddr = t.session_addr
>  ORDER BY temp_mb DESC;
> -- 若TEMP不够可临时加一个临时文件应急：ALTER TABLESPACE temp ADD TEMPFILE '...' SIZE 20G;
> -- 长期解决方案：调大PGA_AGGREGATE_TARGET（WORKAREA_SIZE_POLICY=AUTO）减少磁盘排序；或大表加合适索引避免排序。
> ```

## 6.1.4 撤销表空间（Undo Tablespace / UNDOTBS）详解

> [!definition] 撤销表空间（Undo Tablespace）
> 存储**撤销段（Undo Segment，也叫回滚段Rollback Segment）**的专用表空间，Oracle 11g+默认**AUM自动撤销管理模式（Automatic Undo Management）**，DBA只需创建撤销表空间、设置UNDO_RETENTION，Oracle自动管理撤销段的创建/扩展/回收/在线切换，**不用手动管理回滚段（MUM手动管理已淘汰）**。

### 1. 撤销数据的四大作用

| 作用 | 说明 |
| ---- | ---- |
| **① 事务回滚（ROLLBACK）** | 用户执行ROLLBACK或会话异常终止，用撤销段里的前镜像把数据恢复到事务开始前 |
| **② 读一致性（Consistent Read）** | 会话A正在UPDATE某行未COMMIT，会话B读该行时，Oracle从撤销段取出该行列的前旧值返回给B，保证B看到的是一致时间点，不读脏数据 |
| **③ 实例恢复** | SHUTDOWN ABORT后SMON前滚REDO完成，需要用撤销段回滚前未提交的事务（打开数据库后后台SMON做） |
| **④ 闪回功能** | Flashback Query（闪回查询）、Flashback Table（闪回表）、Flashback Version Query、Flashback Transaction Query等都是基于撤销段中的历史镜像 |

### 2. 创建与维护SQL

```sql
-- ===========================================
-- (1) 创建备用撤销表空间（切换用、扩容用）
-- ===========================================
CREATE UNDO TABLESPACE undotbs2
  DATAFILE '/u02/oradata/orcl/undotbs2_01.dbf' SIZE 20G REUSE
    AUTOEXTEND ON NEXT 1G MAXSIZE UNLIMITED
  EXTENT MANAGEMENT LOCAL AUTOALLOCATE
  RETENTION NOGUARANTEE;  -- 默认NOGUARANTEE；GUARANTEE见下文详解

-- ===========================================
-- (2) 切换系统默认撤销表空间（热切换，实例不用重启！）
-- ===========================================
ALTER SYSTEM SET undo_tablespace = undotbs2 SCOPE=BOTH;
-- 切换后：新事务用UNDOTBS2的撤销段，老事务继续在UNDOTBS1直到提交
-- 等V$UNDOSTAT显示所有事务都用UNDOTBS2后（通常15分钟~几小时，看老事务时长），旧UNDOTBS1可删

-- ===========================================
-- (3) RETENTION GUARANTEE（保证撤销保留，一致性读保障）
-- ===========================================
ALTER TABLESPACE undotbs2 RETENTION GUARANTEE;
-- 默认RETENTION NOGUARANTEE：撤销表空间不足时，即使有长查询还需要旧撤销数据，也会覆盖重用（报错ORA-01555: Snapshot too old）
-- RETENTION GUARANTEE：保证UNDO_RETENTION时间内的撤销数据一定不被覆盖（即使空间不足，也不会覆盖保留期内的撤销，而是DML报错ORA-30036: unable to extend segment by 8 in undo tablespace...）
-- 适合：报表库/有大量长查询的系统（宁可DML报错也不许查询出ORA-01555）
ALTER TABLESPACE undotbs2 RETENTION NOGUARANTEE;   -- 切回默认

-- ===========================================
-- (4) 调整UNDO_RETENTION（参数，秒单位）
-- ===========================================
ALTER SYSTEM SET undo_retention = 21600 SCOPE=BOTH;   -- 保留6小时
-- 注意：UNDO_RETENTION是目标值，能不能真保留取决于UNDOTBS大小+RETENTION GUARANTEE
-- 生产建议：UNDO_RETENTION >= 最长查询耗时 + 闪回需求窗口（如想保留2小时闪回，UNDO_RETENTION至少设7200以上）

-- ===========================================
-- (5) 删除旧撤销表空间
-- ===========================================
-- 切换完成且所有旧撤销段OFFLINE后
DROP TABLESPACE undotbs1 INCLUDING CONTENTS AND DATAFILES;
```

### 3. 撤销管理关键视图

| 视图 | 用途 | 典型SQL |
| ---- | ---- | ---- |
| **V$UNDOSTAT** | AUM撤销段统计快照（每10分钟一行，保留最近4天）★最常用 | `SELECT TO_CHAR(begin_time,'YYYY-MM-DD HH24:MI') btime, ssolderrcnt ORA1555次数, txncount 事务数, undoblks*8/1024 撤销MB, tuned_undoretention 实际调整的UNDO_RETENTION, maxquerylen 最长查询秒 FROM v$undostat ORDER BY begin_time DESC;` |
| **DBA_UNDO_EXTENTS** | 撤销区状态（EXPIRED已过期可重用/UNEXPIRED未过期保留期内/ACTIVE活动事务在用） | `SELECT tablespace_name, status, COUNT(*), SUM(bytes)/1024/1024 mb FROM dba_undo_extents GROUP BY tablespace_name, status;` |
| **V$ROLLSTAT / V$ROLLNAME** | 当前活动撤销段状态（AUM下了解即可） | `SELECT r.name, rs.status, rs.extents, rs.rssize/1024/1024 mb, rs.optsize/1024/1024 opt_mb, rs.hwmsize/1024/1024 hwm_mb FROM v$rollname r, v$rollstat rs WHERE r.usn=rs.usn;` |
| **DBA_ROLLBACK_SEGS** | 所有回滚段定义（AUM下Oracle自动创建） | `SELECT owner, segment_name, tablespace_name, status FROM dba_rollback_segs ORDER BY segment_name;` |

> [!tip] UNDO表空间大小计算公式（Oracle官方推荐）
> ```
> 所需UNDO空间(MB) = UNDO_RETENTION(秒) × (每秒平均产生撤销块数 × db_block_size/1024/1024) × 1.2(冗余20%)
> ```
> 实例：UNDO_RETENTION=21600秒，每秒平均100个撤销块，8K块：
> Required MB = 21600 × (100 × 8/1024) × 1.2 ≈ 20250 MB ≈ 20 GB

## 小结

本节详述了Oracle三大核心表空间：**永久表空间**（对象容器，CREATE/DROP/ALTER TABLESPACE，重点是LMT+ASSM生产最佳组合、LOGGING vs NOLOGGING使用、AUTOEXTEND配置、DROP INCLUDING CONTENTS AND DATAFILES高风险、BigFile vs SmallFile）、**临时表空间**（排序专用，TEMPFILE而非DATAFILE、临时表空间组分散IO、切换默认临时表空间）、**撤销表空间**（AUM自动模式、热切换UNDOTBS、RETENTION GUARANTEE、UNDO_RETENTION参数、ORA-01555与V$UNDOSTAT）。对比了5大默认表空间SYSTEM/SYSAUX/TEMP/USERS/UNDOTBS1的职责边界。通过DBA_DATA_FILES+DBA_FREE_SPACE使用率SQL、V$TEMPSEG_USAGE定位会话、V$UNDOSTAT监控撤销使用量形成完整的存储运维视图。
