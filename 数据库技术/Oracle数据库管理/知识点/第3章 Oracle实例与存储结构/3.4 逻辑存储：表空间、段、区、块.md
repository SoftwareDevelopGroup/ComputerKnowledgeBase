# 3.4 逻辑存储：表空间→段→区→块

Oracle采用四层逻辑存储结构，从大到小依次是：**表空间 Tablespace → 段 Segment → 区 Extent → 块 Block**，最终块映射到物理磁盘的一个文件偏移量。四层逻辑结构是Oracle空间管理、容量规划、性能调优（段/区/块管理）的基础。

## 一、表空间 Tablespace

> [!definition] Tablespace表空间
> Oracle数据库逻辑最大的容器，**物理上对应N个数据文件.dbf**。作用：
> ① 物理隔离业务（销售表空间、用户表空间、索引表空间分离存储在不同磁盘）
> ② 空间配额（用户在表空间QUOTA配额
> ③ 表空间级备份恢复（PITR表空间时间点恢复
> ④ 表空间级冷热数据分离/压缩/传输表空间跨库迁移

### 默认表空间详解（Oracle 19c CDB默认

| 表空间 | 是否必选 | 作用 | 说明 |
|---|---|---|---|
| **SYSTEM** | ✅必选不能少 | 数据字典基表（SYS用户obj$/tab$/col$）、PL/SQL代码、System Rollback Segment | 不能删除不能重命名不能只读 |
| **SYSAUX** | ✅必选 | SYSTEM辅助表空间，AWR/ASH/ADDM、OEM、Oracle Text、Data Pump、XDB、LogMiner、Workspace Manager | 不能删除，损坏可以重建SYSAUX |
| **UNDOTBS1** | ✅必选（自动Undo管理模式下） | UNDO撤销数据（回滚未提交、读一致性、闪回查询 | 可以切换到其他UNDO表空间后DROP |
| **TEMP** | ✅至少一个默认临时表空间 | 排序/哈希/临时段存储（会话级/实例级临时 | 不能删除默认TEMP（需要先建临时表空间替换 |
| **USERS** | ⚠️默认 | 新建用户默认永久表空间 | 生产不用USERS，独立创建业务表空间 |
| **PDB$SEED**（CDB模式） | ✅CDB种子PDB | PDB创建时的克隆模板PDB | 只读模板 |

### 表空间四大类型

| 类型 | 用途 | 典型示例 |
|---|---|---|
| **永久表空间 Permanent** | 存储永久对象（表/索引/LOB） | SYSTEM/SYSAUX/USERS/业务数据表空间sale_data_tbs |
| **临时表空间 Temporary** | 存储临时段（排序/哈希/临时表/索引创建 | TEMP默认临时表空间 |
| **撤销表空间 Undo** | 存储UNDO撤销数据 | UNDOTBS1 |
| **大文件表空间 Bigfile**（Oracle专有） | 一个表空间只能1个数据文件，单个文件128TB（8K块） | VLDB数据仓库超大型对象存储 |

### 表空间区管理方式（Oracle专有）

> [!warning] DMT vs LMT（必考！Oracle专有的两种Extent管理

| 对比维度 | DMT 字典管理表空间（Dictionary Managed Tablespace，已淘汰 |
|---|---|
| 区分配/回收方式 | 记录在数据字典表（FETS$/UET$基表） |
| 性能 | 分配/回收频繁产生递归SQL（查字典表）、性能差 |
| 碎片 | 易产生磁盘碎片，需要手工合并空闲Coalesce |
| 参数 | 存储参数NEXT/PCTINCREASE/MINEXTENTS/MAXEXTENTS |
| 现状 | 8i前默认；Oracle 9i引入LMT后淘汰，19c**不支持DMT**创建 |

**LMT 本地管理表空间（Locally Managed Tablespace，19c默认**

| 对比维度 | LMT 本地管理表空间（Oracle 19c默认！推荐生产必须使用 |
|---|---|
| 区分配/回收方式 | 表空间每个数据文件头部有一个**位图块Bitmap**记录区使用情况 |
| 性能 | 分配/回收更新位图（比字典快）、无递归SQL |
| 碎片 | 自动跟踪，不易碎片 |
| 两种分配模式 | `AUTOALLOCATE`（Oracle自动区大小，推荐）/`UNIFORM SIZE n`（统一区大小） |
| 现状 | 19c默认创建，强制使用 |

> [!example] Oracle 19c 创建表空间语法示例
> ```sql
> -- 1. 推荐：LMT + 自动分配区大小AUTOALLOCATE + ASSM段管理（生产标配
> CREATE TABLESPACE sale_data_tbs
> DATAFILE '/u02/oradata/ORCL/sales_data01.dbf' SIZE 10G
> AUTOEXTEND ON NEXT 500M MAXSIZE 32G
> EXTENT MANAGEMENT LOCAL AUTOALLOCATE    -- LMT + 自动区大小
> SEGMENT SPACE MANAGEMENT AUTO;          -- ASSM段空间自动管理
> 
> -- 2. 索引表空间（索引单独放独立表空间分离磁盘I/O
> CREATE TABLESPACE sale_idx_tbs
> DATAFILE '/u03/oradata/ORCL/sales_idx01.dbf' SIZE 5G
> AUTOEXTEND ON NEXT 200M MAXSIZE 32G
> EXTENT MANAGEMENT LOCAL AUTOALLOCATE
> SEGMENT SPACE MANAGEMENT AUTO;
> 
> -- 3. 临时表空间（使用TEMPFILE
> CREATE TEMPORARY TABLESPACE temp2
> TEMPFILE '/u04/oradata/ORCL/temp2_01.dbf' SIZE 8G
> EXTENT MANAGEMENT LOCAL UNIFORM SIZE 16M;  -- 临时表空间推荐UNIFORM统一区
> 
> -- 4. 切换默认临时表空间：
> ALTER DATABASE DEFAULT TEMPORARY TABLESPACE temp2;
> 
> -- 5. UNDO表空间切换：
> CREATE UNDO TABLESPACE undotbs2 DATAFILE '/u01/...undotbs2.dbf' SIZE 20G;
> ALTER SYSTEM SET undo_tablespace=undotbs2 SCOPE=BOTH;
> DROP TABLESPACE undotbs1 INCLUDING CONTENTS AND DATAFILES;
> 
> -- 6. 表空间脱机/联机：
> ALTER TABLESPACE sale_data_tbs OFFLINE IMMEDIATE;
> ALTER TABLESPACE sale_data_tbs ONLINE;
> 
> -- 7. 表空间只读/读写：
> ALTER TABLESPACE sale_data_tbs READ ONLY;
> ALTER TABLESPACE sale_data_tbs READ WRITE;
> 
> -- 8. 删除表空间（含物理文件彻底删除！生产慎用
> DROP TABLESPACE sale_data_tbs INCLUDING CONTENTS AND DATAFILES CASCADE CONSTRAINTS;
> -- CASCADE CONSTRAINTS删除其他表空间对本表空间表的外键引用
> ```

> [!warning] 段空间管理方式：MSSM vs ASSM（Oracle专有
> 每个段中每个数据块内空闲空间管理方式：
> | 方式 | 说明 | 生产推荐 |
> |---|---|---|
> | **MSSM手动段管理（Manual Segment Space Management** | 用PCTUSED（块使用率下限）、FREELISTS（空闲块链表、FREELIST GROUPS管理空闲块 | ❌不推荐，旧方式，高并发插入导致FREELIST争用 |
> | **ASSM自动段管理（Automatic Segment Space Management）** ✅19c默认创建表空间指定SEGMENT SPACE MANAGEMENT AUTO | 用位图块管理空闲空间（3个位图：块状态：空/75-100%/50-75%/25-50%/<25%，自动管理PCTFREE仍生效PCTFREE不生效 | ✅生产必须使用ASSM |

## 二、段 Segment

> [!definition] Segment段
> 表空间里为某个**数据库对象（表/索引/回滚/临时/LOB）分配的一整块存储空间**。一个段对应一个逻辑对象：CREATE TABLE xxx创建一个表段，CREATE INDEX创建一个索引段... 段由一到多个Extent（区）组成，段大小=该区段所有Extent大小总和。

### 段类型分类

| 段类型 | 说明 | 示例 |
|---|---|---|
| **表段 Table Segment（非分区堆表段）** | 普通堆表数据存储位置 | SCOTT.EMP表段 |
| **表分区段 Table Partition Segment**（Oracle EE专有分区功能） | 分区表每个分区一个独立段（各自存储 | SALE表的202401/202402分区段 |
| **索引段 Index Segment | B*树索引的分支/叶子块存储位置 | IDX_EMPNO索引段 |
| **索引分区段 Index Partition Segment** | 分区索引每个分区独立段 | 本地索引的分区段 |
| **回滚段/UNDO段 Undo Segment** | UNDO表空间里的回滚段（存储前像 | 自动Undo管理下Oracle自动创建/销毁 |
| **临时段 Temporary Segment** | 临时表/排序/哈希连接临时存储段 | TEMP表空间里排序段 |
| **LOB段 LOB Segment** | CLOB/BLOB大对象大字段独立段（LOBINDEX/LOBSEGMENT两个段 | DBMS_LOB存储图片/文档独立段 |
| **嵌套表段 Nested Table Segment** | 嵌套表类型列存储段 | |
| **索引组织表段 IOT Segment** | IOT索引组织表（主键排序存储 | |

> [!example] Oracle 19c 段查询SQL
> ```sql
> -- 1. 查询某用户所有段+大小Top10（Top Segments：
> SELECT owner, segment_name, segment_type, tablespace_name,
>        bytes/1024/1024 size_mb, extents, blocks
> FROM dba_segments
> WHERE owner='SH'
> ORDER BY bytes DESC
> FETCH FIRST 10 ROWS ONLY;
> 
> -- 2. 统计表空间中段数/总大小：
> SELECT tablespace_name, COUNT(*) seg_count,
>        SUM(bytes)/1024/1024 total_mb
> FROM dba_segments
> GROUP BY tablespace_name;
> 
> -- 3. 查看段中区分配详情：
> SELECT owner, segment_name, extent_id, file_id, block_id, blocks, bytes/1024 size_kb
> FROM dba_extents
> WHERE owner='SCOTT' AND segment_name='EMP'
> ORDER BY extent_id;
> 
> -- 4. 段收缩（高水位线回收ASSM段空间，DELETE后空间不自动释放，需手动SHRINK：
> -- 4.1 先启用行迁移（row movement）
> ALTER TABLE sales ENABLE ROW MOVEMENT;
> -- 4.2 先压缩整理段内碎片（compact不降低HWM，不影响DML）：
> ALTER TABLE sales SHRINK SPACE COMPACT;
> -- 4.3 再收缩空间降低HWM，释放空间给表空间（短暂DML短暂锁表：
> ALTER TABLE sales SHRINK SPACE;
> -- 4.4 级联收缩索引段：
> ALTER TABLE sales SHRINK SPACE CASCADE;
> ```

## 三、区 Extent

> [!definition] Extent区
> 区=一组**物理上连续分配的Oracle Block（数据块**，是Oracle空间分配的最小单位。创建表时分配初始区Initial Extent，块用完不够用自动分配下一个区（Next Extent。段=1个或多个区。

> [!note] Oracle专有：LMT区分配两种模式
> | 模式 | 说明 | 适用场景 |
> |---|---|---|
> | **AUTOALLOCATE 自动分配（Oracle自动决定下一个区大小** | 区大小自动64K→1M→8M→64M→递增，小表小分区，大表自动分配大分区 | 绝大多数场景默认，生产推荐 |
> | **UNIFORM SIZE n 统一大小** | 所有区固定大小n（如1M/16M/64M） | 临时表空间推荐UNIFORM；大表大索引固定大小分配区减少碎片 |
>
> ```sql
> CREATE TABLESPACE test_lmt DATAFILE '...' SIZE 10G
> EXTENT MANAGEMENT LOCAL UNIFORM SIZE 16M; -- 所有区16MB统一大小
> ```

> [!example] Oracle 19c 区管理SQL
> ```sql
> -- 1. 查询某对象区分布（多少个区/每个区大小/位置：
> SELECT extent_id, file_id, block_id, blocks, bytes/1024 ext_kb
> FROM dba_extents
> WHERE owner='SALES' AND segment_name='BIG_TABLE'
> ORDER BY extent_id;
> 
> -- 2. 手动分配额外区（预分配空间给大表，避免运行时动态分配导致卡顿：
> ALTER TABLE sales_big ALLOCATE EXTENT SIZE 10G DATAFILE '/u02/.../sales02.dbf';
> 
> -- 3. 回收未使用空间（段末尾未用区回收给表空间：
> ALTER TABLE sales_big DEALLOCATE UNUSED;
> ```

## 四、块 Block（Oracle Block）

> [!definition] Oracle Block块
> Oracle数据库中**最小I/O单元**，不同于OS块（一般4KB）。Oracle每次读写磁盘都是整数个Oracle Block。数据库创建时指定DB_BLOCK_SIZE参数（默认8KB，19c不可更改标准块大小）。非标准块使用2K/4K/16K/32K建表空间时指定。

### 标准块大小对比
| DB_BLOCK_SIZE | 小文件数据文件最大 | 适用场景 |
|---|---|---|
| 4KB | 16GB | 小行小表OLTP，减少块内争用 |
| **8KB（默认推荐）** | 32GB | 绝大多数业务 |
| 16KB | 64GB | 数据仓库/DSS大表减少I/O次数 |
| 32KB | 128GB | 大文件/大对象VLDB |

### Oracle Block块内部结构（重点）


> [!definition] 关键参数PCTFREE、PCTUSED

| 参数 | 含义 | 示例PCTFREE=10 |
|---|---|---|
| **PCTFREE** | 块预留多少百分比给行UPDATE更新（行长度扩展）。10=保留10%空间不INSERT，只用于UPDATE。默认10% | 90%满就不再INSERT新行 |
| **PCTUSED** | 仅MSSM模式使用（ASSM已废弃PCTUSED！）：DELETE后块使用率降到多少以下才重新允许INSERT新行 | ASSM不用PCTUSED |

> [!warning] 行链接 Row Chaining vs 行迁移 Row Migration（Oracle专有概念
> | 现象 | 原因 | 后果 | 解决方案 |
> |---|---|---|---|
> | **行链接 Row Chaining** | 一行太大（如带CLOB/BLOB或列很多行长超过一个Block大小 | 一行跨多个Block存储，读这行需要多次I/O读多个块→性能差 | 用更大的DB_BLOCK_SIZE（如16KB建表空间），或将LOB列独立存到LOB表空间 |
> | **行迁移 Row Migration** | 行UPDATE变长增长（如VARCHAR2(100原本5字节→95字节增长，块PCTFREE预留空间不够，整行搬到新块，原块只留一个转发指针指向新块 | 读这行需要读原块+新块两次I/O→性能差。UPDATE频繁变长行常见 | 设置足够的PCTFREE（比如20/30），或ALTER TABLE xxx MOVE重建表+重建索引 |

> [!example] Oracle 19c Block诊断SQL
> ```sql
> -- 1. 查询标准块大小：
> SHOW PARAMETER db_block_size;
> -- VALUE=8192=8KB
> 
> -- 2. 查询表中行链接/迁移情况（ANALYZE后查CHAIN_CNT）：
> ANALYZE TABLE sales_big COMPUTE STATISTICS;
> SELECT table_name, num_rows, chain_cnt,
>        ROUND(chain_cnt / NULLIF(num_rows,0) * 100, 2) chain_pct
> FROM user_tables
> WHERE table_name = 'SALES_BIG';
> -- chain_pct>10%考虑处理行迁移
> 
> -- 3. 行迁移解决方案（MOVE重建表+重建索引：
> ALTER TABLE sales_big MOVE TABLESPACE sale_data_tbs UPDATE INDEXES;
> -- UPDATE INDEXES同时重建所有索引（避免索引UNUSABLE
> ```

|---|---|---|
| **表空间Tablespace** | DBA_TABLESPACES、V$TABLESPACE | tablespace_name, extent_management, allocation_type, segment_space_management, status, bigfile |
| **数据文件Data File** | DBA_DATA_FILES、V$DATAFILE | file_id, file_name, tablespace_name, bytes, autoextensible, maxbytes, status |
| **段Segment** | DBA_SEGMENTS | owner, segment_name, segment_type, tablespace_name, bytes, extents, blocks |

> [!example] Oracle 19c 四层结构综合查询SQL
> ```sql
> -- 综合查询：销售表SALES_BIG属于哪个表空间、数据文件路径、多少段多少区多少块：
> SELECT t.tablespace_name,
>        df.file_name,
>        s.segment_name, s.segment_type,
>        s.bytes/1024/1024 seg_mb, s.extents, s.blocks seg_blocks,
>        t.block_size,
>        ROUND(s.bytes / t.block_size) calc_blocks
> FROM dba_tables dt
> JOIN dba_segments s ON dt.owner=s.owner AND dt.table_name=s.segment_name AND s.segment_type='TABLE'
> JOIN dba_tablespaces t ON s.tablespace_name=t.tablespace_name
> JOIN dba_data_files df ON t.tablespace_name=df.tablespace_name
> WHERE dt.owner='SH' AND dt.table_name='SALES_BIG';
> ```

## 小结

- 四层逻辑映射：**Tablespace表空间（逻辑容器→数据文件.dbf）→Segment段（表/索引对应）→Extent区（连续Block）→Block块（最小I/O单元默认8KB）**
- 表空间：永久/临时/UNDO三大类，区管理LMT（默认），段管理ASSM（默认），Bigfile大文件表空间
- 段：表/索引/UNDO/临时/LOB段，段管理ASSM自动，空间不足自动分配新区或手动ALLCATE EXTENT
- 区：LMT自动AUTOALLOCATE或统一UNIFORM
- 块：默认8KB，结构=头+目录+行+空闲；PCTFREE预留UPDATE空间；行链接vs行迁移诊断+处理
