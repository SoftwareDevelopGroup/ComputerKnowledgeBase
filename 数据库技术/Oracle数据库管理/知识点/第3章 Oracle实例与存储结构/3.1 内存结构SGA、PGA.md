# 3.1 内存结构SGA、PGA

Oracle实例内存分为两大截然不同的区域：**SGA（System Global Area 系统全局区）= 所有服务器/后台进程共享的内存（全局共享，数据库核心缓存），PGA（Program Global Area 程序全局区）=每个服务器进程私有的内存（不共享，连接级缓存。两者调优直接决定Oracle性能上限。

> [!warning] 调优前提
> 生产环境Oracle 19c推荐使用**ASMM（自动共享内存管理）= SGA_TARGET参数**自动调SGA内部各组件+**自动PGA= PGA_AGGREGATE_TARGET**自动管理PGA，不推荐手动设置每个组件（DB_CACHE_SIZE、SHARED_POOL_SIZE）除非有AWR报告明确证据表明某组件不足。

## SGA系统全局区

> [!definition] SGA
> SGA是Oracle实例启动时分配的**一大段共享内存**，所有连接到实例的用户进程/服务器进程/后台进程共享SGA中数据。SGA = Oracle数据库的"大脑缓存"，SGA越大，缓存热数据块越多，物理I/O越少，性能越好。SGA参数：SGA_MAX_SIZE（最大上限）/SGA_TARGET（ASMM自动调优目标）。

### SGA五大核心组件详解

#### ① 数据库缓冲区高速缓存 DB Buffer Cache ⭐⭐⭐⭐⭐

> [!definition] DB Buffer Cache
> 缓存从数据文件读入的**Oracle数据块（Block）**。用户SELECT读块时先查缓存命中直接返回→命中叫逻辑读，没命中（缓存没有，产生物理I/O读磁盘）。DML修改块也在缓存中改（产生脏块Dirty Buffer），后台DBWn批量写回磁盘。

| 子池 | 作用 | 典型参数 |
|---|---|---|
| **DEFAULT 默认池** | 绝大多数对象（没有指定KEEP/RECYCLE的段都缓存于此 | DB_CACHE_SIZE（ASMM自动 |
| **KEEP 保持池** | 常访问的小表/索引（如代码表、字典表）手动指定`BUFFER_POOL KEEP`，缓存常驻，尽量不被换出，提高命中率 | DB_KEEP_CACHE_SIZE |
| **RECYCLE 回收池** | 大表全表扫描（一次性使用的冷数据，用完立即换出，避免挤掉DEFAULT池中的热数据） | DB_RECYCLE_CACHE_SIZE |
| **nK 非标准块大小池** | 支持2/4/8/16/32K块大小表空间（迁移/不同块大小的库迁移时用）。默认8KB=DB_nK_CACHE_SIZE | DB_2K_CACHE_SIZE...DB_32K_CACHE_SIZE |

> [!tip] 关键命中率指标
> ```
> Buffer Cache Hit Ratio = 1 - (物理读 / (逻辑读)) = 缓存命中率
> 生产理想值：OLTP系统 ≥99%，DSS分析 ≥95%
> <95%：需要加大DB_CACHE_SIZE/SGA_TARGET或SQL优化减少全表扫
> ```

#### ② 共享池 Shared Pool ⭐⭐⭐⭐⭐

> [!definition] Shared Pool
> 缓存SQL和PLSQL解析结果、数据字典元信息。两大核心子组件：**Library Cache**和**Data Dictionary Cache**。Shared Pool不足会导致严重CPU飙升（硬解析）和物理I/O（读字典）。

| 子组件 | 作用 |
|---|---|
| **Library Cache 库缓存** | 缓存SQL/PLSQL的解析树（Parse Tree）和执行计划（Execution Plan）。相同SQL第二次执行命中缓存→软解析（Soft Parse，省CPU）。没命中→硬解析（Hard Parse，CPU消耗大，Latch竞争严重） |
| **Row Cache（Data Dictionary Cache）** | 缓存数据字典信息（表/列/用户/权限/约束定义，SYS用户OBJ$/TAB$/COL$等基表）。Row Cache命中率低→频繁物理读SYSTEM表空间 |
| **Reserved Pool** | 大内存分配预留区（>4KB的大对象分配从这里，避免Shared Pool碎片 |

> [!warning] 硬解析 vs 软解析
> - 硬解析（Hard Parse）：SQL第一次执行→语法分析→语义分析→查询重写→生成执行计划→所有步骤全流程，CPU密集型（90%时间在解析）。OLTP系统禁止！
> - 软解析（Soft Parse）：SQL命中Library Cache→直接复用执行计划。CPU消耗仅为硬解析1%以下
> - **优化核心目标**：尽量多软解析，极少硬解析。绑定变量+Cursor Sharing是关键。

#### ③ 重做日志缓冲区 Redo Log Buffer ⭐⭐⭐⭐

> [!definition] Redo Log Buffer
> 循环写的小缓冲区（一般几十MB~几百MB），所有DML/DDL产生的**Redo Entries（重做条目）**先写入这里，后台LGWR进程批量/触发条件写进在线重做日志文件。预写式日志WAL的核心缓冲区。

| 关键属性 | 说明 |
|---|---|
| **粒度** | 16字节Redo记录 |
| **写顺序** | 严格按事务变更顺序写（循环使用） |
| **典型大小** | 默认几十MB，大型OLTP可设到256MB-1GB |
| **参数** | LOG_BUFFER（19c ASMM自动调整，一般不需手动设 |
| **触发写盘** | 见3.2节LGWR五大条件（COMMIT/3秒/1/3满/1MB满/DBWn前同步 |

> [!note] Oracle专有：Redo Buffer的Force Logging
> Oracle支持`ALTER DATABASE FORCE LOGGING`强制所有变更（即使NOLOGGING操作）也写Redo，Data Guard物理备库场景必须开启FORCE LOGGING保证备库同步。NOLOGGING操作虽然加速但不写Redo=介质恢复时丢失该操作且备库Gap。

#### ④ 大型池 Large Pool ⭐⭐⭐

> [!definition] Large Pool
> Oracle专有的"大内存分配专用池"，避免大内存分配挤占Shared Pool导致Shared Pool碎片。**不是必须，但建议配置**。

| 典型用途 | 说明 |
|---|---|
| **共享服务器模式（MTS）** | 会话UGA用户全局区内存（UGA）存放在Large Pool（不用Shared Pool防碎片 |
| **RMAN备份恢复** | RMAN备份I/O缓冲区（磁盘/磁带I/O缓冲 |
| **并行查询 PQ** | 并行执行服务器之间消息缓冲区 |
| **DBMS_STATS** | 大表统计收集大内存分配 |

参数：LARGE_POOL_SIZE（ASMM自动，RMAN备份大库建议手动至少设128MB-1GB）

#### ⑤ Java池 Java Pool ⭐⭐

> [!definition] Java Pool
> 数据库内Java虚拟机JVM使用的内存（Java存储过程/触发器/Java类加载）。不用Java存储过程时设置很小即可（几十MB）。使用OJVM Java功能时必须配大。参数：JAVA_POOL_SIZE。

> [!note] 可选SGA组件
> - **Streams Pool 流池**：Oracle Streams、GoldenGate集成捕获/应用进程（流复制）。STREAMS_POOL_SIZE
> - **IM Column Store 列存储内存**（12c+）：In-Memory选件列式存储区，INMEMORY_SIZE，分析场景专用。需要单独选件授权
> - **Fixed SGA**：Oracle内部固定大小的SGA区（几百MB），存放内部锁、 latch等结构

## PGA程序全局区

> [!definition] PGA（Program Global Area）
> 每个服务器进程（Server Process）启动时分配的**私有内存段**，其他进程无法访问。连接断开时PGA释放。PGA是每个连接独占的"工作台"。Oracle 19c默认使用**自动PGA管理**（PGA_AGGREGATE_TARGET参数限制所有进程总PGA上限，Oracle内部自动调每个进程的各区大小）。

### PGA核心区域

| 区域 | 作用 | 自动PGA管理时行为 |
|---|---|---|
| **排序区 Sort Area** | ORDER BY、GROUP BY、UNION、索引创建CREATE INDEX等内存排序（内存不够用临时表空间磁盘排序，极慢！） | 自动分配，不足时溢出到TEMP临时段 |
| **哈希连接区 Hash Area** | Hash Join（大表连接默认算法）内存放哈希表 | 自动分配，不足写临时段 |
| **位图合并区 Bitmap Merge** | 位图索引扫描合并位图 | 自动分配 |
| **UGA 用户全局区** | 会话级状态：游标状态、变量、登录信息、NLS参数 | 专用服务器模式UGA在PGA内；共享服务器模式UGA在SGA的Large Pool |

> [!warning] 磁盘排序代价
> Sort Area不足→排序溢出到磁盘（TEMP临时表空间）→性能暴跌（磁盘比内存慢1000倍以上）。AWR报告中"Disk Sort占Total Sort比率>5%"要加大PGA_AGGREGATE_TARGET，同时SQL优化减少不必要的大排序。

## SGA vs PGA 核心对比

| 维度 | SGA 系统全局区 | PGA 程序全局区 |
|---|---|---|
| **共享性** | **全局共享**（所有用户/后台进程共享同1份） | **进程私有**（每个服务器进程1份，互相不能访问） |
| **生命周期** | 实例启动时分配→实例关闭释放（整个实例生命周期 | 服务器进程创建时分配→进程终止时释放（连接生命周期） |
| **分配方式** | 实例启动时一次性或动态扩展SGA_MAX_SIZE | 按需动态分配/释放（受PGA_AGGREGATE_TARGET总上限 |
| **核心参数** | SGA_MAX_SIZE / SGA_TARGET（ASMM自动调 | PGA_AGGREGATE_TARGET（自动PGA） |
| **组成核心** | DB Buffer Cache + Shared Pool + Redo Buffer + Large/Java Pool | SQL工作区（Sort/Hash/Create Index）+ UGA |
| **典型大小** | 大（占数据库服务器内存**60~80%**，16GB RAM服务器可设10-12GB） | 小（总PGA=剩余内存20~40%，每个连接几MB~几GB不等 |
| **影响的性能指标** | 逻辑读命中率、硬解析率、物理I/O次数 | 排序/哈希内存命中率、磁盘排序率、OLAP复杂查询性能 |
| **调优目标** | Buffer Cache命中率≥99%（OLTP）；硬解析接近0 | 磁盘排序率<5%；Hash Join大部分在内存完成 |
| **Oracle专有** | KEEP/RECYCLE池、多块大小池、Shared Pool LRU latch链 | 自动PGA目标管理（10g+的PGA_AGGREGATE_TARGET+工作区大小自动） |

> [!note] Oracle专有 ASMM vs AMM
> - **ASMM（Automatic Shared Memory Management）自动共享内存**（推荐生产）：SGA_TARGET设一个总大小，SGA内部DB_CACHE_SIZE/SHARED_POOL_SIZE/LARGE_POOL_SIZE/JAVA_POOL_SIZE等组件Oracle自动调，DBA只需管总SGA和总PGA。参数：SGA_TARGET / PGA_AGGREGATE_TARGET。19c默认。
> - **AMM（Automatic Memory Management）自动内存管理**：MEMORY_TARGET设一个总上限，SGA和PGA之间Oracle动态互调（SGA不足从PGA借、反之）。参数MEMORY_TARGET / MEMORY_MAX_TARGET。**19c生产不推荐**（会用tmpfs /dev/shm，需要tmpfs够大；内存压力时swap抖动）。Linux下19c ASMM更稳定。

> [!example] Oracle 19c 生产内存参数设置示例
> ```sql
> -- 128GB RAM的OLTP服务器：OS留16GB，SGA约72GB，PGA约36GB（总计108GB
> -- 推荐ASMM模式（SGA_TARGET + PGA_AGGREGATE_TARGET，不用MEMORY_TARGET）
> 
> -- SGA参数（SGA_TARGET<=SGA_MAX_SIZE，SPFILE静态参数，重启生效
> ALTER SYSTEM SET SGA_MAX_SIZE=72G SCOPE=SPFILE;
> ALTER SYSTEM SET SGA_TARGET=72G SCOPE=SPFILE;   -- ASMM自动调内部组件
> 
> -- PGA参数（PGA_AGGREGATE_TARGET动态参数，立即生效
> ALTER SYSTEM SET PGA_AGGREGATE_TARGET=36G SCOPE=BOTH;
> 
> -- 19c默认关闭AMM（MEMORY_TARGET=0），保持ASMM即可：
> SHOW PARAMETER MEMORY_TARGET;   -- 期望 0
> ```

> [!example] Oracle 19c 查询SGA/PGA信息SQL
> ```sql
> -- 1. SGA整体分配：
> SELECT * FROM v$sga;
> -- 或新视图：
> SELECT component, current_size/1024/1024 size_mb
> FROM v$sga_dynamic_components
> WHERE component IN ('DEFAULT buffer cache','shared pool','large pool','java pool','PGA Target');
> 
> -- 2. SGA各组件动态大小（ASMM调过的历史：
> SELECT component, oper_type, oper_mode, parameter, initial_size/1024/1024 init_mb, final_size/1024/1024 final_mb
> FROM v$sga_resize_ops
> ORDER BY start_time DESC FETCH FIRST 20 ROWS ONLY;
> 
> -- 3. Buffer Cache命中率（OLTP≥99%良好
> SELECT ROUND((1 - (phy.value / (cur.value + con.value))) * 100, 2) "Buffer Cache Hit Ratio %"
> FROM v$sysstat cur, v$sysstat con, v$sysstat phy
> WHERE cur.name = 'session logical reads'
>   AND con.name = 'physical reads direct'  -- 直接读不进Buffer Cache（直接路径读
>   AND phy.name = 'physical reads';
> 
> -- 4. Library Cache命中率（SQL软解析率≥95%良好
> SELECT SUM(pinhits)/SUM(pins)*100 "Library Cache Hit Ratio %"
> FROM v$librarycache;
> 
> -- 5. PGA总览（PGA_AGGREGATE_TARGET目标 vs 实际使用
> SELECT name, unit, value/1024/1024 value_mb
> FROM v$pgastat
> WHERE name IN ('aggregate PGA target parameter','aggregate PGA auto target',
>                'global memory bound','total PGA inuse','total PGA allocated',
>                'maximum PGA allocated','extra bytes read/written','cache hit percentage');
> 
> -- 6. PGA工作区执行概况（100%最优=所有SQL工作区在内存完成，没写磁盘
> SELECT name, low_optimal_size/1024 low_kb, high_optimal_size/1024 high_kb,
>        optimal_executions "内存执行次数", onepass_executions "一次通过磁盘", multipasses_executions "多次磁盘扫描"
> FROM v$sql_workarea_histogram
> WHERE optimal_executions + onepass_executions + multipasses_executions > 0
> ORDER BY low_optimal_size;
> ```

> [!warning] 常见内存错误
> - **ORA-04031: unable to allocate N bytes of shared memory**：Shared Pool/Large Pool不足。通常是SQL没有绑定变量导致硬解析过多Shared Pool碎片，或者SGA_TARGET设太小。
> - **ORA-04030: out of process memory when trying to allocate N bytes**：PGA不足。单个SQL工作区超大（超大排序/哈希连接）或总PGA_AGGREGATE_TARGET太小，或者连接数过多每个PGA累积超上限。
> - **ORA-00845: MEMORY_TARGET not supported on this system**：AMM模式tmpfs /dev/shm小于MEMORY_TARGET。要么调大tmpfs要么切换到ASMM（推荐后者）。
> - **ORA-27102: out of memory**：SGA_MAX_SIZE设的超过了操作系统shmmax限制，需要调大kernel.shmmax内核参数（参见2.1节）

## 小结

- **SGA**=全局共享内存，核心是Buffer Cache（数据块缓存）和Shared Pool（SQL解析缓存），影响物理I/O和CPU消耗
- **PGA**=每个连接私有内存，核心是SQL工作区（排序/哈希），影响大查询是否写磁盘
- SGA vs PGA的调优目标：SGA命中率高（热块缓存），PGA工作区内存执行率100%（不写TEMP磁盘）
- 生产推荐ASMM：SGA_TARGET+PGA_AGGREGATE_TARGET自动调，不用AMM（MEMORY_TARGET）
- 通过v$SGA动态视图、v$PGASTAT、命中率SQL可以实时诊断内存瓶颈
