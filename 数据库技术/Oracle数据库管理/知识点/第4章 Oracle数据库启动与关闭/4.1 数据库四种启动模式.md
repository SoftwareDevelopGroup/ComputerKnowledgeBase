# 4.1 数据库四种启动模式

本节解决的核心问题是：**Oracle数据库从关闭到可用，经历了哪些阶段？每个阶段能做什么操作？** Oracle采用**分层逐步启动**的设计，这种设计使得DBA可以在不同阶段执行不同级别的维护操作（如重建控制文件需在NOMOUNT，切换归档模式需在MOUNT），是理解备份恢复与故障处理的前提。

## 4.1.1 四种启动模式层级总览

> [!definition] Oracle启动模式（Startup Modes）
> Oracle数据库启动过程分为四个由低到高的模式层级：**SHUTDOWN（关闭） → NOMOUNT（实例启动） → MOUNT（装载数据库） → OPEN（打开数据库）**。每个阶段完成特定的初始化工作，并允许执行特定的SQL命令。可以一步到位启动到OPEN，也可以逐步进阶。

```mermaid
stateDiagram-v2
    direction LR
    [*] --> SHUTDOWN
    SHUTDOWN --> NOMOUNT : STARTUP NOMOUNT
    NOMOUNT --> MOUNT : ALTER DATABASE MOUNT
    MOUNT --> OPEN : ALTER DATABASE OPEN
    NOMOUNT --> SHUTDOWN : SHUTDOWN
    MOUNT --> SHUTDOWN : SHUTDOWN
    OPEN --> SHUTDOWN : SHUTDOWN

    state NOMOUNT {
        description: 读参数文件 → 分配SGA → 启动后台进程
        V$INSTANCE.STATUS = STARTED
    }
    state MOUNT {
        description: 关联实例与数据库 → 读控制文件
        V$INSTANCE.STATUS = MOUNTED
    }
    state OPEN {
        description: 打开数据文件 → 打开重做日志
        V$INSTANCE.STATUS = OPEN
    }
```

> [!note] 状态查询
> 每个阶段对应的 **V$INSTANCE.STATUS**：
> - NOMOUNT → **STARTED**
> - MOUNT → **MOUNTED**
> - OPEN → **OPEN**
> 查询SQL：`SELECT status FROM v$instance;`

## 4.1.2 NOMOUNT阶段（实例启动阶段）

> [!definition] NOMOUNT阶段
> NOMOUNT阶段只启动**Oracle实例（Instance）**，不关联任何数据库。即：读参数文件 → 分配SGA → 启动后台进程 → 打开告警日志和跟踪文件。

### 1. NOMOUNT阶段完成的操作

| 步骤 | 操作内容 | 说明 |
| ---- | ---- | ---- |
| ① | 读取参数文件 | 优先读spfile（spfile<SID>.ora），其次读pfile（init<SID>.ora），最后读默认init.ora。可用`STARTUP PFILE='路径'`指定。 |
| ② | 分配SGA共享内存 | 根据参数文件中的SGA_MAX_SIZE、SGA_TARGET、MEMORY_TARGET等参数分配共享内存区（Buffer Cache、Shared Pool、Redo Log Buffer等）。 |
| ③ | 启动后台进程 | 启动DBWn、LGWR、CKPT、SMON、PMON、RECO等必需后台进程。 |
| ④ | 打开告警日志和跟踪文件 | 告警日志路径由DIAGNOSTIC_DEST参数决定（11g+ ADR自动诊断库）。 |

### 2. NOMOUNT阶段可执行的操作

- **CREATE DATABASE**：创建全新数据库（包括控制文件、重做日志、SYSTEM/SYSAUX表空间等）。
- **CREATE SPFILE FROM PFILE** / **CREATE PFILE FROM SPFILE**：参数文件互转、修复损坏的参数文件。
- **SHUTDOWN系列命令**：关闭实例。
- **查询V$INSTANCE、V$SGA、V$PARAMETER、V$SESSION等动态性能视图**（这些视图基于实例内存，不依赖数据库文件）。
- **STARTUP FORCE NOMOUNT**等进阶启动选项。

### 3. NOMOUNT阶段的典型使用场景

> [!example] NOMOUNT应用场景
> 1. **重建控制文件**：控制文件全部丢失时，需NOMOUNT启动后执行`CREATE CONTROLFILE ...`命令重建。
> 2. **新建数据库**：DBCA图形化建库或手工建库的第一步就是NOMOUNT。
> 3. **参数文件修复**：参数文件损坏无法启动到更高阶段时，NOMOUNT后重建spfile。
> 4. **备份恢复中的特殊场景**：RMAN恢复控制文件时需要NOMOUNT状态。

### 4. SQL命令示例（Oracle 19c）

```sql
-- 方式一：分步启动到NOMOUNT
STARTUP NOMOUNT;

-- 方式二：使用指定pfile启动（spfile损坏时）
STARTUP NOMOUNT PFILE='/u01/app/oracle/product/19c/dbhome_1/dbs/initorcl.ora';

-- 验证NOMOUNT状态：V$INSTANCE.STATUS = 'STARTED'
SELECT status, instance_name, startup_time FROM v$instance;
-- 输出示例：STATUS=STARTED

-- 查询SGA分配情况
SELECT name, value/1024/1024 "Size MB" FROM v$sga;
```

## 4.1.3 MOUNT阶段（装载数据库阶段）

> [!definition] MOUNT阶段
> MOUNT阶段将已启动的**实例与数据库关联**起来。即：根据参数文件中的CONTROL_FILES参数，找到并读取控制文件，从控制文件中获取数据文件、重做日志文件的清单和状态。此时数据库文件还**未打开**，只有DBA可访问。

### 1. MOUNT阶段完成的操作

| 步骤 | 操作内容 | 说明 |
| ---- | ---- | ---- |
| ① | 读取CONTROL_FILES参数 | 从参数文件获取多路复用控制文件的路径列表。 |
| ② | 校验并读取所有控制文件 | Oracle要求所有控制文件必须同时存在且内容一致（多路复用镜像）。任一个损坏就报错ORA-00205。 |
| ③ | 从控制文件读取文件清单 | 获取数据文件（Data Files）、在线重做日志文件（Online Redo Logs）的路径、数量、状态信息。 |

### 2. MOUNT阶段可执行的操作

- **重命名/添加/删除数据文件**：`ALTER DATABASE RENAME FILE`、`ALTER TABLESPACE ... ADD DATAFILE`等（注意：SYSTEM表空间数据文件不能在MOUNT阶段重命名）。
- **切换归档模式**：`ALTER DATABASE ARCHIVELOG` / `NOARCHIVELOG`（必须MOUNT状态执行，见第7章）。
- **执行完整/不完全数据库恢复**：RMAN或手动RECOVER DATABASE，恢复后再OPEN。
- **修改数据文件的ONLINE/OFFLINE状态**（除了SYSTEM表空间）。
- **查询V$DATAFILE、V$LOGFILE、V$TABLESPACE、V$CONTROLFILE等视图**（这些视图从控制文件读取）。
- **DROP DATABASE**（10g+）：删除整个数据库的所有文件。

### 3. SQL命令示例（Oracle 19c）

```sql
-- 方式一：直接启动到MOUNT
STARTUP MOUNT;

-- 方式二：从NOMOUNT进阶到MOUNT
ALTER DATABASE MOUNT;

-- 验证MOUNT状态：V$INSTANCE.STATUS = 'MOUNTED'
SELECT status, instance_name FROM v$instance;
-- 输出示例：STATUS=MOUNTED

-- 切换归档模式（必须MOUNT状态）
ALTER DATABASE ARCHIVELOG;
ALTER DATABASE OPEN;

-- 查看控制文件路径
SELECT name FROM v$controlfile;

-- 查看数据文件清单
SELECT file#, name, status FROM v$datafile;
```

## 4.1.4 OPEN阶段（打开数据库阶段）

> [!definition] OPEN阶段
> OPEN阶段使数据库对**普通用户可用**。即：打开所有在线数据文件 → 打开在线重做日志文件 → 执行约束检查和未提交事务的回滚（由SMON自动完成）。OPEN完成后，拥有CREATE SESSION权限的用户即可正常登录。

### 1. OPEN阶段完成的操作

| 步骤 | 操作内容 | 说明 |
| ---- | ---- | ---- |
| ① | 检查数据文件一致性 | Oracle检查控制文件中记录的SCN与各数据文件头部SCN是否一致。 |
| ② | 打开所有在线数据文件 | 除了OFFLINE的表空间数据文件，其余数据文件全部打开。如果有数据文件缺失或损坏，报错ORA-01157。 |
| ③ | 打开在线重做日志文件 | 重做日志组的CURRENT/ACTIVE成员文件必须可用。 |
| ④ | 事务恢复（自动） | 如果前次关闭不是干净关闭（如ABORT），SMON自动执行**实例恢复**：前滚（Redo）→ 打开数据库 → 回滚（Undo）未提交事务。 |

### 2. OPEN阶段的子模式

| 子模式 | 命令 | 说明 |
| ---- | ---- | ---- |
| **READ WRITE**（默认） | `ALTER DATABASE OPEN READ WRITE;` | 正常读写模式，可执行DML/DDL。 |
| **READ ONLY** | `ALTER DATABASE OPEN READ ONLY;` | 只读模式，只能SELECT，不能修改。用于数据报表库或迁移验证。 |
| **UPGRADE** | `STARTUP UPGRADE;` | 数据库版本升级专用模式，限制部分操作，升级脚本执行后需重启到正常模式。 |
| **RESTRICT** | `STARTUP RESTRICT OPEN;` | 只有RESTRICTED SESSION权限用户可登录，用于维护窗口。 |

### 3. SQL命令示例（Oracle 19c）

```sql
-- 方式一：直接正常启动（最常用）
STARTUP;   -- 等价于 STARTUP OPEN READ WRITE

-- 方式二：从MOUNT进阶到OPEN
ALTER DATABASE OPEN;

-- 启动到只读模式（报表查询）
STARTUP MOUNT;
ALTER DATABASE OPEN READ ONLY;

-- 验证OPEN状态：V$INSTANCE.STATUS = 'OPEN'
SELECT status, open_mode, log_mode FROM v$instance;
-- 输出示例：STATUS=OPEN, OPEN_MODE=READ WRITE, LOG_MODE=ARCHIVELOG/NOARCHIVELOG

-- 限制模式启动（维护窗口）
STARTUP RESTRICT;
-- 维护完成后解除限制
ALTER SYSTEM DISABLE RESTRICTED SESSION;
```

## 4.1.5 STARTUP命令完整参数汇总

> [!definition] STARTUP命令语法
> ```sql
> STARTUP [FORCE] [RESTRICT] [NOMOUNT | MOUNT | OPEN [READ ONLY | READ WRITE] | UPGRADE | DOWNGRADE]
>         [PFILE = 'pfile路径']
> ```

| 参数 | 作用 | 说明 |
| ---- | ---- | ---- |
| **NOMOUNT** | 仅启动实例 | 不装载数据库，不打开文件。 |
| **MOUNT** | 启动实例+装载数据库 | 读取控制文件，但不打开数据文件。 |
| **OPEN**（默认） | 启动+装载+打开 | 一步到位完整启动，对用户可用。 |
| **FORCE** | 强制启动 | = `SHUTDOWN ABORT` + `STARTUP`。仅在实例挂起无法正常关闭时用！ |
| **RESTRICT** | 限制会话 | 仅拥有RESTRICTED SESSION权限的用户可登录。 |
| **OPEN READ ONLY** | 只读打开 | 禁止任何修改操作，用于报表。 |
| **OPEN READ WRITE** | 读写打开（默认） | 正常模式。 |
| **UPGRADE** | 升级模式 | 版本升级专用。 |
| **PFILE='path'** | 指定参数文件 | spfile损坏时用指定pfile启动。 |

> [!danger] STARTUP FORCE 强制启动
> ```sql
> STARTUP FORCE;
> ```
> **本质 = SHUTDOWN ABORT + STARTUP**。用于数据库实例挂起、无法正常SHUTDOWN的紧急场景。
> **注意**：SHUTDOWN ABORT不写检查点、不回滚未提交事务，因此紧随其后的STARTUP必须由SMON自动执行实例恢复（前滚+回滚）。可能需要比正常启动更长的时间。**非紧急情况严禁使用！**

> [!warning] RESTRICT模式
> `STARTUP RESTRICT`启动后，**普通用户会收到ORA-12526/ORA-01035错误无法登录**。只有拥有`RESTRICTED SESSION`系统权限的用户（通常是SYS、SYSTEM）可以登录。维护完成后务必执行：
> ```sql
> ALTER SYSTEM DISABLE RESTRICTED SESSION;
> ```
> 否则业务用户一直无法接入！

## 4.1.6 四种模式下V$视图查询权限对比

| 视图家族 | NOMOUNT | MOUNT | OPEN | 数据来源 |
| ---- | ---- | ---- | ---- | ---- |
| V$INSTANCE、V$SGA、V$PARAMETER | ✅ | ✅ | ✅ | 实例内存/参数文件 |
| V$SESSION、V$PROCESS、V$BGPROCESS | ✅ | ✅ | ✅ | 实例内存 |
| V$CONTROLFILE | ❌ | ✅ | ✅ | 控制文件 |
| V$DATAFILE、V$TABLESPACE | ❌ | ✅ | ✅ | 控制文件 |
| V$LOGFILE、V$LOG、V$ARCHIVED_LOG | ❌ | ✅ | ✅ | 控制文件 |
| DBA_、ALL_、USER_数据字典 | ❌ | ❌ | ✅ | SYSTEM表空间数据字典表 |

> [!tip] 快速记忆
> - **内存级视图（V$INSTANCE/V$SGA等）**：NOMOUNT即查，基于实例内存。
> - **控制文件级视图（V$DATAFILE/V$LOGFILE等）**：MOUNT起查，基于控制文件。
> - **数据字典视图（DBA_/ALL_/USER_）**：必须OPEN，基于SYSTEM表空间中的数据字典基表。

## 小结

本节详述了Oracle数据库四种启动模式的层级关系（SHUTDOWN → NOMOUNT → MOUNT → OPEN），每个阶段完成的操作、可执行的SQL命令及典型应用场景。配合STARTUP命令的完整参数（FORCE、RESTRICT、READ ONLY等）与V$INSTANCE.STATUS状态值（STARTED/MOUNTED/OPEN）形成完整的启动操作体系。理解四个阶段是后续执行备份恢复、归档模式切换、控制文件重建等DBA高级操作的前提。
