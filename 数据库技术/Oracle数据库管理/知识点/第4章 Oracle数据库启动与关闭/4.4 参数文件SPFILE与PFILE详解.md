# 4.4 参数文件SPFILE与PFILE详解

本节解决的核心问题是：**Oracle数据库参数文件SPFILE与PFILE有什么区别？参数有哪些类型？如何修改、备份与恢复参数文件？** 参数文件决定了SGA分配、后台进程数量、控制文件路径等核心配置，是实例启动的第一要素。

## 4.4.1 PFILE与SPFILE对比

> [!definition] PFILE（Parameter File）
> 传统的**文本格式**参数文件，默认路径：`$ORACLE_HOME/dbs/init<SID>.ora`。可直接用vi/记事本编辑，但修改后需重启实例才生效（除极少数例外）。9i之前的唯一选择。

> [!definition] SPFILE（Server Parameter File）
> Oracle 9i引入的**二进制格式**服务器参数文件，默认路径：`$ORACLE_HOME/dbs/spfile<SID>.ora`。**不可直接编辑**（二进制文件，编辑器打开会损坏），必须通过`ALTER SYSTEM SET ... SCOPE=...`命令修改。是11g+的默认首选。

| 对比项 | PFILE（init<SID>.ora） | SPFILE（spfile<SID>.ora） |
| ---- | ---- | ---- |
| **格式** | 纯文本（ASCII） | 二进制 |
| **直接编辑** | ✅ vi/记事本直接改 | ❌ 必须用ALTER SYSTEM命令，直接编辑会损坏文件！ |
| **RAC集群支持** | ❌ 每个节点需独立PFILE | ✅ 单份SPFILE共享，支持各节点参数不同（带SID前缀） |
| **修改生效方式** | ❌ 修改后必须重启实例 | ⚠️ 分静态参数（需重启）与动态参数（立即生效） |
| **自检与语法校验** | ❌ 启动时才报错（拼错参数名/值直接启动失败） | ✅ ALTER SYSTEM修改时即时校验，非法值直接拒绝 |
| **RMAN备份支持** | ❌ 需手动OS备份 | ✅ RMAN可把SPFILE纳入自动备份 |
| **启动优先级** | 低（SPFILE不存在才找PFILE） | **高**（STARTUP默认先找SPFILE） |
| **典型使用场景** | SPFILE损坏时应急启动、新建数据库时的种子模板 | **生产环境默认使用** |

> [!note] Oracle 19c默认启动参数文件查找顺序
> STARTUP不带PFILE参数时，Oracle按以下顺序搜索：
> 1. `spfile<SID>.ora`（首选，实例级专属SPFILE）
> 2. `spfile.ora`（通用SPFILE，RAC多实例共用时可选）
> 3. `init<SID>.ora`（PFILE，最后兜底）
> 都找不到就报错`ORA-01078: failure in processing system parameters`。

## 4.4.2 SPFILE与PFILE互转

> [!definition] 互转命令
> SQL提供三个互转命令，任意启动模式下都可执行（包括NOMOUNT）。

### 1. SQL互转命令（Oracle 19c）

```sql
-- 1. SPFILE → PFILE（把SPFILE中的当前参数导出为文本PFILE，便于查看或备份）
CREATE PFILE='/u01/backup/initorcl_20240101.ora' FROM SPFILE;
-- 不指定路径则写到默认位置 $ORACLE_HOME/dbs/init<SID>.ora
CREATE PFILE FROM SPFILE;

-- 2. PFILE → SPFILE（从文本PFILE生成二进制SPFILE）
CREATE SPFILE='/u01/app/oracle/product/19c/dbhome_1/dbs/spfileorcl.ora'
  FROM PFILE='/u01/backup/initorcl_20240101.ora';
CREATE SPFILE FROM PFILE;   -- 用默认位置互转

-- 3. 内存 → PFILE/SPFILE（11g+新功能，从当前运行实例的内存参数值生成文件）
CREATE PFILE FROM MEMORY;   -- 把当前内存中生效的所有参数导出为PFILE
CREATE SPFILE FROM MEMORY;  -- 从内存生成SPFILE（SPFILE损坏时救命神器）
```

> [!tip] 参数文件日常备份最佳实践
> 每次执行`ALTER SYSTEM`修改参数后，立即导出一份日期命名的PFILE：
> ```sql
> CREATE PFILE='$ORACLE_HOME/dbs/initorcl.' || TO_CHAR(SYSDATE, 'YYYYMMDD_HH24MISS')
>   FROM SPFILE;
> ```
> 同时RMAN也要定期备份SPFILE：`CONFIGURE CONTROLFILE AUTOBACKUP ON;`（默认开启）会在备份数据库时自动备份SPFILE和控制文件。

### 2. PFILE内容示例

```pfile
# initorcl.ora 文本格式（节选关键参数，生产环境通常有50+参数）
orcl.__data_transfer_cache_size=0
orcl.__db_cache_size=1509949440
orcl.__java_pool_size=16777216
orcl.__large_pool_size=33554432
orcl.__oracle_base='/u01/app/oracle'
orcl.__pga_aggregate_target=805306368
orcl.__sga_target=2415919104
orcl.__shared_io_pool_size=117440512
orcl.__shared_pool_size=671088640
orcl.__streams_pool_size=0
*.audit_file_dest='/u01/app/oracle/admin/orcl/adump'
*.audit_trail='db'
*.compatible='19.0.0'
*.control_files='/u01/app/oracle/oradata/orcl/control01.ctl',
                '/u01/app/oracle/fast_recovery_area/orcl/control02.ctl'
*.db_block_size=8192
*.db_name='orcl'
*.db_recovery_file_dest='/u01/app/oracle/fast_recovery_area'
*.db_recovery_file_dest_size=10737418240
*.diagnostic_dest='/u01/app/oracle'
*.memory_target=3221225472
*.open_cursors=300
*.processes=300
*.remote_login_passwordfile='EXCLUSIVE'
*.undo_tablespace='UNDOTBS1'
```

> [!note] PFILE中的SID前缀规则
> - `*.参数名=值`：所有实例通用（RAC多实例共用）
> - `<SID>.参数名=值`：仅特定SID实例生效（RAC中各实例配置不同SGA等）
> 例如 RAC双节点：
> ```pfile
> *.db_name=racdb
> orcl1.instance_number=1
> orcl1.thread=1
> orcl2.instance_number=2
> orcl2.thread=2
> ```

## 4.4.3 参数类型：静态参数 vs 动态参数

> [!definition] 参数按生效方式分类
> - **静态参数（Static Parameter）**：修改后**必须重启实例**才能生效，通常修改SPFILE后重启。
> - **动态参数（Dynamic Parameter）**：修改后**立即生效**，无需重启。动态参数又分为会话级（SESSION级，只影响当前会话）与系统级（SYSTEM级，影响所有新会话）。

### 1. 参数修改命令ALTER SYSTEM / ALTER SESSION（Oracle 19c）

```sql
-- =========================================
-- ALTER SYSTEM SET（系统级修改，影响所有会话）
-- SCOPE = MEMORY | SPFILE | BOTH（默认BOTH）
-- =========================================

-- SCOPE=BOTH（默认）：当前内存+SPFILE同时修改，下次重启也保留
ALTER SYSTEM SET memory_max_target=4G SCOPE=BOTH;
ALTER SYSTEM SET open_cursors=500;   -- 省略SCOPE就是BOTH

-- SCOPE=MEMORY：仅修改当前内存生效，重启后丢失恢复为SPFILE原值
ALTER SYSTEM SET sql_trace=TRUE SCOPE=MEMORY;  -- 临时开启SQL追踪

-- SCOPE=SPFILE：仅修改SPFILE，当前不生效，必须重启后才生效
-- （静态参数必须用SCOPE=SPFILE，否则直接报错ORA-02095）
ALTER SYSTEM SET processes=500 SCOPE=SPFILE;   -- processes是静态参数
ALTER SYSTEM SET sga_max_size=6G SCOPE=SPFILE; -- sga_max_size是静态参数

-- 带COMMENT注释（方便日后知道为什么改）
ALTER SYSTEM SET pga_aggregate_target=2G
  COMMENT='2024-01-01: 业务扩容，提高PGA上限'
  SCOPE=BOTH;

-- =========================================
-- ALTER SESSION SET（会话级，仅影响当前登录会话）
-- =========================================
ALTER SESSION SET nls_date_format='YYYY-MM-DD HH24:MI:SS';
ALTER SESSION SET sort_area_size=104857600;
ALTER SESSION SET optimizer_mode=FIRST_ROWS_10;
```

> [!warning] SCOPE参数使用规则
> | 参数类型 | SCOPE=MEMORY | SCOPE=SPFILE | SCOPE=BOTH |
> | ---- | ---- | ---- | ---- |
> | **动态参数** | ✅ 立即生效，重启失效 | ✅ 重启后生效 | ✅ 推荐：立即+永久 |
> | **静态参数** | ❌ 报错 ORA-02095 | ✅ 必须重启 | ❌ 报错 ORA-02095 |

### 2. 如何判断参数是静态还是动态

```sql
-- V$PARAMETER视图的ISSYS_MODIFIABLE字段
SELECT name, type, value, issys_modifiable, isses_modifiable, isdefault
  FROM v$parameter
 WHERE name IN ('processes', 'memory_target', 'sga_max_size', 'open_cursors', 'nls_date_format')
 ORDER BY name;
```

| ISSYS_MODIFIABLE值 | 含义 | ALTER SYSTEM能否修改 |
| ---- | ---- | ---- |
| **IMMEDIATE** | 动态参数（SCOPE=MEMORY/BOTH可立即生效） | ✅ 能 |
| **DEFERRED** | 延迟生效的动态参数（只影响修改后新建立的会话） | ✅ 需加DEFERRED |
| **FALSE** | **静态参数**，只能改SPFILE，必须重启 | ⚠️ 仅SCOPE=SPFILE |
| **ISSES_MODIFIABLE=TRUE** | 可ALTER SESSION会话级修改 | - |

> [!example] 常见静态参数 vs 动态参数
> | 参数 | 类型 | 说明 |
> | ---- | ---- | ---- |
> | `processes` | 静态 | 最大OS进程数，修改需重启 |
> | `sga_max_size` | 静态 | SGA上限，修改需重启 |
> | `memory_max_target` | 静态 | 自动内存管理上限，需重启 |
> | `db_block_size` | 静态 | **建库后永久不可修改**！ |
> | `control_files` | 静态 | 控制文件路径，需重启 |
> | `memory_target` | 动态 | 当前实际使用的自动内存量 |
> | `sga_target` | 动态 | ASM模式下SGA实际值 |
> | `open_cursors` | 动态 | 每会话最大游标数 |
> | `undo_retention` | 动态 | 撤销保留时间（秒） |

## 4.4.4 关键参数查询视图

| 视图 | 用途 | 典型SQL |
| ---- | ---- | ---- |
| **V$PARAMETER** | 当前会话生效的参数值（含ALTER SESSION修改） | `SELECT name, value FROM v$parameter WHERE name LIKE '%sga%';` |
| **V$SYSTEM_PARAMETER** | 实例系统级参数值（SYSTEM级默认） | `SELECT name, value FROM v$system_parameter;` |
| **V$SPPARAMETER** | SPFILE文件中存储的参数值（磁盘上的） | `SELECT name, value, isspecified FROM v$spparameter;` |
| **V$PARAMETER_VALID_VALUES** | 某个参数允许的合法取值列表 | `SELECT * FROM v$parameter_valid_values WHERE name='optimizer_mode';` |

```sql
-- 对比SPFILE中存储的值 vs 内存当前值（用于排查修改未生效）
SELECT p.name, p.value AS current_value, s.value AS spfile_value
  FROM v$parameter p
  JOIN v$spparameter s ON p.name = s.name
 WHERE s.isspecified='TRUE'
   AND p.value <> s.value;
```

> [!tip] SHOW PARAMETER 快捷命令
> ```sql
> SHOW PARAMETER sga;       -- 等价于从V$PARAMETER查name含sga的
> SHOW PARAMETER processes; -- 生产最常用，看最大进程数
> SHOW SGA;                 -- 查看SGA各组件分配情况
> ```

## 4.4.5 参数文件损坏应急恢复流程

> [!danger] 真实场景：误操作把非法参数写入SPFILE导致无法启动
> ```
> ORA-00823: Specified value of sga_target greater than sga_max_size
> ORA-01078: failure in processing system parameters
> ```
> 以下是标准应急恢复步骤：

```bash
# 步骤1：用备份PFILE先启动（SPFILE损坏时）
cd $ORACLE_HOME/dbs
ls initorcl.*   # 找之前备份的PFILE（日常备份很重要！）

# 步骤2：用PFILE启动到NOMOUNT
sqlplus / as sysdba
STARTUP NOMOUNT PFILE='$ORACLE_HOME/dbs/initorcl.20240101_120000';

# 步骤3：从PFILE或内存重建SPFILE
CREATE SPFILE FROM PFILE='$ORACLE_HOME/dbs/initorcl.20240101_120000';
-- 或从当前内存（NOMOUNT已经分配SGA）：
CREATE SPFILE FROM MEMORY;

# 步骤4：正常重启
SHUTDOWN IMMEDIATE;
STARTUP;   -- 现在用新SPFILE启动
```

> [!note] 完全没有任何备份PFILE怎么办？
> 回到[[4.3 启动故障简单排查]]的方案C：去告警日志alert_SID.log中找最近一次正常启动时打印的完整参数列表（每次启动告警日志都会输出所有非默认参数），复制出来手工拼成最小PFILE，再按上述步骤重建SPFILE。
