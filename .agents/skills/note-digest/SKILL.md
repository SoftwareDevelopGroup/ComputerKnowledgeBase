# 笔记重点归纳（note-digest）

把知识库中**已有的笔记**归纳为一份可检索、可复习、可导航的"重点总结"笔记。本技能只做归纳与提炼，**不新造知识**：所有要点必须能在原笔记中找到依据，无法确认的内容保持"待核实"。

## 何时使用

- 用户对一篇笔记、一个章节目录、一门课程或一个领域说"整理重点 / 归纳总结 / 提炼要点 / 复习总结 / 考前速记 / 知识要点"。
- 范围自动识别，按用户提到的目标决定粒度：
  - 单篇笔记路径 → 浓缩该篇
  - 章节目录 → 该目录下全部笔记
  - 课程目录（含 MOC）→ 整门课程，以 MOC 结构为骨架
  - 领域目录（含多门课程）→ 先逐课程归纳，再汇总；若过大则提示用户按课程分批

## 工作流

1. **确认输入与范围**：从用户消息中提取目标路径；含糊时用 AskUserQuestion 确认，不要猜测。范围过大（超过约 30 篇笔记）先与用户确认是否分批。
2. **遵守 AGENTS.md**：读取库根 `AGENTS.md` 与目标目录的局部 `AGENTS.md`，按其 Frontmatter 词表、命名、链接、Callout 规则执行；本技能与局部规则冲突时以更具体者为准。
3. **全面读取，不全靠抽样**：读取范围内全部相关笔记。先读范围所属 MOC（如 `MOC - 名称.md`），用其结构作为总骨架；再逐篇提取稳定概念、定义、原理、公式、算法步骤、易错点、示例。
4. **识别"重点"信号**：综合以下线索判断，而不是机械照抄：
   - 原笔记中的高亮（`==...==`）、"重要/核心/注意/易错"字样的 Callout；
   - 反复出现、跨篇关联的概念（如网络层里 IP/ARP/路由在三处都出现）；
   - 计算/过程类内容（公式、步骤、单位、适用条件）；
   - 结构信号：MOC 的入口与分支、章节间的依赖关系。
5. **输出：新建重点总结笔记**，命名 `XX重点总结.md`（XX 为范围主题），放在范围所属目录下（课程级放课程根目录，与 MOC 并列；章节级放章节目录）。若已存在同名或功能重复笔记，先比较再决定合并、更新或新建，不制造平行孤岛。
6. **验证**：检查 Frontmatter 可解析、所有 `[[链接]]` 与 `![[嵌入]]` 目标存在、Callout 语法正确、LaTeX 可用、行尾与所在目录保持一致。

## 重点总结笔记的结构（按范围适配）

参考范本：`网络与安全/计算机网络A/知识点/期末考试重点知识.md`。以下为完整骨架，单篇/章节级可裁剪：

```yaml
---
domain: <该领域稳定词，如 网络与安全>
type: 主题综述        # 整门课程/跨篇总结用"主题综述"；单篇浓缩可用"概念"
status: 整理中
course: <课程名，适用时>
aliases:
  - <常见异名、英文名>
tags:
  - <少量稳定标签>
cssclasses:
  - <如适用：exam-note 表示偏复习导向>
prerequisites:
  - "[[先修笔记]]"
moc: "[[MOC - 课程名]]"      # 声明归属的 MOC（如存在）
created: YYYY-MM-DD
updated: YYYY-MM-DD
source: <归纳自哪些笔记/来源，适用时>
---
```

正文按以下顺序组织：

1. **开头定位**（1–3 句）：这份总结覆盖什么范围、解决什么问题、与原笔记什么关系。
2. **使用方式** Callout：说明三种用法（快速定位 / 考前串联 / 概念复习）。
3. **快速导航表**：`| 主题/章节 | 复习主线 | 入口 |`，入口链接到本笔记章节标题或原笔记。
4. **跨主题速查表**（课程/领域级适用）：用一个表格横向对比贯穿主题的维度（如网络层五层、各章核心问题）。
5. **按主题/章节展开**，每个主题：
   - 该主题"高频考点/核心要点" Callout（`> [!abstract]-`），列 3–6 个最可能被考察的点；
   - 要点用简短条目：定义一句话、原理/机制、公式（LaTeX 且说明符号与适用条件）、关键步骤（可用编号列表）；
   - 易错点/边界用 `> [!warning]` 或 `> [!tip]`；
   - **链接回原笔记**的具体标题或块（`[[原笔记#标题]]`），正文不复制大段原文。
6. **计算/过程题统一步骤**（如范围含计算或过程题）：给出可复用的答题链。
7. **结尾**：先修与后继关系、与 MOC 的链接、遗留"待核实"项。

## 关键约束

- **只归纳，不新造**：所有断言必须能追溯原笔记或已核实来源；来源冲突时并列并标"待核实"。
- **不复制正文**：重点总结是"索引 + 浓缩"，详细内容用链接回原笔记，避免同一知识双份维护。
- **命名与词表遵守 AGENTS.md**：status 用文字值（整理中/已完成等）不用 emoji；type 从词表选择；不堆叠同义词进文件名。
- **保留原文**：不修改、不删除范围内的原笔记；总结是新增文件。
- **范围外不扩散**：只处理与本次归纳相关的笔记和链接，不顺手整库美化。

## 交付汇报

完成后报告：新建了哪个文件（路径）、覆盖范围、采用了哪种粒度与骨架、关键提炼判断（哪些算重点、为什么）、遗留的待核实项、回退方式（新文件可删除，不影响原笔记）。
