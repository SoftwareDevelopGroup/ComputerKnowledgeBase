# 5.3 视频技术

> [!abstract] 核心问题
> 视频如何编码和压缩？流媒体技术是如何工作的？

## 一、视频基础

### 1. 视频概念

**视频（Video）**是连续播放的图像序列：

| 概念 | 说明 |
|-----|------|
| **帧（Frame）** | 视频的单个图像 |
| **帧率（Frame Rate）** | 每秒播放的帧数 |
| **帧间冗余** | 相邻帧之间的相似性 |

### 2. 帧率

| 帧率 | 说明 | 应用 |
|-----|------|-----|
| **24 fps** | 电影帧率 | 电影 |
| **25 fps** | PAL制式 | 欧洲、中国 |
| **30 fps** | NTSC制式 | 美国、日本 |
| **60 fps** | 高帧率 | 游戏、体育直播 |

### 3. 视频分辨率

| 分辨率 | 说明 | 应用 |
|-----|------|-----|
| **480p** | SD（标清） | 旧电视 |
| **720p** | HD（高清） | 网络视频 |
| **1080p** | Full HD（全高清） | 主流视频 |
| **4K** | UHD（超高清） | 高端视频 |
| **8K** | 超高清 | 未来标准 |

## 二、视频编码

### 1. 编码原理

**视频编码**是压缩视频数据的技术：

| 压缩方式 | 说明 |
|-----|------|
| **帧内压缩** | 压缩单个帧（空间冗余） |
| **帧间压缩** | 压缩相邻帧之间的差异（时间冗余） |

### 2. 帧类型

| 帧类型 | 说明 |
|-------|------|
| **I帧（Intra Frame）** | 关键帧，完整图像 |
| **P帧（Predictive Frame）** | 预测帧，基于前一帧预测 |
| **B帧（Bidirectional Frame）** | 双向预测帧，基于前后帧预测 |

### 3. 视频编码标准

| 标准 | 说明 | 应用 |
|-----|------|-----|
| **MPEG-1** | 早期标准 | VCD |
| **MPEG-2** | DVD标准 | DVD、数字电视 |
| **MPEG-4** | 高效压缩 | 网络视频、流媒体 |
| **H.264/AVC** | 广泛使用 | 蓝光、网络视频 |
| **H.265/HEVC** | 更高压缩率 | 4K视频 |
| **AV1** | 开源标准 | 流媒体 |

### 4. H.264编码原理

```mermaid
flowchart TD
  A[原始视频] --> B[帧内预测]
  A --> C[帧间预测]
  B --> D[变换编码]
  C --> D
  D --> E[量化]
  E --> F[熵编码]
  F --> G[压缩视频]
```

| 步骤 | 说明 |
|-----|------|
| **帧内预测** | 使用帧内像素预测当前块 |
| **帧间预测** | 使用运动估计和补偿 |
| **变换编码** | DCT变换，将空间域转换为频率域 |
| **量化** | 丢弃不重要的频率分量 |
| **熵编码** | Huffman或CABAC编码 |

## 三、视频格式

### 1. 常见格式

| 格式 | 编码 | 特点 | 应用 |
|-----|------|-----|-----|
| **AVI** | 多种编码 | 兼容性好，文件大 | 旧视频 |
| **MP4** | H.264/H.265 | 高效压缩，广泛支持 | 网络视频 |
| **MKV** | 多种编码 | 开源，支持多音轨 | 高清视频 |
| **MOV** | ProRes/H.264 | Apple格式 | macOS/iOS |
| **FLV** | VP6/H.264 | Flash格式，已淘汰 | 旧网页 |
| **WebM** | VP8/VP9/AV1 | 开源，适合网页 | 现代网页 |

### 2. 容器与编码的关系

| 容器 | 支持的编码 |
|-----|-----------|
| **MP4** | H.264, H.265, MPEG-4 |
| **MKV** | 几乎所有编码 |
| **WebM** | VP8, VP9, AV1 |

## 四、流媒体技术

### 1. 流媒体概念

**流媒体（Streaming）**是边下载边播放的技术：

| 类型 | 说明 |
|-----|------|
| **直播流媒体** | 实时直播 |
| **点播流媒体** | 按需播放 |

### 2. 流媒体协议

| 协议 | 说明 | 应用 |
|-----|------|-----|
| **RTSP** | 实时流协议 | 直播 |
| **RTMP** | 实时消息协议 | Flash直播 |
| **HLS** | HTTP直播流 | Apple设备 |
| **DASH** | 动态自适应流 | 现代流媒体 |

### 3. HLS工作原理

```mermaid
flowchart TD
  A[服务器] --> B[视频分段]
  B --> C[创建播放列表]
  C --> D[客户端请求]
  D --> E[服务器返回片段]
  E --> F[客户端播放]
```

**步骤**：
1. 服务器将视频分成小片段（通常10秒）
2. 创建M3U8播放列表文件
3. 客户端下载播放列表
4. 客户端依次下载和播放片段

### 4. 自适应比特率

**自适应比特率（ABR）**根据网络状况调整视频质量：

| 原理 | 说明 |
|-----|------|
| **多码率编码** | 同一视频编码为多个比特率版本 |
| **动态切换** | 根据网络带宽切换码率 |
| **缓冲管理** | 维持足够的缓冲，避免卡顿 |

## 六、视频文件大小计算

### 1. 计算公式

**文件大小(字节) = 比特率(bps) × 时间(秒) / 8**

### 2. 比特率选择

| 分辨率 | 推荐比特率 |
|-------|-----------|
| **720p** | 2-5 Mbps |
| **1080p** | 5-10 Mbps |
| **4K** | 15-25 Mbps |

### 3. 示例

**计算1分钟1080p视频的文件大小**：
- 分辨率：1920×1080
- 帧率：30 fps
- 比特率：8 Mbps
- 时间：60秒
- 文件大小 = 8 × 1024 × 1024 × 60 / 8 = 62,914,560字节 ≈ 60 MB

## 七、易错点提示

> [!warning] 常见误区
> - **"视频格式就是编码格式"**：视频格式是容器，编码格式是压缩算法，两者不同。
> - **"帧率越高，视频越清晰"**：帧率影响流畅度，分辨率影响清晰度。
> - **"流媒体就是下载后播放"**：流媒体是边下载边播放，不需要等待完整下载。
> - **"H.265一定比H.264好"**：H.265压缩率更高，但兼容性不如H.264。

## 八、示例与练习

### 示例

**例1**：分析视频卡顿的原因

**解析**：
- 网络带宽不足，无法及时下载视频片段
- 设备性能不足，无法及时解码视频
- 视频比特率过高，超过设备处理能力
- 服务器负载过高，响应慢
