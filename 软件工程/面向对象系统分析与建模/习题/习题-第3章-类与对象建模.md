<details>
<summary>四、简答题答案（点击展开）</summary>

**21.** `+` public（公有，对外公开）；`-` private（私有，仅类内访问）；`#` protected（受保护，类内及子类访问）；`~` package（包级，同包可访问）。Java 中分别对应 `public`、`private`、`protected`、默认包访问。

**22.** 区别在于部分的生命周期是否与整体一致。聚合是弱关系，部分可独立存在，整体不负责部分的销毁，图符为空心菱形，如“部门”聚合“员工”。组合是强关系，部分与整体同生共死，整体负责创建与销毁部分，图符为实心菱形，如“订单”组合“订单项”。

**23.** `1..1`：恰好一个，如“订单”对应“一个顾客”；`0..*`：零个或多个，如“顾客”可拥有“多个地址”或没有；`1..*`：至少一个，如“订单”至少含“一个订单项”；`0..1`：零个或一个，如“员工”可选“一个配偶”。

**24.** 对象图是类图在某一时刻的实例化快照，展示具体的对象实例及其链。类图描述“类型与结构”，对象图描述“某时刻的值与连接”。对象图常用于验证类图的正确性或解释复杂场景。例如类图“订单—订单项”可实例化为对象图“订单#001 含两个订单项对象”。

</details>

<summary>五、建模分析题参考答案（点击展开）</summary>

**25. 参考要点**
- 类：顾客（customerId, name, phone）、订单（orderId, status, createTime）、订单项（itemId, qty, price）、商品（productId, name, stock）、类别（catId, name）、地址（addressId, detail）、支付记录（payId, amount, time）。
- 关系：顾客 1 — 0..* 订单；订单 1 组合 1..* 订单项；订单项 * — 1 商品；商品 * — 1 类别；顾客 1 — 1..* 地址；订单 1 — 1 支付记录（依赖）。
- 组合理由：订单删除则订单项无意义，生命周期一致。

**26. 参考要点**
- 汽车 1 组合 4 轮子（实心菱形，轮子随汽车销毁）；
- 部门 1 聚合 1..* 员工（空心菱形，员工可调离）；
- 学生 * — * 课程（普通关联线，多对多）；
- 司机 ——> 汽车（虚线箭头，依赖，临时使用）。
- 组合与聚合区分：轮子随汽车整体销毁故组合；员工不随部门销毁故聚合。

**27. 参考要点**
- 对象图：`订单#001:Order`（orderId=#001, status=待支付）；
  `订单项1:OrderItem`（qty=2, price=59.0）链向《UML 建模》:Product（stock=98）；
  `订单项2:OrderItem`（qty=1, price=79.0）链向《设计模式》:Product（stock=50）。
- 链：订单#001 —— 订单项1、订单#001 —— 订单项2。
- 验证：对象图可实例化说明类图结构合理、多重性满足。

**28. 参考要点**
```java
public class Order {
    private String orderId;
    private Date createTime;
    private Customer customer;            // 关联：引用
    private List<OrderItem> items = new ArrayList<>();  // 组合：持有集合并负责创建
    public void addItem(Product p, int qty) {
        OrderItem item = new OrderItem(p, qty);  // 组合：整体创建部分
        items.add(item);
    }
}
class OrderItem {
    private Product product;             // 关联
    private int qty;
}
class Customer {}
class Product {}
```
- 组合：整体用集合持有部分并负责创建；关联：仅引用，不负责生命周期。
