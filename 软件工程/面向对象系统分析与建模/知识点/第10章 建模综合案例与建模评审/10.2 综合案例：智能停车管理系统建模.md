# 10.2 综合案例：智能停车管理系统建模

本节以“智能停车管理系统”为综合案例，演示物联网场景下的系统建模。与在线书店不同，本案例强调硬件设备（摄像头、道闸、传感器）与软件系统的交互、停车流程的实时性与状态机驱动。覆盖用例、领域、动态与架构建模，重点展示停车流程时序图与部署图。

## 系统需求概述

智能停车管理系统为停车场实现无人值守的车辆进出管理、车位调度、计费与支付。

**功能性需求**：
- 车辆进出场自动识别车牌、抬杆放行
- 实时车位计数与引导（剩余车位显示）
- 按时长计费，支持扫码支付、月卡扣费
- 月卡用户管理（开卡、续费、注销）
- 管理员查看车位占用、收费统计、异常告警

**非功能性需求**：
- 实时性：车牌识别到抬杆 ≤ 2s
- 可用性：7×24 运行，设备故障自动降级
- 可靠性：断网时本地缓存，恢复后同步
- 安全：车牌数据隐私保护

## 用例建模

### 参与者识别

| 参计者 | 类型 | 职责 |
| --- | --- | --- |
| 临时车主 | 主要参与者 | 进场取卡、出场扫码支付 |
| 月卡车主 | 主要参与者 | 自动进出、月卡扣费 |
| 管理员 | 主要参与者 | 管理月卡、查看统计、处理异常 |
| 摄像头设备 | 次要参与者 | 识别车牌、上报事件 |
| 道闸设备 | 次要参与者 | 执行抬杆/落杆 |
| 支付平台 | 次要参与者 | 处理扫码支付 |

### 用例描述：车辆进场

| 要素 | 内容 |
| --- | --- |
| 用例名 | 车辆进场 |
| 参与者 | 临时车主/月卡车主（主）、摄像头、道闸（次） |
| 前置条件 | 停车场有空位 |
| 后置条件 | 创建停车记录，车位数 -1，道闸抬起 |
| 主成功场景 | 1. 车辆驶入入口 2. 摄像头识别车牌 3. 系统查询车牌（月卡？） 4. 系统创建停车记录 5. 系统更新剩余车位 6. 系统指令道闸抬杆 7. 车辆通过，道闸落杆 |
| 扩展 | 3a. 月卡有效：直接放行；3b. 无空位：提示已满不放行；2a. 识别失败：人工录入 |

## 领域建模

### 概念类图

```mermaid
classDiagram
    class Vehicle {
        +plateNo: String
        +ownerType: OwnerType
    }
    class ParkingRecord {
        +recordId: Long
        +entryTime: DateTime
        +exitTime: DateTime
        +fee: BigDecimal
        +status: RecordStatus
        +calculateFee(): BigDecimal
        +close()
    }
    class ParkingLot {
        +lotId: Long
        +totalSpaces: int
        +available: int
        +enter()
        +exit()
    }
    class MonthlyCard {
        +cardId: Long
        +plateNo: String
        +startTime: Date
        +endTime: Date
        +isValid(): boolean
    }
    class Camera {
        +deviceId: String
        +location: String
        +recognizePlate(): String
    }
    class Gate {
        +deviceId: String
        +location: String
        +raise()
        +lower()
    }
    class Payment {
        +paymentId: Long
        +method: PayMethod
        +amount: BigDecimal
        +payTime: DateTime
    }

    Vehicle "1" --> "0..*" ParkingRecord
    ParkingRecord "*" --> "1" ParkingLot
    Vehicle "1" --> "0..1" MonthlyCard
    ParkingRecord "1" --> "0..1" Payment
    Camera --> ParkingRecord : 触发
    Gate --> ParkingRecord : 执行
```

> [!note] 类图设计要点
> - `ParkingRecord` 是核心实体，记录进出时间与费用，状态机驱动其生命周期；
> - `Vehicle` 与 `MonthlyCard` 是 1:0..1，临时车无月卡；
> - `Camera` 与 `Gate` 作为设备类，与 `ParkingRecord` 关联但不是实体（无业务生命周期），属边界/设备抽象；
> - 费用计算封装在 `ParkingRecord.calculateFee()`，避免贫血模型。

## 动态建模

### 车辆进场时序图

```mermaid
sequenceDiagram
    actor Driver as 车辆
    participant Cam as 入口摄像头
    participant Ctrl as EntryController
    participant Lot as ParkingLot
    participant Rec as ParkingRecord
    participant Card as MonthlyCard
    participant Gate as 入口道闸

    Driver->>Cam: 驶入感应区
    Cam->>Cam: 识别车牌
    Cam->>Ctrl: plateRecognized(plateNo)
    Ctrl->>Card: findByPlate(plateNo)
    alt 月卡有效
        Card-->>Ctrl: validCard
    else 临时车
        Card-->>Ctrl: null
    end
    Ctrl->>Lot: checkAvailable()
    Lot-->>Ctrl: true
    Ctrl->>Rec: create(plateNo, entryTime)
    Rec-->>Ctrl: recordId
    Ctrl->>Lot: decrementAvailable()
    Ctrl->>Gate: raise()
    Gate-->>Ctrl: raised
    Driver->>Gate: 车辆通过
    Gate->>Gate: 落杆
```

### 车辆出场时序图

```mermaid
sequenceDiagram
    actor Driver as 车辆
    participant Cam as 出口摄像头
    participant Ctrl as ExitController
    participant Rec as ParkingRecord
    participant Pay as 支付平台
    participant Gate as 出口道闸

    Driver->>Cam: 驶入出口感应区
    Cam->>Ctrl: plateRecognized(plateNo)
    Ctrl->>Rec: findActive(plateNo)
    Rec-->>Ctrl: record(entryTime)
    Ctrl->>Rec: calculateFee()
    Rec-->>Ctrl: fee
    alt 已扫码支付
        Ctrl->>Rec: isPaid()
        Rec-->>Ctrl: true
    else 未支付
        Ctrl-->>Driver: 显示二维码
        Driver->>Pay: 扫码支付(fee)
        Pay-->>Ctrl: paid
        Ctrl->>Rec: markPaid()
    end
    Ctrl->>Rec: close(exitTime)
    Ctrl->>Gate: raise()
    Gate-->>Ctrl: raised
    Driver->>Gate: 车辆通过
```

### 停车记录状态图

```mermaid
stateDiagram-v2
    [*] --> 进场中: 车牌识别
    进场中 --> 停车中: 道闸抬起,车辆通过
    停车中 --> 待支付: 车辆驶入出口
    待支付 --> 已支付: 扫码支付完成
    待支付 --> 已支付: 月卡自动扣费
    已支付 --> 已离场: 道闸抬起,车辆通过
    进场中 --> 异常: 识别失败
    停车中 --> 异常: 超时未离场
    异常 --> [*]: 人工处理
    已离场 --> [*]
```

> [!tip] 状态机驱动设计
> 停车记录是典型的状态机驱动对象：进场中→停车中→待支付→已支付→已离场，每步触发不同行为（计费、抬杆、关闭记录）。用状态模式（见 [[5.3 状态模式与代码实现]]）把每个状态封装为类，状态转换与行为解耦，便于扩展（如新增“VIP 通道”状态）。

### 部署图

```mermaid
flowchart TB
    subgraph 入口节点
        Cam1[入口摄像头]
        Gate1[入口道闸]
        Edge1[边缘网关1]
    end
    subgraph 出口节点
        Cam2[出口摄像头]
        Gate2[出口道闸]
        Edge2[边缘网关2]
    end
    subgraph 机房服务器
        App[应用服务器]
        DB[(数据库)]
        Cache[(Redis)]
    end
    subgraph 管理端
        Console[管理后台]
    end
    ExtPay[云支付平台]

    Cam1 <-->|RTSP/HTTP| Edge1
    Gate1 <-->|GPIO/串口| Edge1
    Cam2 <-->|RTSP/HTTP| Edge2
    Gate2 <-->|GPIO/串口| Edge2
    Edge1 <-->|MQTT/HTTP| App
    Edge2 <-->|MQTT/HTTP| App
    App <-->|JDBC| DB
    App <-->|TCP| Cache
    App <-->|HTTPS| ExtPay
    Console <-->|HTTPS| App
```

> [!example]- 部署图说明
> - **入口/出口节点**部署摄像头、道闸与边缘网关，边缘网关负责设备协议转换与断网缓存；
> - **机房服务器**部署应用、数据库与缓存，应用通过 MQTT/HTTP 与边缘网关通信；
> - **管理端**通过 HTTPS 访问应用，远程监控与统计；
> - 边缘网关断网时本地缓存进出记录，网络恢复后同步到中心库，保证可靠性。

## 小结

智能停车管理案例展示了物联网场景建模特点：参与者包含硬件设备（摄像头、道闸、传感器），用例需刻画设备事件触发；领域模型中设备类与业务实体类并存；动态模型强调实时性与状态机驱动（停车记录从进场到离场的状态流转）；架构采用“边缘-应用-数据”三层，边缘网关解决断网可靠性与协议异构。与在线书店对比，本案例更强调实时性、设备交互与可靠性，部署图需标注通信协议（RTSP/MQTT/串口）。
