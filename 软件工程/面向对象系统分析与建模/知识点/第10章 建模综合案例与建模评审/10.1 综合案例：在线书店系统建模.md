# 10.1 综合案例：在线书店系统建模

本节以“在线书店系统”为综合案例，演示从需求到部署的端到端建模过程。覆盖用例建模、领域建模、动态建模与架构建模四个层次，是前 9 章知识的综合应用。案例聚焦核心业务，省略次要细节以便理解主线。

## 系统需求概述

在线书店系统为读者提供图书浏览、检索、购物车、下单、支付、订单跟踪等功能，为管理员提供图书管理、订单管理、库存管理功能。

**功能性需求**：
- 读者注册/登录、浏览图书、按关键词/分类检索
- 购物车增删改、提交订单
- 在线支付（支持多种支付方式）
- 订单状态跟踪、取消/确认收货
- 管理员管理图书、库存、订单

**非功能性需求**：
- 性能：检索响应 ≤ 2s
- 可用性：7×24，可用率 ≥ 99.5%
- 安全：支付数据加密传输
- 可扩展：支持新增支付方式

## 用例建模

### 参与者识别

| 参与者 | 类型 | 职责 |
| --- | --- | --- |
| 读者 | 主要参与者 | 浏览、下单、支付、跟踪订单 |
| 管理员 | 主要参与者 | 管理图书、库存、订单 |
| 支付网关 | 次要参与者 | 处理在线支付 |
| 库存系统 | 次要参与者 | 同步库存（外部） |

### 用例图

```mermaid
flowchart LR
    Reader((读者)) --- UC1[注册登录]
    Reader --- UC2[浏览检索图书]
    Reader --- UC3[管理购物车]
    Reader --- UC4[下单]
    Reader --- UC5[支付订单]
    Reader --- UC6[跟踪订单]
    Admin((管理员)) --- UC7[管理图书]
    Admin --- UC8[管理库存]
    Admin --- UC9[处理订单]
    Pay((支付网关)) --- UC5
    UC4 -.->|include| UC10[校验库存]
    UC5 -.->|extend| UC11[使用优惠券]
    UC6 -.->|extend| UC12[取消订单]
```

> [!note] 用例关系说明
> - `下单` `«include»` `校验库存`：下单必经库存校验，复用性强；
> - `支付订单` `«extend»` `使用优惠券`：支付时可选使用优惠券，是条件扩展；
> - `跟踪订单` `«extend»` `取消订单`：在特定状态下可取消，是扩展点。

### 用例描述：下单

| 要素 | 内容 |
| --- | --- |
| 用例名 | 提交订单 |
| 参与者 | 读者（主） |
| 前置条件 | 读者已登录且购物车非空 |
| 后置条件 | 创建订单（待支付），库存锁定 |
| 主成功场景 | 1. 读者确认购物车商品 2. 选择收货地址 3. 选择支付方式 4. 系统校验库存 5. 系统创建订单并锁定库存 6. 系统返回订单号与支付链接 |
| 扩展 | 4a. 库存不足：提示并返回购物车；3a. 选择优惠券：计算优惠金额 |
| 业务规则 | 每单最多 50 件商品；下单后 30 分钟未支付自动取消 |

## 领域建模

### 概念类图

```mermaid
classDiagram
    class User {
        +userId: Long
        +name: String
        +email: String
        +login(): boolean
    }
    class Cart {
        +cartId: Long
        +addItem(product, qty)
        +removeItem(itemId)
        +totalAmount(): BigDecimal
    }
    class CartItem {
        +quantity: int
        +subtotal(): BigDecimal
    }
    class Product {
        +productId: Long
        +title: String
        +price: BigDecimal
        +stock: int
    }
    class Order {
        +orderId: Long
        +createTime: DateTime
        +status: OrderStatus
        +totalAmount: BigDecimal
        +pay()
        +cancel()
    }
    class OrderItem {
        +quantity: int
        +unitPrice: BigDecimal
        +subtotal(): BigDecimal
    }
    class Payment {
        +paymentId: Long
        +method: PaymentMethod
        +amount: BigDecimal
        +payTime: DateTime
    }
    class Address {
        +addressId: Long
        +detail: String
        +phone: String
    }
    User "1" --> "1" Cart
    User "1" --> "0..*" Address
    User "1" --> "0..*" Order
    Cart "1" --> "0..*" CartItem
    CartItem "*" --> "1" Product
    Order "1" --> "1..*" OrderItem
    OrderItem "*" --> "1" Product
    Order "1" --> "0..1" Payment
    Order "*" --> "1" Address
```

> [!tip] 类图要点
> - `User` 与 `Cart` 是 1:1，每个用户一个购物车；
> - `Order` 与 `OrderItem` 是 1:N，订单由多个订单项组成；
> - `Order` 与 `Payment` 是 1:0..1，订单可有零或一次支付（取消则无支付）；
> - `CartItem` 与 `Product` 是 N:1，购物车项引用商品；
> - 状态用枚举 `OrderStatus`、`PaymentMethod` 表示，避免字符串散乱。

## 动态建模

### 下单时序图

```mermaid
sequenceDiagram
    actor Reader
    participant Form as OrderForm
    participant Ctrl as OrderController
    participant Cart
    participant Order
    participant Inv as InventoryService
    participant Pay as PaymentGateway

    Reader->>Form: 提交订单(地址, 支付方式)
    Form->>Ctrl: submitOrder(userId, addrId, payMethod)
    Ctrl->>Cart: getItems(userId)
    Cart-->>Ctrl: items[]
    Ctrl->>Inv: checkStock(items)
    Inv-->>Ctrl: ok
    Ctrl->>Order: create(userId, items, addrId)
    Order-->>Ctrl: orderId
    Ctrl->>Inv: lockStock(orderId, items)
    Inv-->>Ctrl: locked
    Ctrl->>Pay: createPayment(orderId, amount, payMethod)
    Pay-->>Ctrl: payUrl
    Ctrl-->>Form: orderId + payUrl
    Form-->>Reader: 跳转支付
```

### 订单状态图

```mermaid
stateDiagram-v2
    [*] --> 待支付: 创建订单
    待支付 --> 已支付: 支付成功
    待支付 --> 已取消: 用户取消/超时
    已支付 --> 已发货: 管理员发货
    已支付 --> 已退款: 申请退款
    已发货 --> 已完成: 确认收货
    已发货 --> 已退款: 退货退款
    已完成 --> [*]
    已取消 --> [*]
    已退款 --> [*]
```

> [!note] 状态图说明
> 订单生命周期有 6 个状态：待支付、已支付、已发货、已完成、已取消、已退款。转换由事件触发，部分带守卫条件（如“待支付超时 30 分钟”触发自动取消）。状态机封装在 `Order` 实体中，行为随状态变化（状态模式，见 [[5.3 状态模式与代码实现]]）。

### 支付时序图（含异常）

```mermaid
sequenceDiagram
    actor Reader
    participant Ctrl as OrderController
    participant Pay as PaymentGateway
    participant Order

    Reader->>Ctrl: 支付(orderId, method)
    Ctrl->>Order: getStatus(orderId)
    Order-->>Ctrl: 待支付
    Ctrl->>Pay: charge(amount, method)
    alt 支付成功
        Pay-->>Ctrl: success
        Ctrl->>Order: markPaid(orderId)
        Order-->>Ctrl: 已支付
        Ctrl-->>Reader: 支付成功
    else 支付失败
        Pay-->>Ctrl: fail
        Ctrl-->>Reader: 支付失败,重试
    end
```

## 架构建模

### 组件图

```mermaid
flowchart LR
    subgraph 前端
        Web[Web 客户端]
    end
    subgraph 应用层
        API[API 网关]
        US[用户服务]
        OS[订单服务]
        PS[商品服务]
        PAY[支付服务]
    end
    subgraph 数据层
        DB1[(用户库)]
        DB2[(订单库)]
        DB3[(商品库)]
        Cache[(缓存)]
    end
    Ext1[支付网关]
    Ext2[库存系统]

    Web <--> API
    API <--> US
    API <--> OS
    API <--> PS
    API <--> PAY
    US <--> DB1
    OS <--> DB2
    PS <--> DB3
    PS <--> Cache
    PAY <--> Ext1
    OS <--> Ext2
```

### 部署图

```mermaid
flowchart TB
    subgraph 客户端节点
        B[浏览器]
    end
    subgraph Web 服务器
        Nginx[Nginx 反向代理]
    end
    subgraph 应用服务器
        App[应用容器<br/>Tomcat]
    end
    subgraph 数据库服务器
        DB[(MySQL 主从)]
    end
    subgraph 缓存服务器
        Redis[(Redis)]
    end
    ExtPay[外部支付网关]

    B <-->|HTTPS| Nginx
    Nginx <-->|HTTP| App
    App <-->|JDBC| DB
    App <-->|TCP| Redis
    App <-->|HTTPS| ExtPay
```

> [!example]- 架构图说明
> - **组件图**按业务能力拆分微服务，每服务独立数据库（Database-per-service）；
> - **部署图**展示物理节点：浏览器→Nginx 反向代理→应用容器→数据库与缓存；
> - 外部系统（支付网关、库存系统）通过 HTTPS 接入；
> - 缓存提升商品检索性能，主从数据库提升可用性。

## 小结

本案例以在线书店为载体，完整演示了 OOA+OOD 的建模流程：需求概述划定范围 → 用例图识别参与者与用例 → 概念类图建立领域结构 → 时序图与状态图刻画动态行为 → 组件图与部署图表达架构。各图之间互相支撑、交叉验证，共同构成可被开发与评审的系统模型。案例中可看到 SOLID 原则（如 `OrderController` 单一职责）、设计模式（状态模式用于订单状态）与架构建模（微服务+部署）的综合应用。
