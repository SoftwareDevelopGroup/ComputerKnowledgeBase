# 10.2 模块化与项目构建

JavaFX 项目从“能跑的几行代码”到“可维护的应用”，必须解决两个工程问题：依赖如何管理、源码如何组织。本节解决的问题是：用 Java 平台模块系统（JPMS）的 `module-info.java` 声明模块边界，用 Maven 的 `pom.xml` + JavaFX Maven Plugin 管理依赖与运行，了解 Gradle 的等价配置。

## Java 模块系统：module-info.java

Java 9 引入平台模块系统（JPMS），用 `module-info.java` 声明模块的依赖与导出。JavaFX 11+ 自身拆分为 `javafx.base`、`javafx.controls`、`javafx.graphics`、`javafx.fxml` 等模块，应用需显式 `requires`。

```java
// src/main/java/module-info.java
module com.example.app {
    // 依赖 JavaFX 模块
    requires javafx.controls;
    requires javafx.fxml;
    requires javafx.graphics;

    // 第三方库（如字体图标）
    requires org.kordamp.ikonli.javafx;
    requires org.kordamp.ikonli.fontawesome5;

    // 允许 FXML 反射访问控制器包
    opens com.example.app.controller to javafx.fxml;

    // 导出主类包供启动器访问
    exports com.example.app;
}
```

| 关键字 | 作用 |
| --- | --- |
| `module` | 声明模块名 |
| `requires` | 依赖其他模块（普通依赖） |
| `requires transitive` | 依赖并传递给依赖本模块者 |
| `requires static` | 编译期依赖，运行期可选 |
| `exports` | 导出包供其他模块访问 |
| `opens` | 运行期开放包供反射访问（FXML/序列化） |
| `opens ... to` | 仅对指定模块开放反射 |
| `uses`/`provides` | 服务发现机制 |

> [!warning] FXML 与 opens
> > FXML 加载时通过反射实例化控制器类并注入字段。若控制器包未 `opens`，运行时会抛 `InaccessibleObjectException`。常见写法：`opens com.example.app.controller to javafx.fxml;`。同样，Gson/Jackson 序列化也需 `opens` 对应包。

> [!note] 命名建议
> > 模块名用反向域名风格（如 `com.example.app`），与主包名一致。模块名一旦确定很难改（影响 `requires`），初期就要规划好。

## Maven 构建 JavaFX 项目

Maven 用 `pom.xml` 描述项目坐标、依赖、构建插件。JavaFX 项目的关键依赖来自 `org.openjfx` 的 `javafx-controls` 与 `javafx-fxml`。

### pom.xml 示例

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <groupId>com.example</groupId>
    <artifactId>javafx-app</artifactId>
    <version>1.0.0</version>
    <packaging>jar</packaging>

    <properties>
        <maven.compiler.release>17</maven.compiler.release>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
        <javafx.version>21</javafx.version>
        <main.class>com.example.app.App</main.class>
    </properties>

    <dependencies>
        <!-- JavaFX 控件与 FXML，classifier 按平台 -->
        <dependency>
            <groupId>org.openjfx</groupId>
            <artifactId>javafx-controls</artifactId>
            <version>${javafx.version}</version>
            <classifier>win</classifier>
        </dependency>
        <dependency>
            <groupId>org.openjfx</groupId>
            <artifactId>javafx-fxml</artifactId>
            <version>${javafx.version}</version>
            <classifier>win</classifier>
        </dependency>
        <!-- 字体图标 -->
        <dependency>
            <groupId>org.kordamp.ikonli</groupId>
            <artifactId>ikonli-javafx</artifactId>
            <version>12.3.1</version>
        </dependency>
    </dependencies>

    <build>
        <plugins>
            <!-- JavaFX 运行插件：mvn javafx:run -->
            <plugin>
                <groupId>org.openjfx</groupId>
                <artifactId>javafx-maven-plugin</artifactId>
                <version>0.0.8</version>
                <configuration>
                    <mainClass>${main.class}</mainClass>
                </configuration>
            </plugin>
            <!-- 编译插件 -->
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.11.0</version>
            </plugin>
            <!-- 打可执行 fat jar（可选） -->
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-shade-plugin</artifactId>
                <version>3.5.1</version>
                <executions>
                    <execution>
                        <phase>package</phase>
                        <goals><goal>shade</goal></goals>
                        <configuration>
                            <transformers>
                                <transformer implementation=
                                  "org.apache.maven.plugins.shade.resource.ManifestResourceTransformer">
                                    <mainClass>${main.class}</mainClass>
                                </transformer>
                            </transformers>
                        </configuration>
                    </execution>
                </executions>
            </plugin>
        </plugins>
    </build>
</project>
```

### JavaFX Maven Plugin 关键目标

| 命令 | 作用 |
| --- | --- |
| `mvn javafx:run` | 编译并运行主类 |
| `mvn javafx:jlink` | 用 `jlink` 生成自定义运行时镜像 |

> [!tip] classifier 跨平台
> > JavaFX 依赖的 `classifier`（`win`/`linux`/`mac`/`mac-aarch64`）决定加载哪个平台的本地库。多平台构建可用 Maven profile 按操作系统自动切换 classifier，避免在一台机器上打包另一平台失败。

## Gradle 构建配置

Gradle 用 `build.gradle` 描述构建，语法更简洁，适合复杂多模块项目。JavaFX 提供官方 Gradle 插件 `org.openjfx.javafxplugin`。

```groovy
// build.gradle
plugins {
    id 'java'
    id 'application'
    id 'org.openjfx.javafxplugin' version '0.1.0'
}

group = 'com.example'
version = '1.0.0'

java {
    toolchain { languageVersion = JavaLanguageVersion.of(17) }
}

javafx {
    version = '21'
    modules = ['javafx.controls', 'javafx.fxml']
}

application {
    mainClass = 'com.example.app.App'
}

dependencies {
    implementation 'org.kordamp.ikonli:ikonli-javafx:12.3.1'
    implementation 'org.kordamp.ikonli:ikonli-fontawesome5-pack:12.3.1'
}

// 运行：gradle run
// 打包：gradle jpackageImage（配合 jpackage 插件）
```

| 命令 | 作用 |
| --- | --- |
| `gradle run` | 编译并运行 |
| `gradle jar` | 打 jar |
| `gradle jlink` | 生成自定义镜像（需 `badass-jlink-plugin`） |
| `gradle jpackage` | 生成原生安装包（需 `badass-runtime`/`jpackage` 插件） |

> [!note] Maven vs Gradle
> > Maven 配置声明式、约定优于配置、生态成熟，适合中小项目与教学；Gradle 灵活、增量构建快，适合大型多模块项目。两者对 JavaFX 的支持都完善，选团队熟悉的即可。

## 依赖管理与版本控制

| 实践 | 说明 |
| --- | --- |
| 统一版本属性 | 用 `<properties>` 或 `gradle.properties` 集中管理版本号 |
| 锁定版本 | 生产用固定版本，避免 `LATEST`/`RELEASE` 导致构建不可复现 |
| scope 区分 | `compile`/`implementation`（运行期）、`test`（仅测试） |
| 排除传递依赖 | `<exclusions>` 解决冲突 |
| BOM 导入 | 用 `<dependencyManagement>` 导入 BOM 统一版本 |

> [!warning] JavaFX 版本与 JDK 对齐
> > JavaFX 11+ 与 JDK 解耦，需单独引入 `org.openjfx` 依赖。注意 JavaFX 版本需与 JDK 版本兼容（如 JavaFX 21 配 JDK 17+）。混用 JavaFX 8（内置 JDK）与 JavaFX 11+ 依赖会冲突。

## 易错点

> [!warning] 常见误区
> 1. 忘记 `module-info.java` 或 `requires javafx.controls`，运行时 `ClassNotFoundException`。
> 2. FXML 控制器包未 `opens to javafx.fxml`，运行时 `InaccessibleObjectException`。
> 3. JavaFX 依赖未指定 `classifier`，跨平台运行时找不到本地库。
> 4. 用 `mvn exec:java` 而非 `mvn javafx:run`，模块路径未正确设置导致 JavaFX 模块加载失败。

## 小结

`module-info.java` 声明模块边界，`requires` 依赖 JavaFX 模块，`opens` 允许 FXML 反射，`exports` 暴露主类包。Maven 用 `pom.xml` + `javafx-maven-plugin`（`mvn javafx:run`）管理依赖与运行；Gradle 用 `org.openjfx.javafxplugin` 等价实现。版本统一管理、平台 classifier 与模块 opens 是构建正确性的关键。下一节 [[10.3 打包发布与跨平台部署]] 把构建产物变成可安装应用。
