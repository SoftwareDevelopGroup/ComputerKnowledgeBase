**10.1** C。条件断点满足表达式才暂停，适合循环/事件高频触发场景；方法断点在进入/退出方法时暂停，字段监视在字段读写时暂停。

**10.10** B。`jlink` 根据 `module-info` 裁剪 JDK 模块生成精简自定义 JRE 镜像；`jpackage` 在镜像基础上生成安装包。

<details>
<summary>四、简答题答案</summary>

**10.21** 三大性能陷阱及优化：①**布局嵌套过深**：每个 Pane 都计算子节点尺寸，嵌套越深越慢，优化为扁平化（用 `BorderPane`/`GridPane` 代替多层 VBox/HBox 套娃）、避免不必要的 StackPane 包装、用 `Region` 占位代替空 Pane。②**过度绑定**：`Bindings` 计算链每次依赖变化都重算，链长或监听多会拖慢，优化为用 `InvalidationListener` 惰性求值、减少绑定层级、避免在循环中创建绑定。③**动画/特效滥用**：`DropShadow` 大半径、列表项特效每帧重算，优化为 `setCache(true)` + `CacheHint` 缓存、减少同时动画数、动画期间固定尺寸。

**10.22** 语义：①`requires` 声明依赖其他模块（如 `requires javafx.controls`），普通依赖；`requires transitive` 传递依赖；`requires static` 编译期可选。②`exports` 导出包供其他模块在编译期与运行期访问（如 `exports com.example.app` 让启动器能调用主类）。③`opens` 在运行期开放包供反射访问（如 `opens com.example.app.controller to javafx.fxml`），`exports` 不允许反射。FXML 场景需 `opens` 是因为 FXMLLoader 通过反射实例化控制器类并注入 `@FXML` 字段，若控制器包未开放反射，运行时会抛 `InaccessibleObjectException`。

**10.23** `jlink` 根据 `module-info.java` 把所需 JDK 模块与应用模块裁剪打包成精简自定义 JRE 镜像，去除无关模块，体积从完整 JDK 的 300MB+ 降到 30~60MB，启动快。`jpackage` 在 `jlink` 镜像（或现有 JRE）基础上调用平台工具（WiX/InnoSetup、pkgbuild、dpkg/rpmbuild）生成原生安装包：Windows 的 MSI/EXE、macOS 的 DMG/PKG、Linux 的 DEB/RPM，含图标、快捷方式、卸载器。自包含应用把精简 JRE 与应用一起打包，用户无需预装 Java，避免“装了 Java 但版本不对”的环境问题，双击即装即用，体验接近原生应用。

**10.24** 内存泄漏场景：①**监听器未移除**：短生命周期对象注册到长生命周期属性（如 `stage.widthProperty().addListener`），窗口关闭后 stage 被监听器间接持有无法 GC，解决为窗口关闭时 `removeListener` 或用弱监听。②**静态集合持有节点**：`static List<Node>` 阻止 UI 节点被回收，避免静态持有 UI 节点。③**动画未停止**：`Timeline` 持续运行引用节点，窗口关闭时 `setOnCloseRequest` 中 `timeline.stop()`。④**闭包捕获**：Lambda 捕获外部对象，用弱引用或显式置 null。检测方法：用 `jvisualvm` 或 `jconsole` 连接运行中的 JavaFX 进程，观察堆内存曲线是否持续上涨；用堆转储（Heap Dump）查看哪些对象占用量大，定位监听器或集合泄漏。
</details>

```xml
</build>
```

**10.27** 原因：`build\libs` 中只有普通 jar，缺少 `module-info` 编译产物，`jlink`/`jpackage` 无法在模块路径上找到模块 `com.example.app`。修正思路：① 确保源码中有 `module-info.java` 且 `mvn package` 后产物是模块化 jar（含 `module-info.class`）；② `--module-path` 应指向包含 `module-info.class` 的编译输出目录（如 `target/classes`）或模块化 jar 所在目录，而非仅普通 jar 目录；③ 若应用非模块化，改用 `--input` 指定 jar 目录 + `--main-jar` 指定主 jar（此时打包完整 JDK，体积较大），推荐补全 `module-info` 获得精简镜像。

**10.28** 判断：`events` 阶段耗时高说明瓶颈不在布局/渲染，而在**事件处理**——通常是事件处理器内做了耗时 IO/计算阻塞了 FX 线程，或后台高频 `Platform.runLater` 塞满事件队列。排查方向：① 检查事件处理器（`setOnAction`、`ChangeListener`）内是否有同步 IO/循环计算，移到 `Task` 后台线程。② 检查后台线程是否高频 `Platform.runLater`，改用批量缓冲后定时提交（如 `ConcurrentLinkedQueue` + `Timeline` 定时搬运）。③ 用 IDE 断点在事件处理器首行暂停，配合条件断点观察调用频率与单次耗时。
</details>

**10.29** 定位与优化：

问题定位：① `DropShadow`（半径 20）每项都带，列表滚动时每帧重算大量阴影；② 后台每 10ms 一次 `runLater` 致事件队列堆积（`events` 阶段耗时高）。

优化措施：

```java
import javafx.application.Platform;
import javafx.scene.CacheHint;
import javafx.scene.control.ListView;
import javafx.scene.effect.DropShadow;
import javafx.collections.ObservableList;
import javafx.collections.FXCollections;
import java.util.concurrent.ConcurrentLinkedQueue;
import java.util.ArrayList;
import java.util.List;

// 优化1：列表项启用缓存，避免阴影每帧重算
listView.setCellFactory(lv -> {
    javafx.scene.control.ListCell<String> cell = new javafx.scene.control.ListCell<>() {
        @Override
        protected void updateItem(String item, boolean empty) {
            super.updateItem(item, empty);
            if (empty || item == null) {
                setText(null);
                setEffect(null);
            } else {
                setText(item);
                DropShadow shadow = new DropShadow(8, javafx.scene.paint.Color.gray(0, 0.3));
                setEffect(shadow);
                setCache(true);                       // 缓存特效结果
                setCacheHint(CacheHint.SPEED);
            }
        }
    };
    return cell;
});

// 优化2：后台缓冲 + 批量提交，避免 runLater 风暴
ConcurrentLinkedQueue<String> buffer = new ConcurrentLinkedQueue<>();
ObservableList<String> uiList = FXCollections.observableArrayList();
ListView<String> view = new ListView<>(uiList);

// 后台线程只写缓冲
new Thread(() -> {
    while (running) {
        buffer.add(produceData());
        try { Thread.sleep(10); } catch (InterruptedException ignored) {}
    }
}).start();

// 优化3：定时（FX 线程）批量搬运，每 50ms 一次而非每 10ms
import javafx.animation.Timeline;
import javafx.animation.KeyFrame;
import javafx.util.Duration;
Timeline flusher = new Timeline(new KeyFrame(Duration.millis(50), e -> {
    if (buffer.isEmpty()) return;
    List<String> batch = new ArrayList<>();
    while (!buffer.isEmpty()) batch.add(buffer.poll());
    uiList.addAll(batch);                            // FX 线程修改，安全
    if (uiList.size() > 1000) uiList.remove(0, uiList.size() - 1000);
}));
flusher.setCycleCount(Timeline.INDEFINITE);
flusher.play();
```

要点：列表项 `setCache(true)` 缓存阴影、后台缓冲 + 批量提交避免 `runLater` 风暴、`ListView` 虚拟化（本身只渲染可见项）。
