# 5.1 语句覆盖与判定覆盖

白盒测试以程序内部结构为依据设计用例，逻辑覆盖法是其核心方法。语句覆盖与判定覆盖是六种覆盖准则中最基础的两种，它们回答“代码的执行单元是否被覆盖”。本节明确两种覆盖的定义、覆盖率计算方法与适用局限，为后续更强的覆盖准则奠定基础。

## 逻辑覆盖准则体系

白盒测试的逻辑覆盖准则按覆盖强度由弱到强排列：

```mermaid
flowchart LR
    A[语句覆盖] --> B[判定覆盖]
    B --> C[条件覆盖]
    C --> D[判定/条件覆盖]
    D --> E[条件组合覆盖]
    E --> F[路径覆盖]
```

> 本节介绍语句覆盖与判定覆盖；[[5.2 条件覆盖与判定条件覆盖]] 介绍条件覆盖与判定/条件覆盖；[[5.3 条件组合覆盖与路径覆盖]] 介绍条件组合覆盖与路径覆盖。

## 语句覆盖

> [!definition] 语句覆盖
> 语句覆盖（Statement Coverage）是最弱的逻辑覆盖准则，它要求**程序中每条可执行语句至少被执行一次**。

### 覆盖率计算

$$\text{语句覆盖率} = \frac{\text{已执行语句数}}{\text{可执行语句总数}} \times 100\%$$

### 特点

- **优点**：用例数量少，能快速保证所有语句被执行；
- **缺点**：最弱的覆盖准则，对判定的某一分支可能完全未测；无法发现逻辑运算符错误（如 `&&` 与 `||` 混淆）、条件取值错误。

> [!warning] 语句覆盖的局限
> 语句覆盖甚至无法保证判定覆盖。例如判定 `if (a > 0)` 中，只要 a>0 为真即可执行 if 内语句，但 a≤0 的分支可能从未被执行，导致该分支内的语句漏测。

## 判定覆盖

> [!definition] 判定覆盖
> 判定覆盖（Decision Coverage）又称分支覆盖，要求**程序中每个判定的“真”分支与“假”分支至少各执行一次**。

### 覆盖率计算

$$\text{判定覆盖率} = \frac{\text{已覆盖的判定分支数}}{\text{判定分支总数}} \times 100\%$$

每个判定有真、假两个分支，若程序有 $k$ 个判定，则判定分支总数为 $2k$。

### 特点

- **优点**：保证每个判定的两分支都被执行，强于语句覆盖；
- **缺点**：只关注判定整体取值，不关心判定中各条件的取值，可能遗漏条件级错误（见 [[5.2 条件覆盖与判定条件覆盖]]）。

> [!tip] 判定覆盖与语句覆盖的关系
> 满足判定覆盖必满足语句覆盖（因为两分支都执行，分支内语句必被执行），反之不成立。因此判定覆盖强于语句覆盖。

## 代码示例与测试用例设计

### 示例代码

```java
public String classify(int a, int b) {
    // 语句1
    String result;
    // 判定1: a > 0 && b > 0
    if (a > 0 && b > 0) {
        // 语句2
        result = "both positive";
    } else {
        // 语句3
        result = "not both positive";
    }
    // 判定2: a > 0 || b > 0
    if (a > 0 || b > 0) {
        // 语句4
        result = result + ", at least one positive";
    } else {
        // 语句5
        result = result + ", none positive";
    }
    // 语句6
    return result;
}
```

### 控制流图

```mermaid
flowchart TD
    S([开始]) --> A[语句1: 声明result]
    A --> D1{判定1: a>0 && b>0}
    D1 -->|真| B[语句2: both positive]
    D1 -->|假| C[语句3: not both positive]
    B --> D2{判定2: a>0 || b>0}
    C --> D2
    D2 -->|真| E[语句4: +at least one]
    D2 -->|假| F[语句5: +none positive]
    E --> G[语句6: return]
    F --> G
    G --> E2([结束])
```

### 语句覆盖用例

只需让所有语句执行一次：

| 用例号 | a | b | 执行路径 | 覆盖语句 |
| --- | --- | --- | --- | --- |
| SC1 | 1 | 1 | S→A→D1(真)→B→D2(真)→E→G | 1,2,4,6 |
| SC2 | -1 | -1 | S→A→D1(假)→C→D2(假)→F→G | 1,3,5,6 |

两个用例合起来覆盖全部语句 1~6，**语句覆盖率 = 6/6 = 100%**。

### 判定覆盖用例

需要让每个判定的真、假分支各执行一次。判定1 与判定2 各需真假：

| 用例号 | a | b | 判定1 a>0&&b>0 | 判定2 a>0||b>0 | 覆盖分支 |
| --- | --- | --- | --- | --- | --- |
| DC1 | 1 | 1 | 真 | 真 | D1真, D2真 |
| DC2 | -1 | -1 | 假 | 假 | D1假, D2假 |

两个用例覆盖判定1 与判定2 的真、假分支，**判定覆盖率 = 4/4 = 100%**。

> [!example] 观察
> 本例中满足判定覆盖的两个用例恰好也满足语句覆盖。但若存在判定嵌套或短路逻辑，判定覆盖可能比语句覆盖需要更多用例。判定覆盖保证了判定的两分支，是语句覆盖的严格增强。

## 覆盖率对比

| 覆盖准则 | 本例用例数 | 覆盖对象 | 能否发现 `&&` 与 `||` 混淆 |
| --- | --- | --- | --- |
| 语句覆盖 | 2 | 语句 1~6 | 否（短路可能导致条件未求值） |
| 判定覆盖 | 2 | 判定1真假 + 判定2真假 | 部分（能发现判定整体取错） |

> [!warning] 短路求值的陷阱
> Java 等语言对 `&&` 和 `||` 采用短路求值。如 `a > 0 && b > 0`，当 a≤0 时 b 的条件不会被执行。这意味着语句覆盖和判定覆盖都可能让某些条件从未被求值，从而隐藏条件错误——这正是条件覆盖要解决的问题。

## 小结

语句覆盖要求每条语句至少执行一次，是最弱的覆盖准则；判定覆盖要求每个判定的真假分支至少执行一次，强于语句覆盖。二者的覆盖率均按“已覆盖/应覆盖”计算。判定覆盖虽强于语句覆盖，但仍只关注判定整体，无法发现条件级错误，需要更强的条件覆盖准则补充。
