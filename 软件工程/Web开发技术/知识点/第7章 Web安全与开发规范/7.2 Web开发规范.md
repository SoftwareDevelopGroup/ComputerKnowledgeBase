# 7.2 Web开发规范

代码是写给人看的，附带能运行。规范的代码可读、可维护、可协作。本节解决的问题是：HTML、CSS、JavaScript 各自应遵循哪些规范，项目目录如何组织，如何用 Git 管理版本，以及 W3C 标准与 Web 可访问性（WAI-ARIA）的基本要求。

## HTML 规范

### 语义化标签

> [!definition] 语义化标签
> 语义化标签指使用具有明确含义的 HTML 标签（如 `<header>`、`<nav>`、`<article>`、`<section>`、`<footer>`）描述内容结构，而非滥用 `<div>` + `class`。语义化提升可读性、利于 SEO 与无障碍访问。

```html
<!-- ❌ 不规范：全是 div -->
<div class="header">
    <div class="nav">...</div>
</div>
<div class="main">...</div>

<!-- ✅ 规范：语义化标签 -->
<header>
    <nav>...</nav>
</header>
<main>
    <article>
        <h1>标题</h1>
        <p>正文</p>
    </article>
</main>
<footer>...</footer>
```

| 语义标签 | 含义 |
| --- | --- |
| `<header>` | 页眉或区块头部 |
| `<nav>` | 导航 |
| `<main>` | 主要内容 |
| `<article>` | 独立完整的内容（文章） |
| `<section>` | 内容分区 |
| `<aside>` | 侧边栏、附属信息 |
| `<footer>` | 页脚 |

### HTML 其他规范

- **alt 属性**：图片必须提供 `alt`，装饰性图片用 `alt=""`。
- **缩进**：统一 2 或 4 空格，层级对齐。
- **注释**：复杂结构加注释 `<!-- 导航 -->`，但不要过度。
- **小写**：标签与属性一律小写。
- **引号**：属性值用双引号。
- **布尔属性**：`disabled`、`checked` 不写值即可。

```html
<img src="logo.png" alt="网站 Logo" />

<!-- 装饰性图片 -->
<img src="spacer.gif" alt="" />

<!-- 注释分隔区块 -->
<!-- 用户信息卡片 -->
<section class="user-card">...</section>
```

## CSS 规范

### BEM 命名规范

> [!definition] BEM
> BEM（Block Element Modifier）是一种 CSS 命名方法论，格式为 `block__element--modifier`。Block 是独立组件，Element 是组件的子部分，Modifier 是组件或元素的状态变体。BEM 让类名自解释、避免冲突、选择器扁平。

```html
<!-- BEM 命名示例 -->
<div class="card card--featured">
    <h2 class="card__title">标题</h2>
    <p class="card__desc">描述</p>
    <button class="card__button card__button--disabled">按钮</button>
</div>
```

```css
/* Block */
.card { padding: 16px; border: 1px solid #ccc; }

/* Element：双下划线 */
.card__title { font-size: 18px; }
.card__desc { color: #666; }
.card__button { padding: 8px 16px; }

/* Modifier：双连字符 */
.card--featured { border-color: gold; }
.card__button--disabled { opacity: 0.5; cursor: not-allowed; }
```

### CSS 属性顺序

按以下顺序书写属性，便于阅读与维护：

1. **布局属性**：`position`、`display`、`flex`、`grid`、`float`
2. **盒模型**：`width`、`height`、`margin`、`padding`、`border`
3. **文本**：`font`、`color`、`text-align`、`line-height`
4. **视觉**：`background`、`box-shadow`、`opacity`
5. **其他**：`transition`、`animation`

```css
.card {
    /* 布局 */
    display: flex;
    flex-direction: column;
    /* 盒模型 */
    width: 300px;
    padding: 16px;
    border: 1px solid #ccc;
    /* 文本 */
    font-size: 14px;
    color: #333;
    /* 视觉 */
    background: #fff;
    border-radius: 8px;
    /* 其他 */
    transition: box-shadow 0.2s;
}
```

### 避免 !important 滥用

```css
/* ❌ 滥用 !important 掩盖优先级问题 */
.title { color: red !important; }

/* ✅ 通过更精确的选择器或调整顺序解决 */
.card .title { color: red; }
```

> [!warning] !important 的代价
> `!important` 会破坏 CSS 优先级规则，使后续覆盖变难，导致样式难以维护。只在覆盖第三方库样式等不得已场景使用，并加注释说明原因。

## JavaScript 规范

### 命名规范

| 类型 | 规范 | 示例 |
| --- | --- | --- |
| 变量、函数 | `camelCase` 小驼峰 | `userName`、`getUserInfo` |
| 常量 | `UPPER_SNAKE_CASE` 全大写下划线 | `MAX_RETRY`、`API_BASE` |
| 类、构造函数 | `PascalCase` 大驼峰 | `UserController` |
| 私有成员 | 前缀下划线或 `#` | `_internal`、`#secret` |

```javascript
// ✅ 规范命名
const MAX_RETRY = 3;
const API_BASE = "/api";

function getUserInfo(userId) { /* ... */ }

class UserController { /* ... */ }

// ❌ 不规范
const user_name = "alice";      // 应 camelCase
function getuserinfo() {}       // 应 camelCase
```

### 严格模式

```javascript
// 整个脚本启用严格模式
"use strict";

function foo() {
    // 严格模式下：未声明变量赋值会报错
    x = 1;  // ReferenceError
}
```

> [!tip] 严格模式的价值
> `"use strict"` 启用严格模式后：未声明变量赋值报错、`this` 默认为 `undefined`（非 window）、禁止删除不可配置属性、八进制字面量报错等，可避免许多隐性 bug。ES 模块默认启用严格模式。

### ESLint 代码检查

> [!definition] ESLint
> ESLint 是 JavaScript/TypeScript 的静态代码检查工具，可配置规则集自动检测代码风格、潜在 bug 与不安全用法，配合编辑器实现保存即检查，是工程化必备工具。

```json
// .eslintrc.json 示例
{
    "env": { "browser": true, "es2021": true },
    "extends": "eslint:recommended",
    "rules": {
        "no-unused-vars": "warn",       // 未使用变量告警
        "no-undef": "error",            // 未定义变量报错
        "eqeqeq": "error",              // 必须用 === 而非 ==
        "semi": ["error", "always"],    // 必须分号
        "indent": ["error", 4]          // 4 空格缩进
    }
}
```

## 文件组织规范

### 目录结构

```text
my-project/
├── index.html              # 入口页面
├── css/                    # 样式文件
│   ├── reset.css           # 样式重置
│   ├── layout.css          # 布局
│   └── components.css      # 组件样式
├── js/                     # 脚本文件
│   ├── main.js             # 入口
│   ├── utils.js            # 工具函数
│   └── modules/            # 模块
│       └── user.js
├── images/                 # 图片资源
├── assets/                 # 其他静态资源（字体等）
└── README.md               # 项目说明
```

### 命名规则

- 文件名用小写字母与连字符：`user-list.js`、`main-header.css`。
- 避免中文与空格，防止跨平台与 URL 编码问题。
- 同类文件加统一前缀：`btn-primary.css`、`btn-secondary.css`。

## 代码版本管理：Git

> [!definition] Git
> Git 是分布式版本控制系统，记录代码历史、支持分支协作、可随时回退。是现代软件开发的标准工具。

### Git 基本操作

```bash
# 初始化与配置
git init                        # 初始化仓库
git config user.name "alice"    # 配置用户名
git config user.email "a@b.com" # 配置邮箱

# 日常提交流程
git status                      # 查看状态
git add .                       # 暂存所有改动
git add index.html              # 暂存指定文件
git commit -m "feat: 新增登录页" # 提交
git push origin main            # 推送到远程

# 拉取与分支
git pull origin main            # 拉取远程更新
git branch feature-login        # 创建分支
git checkout feature-login      # 切换分支
git merge feature-login         # 合并分支到当前分支
git log --oneline               # 查看简洁历史
```

### 提交信息规范（Conventional Commits）

```text
<type>: <description>

type 可选值：
- feat:     新功能
- fix:      修复 bug
- docs:     文档变更
- style:    代码格式（不影响功能）
- refactor: 重构
- test:     测试相关
- chore:    构建/工具变更
```

```bash
git commit -m "feat: 新增用户登录表单"
git commit -m "fix: 修复购物车数量计算错误"
git commit -m "docs: 更新 README 安装步骤"
```

## W3C 标准与 Web 可访问性

### W3C 标准

> [!note] W3C
> W3C（World Wide Web Consortium，万维网联盟）是制定 Web 技术标准的国际组织，发布的标准包括 HTML、CSS、DOM、WCAG 等。遵循 W3C 标准可保证页面跨浏览器兼容、语义正确、可被搜索引擎与辅助技术正确解析。

### WAI-ARIA 可访问性

> [!definition] WAI-ARIA
> WAI-ARIA（Web Accessibility Initiative - Accessible Rich Internet Applications）是 W3C 的可访问性规范，通过在 HTML 上添加 `role`、`aria-*` 属性，向辅助技术（如屏幕阅读器）补充语义信息，让残障用户也能使用 Web 应用。

```html
<!-- 为 div 补充按钮语义 -->
<div role="button" tabindex="0" aria-label="关闭对话框" onclick="close()">×</div>

<!-- 标记动态区域，屏幕阅读器自动播报更新 -->
<div aria-live="polite" id="status">加载中...</div>

<!-- 表单字段关联说明 -->
<label for="email">邮箱：</label>
<input type="email" id="email" aria-required="true" aria-describedby="email-tip">
<span id="email-tip">请输入有效邮箱地址</span>
```

| 常见属性 | 作用 |
| --- | --- |
| `role` | 元素语义角色（`button`、`navigation`、`dialog`） |
| `aria-label` | 元素的可访问名称 |
| `aria-describedby` | 关联描述元素 ID |
| `aria-live` | 动态内容播报策略（`polite`、`assertive`） |
| `aria-hidden` | 对辅助技术隐藏 |
| `aria-expanded` | 折叠状态 |

> [!tip] 可访问性的首要原则
> 优先使用原生语义化标签（`<button>`、`<nav>`、`<input>`），它们自带可访问性。只有用 `<div>` 模拟交互组件时才需要 ARIA 补充。"能用原生标签就不要用 div + ARIA"。

## 代码示例对比

### 不规范 vs 规范

```html
<!-- ❌ 不规范 -->
<div class="div1">
    <DIV CLASS="Title">标题</DIV>
    <div class="btn" onclick="doSomething()">点击</div>
    <img src="banner.jpg">
</div>
```

```html
<!-- ✅ 规范 -->
<section class="card">
    <h2 class="card__title">标题</h2>
    <button type="button" class="card__button">点击</button>
    <img src="banner.jpg" alt="活动横幅" />
</section>
```

```javascript
// ❌ 不规范
function foo(x,y){
    var data={x:x,y:y}
    return data
}

// ✅ 规范
function createPoint(x, y) {
    return { x, y };
}
```

## 可运行代码示例

以下 HTML 整合语义化标签、BEM 命名与可访问性属性，保存为 `.html` 文件即可在浏览器中运行：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <title>Web 开发规范示例</title>
    <style>
        /* BEM 命名 + 属性顺序规范 */
        .card {
            display: flex;
            flex-direction: column;
            width: 320px;
            margin: 20px auto;
            padding: 20px;
            border: 1px solid #ddd;
            font-family: "Microsoft YaHei", sans-serif;
            color: #333;
            background: #fff;
            border-radius: 8px;
            box-shadow: 0 2px 8px rgba(0,0,0,0.08);
        }
        .card--featured {
            border-color: #FF9800;
        }
        .card__title {
            margin: 0 0 12px;
            font-size: 18px;
        }
        .card__desc {
            margin: 0 0 16px;
            color: #666;
            line-height: 1.6;
        }
        .card__button {
            padding: 8px 16px;
            background: #4CAF50;
            color: #fff;
            border: none;
            border-radius: 4px;
            cursor: pointer;
        }
        .card__button--disabled {
            opacity: 0.5;
            cursor: not-allowed;
        }
        .card__status {
            margin-top: 12px;
            font-size: 13px;
            color: #888;
        }
    </style>
</head>
<body>
    <main>
        <article class="card card--featured">
            <h2 class="card__title">语义化 + BEM + ARIA 示例</h2>
            <p class="card__desc">
                本卡片使用语义化标签 <code>&lt;article&gt;</code>，
                CSS 类名遵循 BEM，按钮含 ARIA 属性。
            </p>
            <button type="button"
                    class="card__button"
                    aria-label="订阅更新"
                    onclick="subscribe()">
                订阅
            </button>
            <!-- aria-live 让屏幕阅读器自动播报状态更新 -->
            <p class="card__status" id="status" aria-live="polite">等待操作...</p>
        </article>
    </main>

    <script>
        "use strict";

        function subscribe() {
            const status = document.getElementById("status");
            status.textContent = "✅ 订阅成功！屏幕阅读器将自动播报此更新。";
        }
    </script>
</body>
</html>
```

## 小结

Web 开发规范覆盖 HTML（语义化标签、alt 属性、小写双引号）、CSS（BEM 命名 `block__element--modifier`、属性顺序、避免 `!important`）、JavaScript（camelCase 命名、严格模式、ESLint 检查）与项目结构（目录划分、连字符命名）。Git 通过 `init`/`add`/`commit`/`push`/`branch`/`merge` 管理版本，提交信息遵循 Conventional Commits。W3C 标准保证兼容性，WAI-ARIA 通过 `role` 与 `aria-*` 属性补充语义，提升可访问性——但首要原则是优先使用原生语义化标签。
