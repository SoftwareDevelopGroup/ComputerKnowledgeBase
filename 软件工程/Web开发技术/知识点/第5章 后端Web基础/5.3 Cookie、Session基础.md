# 5.3 Cookie、Session基础

HTTP 协议本身是无状态的——每次请求相互独立，服务器不会自动记住"上一次是谁"。但登录、购物车、个性化设置等场景都需要"记住用户"。本节解决的问题是：如何用 Cookie 在客户端持久化少量数据，如何用 Session 在服务端维护会话状态，以及二者如何配合工作。

## HTTP 无状态与状态保持

> [!definition] HTTP 无状态
> HTTP 是无状态协议（stateless protocol）：服务器不会自动保留同一客户端多次请求之间的关联信息。每次请求独立处理，优点是简单可扩展，缺点是无法直接识别"同一用户的前后请求"。

为在无状态协议之上实现状态保持，Web 开发采用两种互补机制：

- **Cookie**：把状态保存在客户端。
- **Session**：把状态保存在服务端，仅用一个 ID 标识客户端。

## Cookie 机制

> [!definition] Cookie
> Cookie 是服务器发送并保存在浏览器客户端的小段键值对数据。浏览器后续访问同源站点时自动携带 Cookie，服务器据此识别用户。Cookie 主要用于会话标识、个性化设置、购物车等少量数据。

### Cookie 工作流程

```mermaid
sequenceDiagram
    participant B as 浏览器
    participant S as 服务器

    B->>S: 1. 首次请求（无Cookie）
    S-->>B: 2. 响应 + Set-Cookie: sid=abc; Path=/; HttpOnly
    Note over B: 3. 浏览器存储Cookie
    B->>S: 4. 后续请求自动携带 Cookie: sid=abc
    S-->>B: 5. 服务器读取Cookie识别用户，返回个性化内容
```

### Cookie 常见属性

| 属性 | 作用 | 示例 |
| --- | --- | --- |
| `name` / `value` | 键值对 | `sid=abc123` |
| `expires` / `max-age` | 过期时间；不设则为会话 Cookie | `max-age=3600`（1 小时） |
| `path` | 生效路径 | `path=/`（全站） |
| `domain` | 生效域 | `domain=.example.com`（含子域） |
| `secure` | 仅 HTTPS 下发送 | `secure` |
| `httpOnly` | 禁止 JS 读取，防 XSS 窃取 | `httpOnly` |
| `sameSite` | 跨站发送策略，防 CSRF | `sameSite=Lax` |

```http
Set-Cookie: sid=abc123; Path=/; Domain=.example.com; Max-Age=3600; Secure; HttpOnly; SameSite=Lax
```

> [!warning] Cookie 容量限制
> 单个域名下 Cookie 总数通常不超过 50 个，单条 Cookie 大小约 4KB。Cookie 不适合存放大体积或敏感业务数据，应只存放标识符与少量配置。

### Cookie 应用场景

- **用户认证**：存放 Session ID 或 Token，每次请求自动携带。
- **个性化设置**：主题、语言、布局偏好等少量配置。
- **购物车（轻量）**：未登录用户的临时购物车（登录后通常转存到服务端）。
- **行为追踪**：广告与分析类 Cookie（需遵守隐私合规要求）。

### 客户端操作 Cookie

```javascript
// 写入 Cookie（expires 用 toUTCString）
document.cookie = "theme=dark; max-age=31536000; path=/";

// 读取 Cookie（返回字符串，需自行解析）
console.log(document.cookie);  // "theme=dark; sid=abc123"

// 解析为对象
function parseCookie(str) {
    return Object.fromEntries(
        str.split("; ").map(pair => pair.split("="))
    );
}
console.log(parseCookie(document.cookie));  // { theme: "dark", sid: "abc123" }

// 删除 Cookie：设过期时间为过去
document.cookie = "theme=; max-age=0; path=/";
```

> [!note] httpOnly Cookie 与 JS
> 设置了 `httpOnly` 的 Cookie 无法通过 `document.cookie` 读取，可防御 XSS 窃取会话。会话凭证 Cookie 应始终设置 `httpOnly`。

## Session 机制

> [!definition] Session
> Session（会话）是服务器为每个客户端维护的状态数据结构，存储在服务端内存或外部存储（如 Redis）中。服务器为每个 Session 分配唯一 Session ID，通过 Cookie 传递给浏览器，后续请求中浏览器携带该 ID，服务器据此找到对应会话数据。

### Session 工作流程

```mermaid
sequenceDiagram
    participant B as 浏览器
    participant S as 服务器
    participant Store as Session存储

    B->>S: 1. 首次请求（无SessionID）
    S->>Store: 2. 创建Session，分配ID=abc
    Store-->>S: 3. 返回Session对象
    S-->>B: 4. 响应 + Set-Cookie: sid=abc; HttpOnly
    Note over B: 5. 浏览器保存SessionID
    B->>S: 6. 后续请求携带 Cookie: sid=abc
    S->>Store: 7. 按ID=abc读取Session
    Store-->>S: 8. 返回用户数据{userId:1,...}
    S-->>B: 9. 返回个性化内容
```

### Session 创建、读取、销毁

以 Node.js（Express）为例，使用 `express-session` 中间件：

```javascript
// 安装：npm install express express-session
const express = require("express");
const session = require("express-session");

const app = express();
app.use(session({
    name: "sid",                       // Cookie 名
    secret: "your-secret-key",         // 签名密钥，防止篡改
    resave: false,
    saveUninitialized: false,
    cookie: {
        httpOnly: true,
        maxAge: 30 * 60 * 1000,        // 30 分钟
        secure: false                  // 生产环境配合 HTTPS 设 true
    }
}));

// 创建/写入 Session
app.post("/login", (req, res) => {
    // 假设已校验用户名密码
    req.session.userId = 1001;
    req.session.username = "alice";
    res.json({ msg: "登录成功" });
});

// 读取 Session
app.get("/me", (req, res) => {
    if (!req.session.userId) {
        return res.status(401).json({ msg: "未登录" });
    }
    res.json({ userId: req.session.userId, username: req.session.username });
});

// 销毁 Session（退出登录）
app.post("/logout", (req, res) => {
    req.session.destroy(err => {
        if (err) return res.status(500).json({ msg: "退出失败" });
        res.clearCookie("sid");
        res.json({ msg: "已退出" });
    });
});

app.listen(3000, () => console.log("http://localhost:3000"));
```

> [!tip] Session 失效与超时
> Session 通常在以下情况失效：1) 服务器主动销毁（`destroy`）；2) 超过 `maxAge` 未活动；3) 浏览器关闭（若 Cookie 为会话 Cookie，Session ID 丢失，服务端 Session 待超时清理）。生产环境常把 Session 存入 Redis，便于多实例共享与快速过期。

## Cookie vs Session 对比

| 维度 | Cookie | Session |
| --- | --- | --- |
| 存储位置 | 客户端（浏览器） | 服务端（内存/Redis） |
| 容量 | 单条约 4KB，数量有限 | 由服务器决定，理论更大 |
| 安全性 | 易被读取/篡改 | 不直接暴露给客户端，较安全 |
| 生命周期 | 可长期保存（设 `max-age`） | 默认随会话或超时销毁 |
| 性能开销 | 不占服务端资源 | 占用服务端内存/存储 |
| 跨域 | 受同源策略限制 | 依赖 Cookie 传递 ID，同样受同源限制 |
| 典型用途 | 标识符、偏好设置 | 登录态、敏感业务数据 |

> [!note] 二者的协作关系
> Cookie 与 Session 不是对立关系，而是**配合使用**：Session 数据存服务端，Session ID 通过 Cookie 在客户端与服务端之间传递。没有 Cookie，Session 也能用 URL 参数传递 ID（不推荐，存在泄露风险），但 Cookie 是最常见载体。

## 可运行代码示例

以下 HTML 演示 Cookie 的客户端读写，保存为 `.html` 文件即可在浏览器中运行：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <title>Cookie 读写演示</title>
    <style>
        body { font-family: "Microsoft YaHei", sans-serif; padding: 30px; max-width: 480px; }
        label { display: block; margin: 10px 0 4px; }
        input[type="text"] { width: 100%; padding: 8px; border: 1px solid #ccc; border-radius: 4px; box-sizing: border-box; }
        button { padding: 8px 16px; margin-right: 8px; background: #4CAF50; color: #fff; border: none; border-radius: 4px; cursor: pointer; }
        button.danger { background: #f44336; }
        pre { background: #f4f4f4; padding: 12px; border-radius: 4px; white-space: pre-wrap; word-break: break-all; }
    </style>
</head>
<body>
    <h2>Cookie 读写演示</h2>
    <label>键名：<input type="text" id="key" value="theme"></label>
    <label>键值：<input type="text" id="value" value="dark"></label>
    <p>
        <button onclick="setCookie()">写入 Cookie</button>
        <button onclick="readCookie()">读取全部</button>
        <button class="danger" onclick="delCookie()">删除</button>
    </p>
    <pre id="output">操作结果将显示在此...</pre>

    <script>
        function setCookie() {
            const k = document.getElementById("key").value.trim();
            const v = document.getElementById("value").value.trim();
            if (!k) return alert("键名不能为空");
            // 设 path=/ 使全站可读，max-age=1小时
            document.cookie = `${encodeURIComponent(k)}=${encodeURIComponent(v)}; path=/; max-age=3600`;
            document.getElementById("output").textContent = `已写入：${k}=${v}\n当前 Cookie：\n${document.cookie}`;
        }

        function readCookie() {
            document.getElementById("output").textContent = `当前 Cookie：\n${document.cookie || "（空）"}`;
        }

        function delCookie() {
            const k = document.getElementById("key").value.trim();
            if (!k) return alert("请输入要删除的键名");
            // 设 max-age=0 立即过期
            document.cookie = `${encodeURIComponent(k)}=; path=/; max-age=0`;
            document.getElementById("output").textContent = `已删除：${k}\n当前 Cookie：\n${document.cookie}`;
        }
    </script>
</body>
</html>
```

## 小结

HTTP 无状态，需通过 Cookie 与 Session 实现状态保持。Cookie 是客户端键值对，受约 4KB 限制，常见属性包括 `expires`/`max-age`、`path`、`domain`、`secure`、`httpOnly`、`sameSite`。Session 是服务端会话数据，通过 Session ID（通常存于 Cookie）标识客户端，安全性高于 Cookie 但占用服务端资源。两者配合使用：Session 数据存服务端，Session ID 经 Cookie 传递。会话 Cookie 应设置 `httpOnly` 防 XSS、`secure` 限 HTTPS、`sameSite` 防 CSRF。
