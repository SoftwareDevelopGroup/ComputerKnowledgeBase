### 单选题答案

**1. 答案：B**
解析：Web 1.0 以静态页面为主，内容由网站提供者单向发布，用户只能浏览。A 是 Web 2.0 特征，C、D 是 Web 3.0 特征。

**2. 答案：A**
解析：Web 2.0 强调用户参与和动态交互，典型应用包括博客、Wiki、社交网络。B 是 Web 1.0，C、D 偏向 Web 3.0。

**3. 答案：B**
解析：B/S 架构通过浏览器访问，无需安装客户端，跨平台优势明显。A、C 是 C/S 的优点，D 与架构无关。

**4. 答案：C**
解析：C/S 架构需安装专用客户端程序，可充分利用本地资源。A、B 是 B/S 的特点，D 错误（C/S 跨平台成本高）。

**5. 答案：B**
解析：GET 方法语义为获取资源；POST 用于提交数据；DELETE 用于删除资源；PUT 用于更新资源。

**6. 答案：C**
解析：1xx 信息响应，2xx 成功，3xx 重定向，4xx 客户端错误，5xx 服务端错误。

**7. 答案：C**
解析：404 Not Found 表示请求的资源不存在。200 表示成功，301 表示永久重定向，500 表示服务器内部错误。

**8. 答案：B**
解析：HTTPS = HTTP + SSL/TLS 加密层，保证数据机密性与完整性，并非速度更快。

**9. 答案：D**
解析：URL 结构为 `协议://主机:端口/路径?查询`。`/path/page.html` 是路径部分。

**10. 答案：B**
解析：DNS（Domain Name System）的作用是将域名解析为 IP 地址。

**12. 答案：ABD**
解析：B/S 架构依赖网络、响应速度受限、对复杂图形交互支持较弱。C 是 C/S 架构的缺点。

**13. 答案：ABC**

**14. 答案：ABD**

**15. 答案：ABCD**

**16. 答案：正确（√）**
解析：Web 1.0 是单向发布模式，用户只能浏览内容。

**17. 答案：错误（×）**

**18. 答案：正确（√）**

### 简答题参考答案

**21. 参考答案**
- Web 1.0：静态页面为主，内容由网站提供者单向发布，用户只能浏览。
- Web 2.0：动态交互与用户参与，用户既是读者也是创作者（博客、社交、Wiki）。
- Web 3.0：语义化与去中心化，结合区块链、AI、语义网，数据所有权回归用户。

**22. 参考答案**
B/S 优点：无需安装客户端，通过浏览器访问；维护升级集中在服务器端；跨平台优势明显。
B/S 缺点：依赖网络；响应速度受限于浏览器与网络；对复杂图形交互支持较弱。
C/S 优点：体验流畅、可充分利用本地资源；缺点：需安装升级、跨平台成本高。

**23. 参考答案**
HTTP 请求由请求行（方法 URL 版本）、请求头（键值对元信息）、请求体（可选数据）组成。
常见方法：GET（获取资源）、POST（提交数据）、PUT（更新资源）、DELETE（删除资源）、HEAD（获取响应头）、OPTIONS（查询服务器支持的方法）。

**24. 参考答案**
流程：URL 解析 → DNS 解析获取 IP → 建立 TCP 连接（三次握手）→ 发送 HTTP 请求 → 服务器处理并返回响应 → 浏览器解析 HTML 构建 DOM 树 → 解析 CSS 构建 CSSOM → 合并生成渲染树 → 布局（Layout）计算位置大小 → 绘制（Paint）像素 → 合成显示。

### 分析题参考答案

**25. 参考答案**
1. URL 解析：浏览器解析协议（https）、主机名（www.example.com）、路径（/index.html）。
2. DNS 解析：浏览器缓存→操作系统缓存→本地 DNS 服务器→递归查询，最终获得服务器 IP。
3. 建立 TCP 连接：三次握手建立 TCP 连接，由于是 HTTPS 还需进行 TLS 握手协商加密参数。
4. 发送 HTTP 请求：浏览器构造请求报文（请求行 GET /index.html HTTP/1.1、请求头 Host 等）发送给服务器。
5. 服务器处理并返回响应：服务器接收请求，定位资源，返回响应（状态行 200 OK、响应头 Content-Type、响应体 HTML 内容）。
6. 浏览器解析：解析 HTML 构建 DOM 树，遇到 CSS 解析构建 CSSOM，遇到 JS 下载执行。
7. 渲染：DOM 与 CSSOM 合并生成渲染树 → 布局计算位置大小 → 绘制像素 → 合成显示。

**26. 参考答案**
- 1xx 信息响应：100 Continue，客户端继续发送请求体。
- 2xx 成功：200 OK，请求成功返回资源。
- 3xx 重定向：301 Moved Permanently，资源永久迁移到新地址。
- 4xx 客户端错误：404 Not Found，请求资源不存在。
- 5xx 服务端错误：500 Internal Server Error，服务器内部异常。

**27. 参考答案**
| 对比维度 | GET | POST |
| --- | --- | --- |
| 语义 | 获取资源 | 提交数据 |
| 数据位置 | URL 查询字符串 | 请求体 |
| 安全性 | 数据暴露在 URL，相对不安全 | 数据在请求体，相对安全（但仍需 HTTPS） |
| 长度限制 | 受 URL 长度限制（浏览器限制约 2KB） | 理论上无限制 |
| 缓存 | 可被缓存、可被收藏 | 默认不缓存 |
| 幂等性 | 幂等 | 不幂等 |

**28. 参考答案**
HTTPS 在 HTTP 与 TCP 之间增加 SSL/TLS 加密层。工作流程：
1. 客户端发起 HTTPS 请求，连接服务器 443 端口。
2. 服务器返回数字证书（含公钥，由 CA 机构签名）。
3. 客户端验证证书合法性（CA 签名、有效期、域名匹配）。
4. 客户端生成随机对称密钥，用服务器公钥加密后发送。
5. 服务器用私钥解密获得对称密钥。
6. 双方使用对称密钥加密后续通信数据。
- 非对称加密用于密钥交换（安全但慢），对称加密用于数据传输（高效）。
- 数字证书由可信 CA 签发，防止中间人冒充服务器。

### 综合题参考答案

**29. 参考答案**
建议采用 B/S 架构。理由：
1. 员工遍布多城市，B/S 通过浏览器访问，无需在每台终端安装客户端，部署成本极低。
2. 使用 Windows/Mac/Linux 多种操作系统，B/S 跨平台特性正好满足，浏览器统一入口。
3. OA 系统升级频繁，B/S 升级集中在服务器端，员工无感知，运维成本低。
4. OA 系统以表单、文档、流程为主，对复杂图形交互要求不高，B/S 完全胜任。

需注意的局限性：
- 依赖网络稳定性，网络中断则无法使用，需保证各城市办公网络质量。
- 响应速度受浏览器与网络影响，对实时性要求高的功能（如在线协同编辑）需特殊优化。
- 涉及本地文件操作、打印等场景需结合浏览器 API 或插件实现。
- 安全性需通过 HTTPS、身份认证、权限控制保障。

**30. 参考答案**
请求示例：
```
GET /api/users/123 HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0
Accept: application/json
Cookie: sessionid=abc123
```
请求行：`GET /api/users/123 HTTP/1.1`
请求头：Host、User-Agent、Accept、Cookie 等
请求体：GET 请求一般无请求体

服务器处理：路由匹配 → 查询数据库 → 序列化 JSON

响应示例：
```
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 45

{"id":123,"name":"张三","email":"zhangsan@example.com"}
```
状态行：`HTTP/1.1 200 OK`
响应头：Content-Type、Content-Length
响应体：JSON 数据

若资源已永久迁移，服务器应返回 301 Moved Permanently，并在 Location 响应头中给出新地址：
```
HTTP/1.1 301 Moved Permanently
Location: https://www.example.com/api/v2/users/123
```
浏览器收到 301 后会自动跳转到新地址。
