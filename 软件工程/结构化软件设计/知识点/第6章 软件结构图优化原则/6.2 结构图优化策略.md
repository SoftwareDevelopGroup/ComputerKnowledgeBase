# 6.2 结构图优化策略

在 [[6.1 模块分解与合并原则|分解合并原则]]的指导下，本节阐述结构图的具体优化策略：合并高耦合模块、拆分低内聚模块、提取公共子模块、接口优化与结构优化。目标是提高内聚、降低耦合、简化结构，把 [[MOC - 第4章|变换流]]和 [[MOC - 第5章|事务流]]得到的初始 SC 改进为高质量模块结构。

## 优化目标

> [!definition] 结构图优化目标
> 结构图优化的核心目标是提高内聚、降低耦合、简化结构，使每个模块独立性最强、整体结构最清晰。具体体现为：模块功能单一（高内聚）、模块间依赖最弱（低耦合）、层次与扇出合理、接口简洁。

```mermaid
flowchart LR
    A["提高内聚"] --> G["优化目标<br/>模块独立性强"]
    B["降低耦合"] --> G
    C["简化结构"] --> G
    G --> R["可维护·可测试·可复用"]

    style G fill:#ffd700,stroke:#b8860b,stroke-width:2px
    style R fill:#e6ffe6,stroke:#5cb85c,stroke-width:2px
```

| 优化维度 | 目标 | 手段 |
| --- | --- | --- |
| 内聚 | 提高到功能内聚 | 拆分低内聚模块 |
| 耦合 | 降到数据耦合 | 消除控制/公共耦合 |
| 接口 | 参数少而清晰 | 减少参数、消除控制标志 |
| 结构 | 层次扇出合理 | 减少层次、平衡扇出 |

## 优化手法

### 合并高耦合模块

当两模块间数据耦合参数过多或频繁交互时，合并为一个高内聚模块：

```mermaid
flowchart LR
    subgraph 优化前["优化前: 高耦合"]
        direction LR
        A["模块A"] -->|"参数1·参数2<br/>参数3·参数4"| B["模块B"]
        B -->|"结果1·结果2"| A
    end
    subgraph 优化后["优化后: 高内聚"]
        direction LR
        AB["合并模块AB<br/>功能内聚·内部数据"]
    end
    优化前 -->|合并| 优化后

    style AB fill:#e6ffe6,stroke:#5cb85c,stroke-width:2px
```

> [!tip] 合并判据
> 当两模块间传递的参数超过 5 个、或存在双向频繁数据交换、或总是成对调用不可分离时，合并为单一模块通常能提高内聚并消除接口复杂度。

### 拆分低内聚模块

当一个模块承担多个不相关功能（偶然内聚或逻辑内聚）时，拆分为多个功能内聚模块：

```mermaid
flowchart LR
    subgraph 优化前["优化前: 低内聚"]
        direction TB
        M["模块M<br/>功能1+功能2+功能3<br/>偶然内聚"]
    end
    subgraph 优化后["优化后: 高内聚"]
        direction TB
        M1["模块M1<br/>功能1<br/>功能内聚"]
        M2["模块M2<br/>功能2<br/>功能内聚"]
        M3["模块M3<br/>功能3<br/>功能内聚"]
    end
    优化前 -->|拆分| 优化后

    style M fill:#ffcccc,stroke:#cc0000
    style M1 fill:#e6ffe6,stroke:#5cb85c
    style M2 fill:#e6ffe6,stroke:#5cb85c
    style M3 fill:#e6ffe6,stroke:#5cb85c
```

### 提取公共子模块

多个模块中存在重复操作时，提取为公共子模块以提高扇入与复用：

```mermaid
flowchart TD
    subgraph 优化前["优化前: 重复操作"]
        direction TB
        X1["模块A"] --> R1["重复操作1"]
        X2["模块B"] --> R2["重复操作2"]
        X3["模块C"] --> R3["重复操作3"]
    end
    subgraph 优化后["优化后: 公共子模块"]
        direction TB
        Y1["模块A"] --> C["公共子模块<br/>扇入=3"]
        Y2["模块B"] --> C
        Y3["模块C"] --> C
    end
    优化前 -->|提取| 优化后

    style C fill:#ffd700,stroke:#b8860b,stroke-width:2px
```

> [!example] 提取示例
> 在 [[5.3 事务流设计案例与实践|ATM 案例]]中，存款、取款、转账都需"更新账户"操作，可提取为公共子模块 `更新账户`，扇入为 3，消除三处重复实现。

## 接口优化

接口优化降低模块间耦合强度：

```mermaid
flowchart TD
    subgraph 优化前["优化前: 接口复杂"]
        direction LR
        A1["模块A"] -->|"参数1·参数2·参数3<br/>参数4·参数5·控制标志"| B1["模块B"]
    end
    subgraph 优化后["优化后: 接口简洁"]
        direction LR
        A2["模块A"] -->|"数据结构"| B2["模块B"]
    end
    优化前 -->|优化| 优化后

    style B1 fill:#ffcccc,stroke:#cc0000
    style B2 fill:#e6ffe6,stroke:#5cb85c
```

接口优化要点：

| 优化项 | 方法 | 效果 |
| --- | --- | --- |
| 减少参数数量 | 将相关参数封装为数据结构 | 接口简洁 |
| 消除控制耦合 | 将控制标志改为数据传递 | 降到数据耦合 |
| 消除冗余参数 | 删除未使用或可推导的参数 | 接口清晰 |
| 统一数据格式 | 参数采用系统内部标准格式 | 减少格式转换 |

> [!warning] 控制耦合的危害
> 控制耦合指一个模块通过参数传递控制标志（如"标志位=1 执行 A，=2 执行 B"）影响另一模块的执行逻辑。它使被调用模块依赖于调用者的决策，违反模块独立性，应消除——将控制逻辑移入被调用模块内部，或拆分为独立模块。

## 结构优化

结构优化调整整体层次与扇出：

```mermaid
flowchart TD
    subgraph 优化前["优化前: 层次过深"]
        direction TB
        T1["顶层"] --> M1["中层1"] --> M2["中层2"] --> M3["中层3"] --> B1["底层"]
    end
    subgraph 优化后["优化后: 层次精简"]
        direction TB
        T2["顶层"] --> N1["中层"] --> N2["底层"]
    end
    优化前 -->|精简层次| 优化后

    style N2 fill:#e6ffe6,stroke:#5cb85c,stroke-width:2px
```

结构优化要点：

1. **减少层次**：合并仅做中转的"透传"模块，缩短调用链。
2. **平衡扇出**：扇出过大的模块分组为子树，扇出过小的合并。
3. **调整作用范围**：使受判定影响的模块靠近判定模块。
4. **增加底层扇入**：提取公共操作提高复用。

## 优化流程

```mermaid
flowchart TD
    START["初始 SC"] --> S1["扫描低内聚模块<br/>→ 拆分"]
    START --> S2["扫描高耦合模块对<br/>→ 合并"]
    START --> S3["扫描重复操作<br/>→ 提取公共子模块"]
    S1 --> S4["接口优化<br/>减少参数·消除控制耦合"]
    S2 --> S4
    S3 --> S4

```

## 小结

结构图优化以提高内聚、降低耦合、简化结构为目标。主要手法：合并高耦合模块为高内聚模块、拆分低内聚模块为功能内聚模块、提取重复操作为高扇入公共子模块；接口优化通过减少参数、消除控制耦合降到数据耦合；结构优化通过精简层次、平衡扇出、调整作用范围改善整体形态。优化后模块独立性强、结构清晰，经 [[6.3 设计评审与质量度量|设计评审]]验证方可定稿。
