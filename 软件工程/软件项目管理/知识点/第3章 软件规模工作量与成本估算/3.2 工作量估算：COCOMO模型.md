# 3.2 工作量估算：COCOMO 模型

确定了软件规模（[[3.1 软件规模估算：代码行与功能点]]）后，下一个问题是“要多少人月才能完成”。COCOMO（Constructive Cost Model，构造性成本模型）是软件工程领域最经典的工作量估算模型，由 Boehm 于 1981 年提出。本节阐明 COCOMO 三级模型（基本、中级、高级）、模型参数表与 EAF 调整因子、COCOMO II 概述，并给出完整计算示例。

## COCOMO 模型概述

> [!definition] COCOMO
> COCOMO（Constructive Cost Model，构造性成本模型）是**以软件规模（KLOC）为输入，通过经验公式估算软件开发工作量（人月）**的参数化模型。它由 Barry Boehm 提出，是软件估算领域应用最广的算法模型。

COCOMO 按项目类型分为三种基本类型，对应不同复杂度与约束强度：

| 项目类型 | 特征 | 典型场景 |
| --- | --- | --- |
| 有机型（Organic） | 规模小、约束松、团队熟悉、需求稳定 | 内部小型信息系统 |
| 半分离型（Semi-Detached） | 规模中等、约束与团队经验中等 | 大多数商业软件 |
| 嵌入型（Embedded） | 规模大、约束严、需在硬约束下运行 | 实时系统、嵌入式系统、航电 |

## COCOMO 基本模型

> [!formula] COCOMO 基本模型
> $$E = a \times (KLOC)^b$$
>
> 其中：
> - $E$：工作量（人月，PM）；
> - $KLOC$：千行代码数；
> - $a, b$：模型参数，由项目类型决定。

基本模型参数表：

| 项目类型 | a | b |
| --- | --- | --- |
| 有机型 | 2.4 | 1.05 |
| 半分离型 | 3.0 | 1.12 |
| 嵌入型 | 3.6 | 1.20 |

> [!note] b 的含义
> > 指数 $b$ 反映规模与工作量的非线性关系。有机型 $b=1.05$ 接近线性（小项目协作开销小）；嵌入型 $b=1.20$ 表明规模增大时工作量增速更快——大规模、高约束项目的协作与沟通成本随规模超线性增长。

## COCOMO 中级模型

基本模型只考虑规模，过于粗糙。中级模型引入**工作量调整因子（Effort Adjustment Factor, EAF）**，反映项目具体属性对工作量的影响。

> [!formula] COCOMO 中级模型
> $$E = a \times (KLOC)^b \times EAF$$
>
> 其中 $EAF$ 为工作量调整因子，是 15 项成本驱动因子（Cost Drivers）评分之积。

中级模型 a、b 参数：

| 项目类型 | a | b |
| --- | --- | --- |
| 有机型 | 3.2 | 1.05 |
| 半分离型 | 3.0 | 1.12 |
| 嵌入型 | 2.8 | 1.20 |

> [!warning] 注意参数差异
> > 中级模型的 $a$ 参数与基本模型不同（有机型基本 2.4 vs. 中级 3.2，嵌入型基本 3.6 vs. 中级 2.8）。这是因为中级模型把部分复杂度调整移到了 EAF 中，需使用对应模型的参数，不可混用。

### 15 项成本驱动因子

EAF 由 4 类共 15 项成本驱动因子构成，每项取值范围通常 0.7–1.66（极低-非常高）：

| 类别 | 因子 | 含义 |
| --- | --- | --- |
| 产品属性 | RELY | 软件可靠性要求 |
|  | DATA | 数据库规模 |
|  | CPLX | 产品复杂度 |
| 平台属性 | TIME | 执行时间约束 |
|  | STOR | 主存约束 |
|  | VIRT | 虚拟机易变性 |
|  | TURN | 计算机周转时间 |
| 人员属性 | ACAP | 分析员能力 |
|  | AEXP | 应用经验 |
|  | PCAP | 程序员能力 |
|  | VEXP | 虚拟机经验 |
|  | LEXP | 编程语言经验 |
| 项目属性 | MODP | 现代编程实践 |
|  | TOOL | 软件工具使用 |
|  | SCED | 进度压缩 |

> [!tip] EAF 的作用
> > EAF 把“同样的代码量在不同项目条件下工作量不同”这一现实纳入模型。例如：高可靠性要求（RELY 高）使工作量增加，而强团队能力（ACAP 高）使工作量减少。所有因子评分相乘得到 EAF，范围约 0.7–1.66 之积，典型项目 EAF 在 0.8–1.2 之间。

## COCOMO 高级模型

高级模型在中级模型基础上，进一步把 15 项成本驱动因子按**开发阶段**（需求分析、设计、编码、测试等）分别取值，得到各阶段的工作量分配。它适用于大型项目的精细化估算与阶段资源分配，但计算复杂，工程中常借助工具完成。

> [!note] 三级模型对比
> > - **基本模型**：$E = a \times KLOC^b$，仅考虑规模，适合早期粗估。
> > - **中级模型**：$E = a \times KLOC^b \times EAF$，考虑 15 项成本驱动因子，适合项目计划阶段。
> > - **高级模型**：分阶段调整因子，适合大型项目精细化资源分配。

## COCOMO II 概述

随着软件工程实践演进（面向对象、COTS 复用、敏捷开发），Boehm 于 2000 年提出 COCOMO II，取代 1981 年的原版。

COCOMO II 由三个子模型组成：

| 子模型 | 适用阶段 | 估算对象 |
| --- | --- | --- |
| 应用组装模型 | 早期（原型/MVP） | 用对象点（Object Point）估算 |
| 早期设计模型 | 设计初期 | 用功能点（FP）估算 |
| 后体系结构模型 | 详细设计后 | 用代码行（KLOC）估算，类似中级模型 |

后体系结构模型公式：

$$E = A \times (Size)^E \times \prod EM_i$$

其中 $A$ 为校准常数（约 2.94），$Size$ 为等效规模，$E$ 为规模指数（由 5 项规模驱动因子决定，范围约 1.01–1.26），$EM_i$ 为 17 项工作量乘数。

> [!warning] 待核实
> > COCOMO II 的具体常数（如 $A=2.94$）与因子数量随校准版本而变，使用时应注明来源版本。本节给出的常数为常见教学取值，实际项目估算应以最新校准数据或本组织历史数据为准。

## 完整 COCOMO 计算示例

> [!example] 示例：图书借阅系统中级 COCOMO 估算
> **已知条件**：
> - 估算规模：3.55 KLOC（由 [[3.1 软件规模估算：代码行与功能点]] 示例 67 FP × 53 LOC/FP 换算）；
> - 项目类型：半分离型；
> - 假设 EAF = 1.0（各成本驱动因子均为标称值，乘积为 1.0）。
>
> **第1步：选定参数**
> 半分离型中级模型：$a = 3.0$，$b = 1.12$。
>
> **第2步：代入中级公式**
> $$E = a \times (KLOC)^b \times EAF = 3.0 \times (3.55)^{1.12} \times 1.0$$
>
> **第3步：计算 $(3.55)^{1.12}$**
> $$\ln(3.55) \approx 1.2669$$
> $$1.12 \times 1.2669 \approx 1.4189$$
> $$e^{1.4189} \approx 4.132$$
>
> **第4步：计算 E**
> $$E = 3.0 \times 4.132 \times 1.0 \approx 12.4 \text{ 人月}$$
>
> 系统工作量约为 12.4 人月。
>
> **第5步：估算开发期 TDEV 与平均人数**
> （COCOMO 给出开发期公式，半分离型：$TDEV = 2.5 \times E^{0.35}$）
> $$TDEV = 2.5 \times (12.4)^{0.35} \approx 2.5 \times 2.33 \approx 5.83 \text{ 月}$$
> 平均人数 $= E / TDEV = 12.4 / 5.83 \approx 2.13$ 人。

> [!tip] 估算结果的使用
> > 估算得到的人月（E）是 COCOMO 模型定义的“开发工作量”，包含设计、编码、测试与文档，但通常**不含**需求分析、项目管理、独立的质量保证活动。在编制项目预算时应在此基础上按组织惯例上浮一定比例（如 20%–40%）覆盖管理、沟通与应急。

## 小结

COCOMO 以代码行（KLOC）为输入估算工作量（人月），分基本、中级、高级三级模型。基本模型 $E = a \times KLOC^b$ 仅考虑规模；中级模型引入 15 项成本驱动因子构成的 EAF，公式为 $E = a \times KLOC^b \times EAF$；高级模型按阶段调整因子，适用于大型项目精细化估算。COCOMO II 针对现代软件工程实践扩展为应用组装、早期设计、后体系结构三个子模型。估算结果可作为进度编排与成本预算的基础。
