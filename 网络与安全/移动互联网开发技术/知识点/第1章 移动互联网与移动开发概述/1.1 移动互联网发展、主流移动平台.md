# 1.1 移动互联网发展、主流移动平台

> [!abstract] 本节概述
> 本节梳理移动互联网从功能机时代到智能手机时代的发展脉络，介绍当前三大主流移动平台（Android、iOS、HarmonyOS）的归属与生态特征，并总结移动互联网区别于传统互联网的核心特点。理解这些背景，有助于在后续章节中把握移动开发的技术约束与设计取舍。

## 1.1.1 移动互联网发展历程

移动互联网（Mobile Internet）是移动通信技术与互联网融合的产物，其发展可以划分为三个阶段：

```mermaid

    A["功能机时代<br/>(1990s-2007)"] --> B["智能手机兴起<br/>(2007-2010)"]
    B --> C["移动互联网时代<br/>(2010-至今)"]
    C --> D["万物互联与超级APP<br/>(2015-至今)"]

    A1["WAP/短信/彩信<br/>塞班Symbian"] -. A
    B1["iPhone发布(2007)<br/>Android发布(2008)"] -. B
    C1["4G普及/应用爆发<br/>微信/支付宝崛起"] -. C
    D1["5G/AI/小程序<br/>HarmonyOS"] -. D

    classDef era fill:#e3f2fd,stroke:#1565c0,stroke-width:2px
    classDef detail fill:#fff3cd,stroke:#856404,stroke-width:1px
    class A,B,C,D era
    class A1,B1,C1,D1 detail
```

> [!note] 阶段划分说明
> 上述划分以标志性事件为节点：iPhone 发布（2007）、Android 发布（2008）、4G 牌照发放（中国 2013）、5G 商用（中国 2019）。各阶段并非严格断代，而是渐进演化。

### 功能机时代（1990s—2007）

- 通信以语音、短信、彩信为主，数据业务有限
- WAP（Wireless Application Protocol）提供精简网页访问
- 主导平台：Symbian（诺基亚）、BlackBerry OS、Windows Mobile
- 应用分发依赖运营商门户与手机预装，开发者生态薄弱

### 智能手机兴起（2007—2010）

- **2007 年**：Apple 发布 iPhone，引入多点触控与全屏交互范式
- **2008 年**：Google 发布 Android 1.0，开放手机联盟（Open Handset Alliance）成立
- App Store（2008）与 Android Market（2008，后改名 Google Play）开启应用商店模式
- 应用形态从 WAP 页面转向原生应用，开发者生态开始繁荣

### 移动互联网时代（2010 至今）

- 3G/4G 普及使移动数据带宽满足富媒体应用需求
- **超级 APP 崛起**：以微信（2011 发布）、支付宝移动版为代表，单一应用集成 IM、支付、内容、生活服务、小程序
- 移动支付、共享出行、短视频、直播等场景驱动的应用形态涌现
- 2019 年起 5G 商用，移动端向高带宽、低时延、广连接场景扩展

> [!example] 案例：微信的演进
> 微信的发展折射了移动互联网的整体演进：
> - **2011 年**：以语音/文字 IM 起步，对标 Kik/WhatsApp
> - **2013 年**：引入微信支付，切入移动支付
> - **2014 年**：开放公众号，构建内容生态
> - **2017 年**：发布小程序，构建"应用内的应用"生态
> - **2020 年至今**：视频号、企业微信、小程序协同，成为连接人与服务的超级入口
>
> 微信的成功本质是利用移动互联网的**随身性**与**支付能力**，把碎片化场景整合为单一入口。

## 1.1.2 主流移动平台

> [!definition] 移动平台
> 移动平台（Mobile Platform）指由操作系统、SDK、应用商店、开发者工具组成的完整生态体系。开发者基于平台提供的 API 与分发渠道构建并交付应用。

| 平台 | 所属公司 | 首发年份 | 开源状态 | 主导语言 | 应用商店 |
| ---- | -------- | -------- | -------- | -------- | -------- |
| Android | Google | 2008 | 开源（AOSP） | Java/Kotlin | Google Play |
| iOS | Apple | 2007（iPhone OS） | 闭源 | Swift/Objective-C | App Store |
| HarmonyOS | 华为 | 2019 | 部分开源（OpenHarmony） | ArkTS/Java | AppGallery |

### Android

- **生态特征**：基于 Linux 内核的开源操作系统，设备厂商众多（三星、小米、OPPO、vivo、华为等）
- **技术栈**：Java/Kotlin + Android SDK + Gradle + Android Studio
- **优势**：开源、设备覆盖广、市场份额全球第一
- **挑战**：设备碎片化严重（屏幕尺寸、系统版本、厂商定制 ROM）

### iOS

- **生态特征**：Apple 闭环生态，仅运行于 iPhone/iPad 等自有硬件
- **技术栈**：Swift/Objective-C + Cocoa Touch + CocoaPods/SPM + Xcode
- **优势**：硬件统一、用户体验一致、付费意愿高
- **挑战**：闭源、审核严格、Apple 抽成 15%–30%（"苹果税"）

### HarmonyOS

- **生态特征**：华为自主研发的分布式操作系统，定位"万物互联"
- **技术栈**：ArkTS（基于 TypeScript 扩展）+ ArkUI + DevEco Studio
- **特色**：分布式软总线、跨设备协同、原子化服务
- **挑战**：海外生态受限，开发者迁移成本

> [!tip] 平台选择入门提示
> 本课程后续以 **Android 原生开发**为主线。学习 Android 的同时，建议对照 iOS 的设计理念（如统一设计规范 Human Interface Guidelines），有助于理解移动平台共通的交互范式与差异化的工程取舍。HarmonyOS 在 [[MOC - 第9章|第9章]] 跨平台部分作简要对比。

## 1.1.3 移动互联网的特点

移动互联网并非"互联网+移动设备"的简单叠加，其特性深刻影响移动应用的设计与开发：

> [!definition] 移动互联网四大特点
> 1. **随身性**：设备随身携带，使用场景碎片化、即时化
> 2. **定位能力**：内置 GPS/基站/Wi-Fi 定位，可提供位置服务（LBS）
> 3. **传感器丰富**：加速度计、陀螺仪、摄像头、麦克风、指纹、NFC 等
> 4. **碎片化**：设备型号、屏幕尺寸、系统版本、厂商定制并存

| 特点 | 对应用设计的影响 | 对开发的影响 |
| ---- | ---------------- | ------------ |
| 随身性 | 短时高频使用、推送通知、离线可用 | 关注启动速度、内存占用、电量 |
| 定位能力 | 地图、导航、附近、天气、打车 | 需申请定位权限、关注后台定位策略 |
| 传感器丰富 | 拍照、扫码、运动健康、AR | 需处理传感器数据异步、硬件差异 |
| 碎片化 | 自适应布局、不同 DPI 资源 | 多机型适配测试、版本兼容策略 |

> [!warning] 碎片化是 Android 开发的核心痛点
> Android 设备碎片化导致同一应用在不同厂商、不同系统版本上可能呈现不同行为。典型问题包括：通知栏图标渲染差异、后台保活策略差异（小米/华为/OPPO 各家省电策略）、权限申请时机差异等。开发时需在主流厂商真机上做兼容性测试，不能仅依赖模拟器。

## 1.1.4 超级 APP 的演进逻辑

> [!example] 案例：超级 APP 的形成
> 超级 APP（Super App）指集成众多子能力的单体应用，典型代表为微信、支付宝、美团、抖音。其演进逻辑：
>
> 1. **单一场景切入**：微信从 IM 起步，支付宝从支付起步
> 2. **基础设施沉淀**：账号体系、支付、推送、数据存储形成中台
> 3. **场景横向扩展**：通过公众号/小程序/服务市场接入第三方服务
> 4. **生态自循环**：用户、开发者、商家在单一应用内完成闭环
>
> 超级 APP 的本质是用**高频场景**（社交/内容）带动**低频高价值场景**（支付/服务），其技术架构对原生开发、跨平台开发、动态化能力提出复合要求，这也是 [[1.3 原生开发、跨平台开发方案对比|1.3]] 讨论技术选型的现实背景。

## 本节小结

- 移动互联网经历了功能机 → 智能机 → 应用爆发 → 万物互联四个阶段
- 三大主流平台 Android、iOS、HarmonyOS 各有生态特征，本课程以 Android 为主线
- 移动互联网的四大特点（随身性、定位、传感器、碎片化）共同塑造了移动应用的设计与开发约束
- 超级 APP 的演进揭示了"基础设施沉淀 + 场景扩展"的移动应用发展范式
