## 一、选择题（5 题）

**1.** 下列安全属性中，不属于经典 CIA 三要素的是（ ）

A. 保密性（Confidentiality）
B. 完整性（Integrity）
C. 可用性（Availability）
D. 不可否认性（Non-repudiation）

**2.** 在 STRIDE 威胁模型中，"信息泄露（Information Disclosure）"对应破坏的安全属性是（ ）

A. 完整性
B. 保密性
C. 可用性
D. 认证性

**3.** PDR 模型用时间量衡量系统在某攻击场景下的安全性，其安全性判定条件是（ ）

A. $P_t < D_t + R_t$
B. $P_t > D_t + R_t$
C. $P_t = D_t \times R_t$
D. $P_t + D_t < R_t$

**4.** 关于被动攻击与主动攻击，下列说法正确的是（ ）

A. 被动攻击会修改系统资源，因此容易被检测
B. 主动攻击只破坏保密性，不破坏可用性
C. 被动攻击几乎不可检测，应以加密预防为主
D. 主动攻击因行为隐蔽，应以预防为主、不需检测

**5.** 根据 ITU-T X.800，下列哪一项**不属于** OSI 安全体系结构定义的五类安全服务？（ ）

A. 认证（Authentication）
B. 访问控制（Access Control）
C. 数据完整性（Data Integrity）
D. 流量填充（Traffic Padding）

<details>
<summary>选择题答案</summary>

1. **D**。CIA 三要素为保密性、完整性、可用性。不可否认性是 CIA 之外扩展的安全属性（认证、授权、不可否认、可追溯）。

2. **B**。STRIDE 中 Information Disclosure（信息泄露）破坏保密性。其余映射：S 仿冒→认证、T 篡改→完整性、R 抵赖→不可否认、D 拒绝服务→可用性、E 权限提升→授权。

3. **B**。PDR 模型规定：当保护时间 $P_t$ 大于检测时间 $D_t$ 与响应时间 $R_t$ 之和时，攻击尚未得手即被发现并处置，系统在该场景下是安全的。

4. **C**。被动攻击只监听不修改，无行为异常，几乎不可检测，应靠加密预防；主动攻击破坏完整性/可用性且相对可检测，应靠检测与响应。

5. **D**。X.800 五类安全服务为认证、访问控制、数据保密性、数据完整性、不可否认。流量填充（Traffic Padding）属于八类**安全机制**之一，不是安全服务。

</details>

## 二、填空题（3 题）

**1.** 信息安全三大目标 CIA 是指：______（Confidentiality）、______（Integrity）、______（Availability）。

**2.** STRIDE 威胁模型的六个字母分别代表：______、______、______、______、______、______。

**3.** 风险处置的四种策略是：______、______、______、______；其中把损失后果转给第三方的策略称为______。

<details>
<summary>填空题答案</summary>

1. **保密性**、**完整性**、**可用性**。CIA 三要素是信息安全最基础的目标框架。

2. **Spoofing（仿冒）**、**Tampering（篡改）**、**Repudiation（抵赖）**、**Information Disclosure（信息泄露）**、**Denial of Service（拒绝服务）**、**Elevation of Privilege（权限提升）**。

3. **降低（Mitigate）**、**转移（Transfer）**、**接受（Accept）**、**规避（Avoid）**；把损失后果转给第三方的策略称为**转移（Transfer）**。注意：转移只转移损失后果，不转移安全责任。

</details>

## 三、简答题（4 题）

**1.** 简述 CIA 三要素各自的含义，并为每个要素举一个被破坏的典型场景。

**2.** 简述 STRIDE 威胁模型的六类威胁及其对应的安全属性映射。

**3.** 什么是深度防御（Defense in Depth）？说明其分层结构并指出三条设计原则。

**4.** 简述风险评估的五个步骤，并说明四种风险处置策略的含义。

<details>
<summary>简答题答案</summary>

**1. CIA 三要素**

| 要素 | 含义 | 被破坏的典型场景 |
| ---- | ---- | ---------------- |
| 保密性 | 信息仅被授权实体在授权方式下访问，不被未授权获取 | 数据库拖库、嗅探明文会话 Cookie |
| 完整性 | 信息在存储/传输/处理中不被未授权修改，且变更可被检测 | 篡改转账金额、重放支付指令 |
| 可用性 | 授权实体在需要时能及时可靠地访问资源 | DDoS 致服务中断、勒索软件加密数据 |

**2. STRIDE 模型与安全属性映射**

| 威胁 | 含义 | 破坏的属性 |
| ---- | ---- | ---------- |
| Spoofing 仿冒 | 冒充他人身份 | 认证性 |
| Tampering 篡改 | 修改数据 | 完整性 |
| Repudiation 抵赖 | 否认行为 | 不可否认性 |
| Information Disclosure 信息泄露 | 未授权获取信息 | 保密性 |
| Denial of Service 拒绝服务 | 阻断合法访问 | 可用性 |
| Elevation of Privilege 权限提升 | 越权获得更高权限 | 授权 |

**3. 深度防御**

深度防御主张不依赖任何单一安全措施，在从物理到管理的多个层级部署互补机制，任一层被突破后续层仍能延缓/阻断攻击，把"单点失效"变为"多层叠加"。

分层（由外到内）：物理安全 → 网络边界 → 主机安全 → 应用安全 → 数据安全 → 人员与管理。

三条设计原则：
- **异构冗余**：不同层用不同技术（防火墙 + WAF），避免同源失效；
- **失败安全（Fail-Safe）**：任一层失效时默认拒绝而非放行；
- **最小权限**：每层只授予完成任务所需的最小权限。

（另：可观测——每层都产生日志支撑跨层关联，也可作为原则之一。）

**4. 风险评估五步与处置策略**

五步：
1. **资产识别**：清点数据/系统/服务/凭证，标注 CIA 要求与价值等级；
2. **脆弱性识别**：扫描、代码审计、配置核查、人员访谈找出漏洞与弱点；
3. **威胁分析**：识别威胁源与威胁行为（可用 STRIDE 枚举），评估能力与动机；
4. **风险评级**：用风险矩阵（可能性 × 影响）对每条"威胁-漏洞-资产"组合评级；
5. **处置决策**：按四策略处置，评估残余风险，不可接受则回到评级循环。

四种处置策略：
- **降低（Mitigate）**：部署控制降低可能性或影响；
- **转移（Transfer）**：把损失后果转给第三方（保险/外包），仅转移损失不转移责任；
- **接受（Accept）**：低影响或处置成本过高的风险，书面记录并持续监控；
- **规避（Avoid）**：停止/退出引发风险的活动。

</details>

## 四、分析题（3 题）

**1.（威胁与漏洞案例）** 阅读以下材料，回答问题：
> 2017 年 9 月，美国征信机构 Equifax 披露约 1.47 亿美国人的 SSN、出生日期、地址等信息泄露。攻击者利用其在线争议系统中的 Apache Struts2 漏洞 CVE-2017-5638（OGNL 远程代码执行）获取 Web 服务器 shell，横向移动后拖库。该漏洞补丁在攻击前两个多月已发布，但 Equifax 未完成修复；攻击持续逾两个月才被发现。
>
> (1) 用"威胁、漏洞、风险、攻击"四概念分析本事件，说明四者关系。
> (2) 从 CIA 三要素角度，分析本次事件破坏了哪些属性。
> (3) 从 PDR 模型角度，分析 Equifax 在哪个环节失效，并给出改进建议。

<details>
<summary>案例分析1解答</summary>

**(1) 四概念分析与关系**

| 概念 | 本案体现 |
| ---- | -------- |
| 漏洞 | Apache Struts2 CVE-2017-5638（OGNL RCE），补丁已发布但未修复；数据库凭据明文存储 |
| 威胁 | 外部攻击者，具备利用公开 PoC 的能力与拖库动机 |
| 风险 | 可能性高（漏洞公开、有 PoC）× 影响极高（SSN 等核心身份信息）= 不可接受风险 |
| 攻击 | 恶意 Content-Type 触发 OGNL 注入 → 获取 shell → 横向移动 → 拖库 |

关系：漏洞是系统内部弱点，威胁是外部危害源，"威胁遇上漏洞"形成风险；风险是事前度量，攻击是风险的现实化行为。本案中风险长期存在却未被处置，最终演变为攻击。

**(2) CIA 三要素分析**

| 要素 | 是否被破坏 | 说明 |
| ---- | ---------- | ---- |
| 保密性 | 是（严重） | 1.47 亿人的 SSN 等敏感信息被未授权读走 |
| 完整性 | 是（部分） | 攻击者可能篡改日志、清理审计以掩盖痕迹 |
| 可用性 | 间接影响 | 数据泄露后引发信任危机与监管介入，影响业务连续性 |

**(3) PDR 失效分析与改进**

| 环节 | 失效点 | 改进建议 |
| ---- | ------ | -------- |
| 保护（P） | 补丁管理失效，已知 RCE 漏洞逾两月未修；$P_t$ 过短 | 缩短补丁 SLA（公开 RCE 72 小时内修复）；建立资产清单与第三方组件 SCA 追踪 |
| 检测（D） | 攻击持续逾两月未发现，$D_t$ 过长 | 部署 WAF 覆盖 OGNL/反序列化特征；SSL 解密后送 IDS 监控；数据库审计 |
| 响应（R） | 发现后凭据仍可被横向利用 | 数据库凭据加密存储、最小权限、网络隔离；应急响应预案 |

按 $P_t > D_t + R_t$，本案 $P_t$ 太短（漏洞未修）、$D_t$ 太长（两月未发现），不满足安全条件。改进核心是增大 $P_t$（补丁与组件治理）、减小 $D_t$（流量监控与审计）、减小 $R_t$（凭据隔离与预案）。

</details>

**2.（安全体系设计）** 阅读以下材料，回答问题：
> 某中型互联网企业核心业务为在线交易，需满足等保 2.0 三级要求。企业目前仅有边界防火墙，缺乏体系化安全建设。
>
> (1) 用 PPDR 模型为该企业规划安全能力，说明策略如何驱动保护/检测/响应。
> (2) 用深度防御给出该企业的分层防护方案。
> (3) 用 OSI 五类安全服务核对方案覆盖度，指出至少两处可能缺项。

<details>
<summary>案例分析2解答</summary>

**(1) PPDR 规划**

| 阶段 | 策略依据 | 落地能力 |
| ---- | -------- | -------- |
| 策略（Policy） | 资产分级（交易库 4 级）、威胁评估（STRIDE）、合规（等保 2.0 三级） | 《信息安全管理规范》《数据分级规范》《漏洞管理 SLA》 |
| 保护（P） | 增大 $P_t$ | 下一代防火墙 + WAF + 数据库加密 + 堡垒机 + 最小权限 + 基线加固 |
| 检测（D） | $D_t$≤5 分钟 | IDS/IPS + 数据库审计 + SIEM 跨层关联 + EDR |
| 响应（R） | $R_t$≤15 分钟 | SOAR 自动隔离 + 应急预案 + 双活灾备切换 |

策略驱动：保护/检测/响应的指标都从策略反推（如 4 级资产须 RTO≤15 分钟 → 反推 $D_t + R_t$ 目标），三阶段围绕策略执行，响应结果反馈调整策略。

**(2) 深度防御分层方案**

| 层 | 措施 |
| -- | ---- |
| 物理 | 机房门禁、视频监控、专线接入 |
| 网络边界 | 下一代防火墙、DMZ、Anti-DDoS、VPN |
| 主机 | 基线加固、补丁管理、EDR |
| 应用 | SDLC 安全左移、WAF、API 网关、参数化查询 |
| 数据 | 字段级加密、脱敏、数据库审计、备份 |
| 人员与管理 | 安全培训、权限审批、变更管理、应急演练、审计闭环 |

**(3) OSI 五服务覆盖核对**

| 服务 | 覆盖情况 | 可能缺项 |
| ---- | -------- | -------- |
| 认证 | 传输层 TLS、应用层 OAuth/JWT | — |
| 访问控制 | 堡垒机、RBAC | API 内部调用的服务间访问控制可能缺失 |
| 数据保密性 | TLS、字段加密 | 备份介质加密与密钥轮换可能缺失 |
| 数据完整性 | HMAC、签名 | 日志完整性保护（防篡改审计日志）可能缺失 |
| 不可否认 | 交易签名 + 时间戳 | 内部操作不可否认（堡垒机录像 + 审计签名）可能不足 |

两处典型缺项：**审计日志完整性保护**（防篡改）与**服务间访问控制**（API 网关下的零信任），建议补充。

</details>

**3.（生命周期与改进）** 阅读以下材料，回答问题：
> 某企业安全负责人发现：季度渗透测试中 8 个系统仍存在已知高危漏洞超期未修；SIEM 对 API 异常高频查询的检测耗时约 10 分钟、响应约 30 分钟，未达到策略目标（$D_t$≤3 分钟、$R_t$≤10 分钟）。该企业决定用 PDCA 持续改进。
>
> (1) 用安全生命周期五阶段说明该企业目前处于哪个阶段的何种状态。
> (2) 用 PDCA 设计两轮改进循环，分别针对漏洞超期与 API 检测响应。
> (3) 说明 PDCA 与 PPDR 在本案例中的关系与各自侧重。

<details>
<summary>案例分析3解答</summary>

**(1) 生命周期阶段判断**

该企业已完成"规划-实施-运营"，正处于**监控（Monitor）**阶段：通过季度渗透测试与 SIEM 发现偏差（漏洞超期、$D_t/R_t$ 不达标）。这些偏差需进入**改进（Improve）**阶段，回流到规划形成新一轮循环。状态特征：检测能力已建立但控制有效性不足，闭环尚未收敛。

**(2) 两轮 PDCA**

**第一轮：针对漏洞超期**
- **Plan**：基于风险评估，修订《漏洞管理规范》，高危 7 天、严重 72 小时 SLA，与绩效挂钩；
- **Do**：补丁 SLA 流程上线，SCA 接入 CI/CD 卡门，建立超期告警；
- **Check**：下季度渗透测试 + 月度合规核对，统计 SLA 达成率；
- **Act**：达标则标准化为通用流程；未达标则调整责任机制与自动化工具。

**第二轮：针对 API 检测响应（基于监控反馈触发）**
- **Plan**：增设 API 速率限制与行为基线监测，目标 $D_t$≤3 分钟、$R_t$≤10 分钟；
- **Do**：部署 API 行为分析 + SOAR 自动隔离；
- **Check**：红蓝对抗验证 $D_t$、$R_t$ 实测值；
- **Act**：达标后把"API 行为基线"标准化为通用监测模板复用到其他业务线；未达标则回 Plan 调整阈值。

**(3) PDCA 与 PPDR 的关系**

| 维度 | PDCA | PPDR |
| ---- | ---- | ---- |
| 层级 | 管理体系闭环 | 技术运营闭环 |
| 本案侧重 | 制定 SLA、SCA 卡门、标准化模板等管理与流程改进 | $D_t/R_t$ 收敛、API 监测、SOAR 自动响应等技术防护 |
| 关系 | PDCA 决定"做什么、怎么持续" | PPTR 决定"运营中如何保护-检测-响应" |

两者互补：本案中 PDCA 的 Act 把 PPDR 中验证有效的技术经验（API 行为基线）标准化推广；PPDR 的 $D_t/R_t$ 指标又是 PDCA 的 Check 依据。成熟组织两者并用，PDCA 提供持续改进骨架，PPDR 提供技术运营骨架。

</details>

> [!tip] 复习建议
> - **CIA 三要素**是全章基石，必须能准确说出三者含义、典型威胁、保障机制，并区分认证与授权；案例分析时养成"逐属性核对"的习惯。
> - **STRIDE 六类威胁与属性映射**是高频考点，建议口诀记忆（S仿冒-认证、T篡改-完整、R抵赖-不可否认、I泄露-保密、D拒服-可用、E提权-授权）。
> - **PDR 时间公式 $P_t > D_t + R_t$** 务必理解三个时间量的含义及提升安全的三个方向，案例题常考。
> - **OSI 五服务 vs 八机制**要分清"服务是目标、机制是手段"，注意流量填充是机制不是服务。
> - **深度防御**答题时既给分层（物理→网络→主机→应用→数据→管理）也给原则（异构冗余、失败安全、最小权限）。
> - **PDCA 与 PPDR** 的关系是易错点：PDCA 是管理闭环、PPDR 是技术闭环，层级不同、互补并用。
> - 案例分析题用"框架分析"：用 CIA 分析破坏、用 STRIDE/PDR 分析失效、用深度防御/PPDR 给方案、用 PDCA 给改进。
