## 一、选择题（5 题）

**1.** 关于数据分级与数据分类，下列说法**正确**的是（ ）

A. 分级与分类是同一概念的不同表述
B. 分级按业务属性划分，分类按敏感度划分
C. 同一分类下可有不同分级，二者正交组成控制矩阵
D. PII 数据必须全部归入 L4 机密级

**2.** 下列数据脱敏方法中，**可逆**的是（ ）

A. 掩码（Masking）
B. 替换（Substitution）
C. 泛化（Generalization）
D. 假名化（Pseudonymization）

**3.** 关于透明数据加密（TDE），下列描述**错误**的是（ ）

A. TDE 在数据库引擎写盘前加密、读盘后解密
B. TDE 对应用透明，无需修改 SQL
C. TDE 能防止介质失窃后数据被读取
D. TDE 能防止 DBA 在数据库内查询到明文

**4.** 某业务要求故障后**零数据丢失**，且**业务无缝切换**。对应的 RPO/RTO 与容灾架构应为（ ）

A. RPO=0、RTO=0，主备架构
B. RPO=0、RTO=0，双活架构
C. RPO>0、RTO>0，双活架构
D. RPO=0、RTO>0，两地三中心

**5.** 关于 SSD 数据销毁，下列说法**正确**的是（ ）

A. 用 `shred -n 3` 多遍覆写即可彻底销毁
B. 磨损均衡使主机层覆写不能保证旧物理页被覆盖
C. 消磁是 SSD 销毁的首选方法
D. 快速格式化即可销毁 SSD 上的敏感数据

<details>
<summary>选择题答案</summary>

1. **C**。分级按敏感度（公开/内部/秘密/机密），分类按业务属性（PII/金融/医疗），二者正交；PII 中既有 L2 的姓名也有 L4 的身份证号，并非全部 L4。

2. **D**。假名化用假名替换标识并保留映射表，可逆；掩码、替换、泛化均不可逆。注意假名化映射表必须按 L4 数据保护。

3. **D**。TDE 在数据库引擎内部加解密，DBA 在数据库内查询到的仍是**明文**。TDE 防"介质失窃"不防"DBA 拖库"，要对抗 DBA 需列级加密 + 最小权限。

4. **B**。零丢失（RPO=0）需同步复制，无缝切换（RTO=0）需双活架构；主备与两地三中心均存在切换时间。

5. **B**。SSD 磨损均衡使主机写入新数据时控制器将其写到新物理页，旧物理页标记为无效但电荷数据仍存，覆写不彻底。消磁对 SSD 无效（NAND 不靠磁记录）；快速格式化只清空文件分配表。

</details>

## 二、填空题（3 题）

**1.** 数据分级通常划分为四级：______、______、______、______；其中泄露后影响"灾难性"、要求字段级加密与双人授权的是______级。

**2.** TDE 采用两层密钥结构：用 ______ 加密数据页，再用 ______ 加密前者，后者通常托管于 ______ 中。

**3.** 容灾的关键指标 RPO 指______，RTO 指______；3-2-1 备份法则中的"3-2-1"分别表示______、______、______。

<details>
<summary>填空题答案</summary>

1. **公开（Public）**、**内部（Internal）**、**秘密（Confidential）**、**机密（Secret/Restricted）**；机密级（L4）。

2. **DEK（数据库加密密钥）**、**MK（主密钥）/ 证书 / 非对称密钥**、**KMS / HSM**。

3. **恢复点目标（可容忍的最大数据丢失量）**、**恢复时间目标（最长恢复时间）**；**3 份数据副本**、**2 种不同介质**、**1 份离线/异地**。

</details>

## 三、简答题（4 题）

**1.** 简述静态脱敏（SDM）与动态脱敏（DDM）的区别，并各举一个典型应用场景。

**2.** 画出 TDE 的两层密钥结构示意图，并说明"轮换主密钥只需重加密 DEK"的工程意义。

**3.** 简述全量备份、增量备份、差异备份三者的区别，并说明 Full + Differential 组合为何最常用。

**4.** 简述 SSD 销毁的特殊性，并说明为何加密擦除（CE）是 SSD 销毁的首选方法。

<details>
<summary>简答题答案</summary>

**1. 静态脱敏 vs 动态脱敏**

| 维度 | 静态脱敏 SDM | 动态脱敏 DDM |
| ---- | ------------ | ------------ |
| 作用时机 | 数据导出/复制时 | 查询返回时 |
| 是否生成副本 | 是，脱敏副本 | 否，原文仍在库 |
| 原文位置 | 仅生产库 | 生产库（需配合加密） |
| 性能开销 | 一次性，运行期无开销 | 每次查询实时处理 |
| 适用场景 | 测试库、数据仓库、外部共享 | 客服系统、运维查询、报表展示 |

典型场景：
- 静态脱敏：把生产库导出到开发测试环境用于联调。
- 动态脱敏：客服系统按角色查询客户手机号，普通客服看到 `138****5678`，主管授权后可看完整号码。

**2. TDE 两层密钥结构**

```
KMS/HSM ──托管──> MK（主密钥/证书）
                      │ 加密
                      v
                  DEK（数据库加密密钥，AES-256）
                      │ 加解密
                      v
                  数据页（.mdf/.ldf/.bak）
```

工程意义：日常运维只需轮换 MK，**重加密对象只有 DEK（几 KB）**，业务无感、可在分钟级完成；若直接用口令派生 DEK，轮换口令将触发全库重写，代价不可接受。两层结构把"高频率的密钥轮换"与"低频率的全库重写"解耦。

**3. 三种备份类型与 Full+Differential 组合**

| 类型 | 备份内容 | 恢复依赖 | 恢复速度 |
| ---- | -------- | -------- | -------- |
| 全量 | 全部数据 | 仅本身 | 快 |
| 增量 | 自上次任意备份后的变化 | 全量+整条增量链 | 慢 |
| 差异 | 自上次全量后的变化 | 全量+最近一次差异 | 中 |

Full + Differential 最常用的原因：恢复时只需 2 份（最近一次全量 + 最近一次差异），既不像纯增量那样依赖整条链（任一增量损坏全链失效），又不像纯全量那样备份窗口长。备份窗口与恢复可靠性之间取得了平衡。

**4. SSD 销毁特殊性与加密擦除**

SSD 采用磨损均衡（Wear Leveling）与垃圾回收（GC）：主机向逻辑扇区写入新数据时，控制器实际写到**新物理页**并把 LBA 重映射，旧物理页标记为无效但**电荷数据仍存**，直到 GC 真正擦除。因此主机层 `shred` 覆写不能保证旧物理页被覆盖，逻辑销毁不彻底。

加密擦除（CE）首选原因：
- 如果 SSD 在启用前就开启全盘加密（SED），销毁时只需销毁加密密钥（几毫秒），所有数据立即变为不可解密的无意义密文；
- 速度极快、对介质无物理损伤；
- NIST SP 800-88 推荐为现代 SSD 销毁首选。
- 前提：加密算法可信（AES-256）、密钥确实只存于 SSD 内部且可被销毁、加密未被旁路。

</details>

## 四、方案设计题（3 题）

**1.（数据脱敏方案设计）** 阅读以下场景，回答问题：
> 某城商行核心系统升级，需将生产库的客户表同步到开发测试环境用于联调；同时客服中心需查询客户信息。客户表含字段：客户姓名、身份证号、手机号、银行卡号、账户余额、开户行。生产库为 L4 PII。

> (1) 为每个字段设计脱敏方法并说明理由。
> (2) 区分测试环境与客服查询分别使用静态还是动态脱敏，并说明理由。
> (3) 列出至少 3 项配套控制措施以闭合保密性目标。

<details>
<summary>方案设计1解答</summary>

**(1) 字段级脱敏方法**

| 字段 | 分级 | 测试环境脱敏 | 客服查询脱敏 | 理由 |
| ---- | ---- | ------------ | ------------ | ---- |
| 客户姓名 | L3 | 字典替换为随机中文姓名 | 仅姓+称谓（如"张先生"） | 保留格式，去标识 |
| 身份证号 | L4 | 掩码保留前 6 后 4 | 掩码保留前 6 后 4 | L4 强敏感，仅必要时部分可见 |
| 手机号 | L4 | 掩码保留前 3 后 4 | 掩码保留前 3 后 4 | 联调不需真实号码 |
| 银行卡号 | L4 | 替换为符合 Luhn 校验的测试卡号 | 掩码保留后 4 | 测试需校验逻辑；客服只需核对尾号 |
| 账户余额 | L3 | 扰动 ±10% 保持分布 | 完整可见（按角色） | 测试需保留统计特征；客服需准确值 |
| 开户行 | L2 | 不脱敏 | 完整可见 | 内部信息，影响小 |

**(2) 静态 vs 动态**

| 场景 | 选择 | 理由 |
| ---- | ---- | ---- |
| 测试环境 | 静态脱敏 | 一次性导出脱敏副本，与生产隔离；测试环境无原文风险 |
| 客服查询 | 动态脱敏 | 原文仍在生产库；按角色实时返回掩码结果；可对主管授权临时解掩 |

**(3) 配套控制措施**

1. **生产库开启 TDE + 字段级加密**：身份证号、卡号在库内以密文存储，DBA 直接查询也仅见密文。
2. **最小权限与堡垒机**：测试环境账号只读、仅访问脱敏副本；客服账号绑定角色、所有查询走堡垒机并审计。
3. **审计与告警**：脱敏访问日志入 SIEM，对异常批量查询（如 1 分钟内查 1000 条）触发告警。
4. **测试环境数据治理**：测试库禁止外拷、定期回收、与生产网隔离。
5. **解掩审批流**：主管临时解掩需双人授权并记录原因，事后审计。

</details>

**2.（容灾方案设计）** 阅读以下场景，回答问题：
> 某在线支付平台日均交易 5000 万笔，监管要求核心业务 RTO≤30 分钟、RPO≤1 分钟；现仅有单中心部署，缺乏容灾能力。企业愿投入资金建设两地三中心容灾。

> (1) 设计两地三中心架构，标注各中心距离、复制方式与 RPO/RTO 目标。
> (2) 设计备份策略（基于 3-2-1 + 不可变备份），说明防勒索要点。
> (3) 设计一次容灾切换演练方案，包括演练目标、步骤、验收指标。

<details>
<summary>方案设计2解答</summary>

**(1) 两地三中心架构**

| 中心 | 位置 | 复制方式 | RPO | RTO | 角色 |
| ---- | ---- | -------- | --- | --- | ---- |
| A 生产中心 | 北京 | — | — | — | 主对外服务 |
| B 同城灾备 | 北京周边 ~50km | 存储层同步复制 | ≈0 | 分钟级 | 双活，前端 GSLB 调度 |
| C 异地灾备 | 上海 ~1000km | 异步复制 | ≤1 分钟 | ≤30 分钟 | 大灾备份 |

- A↔B 同步复制：专线往返时延 < 2ms，核心交易双写。
- A→C 异步复制：日志流传输，RPO≤1 分钟。
- GSLB 智能调度：A 故障自动切到 B；A、B 同时失效切到 C。

**(2) 3-2-1 + 不可变备份策略**

| 维度 | 配置 |
| ---- | ---- |
| 3 份副本 | 生产库 + 同城副本（B）+ 异地副本（C） |
| 2 种介质 | SSD 阵列（在线）+ 磁带库 / 对象存储（离线） |
| 1 份离线 | 每周日全量备份写入磁带并离线归档 |
| 不可变备份 | 关键备份启用对象存储 WORM 锁定 30 天，备份账号与生产网隔离 |

防勒索要点：
- **WORM 锁定**：锁定期间任何账号（含 root）无法删除/修改备份，对抗勒索软件加密在线备份。
- **账号隔离**：备份存储专用账号，与生产 DBA 账号分离，凭据托管 KMS。
- **离线归档**：磁带离线后物理隔离，勒索软件无法触达。
- **定期验证**：每月抽测备份可恢复性。

**(3) 容灾切换演练方案**

| 阶段 | 内容 |
| ---- | ---- |
| 目标 | 验证 A→B 同城切换 RTO≤5 分钟、RPO≈0；A、B→C 异地切换 RTO≤30 分钟、RPO≤1 分钟 |
| 步骤 1 准备 | 演练窗口选择业务低峰；通知上下游；准备回滚预案 |
| 步骤 2 模拟故障 | 在 A 注入"核心交换机故障"，触发 GSLB 切流到 B |
| 步骤 3 业务验证 | 在 B 验证交易成功率、数据一致性、对账结果 |
| 步骤 4 异地演练 | 模拟 A、B 同时失效，切到 C；验证 C 数据时点 ≤1 分钟前 |
| 步骤 5 回切 | 演练后回切到 A，恢复原拓扑 |
| 验收指标 | RTO 实测值、RPO 实测值、交易成功率≥99.99%、数据零丢失、回切无残留 |
| 报告 | 演练记录归档，作为等保 2.0 与监管检查材料 |

</details>

**3.（数据销毁方案设计）** 阅读以下场景，回答问题：
> 某企业每年退役 500 块 HDD（含 L3 客户数据）与 300 块 SSD（含 L4 凭证数据），需建立标准化销毁流程以满足等保 2.0 三级审计要求。

> (1) 分别为 HDD 与 SSD 设计销毁方案（方法、工具、验证方式）。
> (2) 设计销毁流程，包括清册登记、销毁执行、双人监督、证书归档各环节。
> (3) 列出至少 3 项审计核查点，说明每项的核查证据。

<details>
<summary>方案设计3解答</summary>

**(1) HDD 与 SSD 销毁方案**

| 介质 | 分级 | 销毁方法 | 工具/命令 | 验证方式 |
| ---- | ---- | -------- | --------- | -------- |
| HDD | L3 | 逻辑覆写 + 物理销毁（消磁或粉碎） | `shred -v -n 3 -z -f /dev/sdX` → 消磁机/粉碎机 | 覆写后读回校验全零；消磁/粉碎录像与抽检碎片 |
| SSD | L4 | 加密擦除（CE）+ 物理粉碎 | 厂商 Secure Erase / Sanitize 命令；失败则物理粉碎 | 控制器返回成功状态；密钥已销毁日志；物理粉碎录像 |

> L4 数据不依赖逻辑销毁，必须物理销毁作为兜底。

**(2) 销毁流程**

| 环节 | 内容 | 责任人 |
| ---- | ---- | ------ |
| 清册登记 | 记录每块盘序列号、原所属系统、数据分级，录入资产系统 | 运维 + 资产管理 |
| 预擦除（仅 HDD） | 机房内 `shred -n 3 -z` 逻辑覆写 | 运维 |
| SSD 处理 | 执行 Secure Erase / Sanitize，验证返回成功 | 运维 |
| 物理销毁 | 交由具备涉密资质的销毁服务商，消磁 + 粉碎，全程录像 | 销毁商 + 安全监督 |
| 双人监督 | 运维 1 人操作 + 安全 1 人核对，在销毁证书签字 | 运维 + 安全 |
| 证书归档 | 销毁证书、录像片段、资产清册归档保存 ≥3 年 | 安全 + 档案 |

**(3) 审计核查点**

| 核查点 | 核查证据 |
| ------ | -------- |
| 介质清册完整性 | 资产系统中退役盘序列号清单 vs 实物清点记录 |
| 销毁方法合规性 | 销毁证书注明方法（DoD 5220.22-M / CE / 物理粉碎）+ 录像片段 |
| 双人监督有效性 | 销毁证书双人签字记录 + 操作日志时间戳一致性 |
| 证书归档可追溯 | 归档清单 + 存档介质 + 保存期限标注 |
| SSD 加密擦除成功证据 | 控制器返回的 Sanitize 成功状态截图 + 密钥销毁日志 |
| 流程闭环 | 退役申请 → 销毁执行 → 证书归档的全链路工单记录 |

</details>

> [!tip] 复习建议
> - **数据分级与分类**必须分清"按敏感度 vs 按业务属性"，并理解两者正交组成控制矩阵；高频选择题考点。
> - **五类脱敏方法**用"是否可逆"分组记忆：假名化（可逆，需保护映射表）、加密（可逆，需密钥）、掩码/替换/扰动/泛化（不可逆）；区分假名化与匿名化。
> - **静态脱敏 vs 动态脱敏**对比表必背，案例题常考"测试环境用静态、客服查询用动态"的组合。
> - **TDE 两层密钥结构**是简答题高频考点，务必能画出 KMS→MK→DEK→数据页的链路；理解"轮换 MK 只需重加密 DEK"的工程意义。
> - **TDE 不能防 DBA**是易错点：TDE 防"介质失窃"不防"DBA 拖库"；对抗 DBA 需列级加密 + 最小权限。
> - **RPO/RTO 与容灾架构的对应关系**：RPO=0/RTO=0→双活；RPO 小/RTO 小→主备或同城；RPO 大/RTO 大→离线备份。两地三中心本质是"同城零丢失 + 异地抗大灾"。
> - **3-2-1 + 不可变备份**是方案设计题的标准答法；防勒索要点：WORM 锁定、账号隔离、离线归档。
> - **SSD 销毁特殊性**必考：磨损均衡使覆写不彻底，逻辑销毁不可靠；推荐加密擦除（CE）或物理销毁；消磁对 SSD 无效。
> - **方案设计题**用"框架答题"：先分级分类→再选方法→再列配套控制（加密、最小权限、审计、监督）；最后给验证指标。
