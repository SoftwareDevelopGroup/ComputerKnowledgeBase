## 一、选择题（5 题）

**1.** 关于计算机病毒、蠕虫、木马的核心区别，下列说法正确的是（ ）

A. 蠕虫需要依附宿主文件才能运行
B. 木马会主动自我复制并感染其他文件
C. 病毒必须依附宿主程序，且需要触发条件激活
D. 三者都通过主动扫描网络漏洞扩散

**2.** 勒索软件采用"对称加密文件 + 非对称加密密钥"的混合设计，其核心目的是（ ）

A. 提高加密速度，同时保证只有攻击者能解密
B. 防止杀毒软件检测特征码
C. 利用非对称加密加速大文件处理
D. 利用对称加密保护私钥不被泄露

**3.** 关于 2017 年 WannaCry 勒索软件全球爆发事件，下列说法错误的是（ ）

A. 利用 EternalBlue（MS17-010）漏洞实现蠕虫式扩散
B. 加密文件使用 AES，加密 AES 密钥使用 RSA
C. 攻击者只要支付赎金即可保证获得完整解密
D. "Kill Switch"域名注册后疫情迅速缓解

**4.** 在恶意代码静态特征识别中，下列哪一项最常用于"大规模扫描与家族识别"？（ ）

A. 文件熵值分析
B. YARA 规则
C. 进程行为监控
D. 沙箱 detonation

**5.** 关于 EDR 与传统杀毒软件（AV）的对比，下列说法正确的是（ ）

A. EDR 取代了 AV 的特征码能力，不再需要签名扫描
B. AV 能识别未知变种，EDR 只能查杀已知威胁
C. EDR 提供持续监控、威胁检测、调查取证、自动响应四类能力
D. EDR 与 SOAR 是同一类产品的两种叫法

<details>
<summary>选择题答案</summary>

1. **C**。病毒必须依附宿主程序，且按特定条件触发激活（寄生性、传染性、触发性）。A 错：蠕虫独立运行无需宿主；B 错：木马不自复制；D 错：病毒和木马不靠主动扫描漏洞扩散。

2. **A**。AES 对称加密文件速度快，适合批量数据；RSA 非对称加密 AES 密钥，只有攻击者的私钥能解开。这是速度与"仅攻击者可解"的折中。

3. **C**。支付赎金不保证获得解密密钥——部分家族根本未保存私钥、或仅部分恢复。攻击者无诚信约束，多国执法机构建议不支付。A、B、D 均正确。

4. **B**。YARA 是基于字节/字符串模式匹配的规则语言，专为大规模扫描与家族识别设计。A 是分析手段但不用于大规模扫描；C、D 属于动态分析而非静态。

5. **C**。EDR 四核心能力：持续监控、威胁检测、调查取证、自动响应（Gartner 定义）。A 错：EDR 叠加而非取代 AV 签名；B 错：正好相反；D 错：SOAR 是编排层，与 EDR 是协同关系而非同一产品。

</details>

## 二、填空题（3 题）

**1.** 计算机病毒区别于蠕虫和木马的核心特征是：必须 ______、能 ______、依赖 ______ 触发激活。

**2.** 勒索软件攻击链中，加密文件通常使用 ______ 加密算法（如 AES），而加密对称密钥则使用攻击者的 ______ 公钥，受害者要还原文件必须获得保存在 ______ 上的私钥。

**3.** EDR 的四个核心能力是：______、______、______、______；与传统杀毒相比，EDR 把检测重心从 ______ 转移到 ______。

<details>
<summary>填空题答案</summary>

1. **依附宿主程序**、**自我复制（感染其他文件）**、**特定条件**。三者构成病毒的寄生性、传染性、触发性。

2. **对称**、**RSA 非对称**、**C2（命令控制服务器）**。混合加密设计是勒索软件的高明之处——对称保证速度，非对称保证"只有攻击者能解"。

3. **持续监控**、**威胁检测**、**调查取证**、**自动响应**；检测重心从 **已知特征（签名/哈希）** 转移到 **行为与上下文**。

</details>

## 三、简答题（4 题）

**1.** 简述计算机病毒、蠕虫、木马三者在"宿主依赖、自我复制、传播方式、典型目的"四个维度上的区别，并各举一个典型案例。

**2.** 说明勒索软件"对称加密文件 + 非对称加密密钥"混合加密设计的工作流程，并解释为何受害者无法自行解密。

**3.** 简述恶意代码静态分析与动态分析的区别，并说明为何沙箱检测结果为"阴性"并不等于样本安全。

**4.** 简述 EDR 的四个核心能力，并说明 AV 与 EDR 是"叠加"而非"替代"关系的原因。

<details>
<summary>简答题答案</summary>

**1. 三类恶意代码四维区别**

| 维度 | 病毒 Virus | 蠕虫 Worm | 木马 Trojan |
| ---- | ---------- | --------- | ----------- |
| 宿主依赖 | 必须依附宿主 | 独立运行 | 独立运行 |
| 自我复制 | 是 | 是（主动） | 否 |
| 传播方式 | 跟随宿主被动传播 | 主动利用漏洞/网络 | 钓鱼/挂马/捆绑下载 |
| 典型目的 | 破坏、炫耀 | 扩散、构建 Botnet | 后门、窃密、远控 |

典型案例：CIH（病毒）、Conficker（蠕虫）、Zeus（木马）。

**2. 勒索软件混合加密流程**

1. 攻击者生成 RSA 密钥对，私钥保存在 C2 服务器，公钥随载荷下发；
2. 对每个待加密文件生成随机 AES 对称密钥 $K_{file}$；
3. 用 $K_{file}$ 以 AES 加密文件内容（对称速度快，适合大文件）；
4. 用攻击者公钥加密 $K_{file}$ 得到 $C_K$；
5. 保存加密文件与 $C_K$，删除原始 $K_{file}$ 与卷影副本。

**为何无法自行解密**：受害者本地只有加密后的文件和加密后的 $K_{file}$（$C_K$），$C_K$ 用的是攻击者的 RSA 公钥，只有攻击者保管的私钥才能解开。RSA 公钥加密的单向性使受害者无能为力——这正是密码学在恶意场景下的应用。

**3. 静态 vs 动态分析**

| 维度 | 静态分析 | 动态分析 |
| ---- | -------- | -------- |
| 是否运行样本 | 不运行 | 在受控环境运行 |
| 典型方法 | 哈希、字符串、YARA、导入表、熵值 | 行为监控、沙箱、API Hook |
| 优点 | 安全、快速、可批量 | 揭示真实行为、识别未知变种 |
| 缺点 | 易被加壳/混淆绕过 | 耗时、可能被反沙箱对抗 |

**沙箱阴性的局限**：现代恶意代码具备反沙箱能力——检测鼠标移动、内存大小、特定进程名等，符合沙箱特征时"装死"不执行恶意行为。因此沙箱阴性只是"未观察到恶意行为"，不等于样本安全。需结合多环境验证、人工分析与行为基线。

**4. EDR 四能力与"叠加"关系**

EDR 四能力：①持续监控（终端 Agent 7×24 采集行为遥测）；②威胁检测（行为规则 + ML + 威胁情报）；③调查取证（事件链、时间线、影响范围）；④自动响应（隔离主机、终止进程、回滚）。

**叠加而非替代的原因**：AV 的特征码扫描对**已知威胁**仍是最快、最低误报、最高性价比的防线；EDR 补齐的是**未知变种与行为异常**的检测、响应与取证能力。现代终端防护平台（NGAV/XDR）通常同时具备签名扫描、启发式、行为检测、ML、威胁情报——形成"已知 + 未知 + 行为"三层覆盖。EDR 缺少 AV 的签名能力会让已知威胁"重新裸奔"，AV 缺少 EDR 会让未知与变种无防护。

</details>

## 四、分析题（3 题）

**1.（病毒/蠕虫/木马分类与案例）** 阅读以下材料，回答问题：
> 某企业内网监控发现：A 主机的 PowerShell 进程异常调用，向一个陌生 IP 发起加密通信；同时多个内网主机的 SMB 445 端口被高速扫描，未打补丁的 Windows 主机被自动植入后门，再回连同一 C2。安全团队溯源发现初始入口是一封伪装成"快递单"的钓鱼邮件附件。
>
> (1) 用"病毒/蠕虫/木马"三类区分框架分析本事件中的恶意代码属于哪一类？说明依据。
> (2) 该事件是否构成僵尸网络（Botnet）？给出判断依据与组成要素。
> (3) 从 [[1.3 信息安全模型、安全体系框架|PPDR 模型]] 角度，针对该事件给出 $P_t$、$D_t$、$R_t$ 的改进方向。

<details>
<summary>案例分析1解答</summary>

**(1) 分类判断**

| 观察到的行为 | 对应类别特征 |
| ------------ | ------------ |
| 钓鱼邮件附件伪装快递单，诱导用户运行 | 木马的"伪装性"特征 |
| 运行后建立加密通信回连 C2，PowerShell 异常调用 | 木马的"后门功能"特征 |
| 不自我复制，由用户被骗执行 | 木马的"非自复制"特征 |
| **高速扫描 445 端口，未打补丁主机被自动植入后门再回连同一 C2** | 蠕虫的"独立性 + 主动性 + 网络扩散"特征 |

**判断**：该事件是**蠕虫型 + 木马功能**的复合恶意代码。蠕虫模块（445 端口扫描、自动植入）负责扩散，木马模块（后门、回连 C2）负责控制。这印证了 [[5.1 计算机病毒、蠕虫、木马区别|5.1]] 中"一个家族可兼具多种特征"——分类维度而非家族维度。

**(2) 僵尸网络判断**

构成僵尸网络。组成要素：

| 要素 | 本案体现 |
| ---- | -------- |
| Bot（僵尸节点） | 被植入后门的 A 主机与被蠕虫扩散感染的内网主机 |
| C2（命令控制服务器） | 那个"陌生 IP"对应的服务器，回收数据并下发指令 |
| Botmaster（控制者） | 发起钓鱼邮件、运营 C2 的攻击者 |

判断依据：受控节点规模可观、统一回连同一 C2、具备远程控制能力——符合 [[5.1 计算机病毒、蠕虫、木马区别|Botnet]] 定义。本案 Botnet 由"蠕虫型扩散 + 木马型后门"组合构建，是典型的 Botnet 运营形态。

**(3) PPDR 改进方向**

| 环节 | 失效点 | 改进方向 |
| ---- | ------ | -------- |
| $P_t$（保护） | 未打补丁主机被自动利用 | 补丁管理 SLA（公开 RCE 72 小时内修复）、网络分段关闭 SMB 公网暴露、宏默认禁用阻断钓鱼附件 |
| $D_t$（检测） | PowerShell 异常调用与 445 扫描未被及时告警 | 部署 [[5.4 杀毒软件、EDR 防护机制\|EDR]] 行为检测、PowerShell 日志审计、流量异常监控，缩短 $D_t$ 至分钟级 |
| $R_t$（响应） | 单一终端告警未触发隔离 | SOAR 联动自动隔离受感染主机、撤销凭据、横向移动遏制 |

按 $P_t > D_t + R_t$，本案 $P_t$ 过短（漏洞未修）、$D_t$ 过长（异常未告警）、$R_t$ 不足（无自动隔离），三方向均需改进。

</details>

**2.（勒索软件防御方案）** 阅读以下材料，回答问题：
> 某中型企业近期遭遇勒索软件攻击：办公终端被加密，业务数据无法访问；攻击者声称已外泄客户数据并要求赎金。事后调查发现：终端未部署 EDR，仅安装传统杀毒；RDP 3389 端口直接暴露公网且使用弱口令；备份服务器与生产网同 VLAN 且可写，被同步加密；补丁管理存在已发布 3 个月的未修复漏洞。
>
> (1) 用 [[5.2 勒索病毒原理与防范方案|5.2]] 防御方案分析该企业在哪些层存在缺失。
> (2) 该事件属于哪种勒索模式？为什么"有备份"也没能避免赎金威胁？
> (3) 设计一套整改方案，给出优先级排序与每项措施缓解的攻击环节。

<details>
<summary>案例分析2解答</summary>

**(1) 防御层缺失分析**

| 防御层 | 缺失点 | 缓解的攻击环节 |
| ------ | ------ | -------------- |
| 备份恢复 | 备份与生产同 VLAN 且可写，被同步加密 | 数据可恢复性完全丧失 |
| 补丁管理 | 已发布 3 个月漏洞未修复 | 漏洞利用横向扩散 |
| 邮件安全 | 未提及，疑似钓鱼投递（需补查） | 初始投递 |
| 终端防护 | 仅 AV 无 EDR，行为层缺失 | 落地执行与加密阶段未拦截 |
| 网络分段 | RDP 公网暴露、备份未隔离 | 横向移动与备份保护双失效 |
| RDP 加固 | 弱口令 + 公网暴露 + 无 NLA | RDP 爆破入口完全敞开 |
| 应急响应 | 无隔离预案，无法快速遏制 | 爆炸半径无法收敛 |

**(2) 勒索模式判断**

属于**双重勒索（Double Extortion）**：攻击者声称已外泄客户数据并要求赎金，即"加密 + 公开数据"双重要挟。

**为何有备份也没用**：①备份本身被同步加密，未做"离线/不可变"，丧失恢复能力；②即便备份可恢复，双重勒索下"数据外泄"威胁仍在——攻击者仍可公开客户数据，备份无法解决外泄问题。这正是 [[5.2 勒索病毒原理与防范方案|5.2]] 中"双重勒索使仅靠备份不足以完全缓解"的现实体现。

**(3) 整改方案与优先级**

| 优先级 | 措施 | 缓解攻击环节 | 预期效果 |
| ------ | ---- | ------------ | -------- |
| P0（立即） | 关闭 RDP 公网暴露、改堡垒机 + MFA | RDP 爆破入口 | 阻断首要入口 |
| P0（立即） | 备份改造为 3-2-1 + 不可变（WORM） | 数据可恢复 | 即使再被攻击也能恢复 |
| P1（1 周内） | 修复已发布 3 个月的高危漏洞 | 漏洞利用 | 阻断横向扩散 |
| P1（1 周内） | 备份网络与生产网隔离（独立 VLAN/物理隔离） | 备份保护 | 防备份被同步加密 |
| P2（1 月内） | 部署 EDR + SOAR 自动响应 | 落地/加密阶段 | $D_t$、$R_t$ 显著改善 |
| P2（1 月内） | 网络微隔离、关闭 SMB/RDP 不必要的横向通道 | 横向移动 | 缩小爆炸半径 |
| P3（持续） | 邮件网关沙箱、宏默认禁用、用户意识培训 | 初始投递 | 阻断钓鱼入口 |
| P3（持续） | 应急响应预案 + 定期演练 | 响应处置 | 缩短 $R_t$，降低损失 |

</details>

**3.（终端防护选型与 SOAR 协同）** 阅读以下材料，回答问题：
> 某企业 SOC 值班人员反馈：传统杀毒软件对近期变种勒索软件几乎无告警，事件多由用户电话报告；EDR 告警量大但值班人员疲于应对，平均响应时间超过 30 分钟。安全负责人考虑引入 EDR + SOAR 协同。
>
> (1) 用 [[5.4 杀毒软件、EDR 防护机制|5.4]] 说明为何传统 AV 对变种勒索无告警。
> (2) 设计 EDR + SOAR 的协同剧本（至少 5 个步骤），说明每步由谁执行、缩短哪个时间量。
> (3) 列出至少 3 项 EDR 自身需要加固的风险点，避免被攻击者禁用或绕过。

<details>
<summary>案例分析3解答</summary>

**(1) 传统 AV 为何对变种无告警**

传统 AV 的检测原理是**已知特征库 + 比对引擎**：从已知样本提取字节序列/哈希作为签名，扫描时比对文件是否命中。变种勒索软件通过加壳、混淆、多态变形即可产生全新的字节序列与哈希，签名库中无对应记录，AV 自然"看不见"。此外 AV 缺少行为遥测与上下文关联，无法识别"加密文件 + 删除 VSS + 联网回传"这类行为链。这正是 [[5.4 杀毒软件、EDR 防护机制|AV 的根本局限]] 与 EDR 兴起的动因。

**(2) EDR + SOAR 协同剧本**

| 步骤 | 执行方 | 动作 | 缩短的时间量 |
| ---- | ------ | ---- | ------------ |
| 1. 检测 | EDR | 行为规则识别"批量文件写入 + VSS 删除 + C2 通信"，触发告警 | $D_t$ |
| 2. 富化 | SOAR | 自动查询进程哈希威胁情报、关联 SIEM 同主机历史事件、查询用户属主 | 减少 SOC 调查时间 |
| 3. 隔离 | SOAR 调用 EDR | 自动触发 EDR 网络隔离该主机出网 | $R_t$ |
| 4. 处置 | SOAR 调用 EDR | 终止恶意进程、回滚文件变更、撤销近期凭据 | $R_t$ |
| 5. 通知 | SOAR | 通知 SOC 值班、创建工单、向主机属主推送说明 | 减少人工通知时间 |
| 6. 报告 | SOAR | 自动生成事件初步报告，归档取证数据 | 减少事后整理时间 |

预期效果：$D_t$ 从分钟级降至秒级，$R_t$ 从 30 分钟降至 1 分钟内。

**(3) EDR 自身加固风险点**

1. **Agent 防卸载**：攻击者首要目标之一是禁用/卸载 EDR Agent。需为 EDR 进程、服务设置防篡改保护，卸载需 MFA 与审批，并审计所有卸载尝试。
2. **凭据与通道安全**：EDR 与云端/SOC 的通信需双向 TLS 验证，避免被中间人劫持或伪造指令；管理控制台凭据需 MFA。
3. **配置审计与告警**：EDR 策略变更、日志停止上报、Agent 离线都应作为高危事件实时告警，避免"静默失效"——攻击者常通过关闭 EDR 数据上报来实现"灯下黑"。

（另可补充：Agent 完整性自校验、防内存注入、与 SIEM 联动的离线检测。）

</details>

> - **静态 vs 动态分析**用对比表记忆，重点理解"沙箱阴性的局限"——反沙箱对抗是现代恶意代码的标配。

> - **AV vs EDR**是"叠加"不是"替代"——这是简答/分析题的常考辨析点。
> - **SOAR 与 EDR 的协同**答题时给出具体剧本步骤，每步标注由谁执行、缩短哪个时间量。
