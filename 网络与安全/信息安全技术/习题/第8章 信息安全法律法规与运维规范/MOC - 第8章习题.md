## 一、选择题（5 题）

**1.** 《中华人民共和国数据安全法》的**施行日期**是（ ）

A. 2017 年 6 月 1 日
B. 2021 年 6 月 10 日
C. 2021 年 9 月 1 日
D. 2021 年 11 月 1 日

**2.** 关于网络安全等级保护制度，下列说法**正确**的是（ ）

A. 等保制度是建议性标准，企业可自愿选择是否执行
B. 等保 2.0 的核心标准是 GB/T 22239-2008
C. 第三级信息系统应每年至少进行一次等级测评
D. 第一级系统需向公安机关备案并接受强制监督

**3.** 关于等保 2.0 与等保 1.0 的区别，下列描述**错误**的是（ ）

A. 等保 2.0 新增了云计算、移动互联、物联网、工控系统、大数据五个扩展
B. 等保 2.0 技术要求重组为"一个中心、三重防御"的结构
C. 等保 2.0 完全取消了管理要求，仅保留技术要求
D. 等保 2.0 强调主动防御、可信验证与集中管控

**4.** 根据《网络安全法》，网络运营者应当留存网络日志**不少于**（ ）

A. 30 天
B. 90 天
C. 3 个月
D. 6 个月

**5.** 应急响应六阶段模型 PICERL 中，"P"代表的阶段是（ ）

A. 检测（Probing）
B. 准备（Preparation）
C. 遏制（Prevention）
D. 总结（Post-mortem）

<details>
<summary>选择题答案</summary>

1. **C**。《数据安全法》2021-06-10 通过，**2021-09-01 施行**。A 是《网络安全法》施行日期；B 是通过日期；D 是《个人信息保护法》施行日期。

2. **C**。等保制度是《网络安全法》确立的**法定强制制度**，非自愿；核心标准是 GB/T 22239-**2019**（非 2008）；第三级系统**每年至少一次**、第四级每半年至少一次等级测评；第一级为用户自主保护级，无需备案强制监督。

3. **C**。等保 2.0 **保留并强化了管理要求**（安全管理制度、安全管理机构、安全管理人员、安全建设管理、安全运维管理），并未取消管理要求。等保的核心思想是"三分技术、七分管理"，技术与管理双轮驱动。

4. **D**。《网络安全法》第 21 条规定网络运营者应当留存网络日志**不少于六个月**。这是法定底线，也是等保 2.0 审计要求的法律来源。

5. **B**。PICERL = **P**reparation（准备）+ **I**dentification（检测分析）+ **C**ontainment（遏制）+ **E**radication（根除）+ **R**ecovery（恢复）+ **L**essons Learned（总结）。"P"是 Preparation 准备阶段。

</details>

## 三、简答题（4 题）

**1.** 简述《网络安全法》《数据安全法》《个人信息保护法》三法的保护对象与核心制度，并说明三者的关系。

**2.** 简述等保 2.0 的定级流程，并说明第三级系统在测评周期与监管要求上的特点。

**3.** 简述安全审计日志的六个核心要素，并说明日志保护的主要要求（至少 4 项）。

**4.** 简述数字取证的易失性顺序（Order of Volatility），并说明为什么在勒索软件事件中应在断网前优先做内存镜像。

<details>
<summary>简答题答案</summary>

**1. 三法的保护对象、核心制度与关系**

| 维度 | 《网络安全法》 | 《数据安全法》 | 《个人信息保护法》 |
| ---- | -------------- | -------------- | ------------------ |
| 保护对象 | 网络与系统运行安全 | 数据本身安全 | 个人信息权益 |
| 核心制度 | 等级保护、CII 保护、实名制 | 数据分类分级、重要数据保护 | 告知同意、敏感信息保护 |

三法关系：
- **分工**：网安法管"载体与运行"、数安法管"数据内容与流通"、个保法管"个人权益与处理行为"。
- **互补**：个人信息既是个保法保护对象，也属于数据受数安法规制，其载体网络受网安法规制，构成"网络—数据—信息"分层保护体系。
- **重叠适用**：同一行为可能同时违反多部法律，按"特别法优于一般法"适用，行政处罚可并罚。

**2. 等保 2.0 定级流程与三级特点**

定级流程五步：
1. **定级**：依据 GB/T 22240 确定系统等级，组织专家评审；
2. **备案**：第二级及以上系统向设区的市级及以上公安机关备案，取得备案证明；
3. **建设整改**：按等级要求建设安全设施并整改不符合项；
4. **等级测评**：委托公安部认可的第三方测评机构开展测评；
5. **监督检查**：公安机关对运营单位履责情况监督检查。

第三级（安全标记保护级）特点：
- 监管层级为**监督保护**，由公安机关监督；
- 测评周期：**每年至少一次**等级测评；
- 受破坏后严重损害社会秩序、公共利益或损害国家安全，重要业务系统与 CII 通常不低于三级；
- 技术与管理要求显著高于二级，需集中管控、双因素认证等。

**3. 审计日志六要素与日志保护要求**

六要素：
| 要素 | 说明 |
| ---- | ---- |
| 时间戳 | 精确到秒/毫秒，NTP 同步 |
| 用户 ID | 操作主体唯一标识 |
| 操作类型 | 登录、读、写、删除等 |
| 操作对象 | 被操作的资源 |
| 操作结果 | 成功/失败及原因 |
| 源地址 | 操作发起 IP/主机 |

日志保护主要要求（至少 4 项）：
1. **留存期限**：网络日志留存不少于 6 个月（网安法 + 等保 2.0）；
2. **防篡改**：日志受保护，避免未预期访问、修改、删除（WORM/签名/哈希链）；
3. **异地备份**：关键日志异地备份防本地灾难丢失；
4. **集中管控**：三级及以上系统建立集中日志/审计平台；
5. **权限分离**：审计员与系统管理员权限分离，避免"自己审自己"；
6. **敏感保护**：日志含敏感信息时脱敏、加密传输。

**4. 易失性顺序与勒索事件内存取证优先**

易失性顺序（从高到低）：
CPU 缓存/寄存器 → 内存 → 网络状态 → 进程 → 临时文件 → 磁盘 → 远程日志。

勒索事件断网前优先内存镜像的原因：
- 内存中可能留存**加密密钥残留**、C2 连接、恶意进程、注入代码等关键证据，断电即失；
- 立即断网虽能阻止扩散，但会丢失这些易失证据，影响根因分析与取证；
- 实务中需在 IRP 预先约定：**关键系统先做内存镜像再断网**；扩散风险极高的事件（如勒索）若评估内存取证耗时可控则先取证，否则优先断网；
- 内存镜像需写阻断采集并 SHA-256 校验，纳入证据链登记。

</details>

## 四、案例分析题（3 题）

**1.（三法合规分析）** 阅读以下场景，回答问题：
> 某社交 APP 拥有 5000 万用户，被监管核查发现以下问题：① 首次启动时在用户未点击"同意"前即收集 IMEI 和地理位置；② 社交功能不需精确定位却默认申请精确定位权限；③ 将用户行为数据共享给广告 SDK 未取得单独同意；④ 收集人脸特征用于"滤镜"功能未取得单独同意；⑤ 未提供撤回同意与账户注销入口。APP 服务端部署在境内云平台。

> (1) 上述行为分别违反了《个人信息保护法》的哪些原则或规则？
> (2) 该 APP 若属于关键信息基础设施运营者，还需承担哪些特别义务？
> (3) 列出至少 3 项整改措施以实现合规。

<details>
<summary>案例分析1解答</summary>

**(1) 违反的个保法原则/规则**

| 行为 | 违反内容 |
| ---- | -------- |
| ① 未同意即收集 | 违反**告知同意**规则，处理个人信息应取得个人明确同意 |
| ② 超范围申请精确定位 | 违反**最小必要**原则，收集应限于实现目的的最小范围 |
| ③ 共享广告 SDK 未单独同意 | 向第三方提供个人信息未取得**单独同意** |
| ④ 人脸特征未单独同意 | 处理**敏感个人信息**（生物识别）未取得单独同意 |
| ⑤ 无撤回同意/注销入口 | 违反**个人权利**保障，应提供撤回同意与注销账户方式 |

**(2) 若为 CII 运营者的特别义务**

| 特别义务 | 要点 |
| -------- | ---- |
| 数据本地化 | 在境内运营中收集和产生的个人信息和重要数据应在境内存储 |
| 出境安全评估 | 数据确需跨境提供的，应通过国家网信部门组织的安全评估 |
| 供应链安全审查 | 采购网络产品和服务应通过网络安全审查 |
| 应急演练 | 定期开展网络安全应急演练 |
| 年度测评 | 每年至少进行一次网络安全检测评估 |

**(3) 整改措施（至少 3 项）**

1. **重构同意流程**：确保"先告知、后收集、单独同意敏感信息"，敏感信息（人脸、位置）单独弹窗同意；
2. **最小化授权**：拆分非必要权限，社交功能改用粗略位置或按需申请精确定位；
3. **第三方 SDK 清单化**：列出所有 SDK 及其收集行为，共享行为单独告知并取得同意；
4. **提供撤回与注销入口**：在设置中提供"撤回同意""注销账户"功能；
5. **建立个人信息处理活动记录**：记录处理目的、方式、范围，定期合规审计；
6. **落实数据本地化与出境评估**（若为 CII）：境内存储，出境前通过安全评估。

</details>

**2.（等保测评与日志管理）** 阅读以下场景，回答问题：
> 某市政务审批系统面向公众办理行政审批，存储大量公民身份、办事记录等个人信息，被定为等保第三级。初次测评发现以下不符合项：① 数据库仅口令登录，审计未开启；② 身份证号明文存储；③ 日志分散在各设备，无集中管控；④ 日志仅留存 30 天；⑤ 无安全管理制度与应急演练记录。

> (1) 针对①②，给出技术整改方案。
> (2) 针对③④，设计日志管理整改方案（含留存、防篡改、异地备份）。
> (3) 针对⑤，列出至少 4 项应建立的安全管理制度，并说明应急演练频率要求。

<details>
<summary>案例分析2解答</summary>

**(1) ①② 技术整改方案**

| 不符合项 | 整改方案 |
| -------- | -------- |
| ① 数据库仅口令、审计未开启 | 启用**双因素认证**（口令+令牌/证书）；开启数据库审计并对接日志平台；管理员通过堡垒机登录，会话录像 |
| ② 身份证号明文存储 | 字段级**加密存储**（AES-256，密钥托管 KMS）；展示时**脱敏**（前 6 后 4 掩码）；查询按角色动态脱敏 |

**(2) ③④ 日志管理整改方案**

| 维度 | 整改方案 |
| ---- | -------- |
| 集中管控（③） | 部署 SIEM 平台（如 ELK），统一采集操作系统、数据库、应用、网络设备、安全设备日志；归一化为 CEF 格式 |
| 留存期限（④） | 日志留存**不少于 6 个月**（满足网安法 + 等保 2.0），热数据 30 天 + 冷归档至 12 个月 |
| 防篡改 | 日志实时转发到隔离平台；WORM 不可变存储；哈希链/签名校验 |
| 异地备份 | 关键日志异地实时备份或每日备份至云上冷归档 |
| 权限分离 | 审计员权限与 DBA/系统管理员分离，审计员只读访问日志平台 |

**(3) ⑤ 应建立的安全管理制度与演练频率**

应建立的制度（至少 4 项）：
1. 《信息安全方针书》——顶层方针；
2. 《访问控制管理制度》——最小权限、三权分立、账号生命周期；
3. 《安全审计与日志管理制度》——对接日志整改；
4. 《安全事件应急响应制度》/IRP——对接应急演练；
5. 《密码与密钥管理制度》《变更管理制度》《备份恢复管理制度》《人员安全管理制度》等。

应急演练频率：
- 等保三级要求**定期开展**应急演练，实务中至少**每年一次**实战演练，CII 运营者建议**每半年一次**；
- 演练后形成记录与改进清单，作为测评与监管检查材料。

</details>

**3.（勒索事件应急响应）** 阅读以下场景，回答问题：
> 某制造企业周末被发现 ERP 服务器文件被加密，勒索信要求支付 50 比特币。SIEM 在周五晚曾告警"主机异常 SMB 连接激增"但未处置。备份策略为 3-2-1，其中一份离线备份幸免。经初步排查，攻击者通过钓鱼邮件落地，利用 MS17-010 横向移动。

> (1) 按应急响应六阶段（PICERL）给出该事件的处置流程。
> (2) 说明取证时应在断网前优先做什么，以及证据链的保管要求。
> (3) 列出至少 4 项根因与对应改进措施，并说明是否应支付赎金及理由。

<details>
<summary>案例分析3解答</summary>

**(1) PICERL 六阶段处置流程**

| 阶段 | 操作 |
| ---- | ---- |
| 准备（P） | 启动 IRP，CSIRT 集结；准备取证工具、隔离手段、备份访问 |
| 检测分析（I） | 确认勒索软件事件，调取 SIEM 日志确定扩散范围；定级Ⅲ级 |
| 遏制（C） | 物理断开 ERP 网线；隔离办公网与生产网；禁用受感染账号；封锁 SMB 等横向端口 |
| 根除（E） | 取证镜像后重装系统；重置所有特权账号密码；修补 MS17-010；清查横向植入 |
| 恢复（R） | 从离线备份恢复最近全量+差异；业务验证后分批上线；监控期 7 天 |
| 总结（L） | 复盘根因，更新 IRP 与防护措施，培训宣贯 |

**(2) 断网前取证优先与证据链保管**

断网前优先做**内存镜像**：
- 内存中可能留存加密密钥残留、C2 连接、恶意进程、注入代码等易失证据，断电即失；
- 按易失性顺序，内存优先级高于磁盘；
- 评估内存取证耗时可控则先取证再断网；扩散风险极高时优先断网（勒索事件通常优先断网，但应保留至少一台主机的内存镜像）。

证据链保管要求：
- **完整性**：写阻断采集，SHA-256 校验镜像与原件一致；
- **不可变性**：原始介质只读访问，WORM 存储；
- **链式保管**：每次交接记录时间、人员、介质、目的；
- **合法合规**：取证需有授权，遵守法定程序；
- **登记归档**：证据链登记表全程留痕，便于呈堂。

**(3) 根因与改进措施（至少 4 项）及赎金决策**

| 根因 | 改进措施 |
| ---- | -------- |
| 周末无 7×24 值守，告警延迟 | 建立 7×24 SOC 值守，高危告警自动电话通知 |
| MS17-010 补丁未打 | 补丁 SLA：高危 7 天内全量修复，建立补丁合规看板 |
| 备份部分在线被加密 | 落实 3-2-1 + 不可变备份，关键备份 WORM 锁定 |
| 告警响应 SOP 缺失 | 更新 IRP，明确"勒索告警 5 分钟内必须响应" |
| 邮件安全薄弱 | 部署邮件沙箱，默认禁用宏，加强钓鱼演练 |

是否支付赎金：**不建议支付**。理由：
- 支付不保证获得解密密钥（部分家族不存私钥）；
- 助长黑色产业，可能违反法律法规；
- 本案例有可用离线备份，可从备份恢复；
- 决策应由法务与高管共同评估，优先从备份恢复 + 取证 + 改进。

> [!tip] 复习建议
> - **三法施行日期与保护对象**必背：网安法 2017-06-01 管网络、数安法 2021-09-01 管数据、个保法 2021-11-01 管个人信息；选择题/填空高频考点。
> - **网络运营者义务**重点记：等级保护、日志留存 6 个月、安全事件报告、CII 数据本地化与安全评估。
> - **等保 2.0 五级名称与定级流程**必背：自主→系统审计→安全标记→结构化→访问验证；定级→备案→建设整改→等级测评→监督检查；三级每年测评。
> - **等保 2.0 vs 1.0 区别**：五个扩展（云/移动/物联网/工控/大数据）、主动防御、一个中心三重防御、保留管理要求（注意"取消管理要求"是错误选项）。
> - **审计日志六要素**必背：时间戳、用户 ID、操作类型、操作对象、操作结果、源地址；日志留存 6 个月是法定底线。
> - **PICERL 六阶段**必背：准备-检测分析-遏制-根除-恢复-总结；勒索事件"先隔离、勿付赎金、留证据、从备份恢复"。
> - **证据链与易失性顺序**：CPU 缓存→内存→网络状态→进程→临时文件→磁盘→远程日志；断网前优先内存镜像。
> - **安全管理制度四层体系**：方针→规范→流程→记录；核心制度（访问控制、变更管理、备份恢复）与人员安全（离职零延迟回收权限）。
> - **案例分析题**用"框架答题"：先识别违规点/不符合项→对应法规/标准条款→给整改方案（技术+管理）→列验证指标。
