## 一、选择题（6 题）

**1.** 下列关于云计算服务模式的描述，正确的是（ ）
A. IaaS 提供完整的软件应用，用户无需管理任何基础设施
B. PaaS 在 IaaS 之上提供操作系统和开发工具，用户只需关注应用开发
C. SaaS 提供最基础的虚拟化服务器，用户需要自行搭建所有环境
D. 三种服务模式的管控自由度从高到低依次为：SaaS > PaaS > IaaS

**2.** 大数据的 4V 特征中，"价值密度低"的含义是（ ）
A. 大数据的价值很低，没有实际用途
B. 海量数据中真正有价值的信息占比很小，需要有效筛选和挖掘
C. 大数据的获取成本很低，因此价值也低
D. 只有少量数据有价值，大部分数据应该被丢弃

**3.** 物联网三层架构中，"感知层"的核心功能是（ ）
A. 数据存储和处理
B. 将采集的物理数据转换为数字信号并传输
C. 运行应用程序并提供用户服务
D. 管理网络路由和数据转发

**4.** 下列关于生成式 AI 和传统 AI 的说法，正确的是（ ）
A. 生成式 AI 只能分析已有数据，不能创造新内容
B. 传统 AI 主要用于内容生成，生成式 AI 主要用于数据分析
C. 生成式 AI 能够生成文本、图像、视频等全新内容，是 AI 技术的重大突破
D. 生成式 AI 和传统 AI 没有本质区别，只是数据量更大

**5.** 区块链中，"PoS（权益证明）"共识算法相较于 "PoW（工作量证明）"的主要优势是（ ）
A. 安全性更高，无法被攻击
B. 能耗更低，出块效率更高
C. 完全去中心化，不受任何人控制
D. 可以支持更多的交易并发

**6.** 下列关于用户画像的描述，最准确的是（ ）
A. 用户画像就是收集用户的个人敏感信息
B. 用户画像是基于多维度数据构建的虚拟用户模型，用于精准营销和个性化服务
C. 用户画像只包含人口属性（年龄、性别等静态信息）
D. 用户画像只能用于推荐系统，没有其他应用场景

<details>
<summary>选择题答案</summary>

1. **B**。A 描述的是 SaaS；C 描述的是 IaaS；D 说法错误，管控自由度从高到低是 IaaS > PaaS > SaaS（IaaS 自由度最高，SaaS 自由度最低）。
2. **B**。4V 中的 Value 指价值密度低——数据量大但有价值的信息占比小，需要大数据技术来筛选挖掘。
3. **B**。感知层负责采集物理世界数据（通过传感器、RFID 等）并转换为数字信号；A 是数据层/平台层功能；C 是应用层功能；D 是网络层功能。
4. **C**。生成式 AI 的核心能力是"生成全新内容"，包括文本、图像、视频、代码等，是从"分析"到"创造"的质变。
5. **B**。PoS 不需要矿工进行算力竞赛，能耗远低于 PoW，且出块速度更快（以太坊 2.0 采用 PoS 后 TPS 大幅提升）。但 PoS 存在"富者愈富"的问题。
6. **B**。用户画像是基于多维度数据（人口属性、行为特征、兴趣偏好等）构建的虚拟模型，合法合规使用，应用场景包括推荐、营销、风控、产品优化等。

</details>

## 三、简答题（6 题）

**1.** 简述云计算的三种服务模式（IaaS、PaaS、SaaS）的核心区别，并分别举一个代表产品。

**2.** 大数据处理流程包括哪些主要环节？各环节的核心任务是什么？

**3.** 简述物联网三层架构中各层的核心功能和关键技术。

**4.** 从技术原理和应用场景两个维度，对比生成式 AI 与 AI Agent 的主要区别。

**5.** 简述区块链的核心原理（包括区块结构、哈希指针、共识机制），并说明其如何实现"不可篡改"。

**6.** 分析大数据时代用户画像的构建对互联网产品的意义，以及可能带来的隐私风险和应对措施。

<details>
<summary>简答题答案</summary>

**1. 三种服务模式的核心区别**：

| 模式 | 核心区别 | 代表产品 |
| ---- | -------- | -------- |
| IaaS | 提供虚拟化基础设施（服务器、存储、网络），用户需自行部署OS、中间件、应用 | 阿里云ECS、AWS EC2 |
| PaaS | 在IaaS之上提供OS、中间件、数据库、开发工具等平台，用户只需关注应用开发 | Heroku、阿里云PaaS |
| SaaS | 直接提供可使用的软件应用，用户通过浏览器/App使用，无需安装维护 | 钉钉、飞书、Zoom |

演进规律：抽象层级逐层上升，用户管控自由度逐层降低，专注业务的程度逐层提高。

**2. 大数据处理流程的五个主要环节**：
- **数据采集**：从业务系统日志、用户行为埋点、IoT设备、第三方数据源等采集数据；
- **数据存储**：通过数据仓库（Hive/Redshift）、数据湖（Hudi/Iceberg）、NoSQL数据库存储海量数据；
- **数据处理**：通过批处理（Spark/Hadoop）和流处理（Flink/Kafka）对数据进行清洗、转换和计算；
- **数据分析**：通过BI报表、数据挖掘、机器学习等方法从数据中提取洞察；
- **价值变现**：将分析结果应用于精准推荐、动态定价、风险控制、运营决策等业务场景。

**3. 物联网三层架构**：
- **感知层**：核心功能是采集物理世界数据并转换为数字信号。关键技术包括RFID、传感器、GPS、摄像头、嵌入式设备等；
- **网络层**：核心功能是可靠传输感知层数据到应用层。关键技术包括WiFi、蓝牙、Zigbee、NB-IoT、5G、LoRa等；
- **应用层**：核心功能是数据处理、分析和决策，提供面向用户的应用服务。关键技术包括云计算、边缘计算、AI、IoT平台等。

**4. 生成式AI vs AI Agent**：

| 维度 | 生成式AI | AI Agent |
| ---- | -------- | -------- |
| 技术原理 | 基于Transformer等生成模型，预测下一个token | 基于LLM+规划+工具调用+记忆的智能体系统 |
| 核心能力 | 生成内容（文本、图像、视频、代码） | 自主规划并执行复杂任务 |
| 交互模式 | 被动响应：用户输入→模型输出 | 主动执行：用户给出目标→Agent自主分解任务、调用工具、完成任务 |
| 应用场景 | 内容创作、客服问答、代码辅助 | 自动化办公、调研分析、自主运营 |
| 代表产品 | ChatGPT、Midjourney、GitHub Copilot | AutoGPT、Microsoft Copilot、Devin |

**5. 区块链核心原理**：
- **区块结构**：每个区块包含区块头（上一区块哈希、时间戳、随机数等）和区块体（交易列表）；
- **哈希指针**：每个区块头包含上一区块的哈希值，形成链式结构；
- **共识机制**：通过PoW/PoS等算法，让网络中所有节点就数据一致性达成共识；
- **不可篡改的实现**：如果篡改历史区块，该区块哈希值改变→后续所有区块哈希校验失败→需重新计算之后所有区块并获得网络多数算力认可（51%攻击）→在公有链上几乎不可能实现。

**6. 用户画像的意义与隐私风险**：
- **意义**：
  1. 实现精准推荐和个性化服务，提升用户体验；
  2. 支撑精准营销，提高广告投放效率；
  3. 辅助产品决策，优化产品设计和运营策略；
  4. 增强风控能力，识别欺诈和异常行为。
- **隐私风险**：
  1. 过度收集用户数据，侵犯个人隐私；
  2. 数据泄露可能导致用户信息被滥用；
  3. 用户画像可能被用于价格歧视等不公平行为。
- **应对措施**：
  1. 遵循最小必要原则，只收集必要数据；
  2. 采用数据脱敏、加密存储等技术保护用户数据；
  3. 建立数据治理机制，明确数据使用权限；
  4. 遵守GDPR、《个人信息保护法》等法律法规，保障用户知情权和选择权。

</details>

## 四、案例分析题（4 题）

**1.（云计算案例）** 某电商平台在双11大促期间面临流量洪峰，日PV从平时的500万飙升至5000万。请结合云计算特性分析：
(1) 云计算的哪些特性能帮助电商应对这种突发流量？
(2) 你建议该电商使用公有云、私有云还是混合云？为什么？
(3) 简述从技术选型到实际落地的关键步骤。

<details>
<summary>案例分析1解答</summary>

**(1) 云计算特性应对突发流量**：
- **弹性伸缩**：分钟级扩容/缩容能力。大促前自动扩容10倍服务器，大促后自动缩容，按使用量付费，节省成本；
- **资源池化**：从海量资源池中按需分配，无需提前采购硬件；
- **按需自助服务**：业务团队可直接申请资源，无需等待IT部门审批；
- **可度量的服务**：精确监控每个资源的使用情况，优化成本。

**(2) 建议使用混合云**：
- **公有云**：部署前台网站、订单系统、CDN等需要弹性扩展的业务，利用公有云的弹性能力应对流量洪峰；
- **私有云**：部署支付系统、用户数据等敏感业务，满足数据安全和合规要求；
- **混合云互联**：通过专线或VPN实现公有云和私有云的安全互联，实现数据互通。
- 理由：电商需要同时满足"弹性应对流量"和"保障数据安全"两个需求，混合云是最佳选择。

**(3) 关键步骤**：
1. **容量评估**：基于历史数据预测大促峰值流量，确定需要的资源规模；
2. **架构设计**：设计混合云架构，明确哪些业务部署在公有云、哪些在私有云；
3. **技术选型**：选择云服务商（阿里云/AWS）、网络架构（VPC/专线）、数据库（RDS/Redshift）；
4. **压力测试**：对系统进行全链路压测，验证弹性伸缩能力和系统稳定性；
5. **灰度发布**：逐步切换流量到云环境，观察稳定性；
6. **实时监控**：大促期间实时监控系统指标，随时调整资源配置。

</details>

**2.（大数据案例）** 某零售企业希望通过大数据实现"精准营销"。请分析：
(1) 该企业需要哪些数据来构建用户画像？
(2) 如何设计标签体系支撑精准营销？
(3) 以"618大促"为例，说明大数据如何驱动精准营销全流程。

<details>
<summary>案例分析2解答</summary>

**(1) 构建用户画像需要的数据**：
- **人口属性数据**：年龄、性别、地域、收入水平（可通过会员注册、第三方数据获取）；
- **行为数据**：浏览记录、点击行为、加购行为、购买行为、访问时长、活跃频率（通过埋点SDK采集）；
- **交易数据**：订单金额、购买品类、购买频次、客单价、退换货记录（来自业务系统）；
- **偏好数据**：收藏、分享、评论、关注品牌（来自App/网站交互）；
- **社交数据**：好友关系、社交群组（来自社交功能）；
- **设备数据**：设备类型、操作系统、网络环境（自动采集）。

**(2) 标签体系设计**：
遵循MECE原则，设计四层标签体系：
- **基础标签**：性别（男/女/未知）、年龄段（18-/18-25/26-35/36-45/46+）、地域（省/市/区）；
- **行为标签**：活跃度（高/中/低）、最近购买时间（7天内/30天内/90天内/90天+）、访问频次；
- **偏好标签**：品类偏好（服装/数码/家居/美妆）、品牌偏好、价格敏感度、促销敏感度；
- **模型标签**：高价值客户（基于RFM模型）、流失风险客户、新客/老客、羊毛党识别。

**(3) 618大促精准营销全流程**：
1. **赛前准备**：
   - 基于历史数据预测各品类销售趋势，制定备货和营销策略；
   - 通过大数据分析识别高价值客户、沉睡客户、流失风险客户；
2. **赛中执行**：
   - 实时监控库存和销售数据，动态调整促销策略；
   - 对不同画像用户推送不同优惠券（如对价格敏感用户推送满减券，对品牌忠诚用户推送品牌券）；
   - 实时优化推荐算法，提升转化率；
3. **赛后复盘**：
   - 分析营销ROI，评估各渠道和策略的效果；
   - 基于新数据更新用户画像和标签体系；
   - 形成数据资产，为下次大促积累经验。

</details>

**3.（AI案例）** 某短视频平台的核心竞争力是AI推荐系统。请回答：
(1) 该推荐系统的工作流程包含哪些核心环节？
(2) 如何利用AI实现"千人千面"的推荐效果？
(3) 分析AI推荐系统带来的伦理挑战及应对方案。

<details>
<summary>案例分析3解答</summary>

**(1) 推荐系统的核心工作流程**：
1. **多路召回**：从不同维度（兴趣召回、协同召回、热门召回、社交召回）快速筛选候选集（从百万级→千级）；
2. **粗排**：用轻量级模型（如LR、GBDT）对候选集快速排序（从千级→百级），筛选出最有潜力的内容；
3. **精排**：用复杂深度学习模型（如双塔模型、DIN、DIEN）精确排序（从百级→十级），综合考虑点击率、完播率、互动率等多个目标；
4. **重排**：加入业务规则（多样性、新鲜度、广告、社交内容等）调整最终排序结果；
5. **反馈闭环**：收集用户行为反馈，持续优化模型参数。

**(2) "千人千面"的实现**：
- **用户画像建模**：基于用户的观看历史、点赞、评论、关注等行为数据，构建用户兴趣模型；
- **内容理解**：对每个视频进行AI分析（内容分类、标签提取、关键帧分析、语音转文字等），构建内容特征向量；
- **相似度计算**：计算用户兴趣向量与内容特征向量的相似度，实现精准匹配；
- **多目标优化**：同时优化点击率、完播率、互动率、留存率等多个目标，实现综合最优推荐；
- **实时更新**：用户兴趣实时变化，推荐系统实时更新用户画像和推荐结果。

**(3) 伦理挑战及应对方案**：
| 挑战 | 说明 | 应对方案 |
| ---- | ---- | -------- |
| 信息茧房 | 用户只看到自己感兴趣的内容，视野变窄 | 引入多样性推荐规则，强制加入不同类型内容 |
| 算法偏见 | 训练数据偏见导致推荐内容偏见 | 数据治理、公平性评估、人工审核 |
| 沉迷问题 | 算法优化用户停留时间，可能导致沉迷 | 设置健康使用提醒、未成年模式 |
| 内容安全 | 推荐违规、有害内容 | AI审核+人工审核双重机制 |
| 数据隐私 | 推荐依赖大量用户数据 | 数据脱敏、隐私计算、合规使用 |

</details>

**4.（区块链案例）** 某供应链金融平台计划利用区块链技术解决中小企业融资难题。请回答：
(1) 传统供应链金融存在哪些痛点？
(2) 区块链技术如何解决这些痛点？
(3) 设计一个基于区块链的供应链金融解决方案的核心架构。

<details>
<summary>案例分析4解答</summary>

**(1) 传统供应链金融的痛点**：
- **信息不对称**：金融机构难以核实交易真实性，中小企业资信不足；
- **流程繁琐**：纸质单据流转慢，审核周期长；
- **数据孤岛**：各参与方（核心企业、供应商、物流、银行）数据不互通；
- **风险高**：无法实时监控交易和物流状态，欺诈风险高；
- **成本高**：人工审核、风控成本高，融资利率高。

**(2) 区块链解决痛点的机制**：
| 痛点 | 区块链解决方案 |
| ---- | -------------- |
| 信息不对称 | 核心企业、供应商、物流、银行共享同一分布式账本，交易信息公开透明、不可篡改 |
| 流程繁琐 | 智能合约自动执行融资审批、放款、还款等流程，无需人工干预 |
| 数据孤岛 | 所有参与方在联盟链上共享数据，打破信息壁垒 |
| 风险高 | 链上可追溯完整交易链，结合物联网数据（GPS、温度传感器）实现实物监控 |
| 成本高 | 自动化流程降低人工成本，风险降低后融资利率下降 |

**(3) 核心架构设计**：
- **参与方**：核心企业（如大型制造商）、供应商（中小企业）、物流企业、商业银行、监管机构；
- **联盟链平台**：基于Hyperledger Fabric或蚂蚁链构建联盟链；
- **核心功能模块**：
  1. **订单存证**：核心企业与供应商的采购订单上链存证；
  2. **物流追踪**：物流企业的运输数据（GPS、签收记录）上链；
  3. **发票存证**：电子发票上链，确保交易真实性；
  4. **智能合约**：
     - 融资申请合约：供应商发起融资申请，系统自动核账；
     - 自动放款合约：审核通过后银行自动放款到供应商账户；
     - 自动还款合约：应收账款到期后自动还款；
  5. **风控模块**：基于链上数据+机器学习模型，实时评估融资风险；
- **技术集成**：与ERP系统对接实现订单数据同步，与IoT设备对接实现物流实时监控。

</details>
