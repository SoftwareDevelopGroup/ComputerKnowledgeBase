# 5.1 云存储体系架构

> [!abstract] 本节导读
> 云存储不是单一技术，而是一个完整的技术体系。本节从块存储、文件存储、对象存储三大类型的分层架构出发，系统对比其特性、接口与适用场景，深入剖析 Ceph 分布式存储的 RADOS、CRUSH、Monitor、OSD 核心架构，最后介绍 OpenStack 存储三件套（Cinder、Manila、Swift）的定位与协作。

### 存储类型对比


### 详细对比表

| 维度 | 块存储 (Block) | 文件存储 (File) | 对象存储 (Object) |
|-----|---------------|----------------|-------------------|
| **数据组织** | 扇区/块 (512B-4KB) | 目录/文件 | 对象 (Key-Value) |
| **访问接口** | 块设备 `/dev/sda` | POSIX 文件系统 | HTTP REST API |
| **共享能力** | 单主机独占（可多路径） | 多主机共享 | 多主机并发访问 |
| **性能** | 最高（微秒级延迟） | 中等（毫秒级） | 较低（毫秒级） |
| **扩展性** | 垂直扩展为主 | 有限水平扩展 | 无限水平扩展 |
| **典型协议** | iSCSI, FC, SATA | NFS, SMB, CIFS | S3, OSS, Swift API |
| **典型产品** | AWS EBS, 阿里云云盘 | AWS EFS, 阿里云NAS | AWS S3, 阿里云OSS |
| **适用场景** | 数据库、VM 系统盘 | 共享文件、日志目录 | 海量数据、备份归档 |
| **成本** | 最高 | 中等 | 最低 |

## 二、Ceph 分布式存储

### RADOS 架构

> [!definition] RADOS
> RADOS（Reliable Autonomous Distributed Object Store）是 Ceph 的核心存储引擎，实现了可靠、自主的分布式对象存储。

```mermaid
graph TB
    subgraph "RADOS 核心机制"
        direction TB
        Obj["对象<br/>→ 固定大小<br/>→ 按PG组织"]
        PG["放置组 PG<br/>→ 逻辑分组<br/>→ 映射到OSD"]
        OSD_Daemon["OSD 守护进程<br/>→ 数据管理<br/>→ 复制/恢复"]
        Crush["CRUSH 算法<br/>→ 数据分布<br/>→ 无表查找"]
    end

    subgraph "数据路径"
        direction TB
        Client[客户端] -->|"读写请求"| OSD_Daemon
        OSD_Daemon -->|"CRUSH 计算<br/>PG→OSD映射"| Crush
        OSD_Daemon -->|"数据复制"| Replica1[副本OSD]
        OSD_Daemon -->|"数据复制"| Replica2[副本OSD]
    end

    Obj --> PG
    PG --> OSD_Daemon
    Crush --> OSD_Daemon

    style Obj fill:#FF5722,color:#fff
    style PG fill:#FF9800,color:#fff
    style OSD_Daemon fill:#4CAF50,color:#fff
    style Crush fill:#2196F3,color:#fff
```

**RADOS 核心特性**：
- **自主**：无需中心节点，每个 OSD 自主管理数据
- **可靠**：多副本机制，支持故障自动恢复
- **分布式**：数据均匀分布在所有 OSD 上
- **可扩展**：线性扩展，EB 级规模

### CRUSH 算法

> [!definition] CRUSH
> CRUSH（Controlled Replication Under Scalable Hashing）是 Ceph 的核心数据分布算法，无需查表即可计算数据的存储位置。

```mermaid
graph TB
    subgraph "CRUSH 数据放置流程"
        direction TB
        Input["输入: 对象ID + 规则"] --> Hash["哈希函数<br/>→ 确定性映射"]
        Hash --> PG["映射到 PG<br/>→ pg_pool((object_id) % pg_num)"]
        PG --> CrushFunc["CRUSH 函数<br/>→ 选择OSD"]
        CrushFunc --> OSD_Result["输出: OSD 列表<br/>→ 主副本 + 副本"]
    end

    subgraph "层级结构"
        direction TB
        Root["Root"]
        Root --> Rack1["机架1"]
        Root --> Rack2["机架2"]
        Rack1 --> Host1["主机1<br/>OSD 0,1,2"]
        Rack1 --> Host2["主机2<br/>OSD 3,4,5"]
        Rack2 --> Host3["主机3<br/>OSD 6,7,8"]
        Rack2 --> Host4["主机4<br/>OSD 9,10,11"]
    end

    OSD_Result --> Host1
    OSD_Result --> Host2
    OSD_Result --> Host3

    style Input fill:#FF5722,color:#fff
    style Hash fill:#FF9800,color:#fff
    style CrushFunc fill:#2196F3,color:#fff
    style OSD_Result fill:#4CAF50,color:#fff
```

**CRUSH vs 一致性哈希**：

| 维度 | CRUSH | 一致性哈希 |
|-----|-------|-----------|
| **查找方式** | 无需查表，O(1)计算 | 需维护哈希环 |
| **元数据** | 无 | 需要 |
| **副本放置** | 支持复杂规则（机架/主机） | 简单映射 |
| **故障处理** | 有规则约束的副本迁移 | 单节点影响 |
| **负载均衡** | 均匀分布 | 基本均匀 |

## 四、小结

> [!summary] 本节要点回顾
> 1. **存储三层**：块存储（高性能、单主机）、文件存储（共享、POSIX）、对象存储（海量、HTTP API）
> 2. **Ceph 架构**：Monitor（集群管理）+ OSD（数据存储）+ MDS（文件元数据）+ RGW（对象网关）
> 3. **RADOS**：Ceph 的可靠自主分布式对象存储引擎
> 4. **CRUSH**：无表查找的数据分布算法，支持复杂故障域规则
> 5. **OpenStack 三件套**：Cinder（块）、Manila（文件）、Swift（对象），可基于 Ceph 统一部署
