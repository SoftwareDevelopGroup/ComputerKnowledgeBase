<details>
<summary>四、简答题答案与解析</summary>

23. **参考答案**：
    - **IaaS**：提供计算/存储/网络等基础设施，用户可控 OS 及以上，可控范围最大；
    - **PaaS**：提供运行平台与开发环境，OS 由云管，用户可控应用与数据，可控范围居中；
    - **SaaS**：提供完整应用，用户仅使用，可控范围最小。

24. **参考答案**：云原生四大核心特征：①容器（轻量封装与隔离）；②微服务（应用拆分为独立服务）；③DevOps（开发运维一体化）；④持续交付（CI/CD 自动化发布）。

25. **参考答案**：
    - **kube-apiserver**：集群统一 API 入口；
    - **kube-scheduler**：调度 Pod 到合适节点；
    - **kube-controller-manager**：运行控制器维持期望状态；
    - **etcd**：分布式键值存储集群状态；
    - **kubelet**：节点上管理 Pod 生命周期；
    - **kube-proxy**：节点网络代理与服务负载均衡。

26. **参考答案**：Service Mesh（如 Istio）分为数据面与控制面。数据面由 Sidecar 代理（Envoy）以独立容器伴随每个服务实例，拦截所有进出流量，执行熔断、限流、负载均衡、加密与可观测采集；控制面（Istiod）统一下发策略配置。业务代码只关心业务逻辑，通信治理全部由 Sidecar 承担，实现解耦。

27. **参考答案**：分布式云是 Gartner 提出的概念，指将公有云服务分布到不同物理位置（含边缘、本地、区域），并由云服务商统一管理运维。区别：传统混合云是用户自管私有云+公有云，管理割裂；分布式云由云商统一管理，消除割裂；与边缘计算相比，分布式云是公有云向边缘的延伸，仍归属云商统一控制面，边缘计算更强调边缘侧能力本身。

<summary>五、计算题/分析题答案与解析</summary>

28. **参考解答**：
    每次执行内存 = 512 MB = 0.5 GB，耗时 200 ms = 0.2 s。
    单次计算费用 = 0.5 GB × 0.2 s × 0.00001667 元/(GB·s) = 0.000001667 元
    单次请求费 = 0.0000013 元
    单次总费用 = 0.000001667 + 0.0000013 = 0.000002967 元
    月度成本 = 5,000,000 × 0.000002967 ≈ 14.835 元
    **优势分析**：Serverless 按调用计费、空闲不计费，在低负载或突发流量场景下成本远低于常驻服务器（后者需持续付费无论是否调用）；但高稳态负载下 Serverless 可能更贵，需结合流量特征选型。

29. **参考解答**：
    每 Pod 2 核/4 GB；每节点可容纳：CPU 限制 16/2 = 8 个，内存限制 64/4 = 16 个，取小者 = 8 个 Pod/节点。
    3 节点最大容纳 = 3 × 8 = 24 个 Pod ≥ 20，**能容纳**全部 20 副本。
    若考虑系统预留与节点污点，实际可用略低；20 副本最少需 ⌈20/8⌉ = 3 个节点。
    **调度约束**：kube-scheduler 需考虑资源请求（CPU/内存）、节点选择器/亲和性、污点与容忍、反亲和（Pod 分散）、存储/网络卷等。

30. **参考解答**：
    - 方案 A 端到端时延 = 传输 120 ms + 推理 30 ms = 150 ms；
    - 方案 B 端到端时延 = 传输 10 ms + 推理 35 ms = 45 ms。
    **选择分析**：从时延看，方案 B（45 ms）远优于方案 A（150 ms），满足自动驾驶低时延要求；从带宽看，方案 A 需上传 100 MB/s 大量数据，回传带宽压力巨大，方案 B 本地处理大幅节省带宽；从隐私看，方案 B 数据不出车，本地化更安全。故应选方案 B（边缘云本地推理）。

</details>

<details>
<summary>六、实操题/论述题答案与解析</summary>

31. **参考要点**：
    - 绘制云原生技术栈分层：基础设施层 → 容器运行时（containerd）→ 编排层（Kubernetes 为核心）→ 服务网格/应用治理层（Istio）→ 可观测层（Prometheus/Grafana）→ 应用层（微服务）。
    - Kubernetes 核心地位：作为编排标准，统一调度容器化微服务，向下管理节点资源，向上支撑服务网格与 CI/CD。
    - Service Mesh 解耦：Sidecar 代理拦截流量，熔断/限流/可观测由 Sidecar 执行，业务代码不感知，治理策略由控制面动态下发，实现业务与治理分离。

32. **参考要点**：
    - 区别：混合云是用户自管私有云+公有云组合，管理割裂；分布式云由云商统一管理分布在不同位置的公有云服务；边缘计算强调边缘能力本身，可独立于公有云。
    - 联系：分布式云是公有云向边缘/本地的延伸，融合了边缘计算的低时延与公有云的统一管理。
    - 5G+边缘云案例（智慧港口远程龙门吊）：5G URLLC 提供低时延高可靠连接，MEC 边缘云在港口本地部署推理算力，操作员远程实时控制龙门吊，端到端时延 < 20 ms；切片隔离保障控制数据安全，本地处理保护港口数据不出园区。

</details>
