# 6.1 NoSQL数据库概述

> [!abstract] 核心问题
> NoSQL数据库有哪些分类？各有什么特点？

## 一、NoSQL概述

### 1. NoSQL的定义

**定义**：NoSQL（Not Only SQL）是指非关系型数据库。

**设计目标**：

| 目标 | 说明 |
|-----|------|
| **高扩展性** | 支持水平扩展 |
| **高性能** | 高性能读写 |
| **灵活数据模型** | 支持灵活的数据模型 |
| **分布式存储** | 支持分布式存储 |

**适用场景**：

| 场景 | 说明 |
|-----|------|
| **海量数据存储** | 存储海量数据 |
| **实时读写** | 实时数据读写 |
| **灵活数据模型** | 需要灵活的数据模型 |
| **高并发** | 高并发访问 |

### 2. NoSQL与传统数据库的对比

**对比表**：

| 对比项 | 传统数据库 | NoSQL |
|-------|-----------|-------|
| **数据模型** | 关系型 | 非关系型 |
| **扩展性** | 垂直扩展 | 水平扩展 |
| **事务支持** | ACID | 最终一致性 |
| **查询语言** | SQL | 多种查询方式 |
| **数据一致性** | 强一致性 | 弱一致性 |

## 二、NoSQL分类

### 1. 键值存储

**定义**：键值存储是最简单的NoSQL数据库，以键值对形式存储数据。

**特点**：

| 特点 | 说明 |
|-----|------|
| **简单** | 数据模型简单 |
| **高性能** | 高性能读写 |
| **扩展性好** | 扩展性好 |

**代表产品**：

| 产品 | 说明 |
|-----|------|
| **Redis** | 内存键值存储 |
| **Memcached** | 分布式缓存 |
| **DynamoDB** | AWS键值存储 |

**应用场景**：

| 场景 | 说明 |
|-----|------|
| **缓存** | 缓存热点数据 |
| **会话管理** | 管理用户会话 |
| **实时计数器** | 实时统计计数 |

### 2. 文档存储

**定义**：文档存储是以文档形式存储数据，文档通常是JSON或BSON格式。

**特点**：

| 特点 | 说明 |
|-----|------|
| **灵活** | 数据模型灵活 |
| **支持查询** | 支持复杂查询 |
| **适合半结构化数据** | 适合半结构化数据 |

**代表产品**：

| 产品 | 说明 |
|-----|------|
| **MongoDB** | 文档数据库 |
| **CouchDB** | 文档数据库 |
| **Cosmos DB** | Azure文档数据库 |

**应用场景**：

| 场景 | 说明 |
|-----|------|
| **内容管理** | 管理内容数据 |
| **用户数据** | 存储用户数据 |
| **日志存储** | 存储日志数据 |

### 3. 列存储

**定义**：列存储是以列为单位存储数据。

**特点**：

| 特点 | 说明 |
|-----|------|
| **列式存储** | 按列存储数据 |
| **适合数据分析** | 适合数据分析 |
| **压缩率高** | 压缩率高 |

**代表产品**：

| 产品 | 说明 |
|-----|------|
| **HBase** | 分布式列式数据库 |
| **Cassandra** | 分布式列式数据库 |
| **BigTable** | Google列式数据库 |

**应用场景**：

| 场景 | 说明 |
|-----|------|
| **大数据存储** | 存储海量数据 |
| **实时读写** | 实时数据读写 |
| **日志存储** | 存储日志数据 |

### 4. 图存储

**定义**：图存储是以图结构存储数据，适合存储关系型数据。

**特点**：

| 特点 | 说明 |
|-----|------|
| **图结构** | 以图结构存储数据 |
| **适合关系数据** | 适合存储关系型数据 |
| **支持图查询** | 支持图查询语言 |

**代表产品**：

| 产品 | 说明 |
|-----|------|
| **Neo4j** | 图数据库 |
| **OrientDB** | 图数据库 |
| **JanusGraph** | 分布式图数据库 |

**应用场景**：

| 场景 | 说明 |
|-----|------|
| **社交网络** | 存储社交关系 |
| **推荐系统** | 构建推荐系统 |
| **知识图谱** | 构建知识图谱 |

### 5. NoSQL分类对比

**对比表**：

| 分类 | 代表产品 | 特点 | 适用场景 |
|-----|---------|------|---------|
| **键值存储** | Redis | 简单、高性能 | 缓存、会话管理 |
| **文档存储** | MongoDB | 灵活、支持查询 | 内容管理、用户数据 |
| **列存储** | HBase | 列式、适合分析 | 大数据存储、实时读写 |
| **图存储** | Neo4j | 图结构、适合关系 | 社交网络、推荐系统 |

## 三、NoSQL特点

### 1. 高扩展性

**扩展性**：

| 扩展性 | 说明 |
|-------|------|
| **水平扩展** | 通过增加节点扩展 |
| **线性扩展** | 性能随节点数量线性增长 |
| **自动分片** | 自动分片数据 |

**示例**：

```
Redis集群：通过增加节点扩展
MongoDB分片：自动分片数据
HBase：通过增加RegionServer扩展
```

### 2. 高性能

**性能特点**：

| 特点 | 说明 |
|-----|------|
| **内存存储** | 数据存储在内存中 |
| **分布式处理** | 分布式处理数据 |
| **异步写入** | 异步写入数据 |

**示例**：

```
Redis：内存存储，读写速度快
MongoDB：内存映射，查询速度快
HBase：内存缓存，读写速度快
```

### 3. 灵活数据模型

**数据模型**：

| 模型 | 说明 |
|-----|------|
| **无Schema** | 不需要预定义Schema |
| **动态字段** | 可以动态添加字段 |
| **嵌套结构** | 支持嵌套结构 |

**示例**：

```json
{
    "id": 1,
    "name": "Alice",
    "age": 25,
    "address": {
        "city": "Beijing",
        "street": "Main Street"
    },
    "hobbies": ["reading", "coding"]
}
```

### 4. 分布式存储

**存储特点**：

| 特点 | 说明 |
|-----|------|
| **数据分片** | 数据分散存储在多个节点 |
| **数据复制** | 数据多副本存储 |
| **故障恢复** | 自动故障恢复 |

**示例**：

```
HBase：数据存储在HDFS上
MongoDB：数据存储在多个节点上
Cassandra：数据复制到多个节点
```

## 四、NoSQL适用场景

### 1. 适用场景

**场景**：

| 场景 | 说明 |
|-----|------|
| **海量数据存储** | 存储海量数据 |
| **实时读写** | 实时数据读写 |
| **灵活数据模型** | 需要灵活的数据模型 |
| **高并发** | 高并发访问 |
| **分布式系统** | 分布式系统 |

### 2. 不适用场景

**场景**：

| 场景 | 说明 |
|-----|------|
| **复杂事务** | 需要复杂事务处理 |
| **复杂查询** | 需要复杂SQL查询 |
| **强一致性** | 需要强一致性保证 |

## 五、NoSQL选择指南

### 1. 选择因素

**因素**：

| 因素 | 说明 |
|-----|------|
| **数据模型** | 数据的结构和关系 |
| **读写模式** | 读多还是写多 |
| **数据规模** | 数据的规模 |
| **一致性要求** | 一致性要求 |
| **查询复杂度** | 查询的复杂度 |

### 2. 选择建议

**建议**：

| 场景 | 推荐数据库 |
|-----|-----------|
| **缓存** | Redis |
| **内容管理** | MongoDB |
| **大数据存储** | HBase |
| **社交网络** | Neo4j |
| **实时分析** | Cassandra |

> [!warning] 易错点
> NoSQL不是替代SQL！而是补充SQL，两者各有适用场景。
